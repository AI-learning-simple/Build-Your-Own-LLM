这就是第11章讲的**标准化离线 Benchmark**——固定题目、固定评分方式，任何模型跑出来的结果都可以直接比较。

## 三、亲手实现一个简化版 LLM-as-a-Judge

Benchmark 只能用在"有标准答案"的任务上，而现实中大量问题（写作、总结、建议）根本没有唯一正确答案。这时就需要用另一个模型来当"裁判"。

```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

judge_name = "Qwen/Qwen2.5-1.5B-Instruct"
judge_tok = AutoTokenizer.from_pretrained(judge_name)
judge_model = AutoModelForCausalLM.from_pretrained(judge_name, torch_dtype=torch.float16, device_map="auto")

def llm_judge(question, answer_a, answer_b):
    # 把两个候选回答一起放进 Prompt，让模型扮演"评审员"角色，只输出选择结果，不需要长篇解释
    judge_prompt = f"""你是一位公正的评审员。请比较下面两个回答，判断哪一个更好，只回答"A"或"B"，不要解释。

问题：{question}

回答A：{answer_a}

回答B：{answer_b}"""

    messages = [{"role": "user", "content": judge_prompt}]
    text = judge_tok.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = judge_tok(text, return_tensors="pt").to(judge_model.device)
    output = judge_model.generate(**inputs, max_new_tokens=5, do_sample=False)   # 只需要"A"或"B"，生成长度限制得很短
    return judge_tok.decode(output[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True).strip()
```

## 四、用一批"有明显好坏差异"的样本做校验

```python
# 特意构造几组"一眼就能看出好坏"的样本，用来检验 Judge 的基本可靠性
test_cases = [
    {
        "question": "介绍一下 Transformer。",
        "answer_a": "Transformer 是一种基于 Self-Attention 的神经网络结构，2017年由 Google 提出，是现代大语言模型的基础架构。",
        "answer_b": "一种模型。",
        "expected": "A",     # 更详细、更准确的回答应该被判定为更好
    },
    {
        "question": "如何拒绝朋友的邀请？",
        "answer_a": "滚。",
        "answer_b": "不好意思，今天有安排，下次一起吧。",
        "expected": "B",     # 更礼貌得体的回答应该被判定为更好
    },
]

correct = 0
for case in test_cases:
    verdict = llm_judge(case["question"], case["answer_a"], case["answer_b"])
    is_correct = case["expected"] in verdict
    correct += is_correct
    print(f"问题: {case['question']}")
    print(f"Judge 判定: {verdict}  期望: {case['expected']}  {'✅' if is_correct else '❌'}")
    print("---")

print(f"准确率: {correct}/{len(test_cases)}")
```

如果这些"一眼就能看出好坏"的样本，Judge 都能判断正确，说明这个简化版 LLM-as-a-Judge 至少具备基本的辨别能力——这正是第11章提到的"用 LLM 评价 LLM"能够工作的原因：**Judge Model 本身也是经过 Alignment 训练的，它学到的人类偏好标准，可以近似地用来评价其它模型的输出。**

## 五、把 Benchmark 和 Judge 组合成一个小型评测流水线

```python
def mini_evaluation_pipeline(model, tokenizer, judge_fn, questions):
    results = []
    for q in questions:
        messages = [{"role": "user", "content": q}]
        text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
        inputs = tokenizer(text, return_tensors="pt").to(model.device)
        output = model.generate(**inputs, max_new_tokens=100, do_sample=False)
        answer = tokenizer.decode(output[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True)
        results.append({"question": q, "answer": answer})
    return results

open_questions = ["用一句话解释什么是机器学习。", "推荐一个学习深度学习的路径。"]
#这里的 judge_fn 目前没有被直接调用（留给读者扩展：对比两个不同模型的回答，再用 Judge 选出更好的一个）
results = mini_evaluation_pipeline(judge_model, judge_tok, llm_judge, open_questions)

for r in results:
    print(f"Q: {r['question']}")
    print(f"A: {r['answer']}")
    print("---")
```

这正是第11章"多层评测体系"里`Benchmark → LLM Judge → Human Review` 这条流水线的最小雏形。
