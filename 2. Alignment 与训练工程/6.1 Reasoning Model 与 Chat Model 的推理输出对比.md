```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

# 一个是专门蒸馏训练过"长推理"能力的模型，一个是普通的 Instruct 对话模型
reasoning_name = "deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B"
chat_name = "Qwen/Qwen2.5-1.5B-Instruct"

reasoning_tok = AutoTokenizer.from_pretrained(reasoning_name)
reasoning_model = AutoModelForCausalLM.from_pretrained(reasoning_name, torch_dtype=torch.float16, device_map="auto")

chat_tok = AutoTokenizer.from_pretrained(chat_name)
chat_model = AutoModelForCausalLM.from_pretrained(chat_name, torch_dtype=torch.float16, device_map="auto")
```

两个模型参数量接近，但 `DeepSeek-R1-Distill-Qwen-1.5B` 是在 DeepSeek-R1 生成的大量长推理轨迹上蒸馏训练出来的——它的训练目标里显式包含"如何思考"，而不只是"如何回答"。

## 二、同一道推理题，两种表现

```python
question = "一个房间里有 3盏灯，每盏灯的开关都连接着房间外的一个开关，你只能进房间一次，如何确定每个开关对应哪盏灯？"

def ask(model, tok, question, max_new_tokens=500):
    messages = [{"role": "user", "content": question}]
    # 用各自模型专属的 Chat Template 格式化输入
    text = tok.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = tok(text, return_tensors="pt").to(model.device)
    output = model.generate(**inputs, max_new_tokens=max_new_tokens, do_sample=False)
    # 只解码"新生成"的部分，跳过原始输入的Token
    return tok.decode(output[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True)

print("========== Chat Model ==========")
print(ask(chat_model, chat_tok, question))

print("\n========== Reasoning Model ==========")
print(ask(reasoning_model, reasoning_tok, question))
```

运行后仔细对比两段输出：Chat Model 通常会给出一个相对简短的答案，可能直接给出结论或者简单几步推理；Reasoning Model 则会输出一段明显更长、更"啰嗦"的思考过程（通常包裹在 `<think>...</think>` 标签里），里面会出现反复假设、自我怀疑、推翻重来的痕迹，最后才收敛到答案。

## 三、把"思考"和"答案"分离出来看

```python
import re

def split_thinking(text):
    # Reasoning Model 通常会把内部思考过程包裹在 <think></think> 标签中，答案在标签之后
    match = re.search(r"<think>(.*?)</think>(.*)", text, re.S)
    if match:
        return match.group(1).strip(), match.group(2).strip()   # (思考过程, 最终答案)
    return None, text.strip()   # 没有检测到 think 标签，说明这不是一个标准的 Reasoning 输出

full_output = ask(reasoning_model, reasoning_tok, question)
thinking, answer = split_thinking(full_output)

print("=== 思考过程（节选前300字）===")
print(thinking[:300] if thinking else "（未检测到 think 标签）")
print("\n=== 最终答案 ===")
print(answer)
```

## 四、一个简化版 Verifier：只关心结果，不关心过程

第6章提到过 Process Supervision（监督整个推理过程）与 Outcome Supervision（只监督最终答案）的区别。我们实现一个最简单的 Outcome Verifier，用于批量测试：

```python
math_questions = [
    {"q": "小明有15个苹果，送给小红6个，又买回来9个，现在有多少个？", "answer": "18"},
    {"q": "一个长方形长8米宽5米，面积是多少平方米？", "answer": "40"},
]

def extract_number(text):
    # 从模型输出的文本里，找出所有数字，取最后一个作为"最终答案"
    # （通常模型会把结论放在推理过程之后，因此最后一个数字更可能是答案）
    numbers = re.findall(r"-?\d+\.?\d*", text)
    return numbers[-1] if numbers else None

for item in math_questions:
    chat_ans = ask(chat_model, chat_tok, item["q"], max_new_tokens=150)
    reason_ans = ask(reasoning_model, reasoning_tok, item["q"], max_new_tokens=500)

    chat_num = extract_number(chat_ans)
    reason_num = extract_number(reason_ans)

    print(f"题目: {item['q']}")
    print(f"标准答案: {item['answer']}")
    print(f"Chat Model 提取答案: {chat_num}  {'✅' if chat_num == item['answer'] else '❌'}")
    print(f"Reasoning Model 提取答案: {reason_num}  {'✅' if reason_num == item['answer'] else '❌'}")
    print("---")
```

这个 Verifier 只检查最终数字对不对——这正是 Outcome Supervision 最朴素的实现方式；而真正的 Process Supervision 需要对"思考过程里的每一步"分别打分，这在训练 Reasoning Model 时通常需要另一个专门的 Process Reward Model，成本要高得多。
