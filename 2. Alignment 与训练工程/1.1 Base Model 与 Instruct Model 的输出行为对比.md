# 1.1 基础模型（Base Model）与指令模型（Instruct Model）的输出行为对比

> **本节目标**：比较同一家族的 Base 与 Instruct 版本，观察后训练如何影响指令跟随与输出格式。先固定原始输入，再为 Instruct 使用推荐的 Chat Template；这个小实验展示行为差异，不能证明 Base 不会执行任何指令，也不能证明两个版本的知识完全相同。
>
> **硬件要求**：每个模型约 5 亿参数。下例优先使用 CUDA，没有 CUDA 时用 CPU + FP32；两个模型同时常驻需要数 GB 内存及额外运行空间，CPU 生成可能较慢。显卡容量、软件版本和生成长度都会影响能否运行。若同时加载两个 FP16 模型仍然显存不足，可用下文介绍的 **int8 量化加载**（需 NVIDIA GPU 与 `bitsandbytes`）把权重占用降到约一半；显卡依旧放不下时请分别加载两个模型。

## 一、准备工作

```bash
pip install torch transformers accelerate bitsandbytes
```

> `bitsandbytes` 只在需要 int8 量化加载时使用；它依赖 CUDA，CPU 环境会退回非量化加载。

> 下载模型的网络说明见《开始之前（前言）》**P0.5 模型与网络（国内访问）**；硬件分级见 **P0.3**，版本与 API 兼容性说明见 **P0.6**。

我们选择 `Qwen2.5-0.5B`（Base）和 `Qwen2.5-0.5B-Instruct`（Instruct）：它们家族与参数规模相同，后者经过指令后训练，但**参数数量相同不等于权重或知识相同**。这里加载公开权重，不沿用第一部分 nanoGPT 的 checkpoint。

> **术语说明**：`Instruct Model` 是 `Aligned Model` 的一个实例——第 1 章第二节给出过这两个术语的定义。本节标题用 `Instruct` 而不是 `Aligned`，是因为这里对比的只是"指令微调后"这一种后训练产物；它不能代表偏好学习、推理对齐、安全对齐等其他对齐方法的效果。

下面使用常见的 Transformers 4.x 加载接口；环境需支持 Qwen2.5，新版本可能提示用 `dtype` 替代 `torch_dtype`。正式复现应固定软件版本和模型 revision，而不是假设任何版本都兼容。

```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig

base_name = "Qwen/Qwen2.5-0.5B"
chat_name = "Qwen/Qwen2.5-0.5B-Instruct"

if torch.cuda.is_available():
    # int8 量化加载：权重按 8 bit 存储，推理时按需反量化，显存约为 FP16 的一半
    load_kwargs = dict(
        quantization_config=BitsAndBytesConfig(load_in_8bit=True),
        device_map="auto",  # 量化模型由 accelerate 分配设备，之后不能再调用 .to()
        # int8 矩阵乘只支持 FP16；显式指定可避免 bf16 激活反复转换并刷警告
        torch_dtype=torch.float16,
    )
else:
    # bitsandbytes 的 int8 加载依赖 CUDA，CPU 环境退回 FP32
    load_kwargs = dict(torch_dtype=torch.float32)

base_tok = AutoTokenizer.from_pretrained(base_name)
base_model = AutoModelForCausalLM.from_pretrained(base_name, **load_kwargs).eval()

chat_tok = AutoTokenizer.from_pretrained(chat_name)
chat_model = AutoModelForCausalLM.from_pretrained(chat_name, **load_kwargs).eval()
```

**关于 int8 加载**：

- 量化模型**不能**再调用 `.to(device)`，设备由 `device_map="auto"` 决定；`generate_raw` 用 `model.device` 搬运输入，依然有效。
- 两个模型应使用**相同**的量化配置，这样对比的是 Base / Instruct 的行为差异，而不是量化误差。int8 会带来少量数值偏差，不要把本次输出与之前 FP16 的输出逐字比较。
- 8 bit 仍不够时，可换成 4 bit：`BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4", bnb_4bit_compute_dtype=torch.float16)`；精度损失会更大，结论需要更谨慎。
- 量化只降低推理显存，不改变模型参数与词表；因此 Chat Template 与解码流程无需改动。

**关于 `MatMul8bitLt: inputs will be cast from torch.bfloat16 to float16 during quantization`**：

Qwen2.5 的权重默认声明为 `bfloat16`，而 bitsandbytes 的 int8 矩阵乘内核只接受 `float16`，于是每层、每次前向都会打印这条警告，几百行都来自它。上面的 `torch_dtype=torch.float16` 让激活直接以 FP16 进入内核，警告随之消失，也省掉了每次前向的重复转换。

如果确实要保留 `bfloat16`（例如担心 FP16 溢出），可以在加载前静默该日志，但它只是不再刷屏，转换开销仍然存在：

```python
import logging
logging.getLogger("bitsandbytes").setLevel(logging.ERROR)
```

## 二、用完全相同的原始文本对比

先不用任何 Chat Template，直接把同一句话喂给两个模型，看它们如何"续写"：

```python
@torch.inference_mode()
def generate_raw(model, tok, prompt, max_new_tokens=128):
    inputs = tok(prompt, add_special_tokens=False, return_tensors="pt").to(model.device)
    output = model.generate(
        **inputs, max_new_tokens=max_new_tokens, do_sample=False,
        pad_token_id=tok.eos_token_id,
    )
    generated = output[0, inputs["input_ids"].shape[1]:]
    return tok.decode(generated, skip_special_tokens=True)

prompt = "帮我写一封请假邮件。"

print("=== Base Model ===")
print(generate_raw(base_model, base_tok, prompt))

print("\n=== Instruct Model（未使用 Chat Template）===")
print(generate_raw(chat_model, chat_tok, prompt))
```

此处只解码新增 Token，不把输入原样算作输出。Instruct 若不用训练时的对话格式，表现可能变差，但并非必然失去指令跟随能力；请记录实际输出，而不是预设哪个模型一定失败。

## 三、用正确的 Chat Template 再对比一次

```python
messages = [{"role": "user", "content": prompt}]
# add_generation_prompt=True 在末尾补上 assistant 开始回答的标记
chat_input = chat_tok.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)

print("\n=== Instruct Model（使用 Chat Template）===")
print(generate_raw(chat_model, chat_tok, chat_input))
```

检查这次输出是否更直接地完成了邮件任务。`generate_raw` 用 `add_special_tokens=False` 编码已经渲染的模板，避免重复加入特殊 Token；生成仍是自回归续写，只是输入格式更符合 Instruct 的训练分布。

## 四、多组Prompt 批量对比

```python
prompts = [
    "帮我写一封请假邮件。",
    "介绍一下 Transformer。",
    "1+1等于几？",
    "把这句话翻译成英文：今天天气真好。",
]

for p in prompts:
    print(f"\n########## Prompt: {p} ##########")

    print("\n--- Base ---")
    # Base Model 全程不使用 Chat Template，直接续写原始文本
    print(generate_raw(base_model, base_tok, p, max_new_tokens=128))

    chat_p = chat_tok.apply_chat_template([{"role": "user", "content": p}], tokenize=False, add_generation_prompt=True)
    print("\n--- Instruct（chat templates）---")
    print(generate_raw(chat_model, chat_tok, chat_p, max_new_tokens=128))
```

逐项记录：是否执行任务、是否保持角色、是否答完、是否出现事实错误。若输出撞到 `max_new_tokens` 上限，先提高预算复查，不要把截断误判为能力不足。还可以给 Base 增加少样本示范，观察提示能改善哪些行为。

**实验边界**：第二节固定原始文本，第三节对同一 Instruct 模型改变模板；批量实验则同时改变了权重与输入格式，展示的是各自使用方式下的体验，不是只隔离“对齐算法”的严格消融。四条提示不足以评价知识保留、整体能力或安全性；这些需要独立测试集与更系统的评估。
