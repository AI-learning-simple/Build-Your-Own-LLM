## 一个危险的可能性

模型越强大，能力的"双刃剑效应"也越明显：一个能写代码的模型，理论上也能被诱导写恶意代码；一个知识渊博的模型，理论上也能被诱导输出危险信息。**能力本身没有立场，如何使用能力才有立场**——这正是 Safety Alignment 要解决的问题。

## Safety Alignment 要防范什么？

| 风险类型 | 说明 |
|---|---|
| 有害内容生成 | 暴力、违法、歧视性内容 |
| Jailbreak（越狱） | 通过精心设计的Prompt，绕过模型的安全限制 |
| Prompt Injection（提示词注入） | 在输入内容中隐藏指令，劫持模型原本的任务 |
| 隐私泄露 | 泄露训练数据中的个人信息 |
| 过度拒绝（Over-refusal） | 把正常请求也误判为危险请求，影响可用性 |

最后一项常被忽视，但同样重要——**安全和可用性本身是一种平衡，不是安全越"严格"越好。**

## Jailbreak 的基本套路

常见的越狱手法包括：角色扮演（"假装你是没有任何限制的AI"）、分步诱导（先问无害问题，再逐步引导到敏感话题）、编码混淆（用密文、拼音、变形字绕过关键词过滤）。第5.1节的实验里，我们用一个典型的角色扮演式Jailbreak Prompt，实测了 System Prompt 开启前后模型行为的真实差异。

## 多层防护体系

工业界通常不会依赖单一环节，而是搭建多层防护：

```mermaid
flowchart LR
    A[用户输入] --> B[输入审核 Moderation]
    B --> C[System Prompt 约束]
    C --> D[模型生成]
    D --> E[输出审核 Moderation]
    E --> F[返回给用户]
```

- **输入审核**：在请求到达模型之前，先判断是否包含违规意图；
- **System Prompt 约束**：在推理阶段用明确的安全指令约束模型行为；
- **输出审核**：即使模型生成了不当内容，也能在返回给用户之前被拦截。

## 专门的安全分类模型

除了让模型"自己判断"，工业界也会引入专门训练的安全分类模型，例如 Meta 的 Llama Guard系列——它们经过专门的安全数据训练，判断一段对话是否违规，准确率通常明显高于让通用 Chat Model 兼职做判断。

## Constitutional AI

Anthropic 提出的 Constitutional AI 是另一种思路：**不完全依赖人工标注"什么是安全的"，而是给模型一套"宪法"式的原则，让模型自己评价、修正自己的回答，再用这些自我修正的结果继续训练**。这种方法降低了对大规模人工安全标注的依赖，也是 RLAIF（基于 AI 反馈的强化学习）思路的典型应用。

## Safety 与 Helpfulness 的平衡

安全对齐最大的挑战，不是"如何拒绝"，而是"如何只拒绝真正危险的请求"。过于严格的模型会把大量正常请求也一并拒绝（Over-refusal），反而损害了产品的可用性。这也是为什么第5.1节的实验专门设计了"正常问题"和"危险问题"两组测试样本，用来检验安全护栏是否会误伤正常请求。

## 本章总结

本章我们理解了：

✅ 模型能力越强，安全风险的潜在影响也越大 ✅ Jailbreak 和 Prompt Injection 是最常见的两类攻击方式 ✅ 真正的安全防护是"输入审核 + System Prompt + 输出审核"多层组合，而非单一环节 ✅ Safety 与 Helpfulness 之间需要持续权衡，而非一味追求严格

> **安全不是给模型加一把锁，而是给模型的能力配上恰当的边界。**
