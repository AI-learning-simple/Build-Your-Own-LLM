# 4.3 知识蒸馏（Knowledge Distillation）——基于 KL 散度的分布对齐

> **本节定位**：本节只做实践。软标签、温度、前向 KL、\(T^2\) 与同词表约束见[第4章第十节](<./4.%20监督微调（SFT）——指令跟随能力的训练.md>)，这里不重复推导。

> **本节目标**：实现一次对数几率（logit）蒸馏：让 `Qwen2.5-0.5B` 学生模型在同一批样本上同时拟合数据集答案（交叉熵）与 `Qwen2.5-1.5B-Instruct` 教师模型的完整概率分布（KL 散度），并用固定验证集比较“纯交叉熵（Cross-Entropy, CE）”与“CE + 知识蒸馏（Knowledge Distillation, KD）”两条分支。重点不是刷出一个更好的模型，而是看清**软标签（soft label）、温度（temperature）、KL 方向与同词表约束**这四件事。
>
> **硬件要求**：单张 NVIDIA CUDA GPU。教师以 4-bit 加载并冻结，学生以 bf16（显卡不支持时退回 fp16）+ LoRA 训练；本节按 8 GB 显存的可尝试预算设计，不能保证所有 8 GB 显卡都能跑。显存不足时先降 `MAX_LENGTH`，再减少样本数；macOS/CPU 可阅读本节，但不直接套用这条训练路径。

## 一、实验设计：只改一个变量

| 项目 | 设置 |
|---|---|
| 教师 | `Qwen/Qwen2.5-1.5B-Instruct`，4-bit 量化，冻结，`eval()` |
| 学生 | `Qwen/Qwen2.5-0.5B`（Base），bf16（或 fp16），LoRA（`r=8`） |
| 训练数据 | `shibing624/alpaca-zh` 过滤后取 480 条，固定切分 440 / 40 |
| 训练配置 | 1 epoch，有效 batch 8，学习率 2e-4，`MAX_LENGTH=192` |
| A 组 | \(\alpha=0\)：只用数据集答案做 CE |
| B 组 | \(\alpha=0.5,\ T=2\)：CE + KL |
| 固定条件 | 随机种子、数据顺序、LoRA 配置、优化器步数、评估样本 |
| 评估 | 验证集交叉熵、与教师的 KL 散度、与教师最高概率词元（top-1）的一致率、3 个未参与训练的提示词（prompt） |

A、B 两组唯一的差别是**损失里是否含软标签项**。教师前向只用于产生目标，不参与反向传播；B 组的额外计算开销来自教师前向，比较效果时要把这部分成本一起记录。

> **这不是“数据蒸馏 vs 对数几率蒸馏”的路线对比。** A、B 两组用的是同一批数据集答案，区别只在是否加软标签项；CE 组也不是 4.2 的复现（学生规模不同）。若要比较路线，需要让教师先为同一批提示词生成答案，再用这些文本做交叉熵训练。

## 二、加载教师模型与学生模型

依赖版本沿用 4.2：`transformers==4.48.3`、`peft==0.14.0`、`accelerate==1.3.0`、`bitsandbytes==0.45.2`、`datasets==3.2.0`、`jinja2==3.1.5`。其中 `jinja2` 不是 `transformers` 的默认依赖，但 `apply_chat_template` 需要它；缺了会在渲染模板时报 `NameError`。教师与学生必须来自**同一词表**的模型家族，否则 logits 的维度含义不对应，KL 无从计算。

```python
from pathlib import Path
import gc, json, random
import torch
import torch.nn.functional as F
from transformers import AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig, set_seed
from peft import LoraConfig, get_peft_model

assert torch.cuda.is_available(), "本节需要单卡 CUDA 环境"
DEVICE = torch.cuda.current_device()
set_seed(42)
compute_dtype = torch.bfloat16 if torch.cuda.is_bf16_supported() else torch.float16

RUN_DIR = Path.home() / "llm-labs" / "part2"
KD_DIR = RUN_DIR / "kd"
TEACHER_NAME = "Qwen/Qwen2.5-1.5B-Instruct"
STUDENT_NAME = "Qwen/Qwen2.5-0.5B"
SYSTEM = "你是一个中文助手，请准确回答并遵循用户的格式要求。"
MAX_LENGTH = 192
TEMPERATURE = 2.0

tokenizer = AutoTokenizer.from_pretrained(TEACHER_NAME)
student_tokenizer = AutoTokenizer.from_pretrained(STUDENT_NAME)
assert tokenizer.get_vocab() == student_tokenizer.get_vocab(), "logit 蒸馏要求教师与学生同词表"
assert tokenizer.chat_template and tokenizer.eos_token == "<|im_end|>"

teacher_quant = BitsAndBytesConfig(
    load_in_4bit=True, bnb_4bit_quant_type="nf4",
    bnb_4bit_use_double_quant=True, bnb_4bit_compute_dtype=compute_dtype,
)
teacher = AutoModelForCausalLM.from_pretrained(
    TEACHER_NAME, quantization_config=teacher_quant, torch_dtype=compute_dtype,
    device_map={"": DEVICE},
).eval()
teacher.config.use_cache = False
teacher.requires_grad_(False)

def load_student():
    model = AutoModelForCausalLM.from_pretrained(
        STUDENT_NAME, torch_dtype=compute_dtype, device_map={"": DEVICE},
    )
    model.config.use_cache = False
    model.gradient_checkpointing_enable(gradient_checkpointing_kwargs={"use_reentrant": False})
    model.enable_input_require_grads()
    model.config.eos_token_id = tokenizer.eos_token_id
    model.config.pad_token_id = tokenizer.pad_token_id
    model.generation_config.eos_token_id = tokenizer.eos_token_id
    model.generation_config.pad_token_id = tokenizer.pad_token_id
    lora = LoraConfig(
        r=8, lora_alpha=16,
        target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
        lora_dropout=0.05, bias="none", task_type="CAUSAL_LM",
    )
    return get_peft_model(model, lora)
```

几点说明：

- 教师用 4-bit 是为了同时放下两个模型；量化会扰动教师的概率分布。若显存允许、且你要研究"教师分布本身"，应把教师换成 bf16 再复测。
- 学生是基础模型（Base），不是指令模型（Instruct）。它默认的 `eos_token_id` 可能与指令模型的模板不一致，所以显式改成 `<|im_end|>`；否则训练时把 `<|im_end|>` 当监督目标、生成时却不会在它处停止。
- `enable_input_require_grads()` 配合 gradient checkpointing，避免冻结基座后输入嵌入不参与梯度图导致反传断链。
- 两个模型都固定在单卡，不使用 `device_map="auto"` 隐式跨卡或 offload。

## 三、样本：继续沿用 4.1 的监督契约

蒸馏只改变损失，不改变"哪些位置被监督"。提示词与系统消息（system）仍是 `-100`，只有助手回答正文和回答结束符（EOS）参与损失；否则 KL 会去对齐用户提问位置，目标就变了。

```python
from datasets import load_dataset

def build_messages(sample):
    instruction = sample["instruction"].strip()
    extra = (sample.get("input") or "").strip()
    user_text = instruction + ("\n\n" + extra if extra else "")
    answer = sample["output"].strip()
    assert instruction and answer
    return [
        {"role": "system", "content": SYSTEM},
        {"role": "user", "content": user_text},
        {"role": "assistant", "content": answer},
    ]

def build_training_sample(sample):
    messages = build_messages(sample)
    assert not any(t in m["content"] for t in tokenizer.all_special_tokens for m in messages)
    prompt = tokenizer.apply_chat_template(messages[:-1], tokenize=False, add_generation_prompt=True)
    full = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=False)
    assert full.endswith(tokenizer.eos_token + "\n")
    full = full[:-1]
    prompt_ids = tokenizer(prompt, add_special_tokens=False)["input_ids"]
    full_ids = tokenizer(full, add_special_tokens=False)["input_ids"]
    assert full.startswith(prompt)
    assert full_ids[:len(prompt_ids)] == prompt_ids, "分词边界变化，不能用长度猜 mask"
    answer_ids = full_ids[len(prompt_ids):]
    assert len(answer_ids) > 1 and answer_ids[-1] == tokenizer.eos_token_id
    labels = [-100] * len(prompt_ids) + answer_ids
    assert len(labels) == len(full_ids)
    return {"input_ids": full_ids, "attention_mask": [1] * len(full_ids), "labels": labels}

EVAL_PROMPTS = [
    "请用恰好两条建议帮助初学者安排每天十五分钟的编程练习。",
    "请写一句不超过二十字的消息，婉拒周末临时的聚餐邀请。",
    "把这句话改成礼貌的请求：马上把报告给我。",
]

raw = load_dataset("shibing624/alpaca-zh", split="train").shuffle(seed=42)
raw = raw.select(range(min(1200, len(raw))))
rows, seen = [], set()
for row in raw:
    if not isinstance(row.get("instruction"), str) or not isinstance(row.get("output"), str):
        continue
    if not row["instruction"].strip() or not row["output"].strip():
        continue
    if row.get("input") is not None and not isinstance(row["input"], str):
        continue
    messages = build_messages(row)
    if any(t in m["content"] for t in tokenizer.all_special_tokens for m in messages):
        continue
    key = messages[1]["content"]
    if key in seen or key in EVAL_PROMPTS:
        continue
    sample = build_training_sample(row)
    if len(sample["input_ids"]) > MAX_LENGTH:
        continue
    seen.add(key)
    rows.append(sample)
    if len(rows) >= 480:
        break

assert len(rows) >= 120, "过滤后样本过少，检查数据集或长度上限"
random.Random(42).shuffle(rows)
val_rows, train_rows = rows[:40], rows[40:]
print("训练/验证样本:", len(train_rows), len(val_rows))

def to_batch(sample):
    return {
        key: torch.tensor([sample[key]], device=DEVICE)
        for key in ("input_ids", "attention_mask", "labels")
    }
```

批次大小（batch size）固定为 1，因此不需要填充（padding）；`attention_mask` 全为 1。若改成多条样本同批，必须同时处理填充位置，并确保它们不进入 KL 与交叉熵。

## 四、蒸馏损失：一次前向、两种目标

先确认张量对齐：语言模型在位置 \(t\) 的输出预测的是 \(t+1\) 号词元（token），所以对数几率与标签（labels）都要错开一位。只有 `labels != -100` 的位置参与损失。

```python
@torch.no_grad()
def teacher_logits(batch):
    out = teacher(input_ids=batch["input_ids"], attention_mask=batch["attention_mask"])
    return out.logits.float()

def kd_terms(student_logits, labels, t_logits, alpha, temperature=TEMPERATURE):
    s = student_logits[:, :-1, :].float()
    y = labels[:, 1:]
    mask = y != -100
    s, y = s[mask], y[mask]
    ce = F.cross_entropy(s, y)
    if alpha == 0.0:
        return ce, ce.detach(), torch.zeros((), device=s.device)
    t = t_logits[:, :-1, :].float()[mask]
    log_p_s = F.log_softmax(s / temperature, dim=-1)
    p_t = F.softmax(t / temperature, dim=-1)
    kl = F.kl_div(log_p_s, p_t, reduction="batchmean") * temperature ** 2
    return (1 - alpha) * ce + alpha * kl, ce.detach(), kl.detach()
```

`F.kl_div` 的 `reduction="batchmean"` 按第一个维度（被监督的 token 数）求平均，因此得到的是每 token 平均 KL。教师 logits 先转 `float32` 再算 softmax，避免 bf16 在 15 万词表上的数值误差。教师前向用 `torch.no_grad()` 而不是 `torch.inference_mode()`：后者产生的 inference tensor 若被保存进反向图，会直接报错。

## 五、训练与评估函数：只切换 \(\alpha\)

两条分支各自从同一个 Base 重新初始化，保证 LoRA 起点、数据顺序和步数一致。

```python
def train_student(alpha, tag, epochs=1, lr=2e-4, accum=8):
    set_seed(42)
    model = load_student()
    model.train()
    params = [p for p in model.parameters() if p.requires_grad]
    optimizer = torch.optim.AdamW(params, lr=lr, weight_decay=0.0)
    order = list(range(len(train_rows)))
    random.Random(42).shuffle(order)
    pending = 0
    for epoch in range(epochs):
        for idx in order:
            batch = to_batch(train_rows[idx])
            out = model(input_ids=batch["input_ids"], attention_mask=batch["attention_mask"])
            t_logits = teacher_logits(batch) if alpha > 0 else None
            loss, ce, kl = kd_terms(out.logits, batch["labels"], t_logits, alpha)
            (loss / accum).backward()
            pending += 1
            if pending == accum:
                torch.nn.utils.clip_grad_norm_(params, 1.0)
                optimizer.step()
                optimizer.zero_grad(set_to_none=True)
                pending = 0
        if pending:
            torch.nn.utils.clip_grad_norm_(params, 1.0)
            optimizer.step()
            optimizer.zero_grad(set_to_none=True)
            pending = 0
        message = f"[{tag}] epoch {epoch + 1} 最后一条 ce={ce.item():.4f}"
        if alpha > 0:
            message += f" kl={kl.item():.4f}"
        print(message)
    return model
```

这里刻意没有用 `Trainer`：自定义损失需要教师 logits，手写循环能让"损失到底由哪两项组成"保持可见。`(loss / accum).backward()` 与每 `accum` 步更新一次，等价于有效 batch 8；每条样本的 loss 仍按 1 条计算，不能额外再乘 `accum`。

评估函数要在跑第一条分支之前定义好，因为 CE 组训练完就要立刻评估并保存，再释放显存。

```python
@torch.inference_mode()
def evaluate(model, samples, temperature=TEMPERATURE):
    model.eval()
    total_ce = total_kl = total_agree = total_tokens = 0
    for sample in samples:
        batch = to_batch(sample)
        s_logits = model(
            input_ids=batch["input_ids"], attention_mask=batch["attention_mask"]
        ).logits.float()
        t_logits = teacher_logits(batch)
        s = s_logits[:, :-1, :]
        t = t_logits[:, :-1, :]
        y = batch["labels"][:, 1:]
        mask = y != -100
        s, t, y = s[mask], t[mask], y[mask]
        total_ce += F.cross_entropy(s, y, reduction="sum").item()
        total_kl += (
            F.kl_div(
                F.log_softmax(s / temperature, dim=-1),
                F.softmax(t / temperature, dim=-1),
                reduction="sum",
            ) * temperature ** 2
        ).item()
        total_agree += (s.argmax(dim=-1) == t.argmax(dim=-1)).sum().item()
        total_tokens += y.numel()
    return {
        "ce": total_ce / total_tokens,
        "kl": total_kl / total_tokens,
        "agree": total_agree / total_tokens,
        "tokens": total_tokens,
    }

@torch.inference_mode()
def generate(model, prompt, max_new_tokens=96):
    messages = [{"role": "system", "content": SYSTEM}, {"role": "user", "content": prompt}]
    text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = tokenizer(text, add_special_tokens=False, return_tensors="pt").to(DEVICE)
    model.eval()
    ids = model.generate(
        **inputs, max_new_tokens=max_new_tokens, do_sample=False,
        eos_token_id=tokenizer.eos_token_id, pad_token_id=tokenizer.pad_token_id,
    )
    return tokenizer.decode(ids[0, inputs["input_ids"].shape[1]:], skip_special_tokens=True)
```

## 六、跑完两条分支：先评估，再释放

```python
KD_DIR.mkdir(parents=True, exist_ok=True)

ce_model = train_student(alpha=0.0, tag="ce")
ce_metrics = evaluate(ce_model, val_rows)
ce_answers = {p: generate(ce_model, p) for p in EVAL_PROMPTS}
ce_model.save_pretrained(KD_DIR / "ce")

kd_answers = {p: generate(kd_model, p) for p in EVAL_PROMPTS}
kd_model.save_pretrained(KD_DIR / "kd")
teacher_answers = {p: generate(teacher, p) for p in EVAL_PROMPTS}

print("指标          CE-only    CE+KD")
for name in ("ce", "kl", "agree"):
    print(f"{name:10s} {ce_metrics[name]:.4f}     {kd_metrics[name]:.4f}")

protocol = {
    "teacher": TEACHER_NAME, "student": STUDENT_NAME, "alpha": 0.5,
    "temperature": TEMPERATURE, "max_length": MAX_LENGTH,
    "train_size": len(train_rows), "val_size": len(val_rows),
    "ce_metrics": ce_metrics, "kd_metrics": kd_metrics,

assert (KD_DIR / "kd" / "adapter_config.json").is_file()
```

顺序很重要：**先评估、先生成、再保存、最后删除**。如果先 `del ce_model` 再调用 `evaluate(ce_model, ...)`，会直接 `NameError`；如果两组模型同时驻留，又会把教师和训练状态的显存叠在一起。先跑 \(\alpha=0\)、评估并释放，再跑 \(\alpha=0.5\)，是本节能落在 8GB 预算内的关键。训练耗时请实测；`440 × 1 epoch` 只是流程规模，不构成效果保证。

三个指标回答的是不同问题：

| 指标 | 含义 | 能说明什么 | 不能说明什么 |
|---|---|---|---|
| 验证集 CE | 对数据集中答案的拟合程度 | 硬标签目标是否被学好 | 答案本身是否正确、是否泛化 |
| 与教师 KL | 两个分布的平均差距（依赖 \(T\)） | 软标签蒸馏是否真的把学生拉向教师 | 教师一定比数据集答案更好 |
| top-1 一致率 | 学生与教师最高概率 token 相同的比例 | 行为层面的接近程度 | 整体回答质量 |

**最值得观察的组合**是：KD 组的 KL 与一致率下降，而验证集 CE 可能上升。这不是实现错误，而是目标变了——学生在模仿教师，而教师分布与数据集答案并不完全一致。如果 CE 大幅恶化，说明 \(\alpha\) 太大或教师在该数据上不可靠；如果 KL 几乎不动，先检查教师是否真的参与损失、温度是否为 1、以及 mask 是否把回答位置漏掉。

生成的三个回答用于定性检查约束遵循与完整性；它们不是基准测试，也不能用三道题证明"蒸馏提升了能力"。

## 七、失败排查与实验边界

- **`NameError: name 'Extension' is not defined`**：这是 `transformers` 4.48.3 在缺少 `jinja2` 时渲染聊天模板抛出的错误，不是模板写错。安装 `jinja2==3.1.5` 后重试。
- **报词表或维度不匹配**：教师与学生必须同 tokenizer 家族。Qwen2.5 不同尺寸共享词表，但仍要用 `assert` 核实，而不是假设。
- **OOM**：依次尝试 `MAX_LENGTH=128`、减少训练样本、把教师换成更小模型。保留完整回答与 EOS 比盲目截断更重要；截断产生的半句监督会污染 CE 与 KL。
- **显存仍紧张**：可以只保留教师的 top-k token 计算 KL（对学生对应位置做 `gather`，并对 top-k 概率重新归一化）。这会改变目标分布，需在记录中注明，不能与全词表 KL 直接比较。
- **loss 为 NaN**：先确认教师 logits 已转 `float32`，再检查温度是否为正、mask 后是否还有 token。全被 mask 时 `cross_entropy` 会得到 NaN。
- **教师没有冻结**：确认 `teacher.eval()`、`requires_grad_(False)`，且教师前向在 `no_grad` 下；否则显存与计算都会失控。
- **两组结果不可比**：检查随机种子、数据顺序、LoRA 配置、优化器步数和评估样本是否完全一致。只改 `alpha`，才是受控对照。

还需要诚实记录三条边界：

1. **教师也会错**：软标签把教师的错误、偏见和风格一并传给学生。教师更强不等于教师在每个样本上都更可靠。
2. **容量差距要合适**：教师过大，学生可能学不动；教师过小，收益有限。1.5B → 0.5B 只是一个可运行的配置，不是最优比例。
3. **单次小实验不外推**：40 条验证样本、1 个训练轮次（epoch）、1 个随机种子，只能说明这条流水线能跑通、指标朝哪个方向动，不能得出"知识蒸馏普遍优于监督微调"。

## 本节小结

本节把"蒸馏"从一句行业术语拆成了可执行的四步：

1. 区分**序列级数据蒸馏**（教师生成文本 + SFT）与 **logit 蒸馏**（教师分布 + KL）；
2. 写清软标签目标：温度 \(T\)、\(T^2\) 缩放、forward KL 与 \(\alpha\) 加权；
3. 复用 4.1 的 assistant-only mask，只对回答位置对齐分布；
4. 用同一份数据、同一组超参跑 \(\alpha=0\) 与 \(\alpha=0.5\) 两条分支，分别报告 CE、KL 与一致率。

它与前后章节的关系是：4.1 定义样本与监督位置，4.2 产出可继续用于 5.2 的监督微调适配器；**4.3 是一条独立分支**，产物写到 `~/llm-labs/part2/kd`，不覆盖 4.2 的适配器。5.x 的偏好学习提供的是"哪个回答更好"的比较信号，与本节"模仿教师分布"不同；6.1 的 R1-Distill 属于序列级蒸馏，不是本节实现的 logit 对齐。
