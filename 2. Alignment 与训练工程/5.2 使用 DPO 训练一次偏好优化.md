# 5.2 使用直接偏好优化（DPO）训练一次偏好模型

> **本节目标**：加载4.2实际保存的SFT产物，用DPO继续训练；参考策略始终是**训练开始时的SFT策略**，而不是未微调的Base，也不是随训练变化的当前adapter。5.1的Reward Model不参与本实验。
>
> **硬件要求**：沿用4.2的Linux单卡NVIDIA CUDA环境。双adapter共享量化基座，但chosen/rejected与参考策略增加前向计算及激活开销，**不能保证1.5B一定在8GB内运行**。可从batch=1、短序列开始实测。

---

# 一、为什么不只对chosen做Cross Entropy？

只训练chosen仍然可以做SFT，但会丢掉“同一问题下chosen相对rejected更好”的成对信息。DPO用两者相对冻结参考策略的对数概率差构造logistic损失；它本身也可视为一种二分类交叉熵，并不是“交叉熵在数学上不能处理偏好”。公式与手算见第5章和5.1。

---

# 二、环境与产物约定

严格沿用4.2的教学组合：`torch==2.5.1`、`transformers==4.48.3`、`peft==0.14.0`、`accelerate==1.3.0`、`bitsandbytes==0.45.2`、`datasets==3.2.0`、`trl==0.15.2`。安装方式与CUDA wheel选择见4.2；本节建议新开Python进程，避免上一节模型仍占显存。

TRL0.15.2的 `DPOTrainer` 使用 `processing_class=tokenizer`；双adapter名字写入 `DPOConfig`。以下根据该固定版本的官方文档及源码核对，**示例未附GPU实跑记录**，不混用最新版示例。

---

# 三、准备偏好数据

每条数据包含同一问题及其chosen/rejected。下面四条训练、两条验证只用于机制检查；**长回答不自动更好**，chosen必须依据问题约束确定。

```python
from datasets import Dataset

data = [
    {"prompt": "如何礼貌地拒绝朋友的邀请？", "chosen": "谢谢邀请，这次有安排，下次再一起吧。", "rejected": "不去。"},
    {"prompt": "用两个步骤说明如何开始学习Python。", "chosen": "1. 学习基础语法。2. 写一个小程序并测试。", "rejected": "学语法，然后做项目，再读源码，最后反复练习。"},
    {"prompt": "只回答数字：2加3是多少？", "chosen": "5", "rejected": "2加3等于5，我来详细说明一下。"},
    {"prompt": "用一句话解释注意力机制。", "chosen": "注意力机制根据当前任务为不同输入分配不同权重。", "rejected": "这是一种机制。"},
]
heldout = [
    {"prompt": "只用一个数字回答：3加4等于多少？", "chosen": "7", "rejected": "经过计算，答案是7。"},
    {"prompt": "同事邀我临时加餐但我已约好家人，怎么回复？", "chosen": "谢谢邀请，我已和家人约好，改天再一起吧。", "rejected": "别叫我。"},
]
assert not ({x["prompt"] for x in data} & {x["prompt"] for x in heldout})
```

这些偏好包含礼貌、格式遵循和信息充分性，不能只用回答长度做代理标签。扩大实验时需要更多有明确标注准则的偏好对、独立验证集和近重复检查；“达到几百条”本身也不保证稳定收益。

# 四、加载 4.2 节微调好的模型

```python
import json
from pathlib import Path
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig, set_seed
from peft import PeftConfig, PeftModel, prepare_model_for_kbit_training
from trl import DPOConfig, DPOTrainer

assert torch.cuda.is_available()
set_seed(42)
RUN_DIR = Path.home() / "llm-labs" / "part2"
SFT_DIR = RUN_DIR / "sft_adapter"
assert (SFT_DIR / "adapter_model.safetensors").is_file(), "请先完成4.2并保存产物"
protocol = json.loads((SFT_DIR / "protocol.json").read_text(encoding="utf-8"))
SYSTEM = protocol["system"]
EVAL_PROMPTS = protocol["eval_prompts"]
base_name = PeftConfig.from_pretrained(SFT_DIR).base_model_name_or_path
assert base_name == protocol["base_model"]
assert not (set(EVAL_PROMPTS) & {x["prompt"] for x in data})
assert not ({x["prompt"] for x in heldout} & set(protocol["sft_prompts"]))
use_bf16 = torch.cuda.is_bf16_supported()
compute_dtype = torch.bfloat16 if use_bf16 else torch.float16
quant_config = BitsAndBytesConfig(
    load_in_4bit=True, bnb_4bit_quant_type="nf4",
    bnb_4bit_use_double_quant=True, bnb_4bit_compute_dtype=compute_dtype,
)
tokenizer = AutoTokenizer.from_pretrained(SFT_DIR)
assert tokenizer.chat_template and tokenizer.eos_token == "<|im_end|>"
base_model = AutoModelForCausalLM.from_pretrained(
    base_name, quantization_config=quant_config, torch_dtype=compute_dtype,
    device_map={"": torch.cuda.current_device()},
)
base_model = prepare_model_for_kbit_training(
    base_model, use_gradient_checkpointing=True,
    gradient_checkpointing_kwargs={"use_reentrant": False},
)
base_model.config.use_cache = False
base_model.config.eos_token_id = tokenizer.eos_token_id
base_model.config.pad_token_id = tokenizer.pad_token_id
model = PeftModel.from_pretrained(base_model, SFT_DIR, adapter_name="default", is_trainable=True)
model.load_adapter(SFT_DIR, adapter_name="reference", is_trainable=False)
model.set_adapter("default")
ref_snapshot = {n: p.detach().cpu().clone() for n, p in model.named_parameters() if ".reference." in n}
assert ref_snapshot
assert all(not p.requires_grad for n, p in model.named_parameters() if ".reference." in n)
assert all(".default." in n for n, p in model.named_parameters() if p.requires_grad)
```

`default`与`reference`从**同一份SFT adapter**初始化，共享冻结的量化Base。参考前向在 `torch.no_grad()` 中切换到reference，然后恢复default；训练只更新default，结束时再用参数快照核验reference未变。这里不合并量化权重，也不传新的 `peft_config` 触发二次包装。

如果仅写 `ref_model=None` 而不指定 `ref_adapter_name`，此版本对PEFT模型会禁用adapter来算参考概率，这里就会错误地拿Base而非SFT当参考。缺少4.2产物时应先完成4.2；改用官方Instruct是另一组实验，不能继续声称“承接本次SFT”。

## 同一模板如何送入DPO？

TRL0.15.2会分别分词prompt/chosen/rejected，并**无条件给每个completion追加EOS**。所以本例先按4.1的同一模板序列化，只把assistant正文传作completion，让TRL追加恰好一个EOS，避免把完整聊天文本和裸回答混用或重复结束符。

```python
def serialize_pair(row):
    prompt_messages = [
        {"role": "system", "content": SYSTEM},
        {"role": "user", "content": row["prompt"].strip()},
    ]
    prompt = tokenizer.apply_chat_template(prompt_messages, tokenize=False, add_generation_prompt=True)
    result = {"prompt": prompt}
    expected = {}
    for key in ("chosen", "rejected"):
        answer = row[key].strip()
        assert answer and not any(t in answer or t in row["prompt"] for t in tokenizer.all_special_tokens)
        messages = prompt_messages + [{"role": "assistant", "content": answer}]
        full = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=False)
        assert full.endswith(tokenizer.eos_token + "\n")
        full = full[:-1]
        assert full.startswith(prompt)
        prompt_ids = tokenizer(prompt, add_special_tokens=False)["input_ids"]
        full_ids = tokenizer(full, add_special_tokens=False)["input_ids"]
        assert full_ids[:len(prompt_ids)] == prompt_ids
        completion = full[len(prompt):-len(tokenizer.eos_token)]
        result[key] = completion
        completion_ids = tokenizer(completion, add_special_tokens=False)["input_ids"] + [tokenizer.eos_token_id]
        assert full_ids == prompt_ids + completion_ids, "分开分词改变了边界"
        assert len(prompt_ids) <= 128 and len(completion_ids) <= 128
        assert len(full_ids) <= 256
        expected[key] = completion_ids
    actual = DPOTrainer.tokenize_row(
        result, tokenizer, max_prompt_length=128, max_completion_length=128, add_special_tokens=False
    )
    assert actual["chosen_input_ids"] == expected["chosen"]
    assert actual["rejected_input_ids"] == expected["rejected"]
    return result

dpo_dataset = Dataset.from_list([serialize_pair(row) for row in data])
eval_dataset = Dataset.from_list([serialize_pair(row) for row in heldout])
```

这些断言把DPO的completion token与4.1的“正文+EOS”监督区间对齐，也确保本例不会被TRL再次截断而丢EOS。换长数据时先做完整样本长度过滤，不要依靠静默截断。此路径传的是已按同模板序列化的标准字符串schema，不再套一次聊天模板。

# 五、配置并启动 DPO 训练

```python
def generate(model, prompt):
    messages = [{"role": "system", "content": SYSTEM}, {"role": "user", "content": prompt}]
    text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = tokenizer(text, add_special_tokens=False, return_tensors="pt")
    inputs = inputs.to(model.get_input_embeddings().weight.device)
    model.eval()
    with torch.inference_mode():
        ids = model.generate(
            **inputs, max_new_tokens=protocol["max_new_tokens"], do_sample=False, use_cache=True,
            eos_token_id=tokenizer.eos_token_id, pad_token_id=tokenizer.pad_token_id,
        )
    return tokenizer.decode(ids[0, inputs["input_ids"].shape[1]:], skip_special_tokens=True)

before = {p: generate(model, p) for p in EVAL_PROMPTS}
dpo_config = DPOConfig(
    output_dir=str(RUN_DIR / "dpo_checkpoints"),
    model_adapter_name="default", ref_adapter_name="reference",
    reference_free=False, sync_ref_model=False,
    per_device_train_batch_size=1, per_device_eval_batch_size=1,
    gradient_accumulation_steps=2, num_train_epochs=1, learning_rate=5e-6,
    beta=0.1, loss_type="sigmoid", bf16=use_bf16, fp16=not use_bf16,
    max_length=256, max_prompt_length=128, max_completion_length=128,
    gradient_checkpointing=True, gradient_checkpointing_kwargs={"use_reentrant": False},
    eval_strategy="epoch", logging_steps=1, save_strategy="no",
    optim="adamw_torch", report_to="none", seed=42,
)
dpo_trainer = DPOTrainer(
    model=model, ref_model=None, args=dpo_config,
    train_dataset=dpo_dataset, eval_dataset=eval_dataset, processing_class=tokenizer,
)
initial_metrics = dpo_trainer.evaluate()
print("DPO训练前验证:", initial_metrics)
model.train()
torch.cuda.reset_peak_memory_stats()
dpo_trainer.train()
print("DPO训练后验证:", dpo_trainer.evaluate())
print("峰值allocated GiB:", torch.cuda.max_memory_allocated() / 2**30)
```

初始策略与参考策略相同，关闭dropout时，sigmoid DPO初始loss应接近 `log(2)≈0.693`。明显偏离时先检查两个adapter与分词边界。这里仅有两个optimizer step，主要测试数据流和训练接口，不保证生成可见变化；不要为“看到改善”在验证题上反复调参。

默认DPO collator用prompt/completion attention mask排除prompt与padding，仅对回答（含EOS）汇总log probability；不直接复用SFT的labels collator。`rewards/margins`是相对参考策略的隐式奖励差，不是客观质量分，也不是第5.1节RM的分数。

# 六、检查参考冻结、比较未见题并保存

```python
model.set_adapter("default")
for name, param in model.named_parameters():
    if name in ref_snapshot:
        assert not param.requires_grad and param.grad is None
        assert torch.equal(param.detach().cpu(), ref_snapshot[name]), "SFT参考adapter被更新了"
after = {p: generate(model, p) for p in EVAL_PROMPTS}
for prompt in EVAL_PROMPTS:
    print("问题:", prompt)
    print("SFT:", before[prompt])
    print("DPO:", after[prompt])
DPO_DIR = RUN_DIR / "dpo_adapter"
model.save_pretrained(DPO_DIR, selected_adapters=["default"])
tokenizer.save_pretrained(DPO_DIR)
(DPO_DIR / "protocol.json").write_text(
    json.dumps({**protocol, "dpo_before": before, "dpo_after": after}, ensure_ascii=False, indent=2),
    encoding="utf-8",
)
assert (DPO_DIR / "adapter_model.safetensors").is_file()
print("DPO adapter已保存:", DPO_DIR)
```

`default`是在原SFT adapter上继续优化的结果，重载时用同一Base加这份DPO adapter，**不要把SFT和DPO adapter再叠加一次**。可照4.2的清理显存、重新加载、相同prompt生成流程核验。

报告训练/验证DPO loss、隐式奖励差，以及固定未见问题的回答；按指令遵循、准确性、礼貌和长度约束逐项比较。输出变长、训练margin增加，都不等于质量提高。只有四条训练样本时，无变化或退化同样是应记录的结果。

---

# 七、`beta`不是效果保证开关

在原始KL正则化推导中，较大beta对应较强的参考约束；在实现中它同时缩放偏好logit与梯度。因此有限步数下，改变beta不保证输出按某个方向单调变化。这里从 `0.1` 开始，与学习率、数据质量、训练步数共同检查；不能把beta当作真实KL的硬上限，也不能靠降低beta补救错误偏好标签。

---

# 八、资源与验收边界

双adapter只多占一份adapter权重，但参考前向与两种completion仍有成本。先记录实际峰值、吞吐与GPU型号，不承诺固定5~7GB。OOM时检查残留模型、长度和batch；切换0.5B必须重新得到匹配的4.2产物。

最低验收项：SFT目录可读；同模板与单EOS断言通过；初始loss接近0.693；loss有限且训练参数存在梯度；reference快照不变；独立题前后比较与产物保存完整。**这些是运行后应完成的检查，不是预先给出的实验结果。**

# 本节小结

本节闭合了 **4.1 assistant-only样本 → 4.2 SFT adapter/tokenizer → 5.2 固定SFT参考策略的DPO**。5.1的RM是独立的PPO机制实验，不是这里的输入；DPO也不保证“比SFT更好”，收益必须由独立评估确认。
