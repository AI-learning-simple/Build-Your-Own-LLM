## 二、亲手写一个最简单的 Triton 算子

Triton 是一个让你能用近似 Python 的语法编写 GPU Kernel 的工具，不需要直接写 CUDA C++。我们从最简单的例子开始：向量加法。此包装仅支持同一 GPU 上、形状相同、连续存储的非空 FP32 张量；它不是支持任意 stride、广播和自动求导的通用 `torch.add` 替代品。`program_id` 标识 Triton program instance，通常映射为一个线程块的工作单元，`tl.arange` 描述逻辑元素，不应简单理解成“一个元素就固定对应一个 CUDA 线程”。

```python
import triton
import triton.language as tl

@triton.jit
def add_kernel(x_ptr, y_ptr, out_ptr, n_elements, BLOCK_SIZE: tl.constexpr):
    # 每个 GPU 线程块（Block）负责处理一段连续的数据，pid 就是当前 Block 的编号
    pid = tl.program_id(axis=0)
    # 计算当前 Block 负责处理的数据在整个数组中的起始位置
    block_start = pid * BLOCK_SIZE
    offsets = block_start + tl.arange(0, BLOCK_SIZE)
    # mask 防止越界：最后一个 Block 可能不满BLOCK_SIZE 个元素
    mask = offsets < n_elements

    x = tl.load(x_ptr + offsets, mask=mask)   # 从 HBM 读取一段 x
    y = tl.load(y_ptr + offsets, mask=mask)   # 从 HBM 读取一段 y
    output = x + y                             # 在计算核心上做加法（这一步几乎不耗时）
    tl.store(out_ptr + offsets, output, mask=mask)  # 把结果写回 HBM


def triton_add(x: torch.Tensor, y: torch.Tensor) -> torch.Tensor:
    assert x.is_cuda and y.is_cuda and x.device == y.device
    assert x.shape == y.shape and x.dtype == y.dtype == torch.float32
    assert x.is_contiguous() and y.is_contiguous() and x.numel() > 0
    output = torch.empty_like(x)
    n_elements = output.numel()
    BLOCK_SIZE = 1024
    # grid 决定启动多少个 Block，每个 Block 处理 BLOCK_SIZE 个元素
    grid = (triton.cdiv(n_elements, BLOCK_SIZE),)
    add_kernel[grid](x, y, output, n_elements, BLOCK_SIZE=BLOCK_SIZE)
    return output
```

下面的测量函数也用于后面的 Attention 对照。**每个实现单独预热**，不把 JIT 编译算进耗时；计时与显存采样分开，避免上一轮输出仍被引用造成双份输出峰值。

```python
import gc
import statistics

@torch.inference_mode()
def measure(fn, *inputs, name, warmup=5, repeats=20):
    gc.collect()
    torch.cuda.synchronize()
    torch.cuda.empty_cache()
    for _ in range(warmup):
        out = fn(*inputs)
        del out
    torch.cuda.synchronize()

    samples_ms = []
    start = torch.cuda.Event(enable_timing=True)
    end = torch.cuda.Event(enable_timing=True)
    for _ in range(repeats):
        start.record()
        out = fn(*inputs)
        end.record()
        end.synchronize()
        samples_ms.append(start.elapsed_time(end))
        del out

    torch.cuda.synchronize()
    baseline = torch.cuda.memory_allocated()
    torch.cuda.reset_peak_memory_stats()
    out = fn(*inputs)
    torch.cuda.synchronize()
    peak = torch.cuda.max_memory_allocated()
    reserved_peak = torch.cuda.max_memory_reserved()
    del out
    result = {
        "ms": statistics.median(samples_ms),
        "baseline_mib": baseline / 2**20,
        "peak_mib": peak / 2**20,
        "extra_mib": (peak - baseline) / 2**20,
        "reserved_peak_mib": reserved_peak / 2**20,
    }
    print(name, result)
    return result


torch.manual_seed(0)
size = 10_000_000
x = torch.rand(size, device="cuda")
y = torch.rand(size, device="cuda")
out_triton = triton_add(x, y)
out_torch = x + y
torch.testing.assert_close(out_triton, out_torch, rtol=0, atol=0)
del out_triton, out_torch
triton_stats = measure(triton_add, x, y, name="Triton add")
torch_stats = measure(torch.add, x, y, name="PyTorch add")

del x, y
gc.collect()
torch.cuda.synchronize()
torch.cuda.empty_cache()
```

`reset_peak_memory_stats()` 只重置统计，不释放活跃张量。这里先删除输出和输入引用，再清理缓存；若在 Notebook 中反复执行过旧代码，还需清掉历史输出（包括 `_`），或重启 Kernel。`peak_mib` 包含常驻输入，`extra_mib` 是本次调用额外的峰值，二者都应报告。`reserved_peak_mib` 是 PyTorch 缓存分配器的预留量，不是活跃张量量；这些指标也不包含全部驱动、通信库和其他进程显存。

这个例子本身不追求"比 PyTorch 更快"（PyTorch 的向量加法已经调用了高度优化的 CUDA Kernel），而是让你亲眼看到：**平时调用的每一个 `+`、`*`，背后都对应着一段像上面这样在成千上万个线程里并行执行的代码**——这正是第8章讲的"算子"最朴素的样子。

## 三、朴素 Attention 实现，并测量它的真实显存与耗时

```python
import torch
import torch.nn.functional as F

def naive_attention(q, k, v):
    # 第8章提到：朴素实现会产生一个完整的 N×N 中间矩阵，并把它写入/读出 HBM 多次
    d_k = q.shape[-1]
    scores = torch.matmul(q, k.transpose(-2, -1)) / (d_k ** 0.5)  # 第一次写入 HBM：N×N 的 scores
    attn = F.softmax(scores, dim=-1)                # 从 HBM 读出 scores，写回 HBM
    out = torch.matmul(attn, v)                                    # 从 HBM 读出 attn，计算最终输出
    return out
```

```python
batch, heads, seq_len, d_k = 2, 8, 4096, 64
shape = (batch, heads, seq_len, d_k)
q = torch.randn(shape, device="cuda", dtype=torch.float16)
k = torch.randn(shape, device="cuda", dtype=torch.float16)
v = torch.randn(shape, device="cuda", dtype=torch.float16)
```

这里固定为**无 mask、非 causal、dropout=0 的前向推理算子**，不构建反向图。朴素实现的单个 FP16 分数矩阵就占 \(2\times8\times4096^2\times2\) 字节，即 512 MiB，实际还会同时存在其他中间张量。若 OOM，重启进程并对两种实现同时降低 `seq_len` 或 `batch`，不要只改其中一组；本实验不能直接代表完整模型训练或单 Token 解码的收益。

## 四、用 PyTorch 内置的 Flash Attention 对比同样的计算

`F.scaled_dot_product_attention` 会根据输入和可用后端选择实现，但不保证始终选到 FlashAttention，也不保证对每种形状都是最快的。这里使用提供 `torch.nn.attention.sdpa_kernel` 的 PyTorch 版本，**只启用 Flash 后端**；不支持当前 GPU、dtype 或形状时应保留错误并标注“不可用”，不能让 math 回退后仍把结果叫 Flash。

```python
from torch.nn.attention import SDPBackend, sdpa_kernel

def flash_attention(q, k, v):
    with sdpa_kernel(SDPBackend.FLASH_ATTENTION):
        return F.scaled_dot_product_attention(q, k, v, dropout_p=0.0, is_causal=False)


with torch.inference_mode():
    naive_out = naive_attention(q, k, v).float().cpu()
    flash_out = flash_attention(q, k, v).float().cpu()
delta = naive_out - flash_out
print("最大绝对误差:", delta.abs().max().item())
print("相对 L2 误差:", (delta.norm() / naive_out.norm().clamp_min(1e-12)).item())
torch.testing.assert_close(flash_out, naive_out, atol=2e-3, rtol=1e-2)
del naive_out, flash_out, delta

naive_stats = measure(naive_attention, q, k, v, name="朴素 Attention")
flash_stats = measure(flash_attention, q, k, v, name="Flash Attention")
```

本例容差对应当前 FP16 随机输入的检查起点，不是所有输入和长度的通用保证。断言失败时先排查 mask、scale、dtype 和数值范围，可用小尺寸 FP64 参考实现进一步诊断；不要为让测试通过而无依据放宽容差。两种算法在实数算术中表达同一公式，浮点输出不保证逐位相同。正确性结果已转到 CPU 并删除，避免污染后续 GPU 峰值。

## 五、结果对比

```python
print("\n===== 本机实测汇总 =====")
for name, stats in [("naive", naive_stats), ("flash", flash_stats)]:
    print(name, stats)
print(f"速度比 naive/flash: {naive_stats['ms'] / flash_stats['ms']:.2f}x")
print(f"总峰值下降: {100 * (1 - flash_stats['peak_mib'] / naive_stats['peak_mib']):.1f}%")
print(f"增量峰值下降: {100 * (1 - flash_stats['extra_mib'] / naive_stats['extra_mib']):.1f}%")
print("形状/dtype:", shape, q.dtype)
print("PyTorch/CUDA/Triton:", torch.__version__, torch.version.cuda, triton.__version__)
```

本节没有预填某张 GPU 的结果，也不保证固定倍数。运行后应保存两组误差、基线、总峰值、增量峰值和耗时；交换测试顺序，并独立重复几轮，观察中位数与波动。FlashAttention 避免完整的 \(N\times N\) 中间矩阵，是可解释的显存优势来源；实际速度还受形状、dtype、内核版本、GPU 利用率和调度影响，不能仅归因于“显存搬运不同”。若一组不可用或 OOM，就不计算伪造的速度比。
