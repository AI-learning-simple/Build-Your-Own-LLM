# 3.2 使用 DPO 训练一次偏好优化

> **本节目标**：第3章讲了 Preference Learning——同一个问题可能有多个"正确"答案，模型需要学会哪种回答更符合人类偏好。本节，我们在 2.2 节微调好的模型基础上，用 **DPO（Direct Preference Optimization）** 继续训练，让模型的回答风格发生可观察的变化。
>
> **硬件要求**：DPO 训练同时需要"当前模型"和一份"参考模型"的对比计算，比普通 LoRA 微调略重，但配合 4-bit 量化 + LoRA，**在 1.5B 模型上依然可以控制在 8GB 显存以内**。

---

# 一、为什么不能直接用 Cross Entropy 训练"偏好"？

SFT 的训练数据是"问题 → 一个标准答案"，用 Cross Entropy 就能训练。但偏好数据是"问题 → 回答A、回答B → 人类认为 A 更好"，这是**相对**关系，不是绝对答案，因此需要专门的偏好优化方法，DPO 就是目前最常用、实现最简单的一种。

# 三、准备偏好数据

偏好数据集需要三个字段：`prompt`（问题）、`chosen`（更好的回答）、`rejected`（较差的回答）。可以用公开数据集，也可以自己构造几十条：

```python
from datasets import Dataset

data = [
    {
        "prompt": "如何拒绝朋友的邀请？",
  "chosen": "可以委婉地说：'不好意思，这次时间上有点安排不开，下次有机会一定参加！'既表达了拒绝，也保留了以后的机会。",
        "rejected": "不去。",
  },
    {
"prompt": "请介绍一下 Transformer。",
"chosen": "Transformer 是一种基于 Attention 机制的神经网络架构，最初用于机器翻译，后来成为 GPT、BERT 等大语言模型的基础，其核心创新是让每个 Token 都能直接关注序列中的任意其他 Token。",
        "rejected": "Transformer 是一种模型。",
    },
    # 实际使用时建议扩充到几百条,可以用公开数据集如 HuggingFaceH4/orca_dpo_pairs
]

dpo_dataset = Dataset.from_list(data)
```

---

# 四、加载 2.2 节微调好的模型

```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig
from peft import PeftModel

base_name = "Qwen/Qwen2.5-1.5B"
quant_config = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_compute_dtype=torch.float16)

tokenizer = AutoTokenizer.from_pretrained(base_name)
base_model = AutoModelForCausalLM.from_pretrained(base_name, quantization_config=quant_config, device_map="auto")
model = PeftModel.from_pretrained(base_model, "./lora_output", is_trainable=True)
```

> 如果没有保存 2.2 节的 LoRA 权重，也可以直接用 `Qwen/Qwen2.5-1.5B-Instruct`（官方已经做过指令微调的版本）作为起点，效果更稳定。

---

# 五、配置并启动 DPO 训练

```python
from trl import DPOConfig, DPOTrainer

dpo_config = DPOConfig(
    output_dir="./dpo_output",
    per_device_train_batch_size=2,
    gradient_accumulation_steps=4,
    num_train_epochs=3,
learning_rate=5e-5,
    beta=0.1,  # 控制"多大程度上信任偏好信号,而不偏离原模型太远"
    fp16=True,
    logging_steps=5,
)

dpo_trainer = DPOTrainer(
    model=model,
  args=dpo_config,
    train_dataset=dpo_dataset,
    tokenizer=tokenizer,
)

dpo_trainer.train()
```

由于示例数据只有几条，这里的训练更多是"跑通流程、观察机制"，实际项目中建议扩充到至少几百条偏好数据才能看到稳定效果。

# 六、训练前后对比

```python
def generate(model, prompt, max_new_tokens=80):
    messages = [{"role": "user", "content": prompt}]
    text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = tokenizer(text, return_tensors="pt").to(model.device)
    output = model.generate(**inputs, max_new_tokens=max_new_tokens, do_sample=False)
    return tokenizer.decode(output[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True)

print("DPO 训练后:", generate(model, "如何拒绝朋友的邀请？"))
```

如果 DPO 训练生效，模型的回答风格会更倾向于训练数据里 `chosen` 那一类——更委婉、更详细、更有帮助，而不是像 `rejected` 那样简短、生硬。

---

# 七、`beta` 参数的直觉理解

`beta` 控制模型"离原模型多远"：`beta` 越大，模型越保守，越不敢偏离原始行为太多；`beta` 越小，模型越激进地拥抱偏好数据，但也越容易"用力过猛"导致输出质量下降或过拟合到训练数据的风格。实践中通常从 `0.1` 左右开始尝试。
