## 二、一个最小的训练脚本

```python
import torch
import torch.nn as nn
from transformers import AutoTokenizer, AutoModelForCausalLM
from accelerate import Accelerator

def build_dummy_batch(tokenizer, batch_size=4, seq_len=256):
    # 用随机 Token ID 构造一批"假数据"，只是为了测量显存占用，不关心训练效果
    input_ids = torch.randint(0, tokenizer.vocab_size, (batch_size, seq_len))
    return {"input_ids": input_ids, "labels": input_ids.clone()}

def train_one_step(model_name, use_gradient_checkpointing=False):
    # Accelerator 会自动处理设备分配（CPU/GPU/多卡），这里单卡场景下相当于一层轻量封装
    accelerator = Accelerator()
    tokenizer = AutoTokenizer.from_pretrained(model_name)
    model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype=torch.float16)

    if use_gradient_checkpointing:
        # 开启后，前向传播不再保存全部中间激活值，反向传播时按需重新计算，用时间换显存
        model.gradient_checkpointing_enable()

    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-5)
    # prepare() 会把模型和优化器包装成分布式训练所需的形态（单卡时改动很小）
    model, optimizer = accelerator.prepare(model, optimizer)

    batch = build_dummy_batch(tokenizer)
    batch = {k: v.to(accelerator.device) for k, v in batch.items()}

    torch.cuda.reset_peak_memory_stats()   # 重置显存统计，确保只测量这一次前向+反向的峰值
    output = model(**batch)
    accelerator.backward(output.loss)      # 等价于 loss.backward()，但适配分布式场景
    optimizer.step()
    optimizer.zero_grad()

    peak_mem = torch.cuda.max_memory_allocated() / 1e9   # 转换成 GB
    return peak_mem

model_name = "Qwen/Qwen2.5-0.5B"

mem_plain = train_one_step(model_name, use_gradient_checkpointing=False)
print(f"普通训练峰值显存: {mem_plain:.2f} GB")

mem_ckpt = train_one_step(model_name, use_gradient_checkpointing=True)
print(f"开启 Gradient Checkpointing 后峰值显存: {mem_ckpt:.2f} GB")
```

Gradient Checkpointing 的思想很简单：**训练时不保存所有中间激活值，而是在反向传播需要时重新计算一次**。这是用计算时间换取显存的经典折衷，在 8GB 显卡上尤其有用。

## 三、DeepSpeed ZeRO 配置文件

DeepSpeed 的 ZeRO 优化不是靠改代码，而是靠一份JSON 配置文件控制。这是一份ZeRO Stage 2（切分Optimizer 状态 +梯度）的最小配置：

```python
zero2_config = {
    "train_batch_size": 4,
    "gradient_accumulation_steps": 1,
    "fp16": {"enabled": True},          # 使用混合精度训练，进一步降低显存占用
    "zero_optimization": {
        "stage": 2,                                # ZeRO Stage 2：切分 Optimizer 状态 + 梯度
        "offload_optimizer": {"device": "cpu"},           # 把 Optimizer 状态转移到 CPU 内存
        "contiguous_gradients": True,
        "overlap_comm": True,                             # 让通信和计算尽量重叠，减少等待时间
    },
}

import json
with open("zero2_config.json", "w") as f:
    json.dump(zero2_config, f, indent=2)

print(open("zero2_config.json").read())
```

`offload_optimizer` 把 Optimizer 状态（Adam 需要保存的一阶、二阶动量，通常是参数量的两倍大小）转移到 CPU 内存，这样即使是单卡也能明显降低 GPU 显存占用——这正是 ZeRO Stage 2 + CPU Offload 的核心思想。

## 四、用 Accelerate 启动一次真实的 DeepSpeed 训练

将下面内容保存为 `train_ds.py`：

```python
# 用字符串拼接生成一份独立的训练脚本文件，因为 accelerate launch 需要以脚本文件的形式启动
train_script = '''
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM
from accelerate import Accelerator

accelerator = Accelerator()
model_name = "Qwen/Qwen2.5-0.5B"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name)
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-5)

model, optimizer = accelerator.prepare(model, optimizer)

input_ids = torch.randint(0, tokenizer.vocab_size, (2, 128)).to(accelerator.device)
output = model(input_ids=input_ids, labels=input_ids)
accelerator.backward(output.loss)
optimizer.step()

# 多卡场景下，只让主进程打印日志，避免每张卡都重复输出
if accelerator.is_main_process:
    print("训练完成，Loss:", output.loss.item())
'''

with open("train_ds.py", "w") as f:
    f.write(train_script)

print("train_ds.py 已生成")
```

```bash
accelerate launch --deepspeed_config_file zero2_config.json train_ds.py
```

即使这里只有一张显卡，`accelerate launch` 依然会按照 DeepSpeed 的配置切分 Optimizer 状态——你可以用 `nvidia-smi` 或前面学过的 `torch.cuda.max_memory_allocated()` 观察，开启 ZeRO Offload 后，同样大小的模型在 GPU 上占用的显存明显更少，多出来的部分转移到了系统内存里。

## 五、三种配置的显存对比总结

| 配置 | GPU 显存占用 | 说明 |
|---|---|---|
| 普通训练（无优化） | 基线 | 模型参数 + 梯度 + Optimizer 状态全部在 GPU |
| + Gradient Checkpointing | 明显降低 | 用重新计算换取显存，训练速度略微下降 |
| + DeepSpeed ZeRO-2 CPU Offload | 进一步降低 | Optimizer 状态转移到 CPU，GPU 只保留参数和梯度 |

请注意，本节的重点不是"训练出一个更好的模型"，而是**亲手体会为什么工业界需要 Accelerate、DeepSpeed 这一整套工程栈**——第7章讲的 Data/Tensor/Pipeline Parallel 在多卡场景下会更明显地发挥作用，而 ZeRO + Gradient Checkpointing 这一组合，即使在你自己的 8GB 显卡上，也已经能实实在在地帮你训练更大的模型。
