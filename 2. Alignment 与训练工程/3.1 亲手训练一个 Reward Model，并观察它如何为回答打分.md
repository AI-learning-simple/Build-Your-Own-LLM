# 3.1 亲手训练一个 Reward Model，并观察它如何为回答打分

> **本节目标**：第13.4节我们已经用 DPO 完整训练过一次偏好优化——DPO 最大的特点就是"不需要 Reward Model"。但要真正理解 RLHF/PPO 的工作原理，就必须理解它"需要"的那个 Reward Model 到底是什么、怎么训练出来的。这一节我们反过来，亲手训练一个最小的 Reward Model，看它是如何学会"给回答打分"的。

---

## 一、偏好数据：谁更好？

```python
# 每条数据包含同一个问题的两个回答：chosen（更好）和rejected（较差）
# Reward Model 要学习的正是"chosen 应该比 rejected 得分更高"
preference_data = [
    {"prompt": "如何学习 Python？", "chosen": "建议先学习基础语法，再完成几个小项目，最后阅读优秀开源代码。", "rejected": "学语法。"},
    {"prompt": "如何拒绝朋友的邀请？", "chosen": "不好意思，今天有安排，下次一起吧。", "rejected": "不去。"},
    {"prompt": "介绍一下 Transformer。", "chosen": "Transformer 是 2017 年提出的基于 Self-Attention 的神经网络结构，是现代大模型的基础。", "rejected": "一种模型。"},
]
```

---

## 二、Reward Model 结构：把语言模型改造成"打分器"

Reward Model 本质上就是一个普通的语言模型，只是把最后预测下一个 Token 的 `lm_head` 换成了一个输出**单一标量分数**的线性层。

```python
import torch
import torch.nn as nn
from transformers import AutoModel, AutoTokenizer

class RewardModel(nn.Module):
    def __init__(self, base_model_name):
        super().__init__()
        # backbone 只保留 Transformer 主干，不需要 lm_head（不做Next Token Prediction）
        self.backbone = AutoModel.from_pretrained(base_model_name)
        hidden_size = self.backbone.config.hidden_size
        # value_head 把每个 Token 的隐藏向量映射成一个标量分数
        self.value_head = nn.Linear(hidden_size, 1)

    def forward(self, input_ids, attention_mask):
        outputs = self.backbone(input_ids=input_ids, attention_mask=attention_mask)
        last_hidden = outputs.last_hidden_state          # shape: [batch, seq_len, hidden_size]
        # 找到每个样本"最后一个真实 Token"的位置（padding 部分不计入）
        last_token_index = attention_mask.sum(dim=1) - 1
        # 取出每个样本最后一个 Token 的隐藏向量，作为整段文本的"总结表示"
        pooled = last_hidden[torch.arange(last_hidden.size(0)), last_token_index]
        # 把这个表示映射成一个标量分数，代表"这段回答的质量"
        reward = self.value_head(pooled)
        return reward.squeeze(-1)# shape: [batch]

model_name = "Qwen/Qwen2.5-0.5B"
tokenizer = AutoTokenizer.from_pretrained(model_name)
reward_model = RewardModel(model_name)
```

---

## 三、Pairwise Loss：让"更好的回答"分数更高

RLHF 里训练 Reward Model 用的是Bradley-Terry 模型的思想：**不要求分数绝对准确，只要求chosen 的分数比rejected 高**。

```python
def compute_pairwise_loss(reward_model, tokenizer, batch):
    # 把 prompt 和对应的回答拼接成完整文本，分别构造 chosen / rejected 两组输入
    chosen_texts = [f"{b['prompt']}\n{b['chosen']}" for b in batch]
    rejected_texts = [f"{b['prompt']}\n{b['rejected']}" for b in batch]

    chosen_inputs = tokenizer(chosen_texts, return_tensors="pt", padding=True)
    rejected_inputs = tokenizer(rejected_texts, return_tensors="pt", padding=True)

    # 分别让 Reward Model 给两组文本打分
    chosen_reward = reward_model(**chosen_inputs)
    rejected_reward = reward_model(**rejected_inputs)

    # Bradley-Terry Loss：希望 sigmoid(chosen - rejected) 尽量接近 1
    # 即 chosen_reward 明显大于 rejected_reward 时，loss 才会小
    loss = -torch.log(torch.sigmoid(chosen_reward - rejected_reward)).mean()
    return loss, chosen_reward, rejected_reward
```

---

## 四、训练循环

```python
optimizer = torch.optim.AdamW(reward_model.parameters(), lr=1e-5)

for epoch in range(20):
    loss, chosen_r, rejected_r = compute_pairwise_loss(reward_model, tokenizer, preference_data)

    optimizer.zero_grad()   # 清空上一轮残留的梯度
    loss.backward()         # 反向传播，计算每个参数的梯度
    optimizer.step()        # 根据梯度更新参数

    if epoch % 5 == 0:
        # 观察 chosen 和 rejected 分数的差距是否在逐渐拉开
        gap = (chosen_r - rejected_r).mean().item()
        print(f"Epoch {epoch}: loss={loss.item():.4f}  chosen-rejected 平均差距={gap:.4f}")
```

训练几十轮之后，你应该能看到 `chosen - rejected` 的差距从接近 0 逐渐变成一个明显的正数——**Reward Model 正在学会"识别更好的回答"**。

---

## 五、用训练好的 Reward Model 给新回答打分

```python
def score(reward_model, tokenizer, prompt, answer):
    text = f"{prompt}\n{answer}"
    inputs = tokenizer(text, return_tensors="pt")
    with torch.no_grad():# 推理阶段不需要梯度，节省显存和计算
        return reward_model(**inputs).item()

test_prompt = "介绍一下 Transformer。"
print("详细回答得分:", score(reward_model, tokenizer, test_prompt,
      "Transformer 是一种基于 Self-Attention 的神经网络结构，被广泛用于现代大语言模型。"))
print("简单回答得分:", score(reward_model, tokenizer, test_prompt, "一种模型。"))
```

你会看到详细回答的得分明显高于简单回答的得分——这正是 PPO 训练时Reward Model 提供给策略模型的那个"奖励信号"。

---

## 六、为什么 DPO 可以跳过这一步？

回顾第3章讲过的公式关系：DPO 的关键洞察是——**Reward 和策略模型之间存在一个数学上的直接映射关系**，因此不需要单独训练Reward Model、也不需要用强化学习去优化策略，直接在 chosen/rejected 数据上优化一个等价的目标函数即可（这正是 13.4 节我们做的事情）。现在你亲手训练了一次 Reward Model，应该更能体会到：**PPO 需要"模型 + Reward Model + 强化学习"三个环节，DPO 把这三者合并成了一步，这就是为什么工业界越来越多转向 DPO 系方法的根本原因。**
