# 5.1 训练奖励模型（Reward Model）与回答评分分析

> **本节定位**：本节只做实践。偏好数据、奖励模型结构与 Bradley-Terry 损失的理论见[第5章](<./5.%20偏好学习（Preference%20Learning）——人类偏好的建模与优化.md>)，这里只跑最小实现并观察分数变化。最后会手写一遍 DPO 损失，为 5.2 的 `DPOTrainer` 做对照。

> **硬件要求**：代码用 0.5B 骨干和全量 FP32 AdamW；CPU 可运行但慢，图形处理器（GPU）更合适，8 GB 显存不保证足够。模型、梯度、优化器及激活都计入预算；本例没有实现低秩适配（LoRA）/量化低秩适配（QLoRA）。沿用 4.2 的依赖版本，代码按顺序执行。本实验仅演示打分机制，不输出可用的生产奖励模型，也不是 5.2 的前置产物。
>

## 一、准备偏好数据

```python
# 每条数据包含同一个问题的两个回答：chosen（更好）和 rejected（较差）
preference_data = [
    {"prompt": "如何学习 Python？", "chosen": "建议先学习基础语法，再完成几个小项目，最后阅读优秀开源代码。", "rejected": "学语法。"},
    {"prompt": "如何拒绝朋友的邀请？", "chosen": "不好意思，今天有安排，下次一起吧。", "rejected": "不去。"},
    {"prompt": "介绍一下 Transformer。", "chosen": "Transformer 是 2017 年提出的基于 Self-Attention 的神经网络结构，是现代大模型的基础。", "rejected": "一种模型。"},
]
```

## 二、把语言模型改造成打分器

只改输出头：去掉预测下一个词元的 `lm_head`，换成一个输出标量的线性层。结构与取舍见第5章。

```python
import torch
import torch.nn as nn
from transformers import AutoModel, AutoTokenizer

class RewardModel(nn.Module):
    def __init__(self, base_model_name):
        super().__init__()
        # backbone（骨干网络）只保留 Transformer 主干，不需要 lm_head（不做下一词元预测）
        self.backbone = AutoModel.from_pretrained(base_model_name)
        hidden_size = self.backbone.config.hidden_size
        # value_head 把每个词元的隐藏向量映射成一个标量分数
        self.value_head = nn.Linear(hidden_size, 1)

    def forward(self, input_ids, attention_mask):
        outputs = self.backbone(input_ids=input_ids, attention_mask=attention_mask, use_cache=False)
        last_hidden = outputs.last_hidden_state
        positions = torch.arange(attention_mask.shape[1], device=attention_mask.device)
        last_token_index = positions.expand_as(attention_mask).masked_fill(attention_mask == 0, -1).max(dim=1).values
        assert (last_token_index >= 0).all()
        batch_index = torch.arange(last_hidden.size(0), device=last_hidden.device)
        pooled = last_hidden[batch_index, last_token_index]
        return self.value_head(pooled).squeeze(-1)

torch.manual_seed(42)
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
model_name = "Qwen/Qwen2.5-0.5B"
tokenizer = AutoTokenizer.from_pretrained(model_name)
tokenizer.padding_side = "right"
assert tokenizer.pad_token_id is not None
reward_model = RewardModel(model_name).to(device)
reward_model.backbone.gradient_checkpointing_enable(gradient_checkpointing_kwargs={"use_reentrant": False})

def pair_text(prompt, answer):
    return f"问题：{prompt}\n回答：{answer}"
```

## 三、实现成对损失

按第5章的 Bradley-Terry 损失实现：不要求分数绝对准确，只要求优选回答的分数高于劣选回答。

```python
def compute_pairwise_loss(reward_model, tokenizer, batch):
    # 把提示词（prompt）和对应的回答拼接成完整文本，分别构造优选 / 劣选两组输入
    chosen_texts = [pair_text(b["prompt"], b["chosen"]) for b in batch]
    rejected_texts = [pair_text(b["prompt"], b["rejected"]) for b in batch]
    device = next(reward_model.parameters()).device
    chosen_inputs = tokenizer(chosen_texts, return_tensors="pt", padding=True).to(device)
    rejected_inputs = tokenizer(rejected_texts, return_tensors="pt", padding=True).to(device)
    assert chosen_inputs["input_ids"].shape[1] <= 256
    assert rejected_inputs["input_ids"].shape[1] <= 256

    # 分别让奖励模型给两组文本打分
    chosen_reward = reward_model(**chosen_inputs)
    rejected_reward = reward_model(**rejected_inputs)

    # Bradley-Terry 损失：希望 sigmoid(chosen - rejected) 尽量接近 1
    # 即 chosen_reward 明显大于 rejected_reward 时，loss 才会小
    loss = -torch.nn.functional.logsigmoid(chosen_reward - rejected_reward).mean()
    return loss, chosen_reward, rejected_reward
```

## 四、训练循环

```python
optimizer = torch.optim.AdamW(reward_model.parameters(), lr=1e-5)
reward_model.train()

for epoch in range(20):
    optimizer.zero_grad(set_to_none=True)
    loss, chosen_r, rejected_r = compute_pairwise_loss(reward_model, tokenizer, preference_data)
    assert torch.isfinite(loss)
    loss.backward()
    optimizer.step()

    if epoch % 5 == 0:
        # 观察 chosen 和 rejected 分数的差距是否在逐渐拉开
        gap = (chosen_r - rejected_r).mean().item()
        print(f"轮次 Epoch {epoch}: loss={loss.item():.4f}  优选-劣选平均差距={gap:.4f}")
```

在固定种子和这三条训练样本上，`chosen - rejected` 的训练集差距可能逐渐变成正数，说明模型正在拟合这份小数据。它不能证明模型已经学会可泛化的回答质量；也可能主要利用回答长度或训练措辞。应同时记录多个随机种子，并用未参与训练的偏好对评估。

## 五、用训练好的奖励模型给新回答打分

```python
def score(reward_model, tokenizer, prompt, answer):
    text = pair_text(prompt, answer)
    inputs = tokenizer(text, return_tensors="pt").to(next(reward_model.parameters()).device)
    reward_model.eval()
    with torch.no_grad():
        return reward_model(**inputs).item()

validation_pairs = [
    {"prompt": "怎样开始学做饭？", "chosen": "先学一道简单菜，备齐食材，再按步骤练习。", "rejected": "自己想。"},
    {"prompt": "只回答数字：2+2等于多少？", "chosen": "4", "rejected": "这道题的答案是4，我来详细介绍计算过程。"},
]
assert not ({x["prompt"] for x in preference_data} & {x["prompt"] for x in validation_pairs})
for row in validation_pairs:
    chosen_score = score(reward_model, tokenizer, row["prompt"], row["chosen"])
    rejected_score = score(reward_model, tokenizer, row["prompt"], row["rejected"])
    print("未见问题:", row["prompt"], "chosen-rejected:", chosen_score - rejected_score)
```

若chosen得分更高，只能说明这两个未见样例的排序符合标注，不能证明泛化；第二条刻意让较短答案更好，用来暴露训练集“长就是好”的捷径。RM原始分数没有跨模型的统一绝对尺度，应关注同prompt下的差值、排序准确率及误差切片。不要反复训练到满足预设结论。

## 六、DPO 为何可以跳过奖励模型

第5章在KL正则化目标与Bradley-Terry偏好假设下推导了奖励和最优策略的关系。DPO据此直接在偏好对上构造监督式损失，不需要显式RM或PPO在线rollout；但这不等于在有限数据、有限模型容量和实际优化中，与任意PPO训练完全等价。参考策略、数据分布和超参数仍会影响结果。**5.2加载4.2的SFT产物，不读取这里的RM。**

## 七、亲手实现一次最简版的 DPO 损失（不依赖 TRL）

实验 5.2 我们将用 `trl` 库的 `DPOTrainer` 跑一次真实的 DPO 训练，但公式本身被完全封装在库内部。现在有了第5章推导出的公式，也亲手训练过 Reward Model、见过 Pairwise Loss 长什么样，可以反过来把 DPO Loss 自己写一遍——你会发现代码量小得惊人。

第5章已把 DPO 拆成两步：先计算 chosen 与 rejected 的隐式奖励，再把二者差值送入 Pairwise Loss。本实验直接沿这条数值链实现，不要求先记住展开后的长公式：

```text
implicit_reward = β × (policy_logp - reference_logp)
DPO Loss = -log sigmoid(chosen_implicit_reward - rejected_implicit_reward)
```

这两行的作用分别是“衡量策略相对参考模型提高了多少概率”和“让 chosen 的相对提升高于 rejected”。完整公式只是把两行代数合并，放在计算完成后对照即可。

真实训练里，`log π(y|x)` 是把回答 `y` 拆成词元，对每个词元在 `x` 给定条件下的对数概率求和得到的（这一步和第一部分 6.2 节计算交叉熵（Cross Entropy）时用到的对数概率完全是同一个东西，只是这里对答案部分的每个词元概率取对数之后不是取负、而是直接累加）。为了让公式的计算过程一步步看得清楚，这里先直接用几个手工设定好的 log 概率数值模拟这一步的结果，跳过分词和模型前向的细节：

```python
import torch

# 模拟"已经算好"的四个对数概率：真实场景中，这些数值来自
# policy_model(input_ids).log_softmax(dim=-1) 沿着回答词元逐位置求和的结果
logp_chosen_policy   = torch.tensor(-12.3, requires_grad=True)   # 策略模型给 chosen 回答打出的 log P(y_w|x)
logp_rejected_policy = torch.tensor(-15.1, requires_grad=True)   # 策略模型给 rejected 回答打出的 log P(y_l|x)
logp_chosen_ref   = torch.tensor(-13.0)   # 参考模型（冻结、不更新）给 chosen 的 log P
logp_rejected_ref = torch.tensor(-14.0)   # 参考模型给 rejected 的 log P

beta = 0.1

def dpo_loss(logp_c_pi, logp_r_pi, logp_c_ref, logp_r_ref, beta):
    # 隐式 Reward：策略模型相对参考模型，在 chosen / rejected 上分别"多给了多少"对数概率
    implicit_reward_chosen = beta * (logp_c_pi - logp_c_ref)
    implicit_reward_rejected = beta * (logp_r_pi - logp_r_ref)
    # DPO Loss：希望 chosen 的隐式 Reward 明显高于 rejected 的隐式 Reward
    return -torch.nn.functional.logsigmoid(implicit_reward_chosen - implicit_reward_rejected)

loss = dpo_loss(logp_chosen_policy, logp_rejected_policy, logp_chosen_ref, logp_rejected_ref, beta)
print("DPO Loss:", loss.item())

loss.backward()
print("对 logp_chosen_policy 的梯度:", logp_chosen_policy.grad.item())
print("对 logp_rejected_policy 的梯度:", logp_rejected_policy.grad.item())
```

**手工验算一遍，确认代码没有算错**：

```
implicit_reward_chosen   = 0.1 × (-12.3 − (-13.0)) = 0.1 × 0.7  =  0.07
implicit_reward_rejected = 0.1 × (-15.1 − (-14.0)) = 0.1 × (-1.1) = -0.11
差值 z = 0.07 − (-0.11) = 0.18
sigmoid(0.18) ≈ 0.5449
Loss = -log(0.5449) ≈ 0.6070
```

**预期输出**：

```
DPO Loss: 0.6070
对 logp_chosen_policy 的梯度: -0.0455
对 logp_rejected_policy 的梯度: 0.0455
```

这两个梯度说明：**把chosen/rejected的log概率当作独立变量时**，梯度下降倾向于提高前者、降低后者。真实语言模型的两项概率共享参数，归一化和其他样本也会耦合更新，因此不能推出每步训练都使chosen的绝对概率上升。DPO直接优化的是相对参考策略的偏好差，而非RM分数。

真实训练时，`logp_chosen_policy`、`logp_rejected_policy` 不再是手工设定的常数，而是策略模型对 chosen/rejected 回答的真实对数概率，会随着这一批参数更新而改变。

`logp_chosen_ref`、`logp_rejected_ref` 则来自一个训练全程冻结、不参与梯度更新的参考模型副本。

把这个 `dpo_loss` 函数换成真实输入，再套上标准的 PyTorch 训练循环，就得到实验 5.2 中 `DPOTrainer` 的核心计算：一个 Bradley-Terry 风格的成对损失，只是把打分函数换成了对数概率比值。

## 实验边界

- 偏好数据量小且由示例构造，奖励模型容易过拟合；
- 成对准确率只衡量“排序是否符合标注”，不等于生成质量；
- 没有接入 PPO/GRPO 做完整 RLHF，奖励模型与策略的交互未验证；
- 未做奖励 hacking、分布外样本与标注噪声分析；
- 评分样例受模型与随机种子影响。

## 本节小结

本节给出了“骨干网络+标量头”、稳定pairwise损失、设备一致的训练/评分代码，以及两个未见偏好对。三条训练数据只能演示拟合，不能据此宣称RM有可靠的质量判断能力。手算DPO得到 `Loss≈0.6070`，说明独立log概率变量的梯度方向；真实模型的概率变化还受共享参数影响。
