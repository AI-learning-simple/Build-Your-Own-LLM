# 7.1 搭建一个最小多轮工具调用强化学习循环

> **本节目标**
>
> - 用一个几十行的玩具环境，把"多轮决策"从概念变成可运行的对象
> - 亲手实现轨迹采样、组内优势、策略梯度更新三个环节
> - 观察两种信用分配粒度（整条轨迹 vs 每一步）在同一个任务上的差别
> - 复现"全对或全错组没有学习信号"这一现象，并解释它为什么会随训练必然出现
>
> **时效与证据**：本节的数值来自一段固定种子的 NumPy 程序，在普通 CPU 上数秒即可跑完；它们依赖随机种子、超参数与环境设计，只用于验证机制，**不是 Agentic RL 在真实 LLM 上的效果基准**。策略是一个表格 softmax，不是语言模型。

---

## 一、为什么需要一个"玩具"环境

第 7 章讲了智能体强化学习的结构：模型在多轮交互中写上下文、调工具、看返回，最后由环境终态给出奖励。如果直接上真实 LLM，需要同时处理权重加载、工具沙箱、异步 rollout、显存与分布式训练——任何一处出错，都很难判断是算法问题还是工程问题。

所以这里把问题缩到最小：**只保留"多轮 + 工具 + 延迟奖励"三个要素，其余全部去掉。** 策略不是 LLM，而是一张按"任务 × 阶段"索引的概率表；动作只有五个；环境是内存里的一个价格表。这样，一次训练在几秒内完成，每个数字都可以手工核对。

玩具环境的设计如下：

| 元素 | 设计 | 对应真实场景的什么 |
|---|---|---|
| 任务 | 求两个物品价格之和，如 A+B | 需要查询多个来源才能回答的问题 |
| 工具 1/2/3 | `lookup A/B/C`，返回一个数字 | 搜索、数据库查询、读文件 |
| 动作 4 | `add`：把最近查到的两个值相加并提交 | 调用计算器或执行最终操作 |
| 动作 5 | `guess`：只凭第一项猜答案 | 不查证直接作答 |
| 观测 | 工具返回的数字追加进上下文 | 环境反馈成为下一步输入 |
| 奖励 | 答对 +1，答错 −1，证据不足就提交 −3，每步 −0.02 | 结果奖励 + 过程成本 |
| 终止 | 提交答案，或 4 步用尽 | 步数预算 |

环境里有一个关键约束：`add` 在只查到 0 或 1 个不同物品时被**屏蔽**。这对应真实系统里的"参数校验"：证据不足时，工具调用应该被拒绝，而不是让模型自由发挥。

## 二、完整代码

下面这段代码自包含，只依赖 NumPy。建议保存为 `toy_agentic_rl.py` 后直接运行。

```python
"""玩具多轮工具调用 RL：验证轨迹采样、组内优势与策略更新。
纯 NumPy，CPU 数秒可跑完。策略是表格 softmax，不是 LLM。
"""
import numpy as np

TABLE = {"A": 12, "B": 7, "C": 5}
TASKS = [("A", "B"), ("B", "C"), ("A", "C")]
ACTIONS = ["lookup A", "lookup B", "lookup C", "add", "guess"]
N_TASK, N_PHASE, N_ACT = len(TASKS), 3, len(ACTIONS)
STEP_COST = 0.02
MAX_STEPS = 4


def softmax(z):
    z = z - z.max(axis=-1, keepdims=True)
    e = np.exp(z)
    return e / e.sum(axis=-1, keepdims=True)


def run_episode(theta, task_idx, rng, greedy=False):
    looked, logps, actions, rewards = [], [], [], []
    target = sum(TABLE[x] for x in TASKS[task_idx])
    for step in range(MAX_STEPS):
        phase = min(len(set(looked)), 2)
        logits = theta[task_idx, phase].copy()
        if phase < 2:
            logits[3] = -1e9  # 证据不足时禁止提交
        p = softmax(logits)
        a = int(np.argmax(p)) if greedy else int(rng.choice(N_ACT, p=p))
        logps.append(float(np.log(p[a] + 1e-12)))
        actions.append(a)
        if a < 3:
            looked.append("ABC"[a])
            rewards.append(-STEP_COST)
            continue
        if a == 3 and len(set(looked)) >= 2:
            distinct = []
            for item in looked:
                if item not in [x[0] for x in distinct]:
                    distinct.append((item, TABLE[item]))
            answer = sum(v for _, v in distinct[-2:])
        elif a == 4:
            answer = TABLE[TASKS[task_idx][0]]  # 只猜第一项，通常错
        else:
            answer = None
        if answer is None:
            rewards.append(-3.0)  # 证据不足就提交，重罚
        else:
            rewards.append(1.0 if answer == target else -1.0)
        correct = answer == target
        return {"R": float(sum(rewards)), "correct": correct, "steps": step + 1,
                "logps": logps, "actions": actions, "rewards": rewards}
    return {"R": float(sum(rewards)) - 1.0, "correct": False, "steps": MAX_STEPS,
            "logps": logps, "actions": actions, "rewards": rewards + [-1.0]}


def phases_from_actions(actions):
    looked, out = [], []
    for a in actions:
        out.append(min(len(set(looked)), 2))
        if a < 3:
            looked.append("ABC"[a])
    return out


def train(mode="trajectory", iters=400, group=16, lr=0.8, seed=0):
    rng = np.random.default_rng(seed)
    theta = np.zeros((N_TASK, N_PHASE, N_ACT))
    zero_signal, total_groups = 0, 0
    early_zero, early_total = 0, 0
    for it in range(iters):
        grad = np.zeros_like(theta)
        for ti in range(N_TASK):
            trajs = [run_episode(theta, ti, rng) for _ in range(group)]
            returns = np.array([t["R"] for t in trajs])
            total_groups += 1
            if it < 100:
                early_total += 1
            if returns.std() < 1e-9:
                zero_signal += 1
                if it < 100:
                    early_zero += 1
            if mode == "trajectory":
                adv = (returns - returns.mean()) / (returns.std() + 1e-8)
                for t, A in zip(trajs, adv):
                    for ph, a in zip(phases_from_actions(t["actions"]), t["actions"]):
                        logits = theta[ti, ph].copy()
                        if ph < 2:
                            logits[3] = -1e9
                        p = softmax(logits)
                        onehot = np.zeros(N_ACT)
                        onehot[a] = 1.0
                        grad[ti, ph] += A * (onehot - p)
            else:
                # turn 级：用"从该步起的未来回报"做基线归一化
                horizon = np.zeros((group, MAX_STEPS + 1))
                mask = np.zeros((group, MAX_STEPS + 1), dtype=bool)
                for gi, t in enumerate(trajs):
                    future = 0.0
                    for k in range(len(t["rewards"]) - 1, -1, -1):
                        future += t["rewards"][k]
                        horizon[gi, k] = future
                        mask[gi, k] = True
                for k in range(MAX_STEPS + 1):
                    col = horizon[mask[:, k], k]
                    if col.size == 0 or col.std() < 1e-9:
                        continue
                    mu, sd = col.mean(), col.std() + 1e-8
                    for gi, t in enumerate(trajs):
                        if k >= len(t["rewards"]):
                            continue
                        A = (horizon[gi, k] - mu) / sd
                        ph = phases_from_actions(t["actions"])[k]
                        a = t["actions"][k]
                        logits = theta[ti, ph].copy()
                        if ph < 2:
                            logits[3] = -1e9
                        p = softmax(logits)
                        onehot = np.zeros(N_ACT)
                        onehot[a] = 1.0
                        grad[ti, ph] += A * (onehot - p)
        theta += lr * grad / (N_TASK * group)
    return theta, (zero_signal / total_groups, early_zero / max(early_total, 1))


def evaluate(theta, episodes=300, seed=1, greedy=True):
    rng = np.random.default_rng(seed)
    ok, steps = 0, 0
    for _ in range(episodes):
        ti = int(rng.integers(N_TASK))
        t = run_episode(theta, ti, rng, greedy=greedy)
        ok += int(t["correct"])
        steps += t["steps"]
    return ok / episodes, steps / episodes


if __name__ == "__main__":
    init = np.zeros((N_TASK, N_PHASE, N_ACT))
    g_success, g_steps = evaluate(init, greedy=True)
    s_success, s_steps = evaluate(init, greedy=False)
    print(f"未训练（贪心）: 成功率={g_success:.2f}, 平均步数={g_steps:.2f}")
    print(f"未训练（随机采样）: 成功率={s_success:.2f}, 平均步数={s_steps:.2f}")

    for mode in ("trajectory", "turn"):
        theta, (zero_ratio, early_ratio) = train(mode=mode, seed=0)
        success, steps = evaluate(theta)
        print(f"训练后（{mode:10s}）: 成功率={success:.2f}, 平均步数={steps:.2f}, "
              f"零信号组占比={zero_ratio:.2%}（前100轮 {early_ratio:.2%}）")

    # 失败案例：同一策略下八条轨迹完全相同 -> 组内优势为零
    fixed = np.zeros((N_TASK, N_PHASE, N_ACT))
    fixed[:, :, 0] = 20.0
    fixed[:, :, 2] = 20.0
    rng = np.random.default_rng(7)
    trajs = [run_episode(fixed, 0, rng) for _ in range(8)]
    rs = np.array([t["R"] for t in trajs])
    print(f"\n全失败且轨迹相同的组，回报: {np.round(rs, 2)}")
    print(f"标准差={rs.std():.4f}，组内优势={np.round((rs - rs.mean()) / (rs.std() + 1e-8), 3)}")
```

代码里有三个决定性的设计，值得对照第 7 章逐条看：

1. **状态由"任务 + 已查到的不同物品数"构成。** 这就是智能体场景里的"策略改变自己的观测"：查到什么，决定下一步看到什么、以及还能做什么。
2. **非法动作被屏蔽，而不是靠惩罚学会。** 第 7 章说过，格式与安全约束不适合做成奖励；能屏蔽就直接屏蔽。
3. **奖励在轨迹末端才出现。** 前两步只有 −0.02 的步数成本，真正区分好坏的是最后一步，这正是信用分配要解决的问题。

## 三、运行结果

在同一台普通笔记本上以固定种子运行，输出如下（截取主要行）：

```console
未训练（贪心）: 成功率=0.00, 平均步数=4.00
未训练（随机采样）: 成功率=0.05, 平均步数=2.61
训练后（trajectory）: 成功率=1.00, 平均步数=3.00, 零信号组占比=54.17%（前100轮 2.33%）
训练后（turn      ）: 成功率=1.00, 平均步数=3.00, 零信号组占比=49.75%（前100轮 0.00%）
```

| 配置 | 成功率 | 平均步数 | 说明 |
|---|---|---|---|
| 未训练，贪心 | 0.00 | 4.00 | 概率全为 0 时 argmax 总选第一个动作，反复查 A，永远凑不齐两项 |
| 未训练，随机采样 | 0.05 | 2.61 | 偶尔碰巧查对两项并提交，但多数轨迹在中途失败 |
| 轨迹级更新 | 1.00 | 3.00 | 学会"查两项 → 合并提交"的最小步数路径 |
| 每步级更新 | 1.00 | 3.00 | 同样学会，但早期零信号组更少 |

训练后的策略很干净：每个任务的第 0 步查第一个物品，第 1 步查第二个，第 2 步合并提交。三个任务的策略各不相同，说明它学到的是"任务与物品的对应关系"，不是一条固定动作序列。

## 四、结果解读：三个容易被忽略的现象

### 现象一：零信号组在训练初期很少，收敛后几乎必然出现

轨迹级更新全程有 **54.17%** 的组标准差为零，但前 100 轮只有 **2.33%**。这不是矛盾，而是收敛的必然结果：策略一旦稳定答对，组内 16 条轨迹的回报完全相同，优势全为 0，梯度也为 0。

这解释了一个实践中的困惑：**训练后期 loss 不再下降，不一定是实现有 bug，可能只是没有学习信号了。** 常见的应对是提高采样温度、增加任务难度、或按 pass-rate 过滤题目，让组内重新出现成功与失败的差异。

### 现象二：全失败且轨迹相同的组，优势严格为零

程序专门构造了一个"永远查 A"的固定策略：

```console
全失败且轨迹相同的组，回报: [-1.08 -1.08 -1.08 -1.08 -1.08 -1.08 -1.08 -1.08]
标准差=0.0000，组内优势=[0. 0. 0. 0. 0. 0. 0. 0.]
```

八条轨迹的回报一模一样，减去均值后全是 0。此时无论梯度算得多精确，参数都不会更新。这正是第 7 章说的"稀疏奖励下最危险的情形"：**不是奖励太小，而是没有对照。**

### 现象三：两种信用分配在本玩具上打平

轨迹级与每步级都达到了 100% 成功率、3.00 步，看不出优劣。这是诚实的结论：本任务只有 3 步、奖励集中在末端、动作空间只有 5 个，两种粒度都足够。真实 LLM 场景里，轨迹可能长达上百步，轨迹级会把"第 1 步的探索"和"第 50 步的失误"算成同一个优势，方差更大；每步级更细，但需要更稳定的基线，且早期容易因为样本不足而噪声更大。

更细的信用分配还可能带来一个新风险：当某一 turn 的基线不稳时，策略可能学会"跳过必要的中间步骤"这类局部占优、整体失败的捷径。是否出现，取决于奖励结构、步数预算与基线估计，不能一概而论。

**不要从这个玩具里得出"每步级一定更好"的结论。** 它只说明两者都能工作，选择取决于轨迹长度、奖励分布与采样预算。

## 五、从玩具到真实 LLM：差在哪里

| 维度 | 本实验 | 真实 Agentic RL |
|---|---|---|
| 策略 | 3×3×5 的概率表 | 数十亿参数的模型，动作是变长 Token 序列 |
| 动作空间 | 5 个离散动作 | 任意文本 + 结构化工具调用 |
| 观测 | 一个数字 | 网页、文件、报错、长文档 |
| 环境 | 内存里的价格表 | 沙箱、模拟器或真实系统，需可复现 |
| 奖励 | 手写规则 | 规则验证器、测试用例、学习型奖励 |
| 训练系统 | 单进程 NumPy | rollout 与训练解耦、异步采样、分布式 |
| 成本 | 数秒 | GPU 小时到 GPU 天 |

这些差异解释了为什么第 7 章把"环境与训练系统"单独列一节：**在真实场景里，最难的部分往往不是更新公式，而是让每一次 rollout 可复现、可审计、成本可控。**

## 六、三个可以马上做的改动

如果想进一步体会第 7 章的论点，可以在这个脚本上做三个小实验：

1. **去掉动作屏蔽**，只靠 −3 的惩罚让模型学会"不要提前提交"。观察它需要多少轮才能学会，以及中途会不会形成"先提交、再纠正"的坏习惯。
2. **把 `add` 换成两次独立的计算**（先加第一项，再加第二项），让奖励只在最后出现。观察轨迹级更新的方差如何变化。
3. **把步数上限从 4 改成 8**，并加入一个"查错物品后需要重新查"的干扰项。观察成功率与平均步数是否同时上升——这是判断模型是否在"用更多步数换正确率"的直接信号。

## 本节小结

- 多轮工具调用的训练循环可以拆成四件事：采样轨迹、算组内相对优势、把优势分配给各步、更新策略。
- 收敛后组内优势会自然趋近于零，训练停滞不一定是实现错误；需要靠难度、采样温度或数据过滤重新制造差异。
- 全失败且轨迹相同的组没有任何学习信号，这是稀疏奖励任务的常态，也是需要课程与过滤的原因。
- 信用分配粒度没有普适最优；玩具任务打平，真实任务取决于轨迹长度、奖励分布与采样预算。
- 本实验验证的是机制，不是 LLM 的训练效果；从玩具到真实系统，主要成本在环境、rollout 与评测。

> 下一章从训练转向防御：模型学会调用工具之后，风险面会显著变大。**第 8 章 安全对齐（Safety Alignment）——风险边界与多层防护**，配套实验 **8.1 输入-输出安全护栏——Llama Guard 实战**。
