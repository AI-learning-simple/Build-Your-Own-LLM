# 8.1 我应该关注谁？——Attention Score 的诞生

上一节，我们知道 Attention 的核心思想是"需要的时候，回头查看历史 Token"。但历史 Token 有`The animal didn't cross the street`，当前处理 `it`，模型到底应该关注 `animal` 还是 `street`，或者全部都看？显然全部都看效率太低。于是 Attention 提出了一个新概念：**Attention Score（注意力分数）**。

---

# 什么是 Attention Score？

Attention Score 就是每个历史 Token 的**重要程度**，例如当前是 `it`：`The 0.02, animal 0.83, didn't 0.05, cross 0.10, street 0.76`。分数越高，说明模型越关注。

一个类比：有人问"谁喜欢音乐？"，你的脑海里不会重新回忆所有内容，而是快速找到"音乐"附近的信息，例如 `Tom likes basketball / Alice likes music`，你自然会重点关注 `music、Alice`，忽略 `basketball`。Attention 就是把这个过程交给神经网络完成。

---

# Experiment 8.1：从人为打分到自动匹配

先手动打分体验一下：

```python
history = ["The", "animal", "didn't", "cross", "the", "street"]
scores = {"The":0.01, "animal":0.95, "didn't":0.02, "cross":0.05, "the":0.01, "street":0.80}
for word in history:
    print(word, "->", scores[word])
```

但真正的大模型不会手写`scores["animal"] = 0.95`，而是自己计算。我们先尝试最简单的规则——字符串匹配：

```python
history = ["Tom", "likes", "basketball", "Alice", "likes", "music"]
query = "music"
scores = [1 if word == query else 0 for word in history]
print(scores)  # [0,0,0,0,0,1]
```

---

# 一个明显的问题

如果 Query 变成 `songs`，历史只有 `music`，字符串匹配立即失效（`songs != music`），但人类知道 `songs ≈ music`。说明 Attention 不能比较字符串，而应该比较**语义（Semantic Similarity）**。

---

# 从字符串到向量

第三章学习的 Embedding 终于派上用场：过去比较 `music == songs`，现在比较 `Embedding("music")` 和 `Embedding("songs")`。如果两个向量很接近，那么 Attention Score就应该更高。

---

# 本章的统一例子

从下一节开始，本章会用同一个句子 `The cat is sleeping` 贯穿到底，给每个 Token 一份 2 维玩具Embedding：

```python
embedding = {
    "The":      [0.1, -0.2],
    "cat":      [1.0,  0.5],
    "is":       [-0.1, 0.1],
    "sleeping": [0.9,  0.6],
}
```

我们会一直站在 `cat` 这个 Token 的视角（它想知道该关注句子里的谁），把 Dot Product → Softmax → Weighted Sum → Q/K/V → Attention Matrix 全部用这同一组数字算一遍。

# 本节总结

本节，我们第一次提出了 Attention Score，它回答的问题很简单：**历史 Token 中，谁最值得关注？** 同时我们也发现，简单的字符串匹配远远不够，真正的大模型比较的是**Embedding 之间的相似程度**。

下一节，我们将亲手发明 **Dot Product（点积）**，看看两个向量到底怎么比较相似——你会发现 Transformer 中最经典的公式 `Q · K`，其实就是高中数学里的向量点积。
