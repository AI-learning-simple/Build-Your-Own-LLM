# 1.1 实现最小 Agent Workflow——Thought、Action 与 Observation

> **硬件要求**：需模型推理。本地运行建议 8GB+ 显存 GPU，也可按本节说明改用 API 或量化方案（云 GPU 见前言 P0.3）
>
> **本节目标**：第1章讲了 Agent 由哪些必需组件构成，这一节我们完全不借助任何 Agent 框架，只用一个 Chat Model + 几行 Python，把这些组件串成一个**固定流程（Workflow）**：`Thought → Action → Observation → Final Answer`。流程的每一步由代码决定，**没有自主循环**——什么时候需要循环、以及它的代价，留到第6章讨论。

## 一、准备一个可以调用的模型

```bash
pip install torch transformers accelerate
```

> 如果你在国内访问 Hugging Face 下载模型缓慢或失败，可以先配置镜像，见 `0. 开始之前/1. 前言.md` 的「P0.4 环境安装」与「P0.5 模型与网络」。

```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

model_name = "Qwen/Qwen2.5-1.5B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype=torch.float16, device_map="auto")

def llm(prompt, stop=None, max_new_tokens=200):
    inputs = tokenizer(prompt, return_tensors="pt").to(model.device)
    output = model.generate(**inputs, max_new_tokens=max_new_tokens, do_sample=False)
    text = tokenizer.decode(output[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True)
    if stop:
        # 遇到 stop 词就截断——例如生成到"Observation:"就应该停下，
        # 因为 Observation 应该由我们的代码填入，而不是让模型自己"编"结果
        for s in stop:
            if s in text:
                text = text.split(s)[0]
    return text
```

## 二、两个最简单的工具

```python
def calculator(expression):
    # 真实执行数学表达式计算——这是模型自己做不到的事情，必须靠代码执行
    try:
        return str(eval(expression))
    except Exception as e:
        return f"计算出错: {e}"

def search(query):
    # 用一个假的知识库模拟"搜索"，重点是演示"外部信息如何被引入对话"这件事
    fake_knowledge_base = {
        "北京到上海的距离": "约1200公里",
        "光速": "每秒约30万公里",
    }
    for key, value in fake_knowledge_base.items():
        if key in query:
            return value
    return "未找到相关信息"

# 用字典把"工具名"映射到"真正的执行函数"，方便后面根据模型输出动态调用
tools = {"calculator": calculator, "search": search}
```

## 三、ReAct 的核心：Prompt 模板

```python
# 这份模板明确告诉模型：必须按照 Thought/Action/Observation 的固定格式输出
# {scratchpad} 会随着对话进行不断累积历史的 Thought/Action/Observation 记录
react_prompt_template = """请一步一步解决下面的问题。你可以使用以下工具：

calculator[表达式]：计算数学表达式
search[关键词]：查询知识库

请严格按照如下格式输出：

Thought: 描述你现在的思考
Action: 工具名[输入内容]
Observation: (工具返回的结果，会自动填入，你不需要自己写)
...(可以重复多次 Thought/Action/Observation)
Thought: 我已经得到了最终答案
Final Answer: 最终答案

问题：{question}

{scratchpad}"""
```

## 四、Workflow：Thought → Action → Observation → Final Answer

这个问题需要两步：先查距离，再算时间。所以我们把流程写成**两个固定阶段**，每个阶段做什么完全由代码决定：

```python
import re

def parse_action(text):
    # 从模型输出中提取 "Action: 工具名[参数]" 这种结构，工具名和参数分别取出
    match = re.search(r"Action:\s*(\w+)\[(.*?)\]", text)
    if match:
        return match.group(1), match.group(2)
    return None, None

def run_one_stage(question, scratchpad):
    """一个固定阶段：让模型输出 Thought+Action，代码执行工具，返回 Observation"""
    prompt = react_prompt_template.format(question=question, scratchpad=scratchpad)
    # stop=["Observation:"] 确保模型只输出到 Action 为止，不会自己伪造 Observation
    response = llm(prompt, stop=["Observation:"], max_new_tokens=150)
    print(response)

    tool_name, tool_input = parse_action(response)
    if tool_name and tool_name in tools:
        observation = tools[tool_name](tool_input)          # 执行器：真正调用工具
    else:
        observation = "未能识别有效的 Action。"

    print(f"Observation: {observation}\n")
    return response, observation

def agent_workflow(question, stages=2):
    """固定 Workflow：执行 stages 个阶段，然后统一生成最终答案"""
    scratchpad = ""

    # 阶段数由代码决定，不是模型说"我还要再来一轮"
    for stage in range(stages):
        print(f"--- Stage {stage + 1} / {stages} ---")
        response, observation = run_one_stage(question, scratchpad)
        scratchpad += response + f"\nObservation: {observation}\n"

        if "Final Answer:" in response:                     # 提前得出答案则直接返回
            return response.split("Final Answer:")[-1].strip()

    # 收尾阶段：带着全部 Observation，让模型给出最终答案
    final_prompt = react_prompt_template.format(question=question, scratchpad=scratchpad)
    final = llm(final_prompt, max_new_tokens=150)
    print("--- Final ---")
    print(final)
    return final.split("Final Answer:")[-1].strip() if "Final Answer:" in final else final.strip()
```

请注意这段代码与"自主循环"的关键差异：**`stages=2` 是我们写死的**。模型只负责在每个阶段里决定调用哪个工具，无权决定"整个流程还要跑几轮"。因此：

- LLM 调用次数固定为 `stages + 1`（本例 3 次），可预先估算成本；
- 不需要 `max_steps` 兜底，也不会出现"模型一直不说结束"的情况；
- 出错时能立刻定位是哪个阶段，而不必回放整条 Trace。

## 五、运行一次完整流程

```python
question = "北京到上海的距离是多少公里？如果一辆车每小时行驶100公里，需要多少小时到达？"
answer = agent_workflow(question, stages=2)
print("\n========== Final Answer ==========")
print(answer)
```

观察打印出来的每个阶段，你会清楚地看到：模型先输出 `Thought`（决定先查距离），再输出 `Action: search[...]`，我们的代码执行真实的 `search` 函数并把结果作为 `Observation` 塞回 Prompt；第二阶段模型基于这个新信息决定用 `calculator` 计算时间；最后一次调用汇总出 `Final Answer`。

**流程走完就结束**，不需要模型主动宣布"任务完成"。

## 六、这就是所有 Agent 框架的"地基"

LangChain、LangGraph、AutoGen 等框架内部本质上都是在做同一件事：**维护一个不断增长的上下文（Scratchpad），在"模型输出"和"工具执行"之间流转**。区别只在于它们把 Prompt 模板、解析逻辑、状态管理这些细节封装得更工程化、更健壮（例如支持并行工具调用、更严格的输出格式约束、失败重试等）。理解了这几十行代码，你就理解了几乎所有 Agent 框架的核心运行机制。

至于"阶段数由代码定"还是"由模型定"，这是编排方式的选择：本节采用前者，第6章会实现后者。

✅ 从零实现了一个最小 Agent Workflow：`Thought → Action → Observation → Final Answer` ✅ 亲手编写了 Prompt 模板和 Action 解析逻辑 ✅ 阶段数由代码写死，因此调用次数与执行路径完全可预测 ✅ 理解了主流 Agent 框架的本质就是这套流程的工程化封装
