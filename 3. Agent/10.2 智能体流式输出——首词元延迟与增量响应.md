# 10.2 智能体流式输出——首词元延迟与增量响应

> **本节定位**：实践第 10 章的流式与延迟测量。两种接口使用同一 `model.generate()` 路径、相同输入和停止条件，不再把手写解码循环与 `generate()` 的耗时混比。
>
> **硬件要求**：Python 3.11+；默认 CPU、本地 Qwen 模型，首次运行可能下载权重，需要足够内存；不使用付费 API。

## 一、先确定测量对象

- **生成端 TTFT**：从开始调用生成函数到第一个新 token 送到 streamer 的时间。本例是 Python 层观察值，不是 GPU 内核级计时；包含预填充及首次采样/生成调度，不含模型加载、HTTP 和排队。
- **客户端首文本时间**：从客户端发送请求到收到第一段非空可显示文本。字符可能需要多个 token 才能完整解码，不能等同于 token 回调时间。
- **客户端总时间**：从发请求到完整响应结束，包括传输与序列化。

非流式客户端通常只能在生成完成后看到文本，但引擎仍较早生成了第一个 token。不能把“非流式总耗时”叫作引擎 TTFT，再声称流式让推理加速数百倍。

## 二、完整服务：缓存解码与 SSE JSON

安装依赖：

```bash
python -m pip install torch transformers accelerate fastapi uvicorn pydantic requests
```

保存为 `stream_service.py`，代码完整写好后再启动：

```python
import json
import time
from threading import Lock, Thread

import torch
from fastapi import FastAPI, HTTPException
from fastapi.responses import StreamingResponse
from pydantic import BaseModel, Field
from transformers import AutoTokenizer, AutoModelForCausalLM, TextIteratorStreamer

MODEL_ID = "Qwen/Qwen2.5-1.5B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(MODEL_ID)
model = AutoModelForCausalLM.from_pretrained(MODEL_ID, torch_dtype=torch.float32).eval()
generation_lock = Lock()
app = FastAPI()

class Query(BaseModel):
    prompt: str = Field(min_length=1, max_length=2000)

class TimedStreamer(TextIteratorStreamer):
    def __init__(self):
        super().__init__(tokenizer, skip_prompt=True, skip_special_tokens=True, timeout=120)
        self.seen_prompt = False
        self.first_token_at = None

    def put(self, value):
        # generate 的第一次 put 是输入 prompt，不计作新 token。
        if not self.seen_prompt:
            self.seen_prompt = True
        elif self.first_token_at is None:
            self.first_token_at = time.perf_counter()
        super().put(value)

def generate_events(prompt):
    streamer = TimedStreamer()
    record = {}

    def worker():
        try:
            with generation_lock, torch.inference_mode():
                text = tokenizer.apply_chat_template(
                    [{"role": "user", "content": prompt}],
                    tokenize=False, add_generation_prompt=True,
                )
                inputs = tokenizer(text, return_tensors="pt")
                record["start"] = time.perf_counter()
                output = model.generate(
                    **inputs, max_new_tokens=128, do_sample=False,
                    use_cache=True, streamer=streamer,
                )
                record["end"] = time.perf_counter()
                record["new_tokens"] = output.shape[1] - inputs["input_ids"].shape[1]
        except Exception as exc:
            record["error"] = type(exc).__name__
            streamer.end()  # 让消费者退出，不能静默卡住

    thread = Thread(target=worker, daemon=True)
    thread.start()
    try:
        for text in streamer:
            if text:
                yield {"type": "text", "text": text}
    except Exception:
        yield {"type": "error", "error": "stream_timeout_or_decode_error"}
        return
    thread.join()
    if "error" in record:
        yield {"type": "error", "error": record["error"]}
        return
    first = streamer.first_token_at
    yield {
        "type": "metrics",
        "engine_ttft_s": None if first is None else first - record["start"],
        "engine_total_s": record["end"] - record["start"],
        "new_tokens": record["new_tokens"],
    }

@app.post("/complete")
def complete(query: Query):
    pieces, metrics = [], {}
    for event in generate_events(query.prompt):
        if event["type"] == "error":
            raise HTTPException(500, event["error"])
        if event["type"] == "text":
            pieces.append(event["text"])
        else:
            metrics = event
    return {"text": "".join(pieces), "metrics": metrics}

@app.post("/stream")
def stream(query: Query):
    def sse():
        for event in generate_events(query.prompt):
            # JSON 将文本中的换行编码为转义序列，避免破坏 SSE 事件边界。
            yield "data: " + json.dumps(event, ensure_ascii=False) + "\n\n"
    return StreamingResponse(sse(), media_type="text/event-stream",
                             headers={"Cache-Control": "no-cache"})
```

```bash
python -m uvicorn stream_service:app --host 127.0.0.1 --port 9001 --workers 1
```

`TextIteratorStreamer` 缓存 token 后解码，输出的块不必等于一个 token。单独 `decode([token_id])` 得到的 `�` 已经是替代字符，事后拼接这些字符串不能恢复原始 UTF-8 字节；必须在**解码前**保留 token/字节上下文。也不要拿逐 token 的 `print()` 时间测推理性能。

## 三、客户端测首文本与总耗时

保存为 `stream_client.py`，另一个终端运行 `python stream_client.py`：

```python
import json
import time
import requests

BASE = "http://127.0.0.1:9001"
PROMPT = "请简要介绍 Transformer 的主要组成。"

def measure(streaming):
    start = time.perf_counter()
    first = None
    pieces, metrics = [], {}
    path = "/stream" if streaming else "/complete"
    with requests.post(BASE + path, json={"prompt": PROMPT},
                       stream=streaming, timeout=300) as response:
        response.raise_for_status()
        if streaming:
            # 小块读取减少客户端自身缓冲对首文本测量的干扰。
            for line in response.iter_lines(chunk_size=1):
                if not line.startswith(b"data: "):
                    continue
                event = json.loads(line[6:].decode("utf-8"))
                if event["type"] == "error":
                    raise RuntimeError(event["error"])
                if event["type"] == "text" and event["text"]:
                    if first is None:
                        first = time.perf_counter() - start
                    pieces.append(event["text"])
                elif event["type"] == "metrics":
                    metrics = event
        else:
            payload = response.json()
            if payload["text"]:
                first = time.perf_counter() - start
            pieces.append(payload["text"])
            metrics = payload["metrics"]
    if not metrics:
        raise RuntimeError("响应未包含完成指标，不能将截断流当作完整结果")
    return {"mode": "stream" if streaming else "complete",
            "client_first_text_s": first,
            "client_total_s": time.perf_counter() - start,
            **metrics, "text": "".join(pieces)}

# 预热不计入正式结果；正式测量交替顺序，保留每轮而非只挑最快的一次。
measure(False)
for order in [(False, True), (True, False), (False, True)]:
    runs = [measure(mode) for mode in order]
    assert runs[0]["text"] == runs[1]["text"], "先检查生成配置与非确定性，再比较延迟"
    for run in runs:
        print(json.dumps(run, ensure_ascii=False))
```

输出字段是 `engine_ttft_s`、`engine_total_s`、`client_first_text_s` 和 `client_total_s`；本教材不保留未复跑的精确秒数。请记录设备、库版本、模型 revision、输入/输出 token 数和重复次数，再计算中位数或分位数。这里的贪心解码有助于控制变量，但不同设备和内核仍可能产生数值差异。

## 四、怎样解释结果

流式通常提前暴露已经生成的文本，而不是改变模型内部第一步出现的时间。缓存解码、网络代理缓冲和客户端读取粒度均可能推迟首文本；服务侧首 token 与用户侧首文本应该同时观察。SSE 事件中的文本用 JSON 编码，可安全承载换行和 Unicode；前端依次拼接 `text` 字段，而不是拼接单 token 的损坏解码结果。

这是单机、单模型、单实验客户端的比较服务，不是生产流式网关：

- `generation_lock` 避免共享模型并发，但没有有界排队；不要用本例做负载测试。
- 超时事件不等于已经取消后台生成；本例未实现断连取消、背压或强制中止，后台任务最多继续到本次生成结束。
- HTTP 200 后的失败以 `error` 事件呈现，客户端必须处理，不能当作完整答案。
- 未实现持久化事件 ID、断点续传、多路复用与多副本广播；`LangGraph.stream()` 的图状态更新也不必然等同于 token 流。

本节实现的是可检查的解码与测量路径，而非承诺固定延迟收益。下一节 10.3 用 Trace 分析任务质量，避免“出字快”掩盖“任务没完成”。
