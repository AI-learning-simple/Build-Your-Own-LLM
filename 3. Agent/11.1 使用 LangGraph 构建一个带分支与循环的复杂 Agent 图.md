# 11.1 使用 LangGraph 构建一个带分支与循环的复杂 Agent 图

> **本节目标**：3.1 节和 6.1 节我们已经用 LangGraph 搭建过简单的线性流程和一个基础循环。这一节我们真正利用 Graph 结构的威力：搭建一个带**条件分支**（根据问题类型走不同处理路径）和**重试循环**（失败自动重试，直到成功或超过次数）的复杂 Agent 图，并把图结构可视化出来。

## 一、场景设计：一个"智能路由"Agent

这个 Agent 需要先判断用户问题的类型（数学计算 / 知识问答 / 闲聊），再路由到不同的处理节点，其中数学计算节点还需要"验证结果 → 不满意就重试"的循环。

```python
import torch
import re
from typing import TypedDict
from transformers import AutoTokenizer, AutoModelForCausalLM
from langgraph.graph import StateGraph, END

model_name = "Qwen/Qwen2.5-1.5B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype=torch.float16, device_map="auto")

def llm(prompt, max_new_tokens=150):
    messages = [{"role": "user", "content": prompt}]
    text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = tokenizer(text, return_tensors="pt").to(model.device)
    output = model.generate(**inputs, max_new_tokens=max_new_tokens, do_sample=False)
    return tokenizer.decode(output[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True)
```

## 二、定义状态与节点

```python
class RouterState(TypedDict):
    question: str
    category: str        # 分类结果：数学计算 / 知识问答 / 闲聊
    answer: str
    retry_count: int      # 已经重试的次数，用于防止无限循环
    verified: bool        # 数学计算结果是否通过验证

def classify_node(state: RouterState) -> RouterState:
    # 第一个节点：判断问题类型，决定接下来走哪条分支
    prompt = f"""判断下面这句话属于哪一类：数学计算、知识问答、闲聊。只回答类别名称。

内容：{state['question']}"""
    category = llm(prompt, max_new_tokens=10).strip()
    return {"category": category}

def math_node(state: RouterState) -> RouterState:
    prompt = f"请计算：{state['question']}，只给出最终数字结果。"
    answer = llm(prompt, max_new_tokens=30)
    # 每次进入这个节点都让 retry_count 加1，方便后面判断是否超过最大重试次数
    return {"answer": answer, "retry_count": state.get("retry_count", 0) + 1}

def verify_math_node(state: RouterState) -> RouterState:
    # 一个极简的验证逻辑：只检查答案里是否包含数字（真实场景可以换成更严格的校验）
    has_number = bool(re.search(r"\d", state["answer"]))
    return {"verified": has_number}

def qa_node(state: RouterState) -> RouterState:
    return {"answer": llm(state["question"])}

def chat_node(state: RouterState) -> RouterState:
    return {"answer": llm(f"请用轻松的语气回复：{state['question']}")}
```

---

## 三、条件路由函数

```python
def route_by_category(state: RouterState) -> str:
    # 根据分类结果，决定图从 classify 节点走向哪一个分支节点
    if "数学" in state["category"]:
        return "math"
    if "知识" in state["category"]:
        return "qa"
    return "chat"

def route_after_verify(state: RouterState) -> str:
    # 验证通过，或者已经重试了3次仍不通过，都结束；否则回到 math 节点重新计算
    if state["verified"] or state["retry_count"] >= 3:
        return "end"
    return "retry"
```

## 四、搭建带分支和循环的图

```python
graph = StateGraph(RouterState)

graph.add_node("classify", classify_node)
graph.add_node("math", math_node)
graph.add_node("verify_math", verify_math_node)
graph.add_node("qa", qa_node)
graph.add_node("chat", chat_node)

graph.set_entry_point("classify")

# 分支：classify 节点执行完后，根据 route_by_category 的结果走向三条不同路径之一
graph.add_conditional_edges(
    "classify",
    route_by_category,
    {"math": "math", "qa": "qa", "chat": "chat"},
)

graph.add_edge("math", "verify_math")
# 循环：验证失败会回到 math 节点重新计算，形成一个"重试环"
graph.add_conditional_edges(
    "verify_math",
    route_after_verify,
    {"retry": "math", "end": END},
)

graph.add_edge("qa", END)
graph.add_edge("chat", END)

app = graph.compile()
```

这张图里同时包含了两种控制流：`classify` 之后的三分支路由（分支）、以及 `math → verify_math → math` 之间的重试环（循环）——这正是 LangGraph 相比一条直线式的 Chain 更强大的地方。

## 五、运行并观察不同路径

```python
test_questions = [
    "帮我计算 128乘以 37",       # 会走 math → verify_math 路径
    "什么是相对论？",            # 会走 qa 路径
    "今天心情不太好",            # 会走 chat 路径
]

for q in test_questions:
    result = app.invoke({"question": q, "category": "", "answer": "", "retry_count": 0, "verified": False})
    print(f"问题: {q}")
    print(f"判定类别: {result['category']}")
    print(f"最终答案: {result['answer']}")
    if result["category"].find("数学") != -1:
        print(f"重试次数: {result['retry_count']}")
    print("---")
```

三个问题会分别走 `classify → math → verify_math → (end 或重试)`、`classify → qa → end`、`classify → chat → end` 三条完全不同的路径。

## 六、把图结构可视化出来

```python
# LangGraph 支持直接把整张图导出成 Mermaid 定义，用于可视化和团队交流
print(app.get_graph().draw_mermaid())
```

把输出的 Mermaid 代码粘贴到任意支持 Mermaid 渲染的编辑器（例如 VS Code 的 Markdown 预览、或在线 Mermaid Live Editor）里，你会直接看到一张带分支箭头和一个自循环箭头的流程图——**这正是 Graph Engineering 相比传统代码最大的优势：控制流不再隐藏在 `if/else`和 `while` 里，而是变成了一份可以直接"看懂"的图。**

---

## 七、为什么这对复杂 Agent 系统很重要？

随着 Agent 需要处理的场景越来越多（不同任务类型、不同失败重试策略、不同的人工介入检查点），传统代码里嵌套的 `if/else/while` 会迅速变得难以维护和调试。而图结构天生具备两个优势：**可视化**（一眼看出所有可能的执行路径）和**可组合**（给某个节点换一个实现，不需要理解整张图的其它部分）。这也是为什么第11章把 Graph Engineering 称为"下一代 Agent Runtime 的工程范式"。
