# 3.1 实现一个任务分解 Planner，并用 LangGraph 复现同一流程

> **本节目标**：第3章讲了 Planning 的思想——把一个复杂目标拆解成多个可执行的子任务。这一节我们先手写一个最简单的 Planner，再用主流框架 LangGraph 把同一个流程实现一遍，直观对比"自己管理状态"和"框架帮你管理状态"到底差在哪里。

## 一、手写版：Plan → Execute 循环

```bash
pip install torch transformers accelerate
```

```python
import torch
import re
from transformers import AutoTokenizer, AutoModelForCausalLM

model_name = "Qwen/Qwen2.5-1.5B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype=torch.float16, device_map="auto")

def llm(prompt, max_new_tokens=200):
    messages = [{"role": "user", "content": prompt}]
    text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = tokenizer(text, return_tensors="pt").to(model.device)
    output = model.generate(**inputs, max_new_tokens=max_new_tokens, do_sample=False)
    return tokenizer.decode(output[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True)

def make_plan(goal):
    # 让模型把一个大目标拆解成若干条编号的子任务
    prompt = f"""请把下面的复杂目标拆解成3-5个有先后顺序的子任务，每行一个，用数字编号，不要输出其它内容。

目标：{goal}"""
    response = llm(prompt)
    # 用正则提取出每一条"数字编号 + 内容"的子任务文本
    steps = re.findall(r"\d+[\.\、]\s*(.+)", response)
    return steps

def execute_step(step, context):
    # 把"已经完成的进度"作为上下文传入，保证模型知道之前发生了什么，避免重复劳动
    prompt = f"""已完成的进度：{context}

请完成下面这一步任务，直接给出结果，不要重复之前的内容：
{step}"""
    return llm(prompt, max_new_tokens=150)

def hand_written_planner(goal):
    steps = make_plan(goal)
    print(f"Planner 拆解出 {len(steps)} 个子任务:")
    for i, s in enumerate(steps):
        print(f"  {i + 1}. {s}")

    context = ""    # 手动维护的进度字符串，随着每一步执行不断累积
    for i, step in enumerate(steps):
        result = execute_step(step, context)
        print(f"\n--- 执行子任务 {i + 1}: {step} ---")
        print(result)
        context += f"\n[{step}] -> {result}"

    return context

goal = "写一份介绍 Transformer 的简短科普文章"
final_context = hand_written_planner(goal)
```

手写版本的核心逻辑其实很直接：**用一个 `context` 字符串手动累积历史进度，用一个 `for` 循环手动串联子任务**。当子任务之间的依赖关系变得复杂（比如某一步需要根据前面某几步的结果做条件判断、某些子任务可以并行执行）时，这种手写方式很快就会变得难以维护。

## 二、用 LangGraph 复现同一个流程

```bash
pip install langgraph langchain-core
```

```python
from typing import TypedDict, List
from langgraph.graph import StateGraph, END

# TypedDict 明确声明了整个流程中会流转的所有状态字段，比手写版的一堆散落变量更清晰
class PlannerState(TypedDict):
    goal: str
    steps: List[str]
    current_step: int
    context: str

def plan_node(state: PlannerState) -> PlannerState:
    # 节点函数只需要接收当前状态、返回需要更新的字段，LangGraph 会自动完成状态合并
    steps = make_plan(state["goal"])
    return {"steps": steps, "current_step": 0, "context": ""}

def execute_node(state: PlannerState) -> PlannerState:
    step = state["steps"][state["current_step"]]
    result = execute_step(step, state["context"])
    new_context = state["context"] + f"\n[{step}] -> {result}"
    return {"context": new_context, "current_step": state["current_step"] + 1}

def should_continue(state: PlannerState) -> str:
    # 条件路由函数：根据当前状态决定下一步走向哪个节点（继续执行 or 结束）
    if state["current_step"] < len(state["steps"]):
        return "execute"
    return "end"

graph = StateGraph(PlannerState)
graph.add_node("plan", plan_node)
graph.add_node("execute", execute_node)

graph.set_entry_point("plan")                      # 图的入口节点
graph.add_edge("plan", "execute")                  # plan 完成后固定进入 execute
# execute 完成后根据 should_continue 的返回值决定：继续回到 execute（循环），还是结束
graph.add_conditional_edges("execute", should_continue, {"execute": "execute", "end": END})

app = graph.compile()   # 编译成可以直接调用的可执行图
```

## 三、运行 LangGraph 版本

```python
# invoke 传入初始状态，图会自动按照定义好的节点和边一路执行到END
result = app.invoke({"goal": goal, "steps": [], "current_step": 0, "context": ""})
print("最终 context:")
print(result["context"])
```

## 四、两种实现方式的对比

| | 手写版 | LangGraph 版 |
|---|---|---|
| 状态管理 | 手动维护 `context` 字符串变量 | `PlannerState` TypedDict 结构化管理，自动在节点间传递 |
| 流程控制 | `for` 循环写死顺序 | `add_conditional_edges` 显式声明分支/循环逻辑 |
| 可视化 | 没有 | 可以直接导出流程图（`app.get_graph().draw_mermaid()`） |
| 扩展性 | 加一个"检查/重试"分支需要改循环逻辑 | 加一个新节点 + 一条新的条件边即可 |

```python
# LangGraph 可以直接把图结构导出成 Mermaid 定义，用于可视化展示
print(app.get_graph().draw_mermaid())
```

运行这行代码，你会得到一份 Mermaid 格式的流程图定义，可以直接粘贴到支持 Mermaid 的 Markdown 编辑器里查看——这正是 LangGraph 相比手写循环最大的工程价值：**把隐式的控制流，变成显式的、可视化的图结构**。
