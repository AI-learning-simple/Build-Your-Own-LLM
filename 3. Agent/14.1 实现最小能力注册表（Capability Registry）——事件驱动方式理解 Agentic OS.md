## 二、实现 Capability Registry

```python
class Capability:
    def __init__(self, name, description, handler):
        self.name = name
        self.description = description
        self.handler = handler# 真正会被调用执行的函数

class CapabilityRegistry:
    def __init__(self):
        self.capabilities = {}       # 用名字索引所有已注册的能力

    def register(self, name, description, handler):
        # 任何一个函数都可以被注册成一个"能力"，Registry 不关心它内部具体做了什么
        self.capabilities[name] = Capability(name, description, handler)
        print(f"[Registry] 注册能力: {name} —— {description}")

    def find_by_keyword(self, keyword):
        # 最简单的能力发现方式：按描述里是否包含关键词匹配（真实系统通常用语义检索）
        return [c for c in self.capabilities.values() if keyword in c.description]

    def invoke(self, name, **kwargs):
        if name not in self.capabilities:
            return f"未找到能力: {name}"
        return self.capabilities[name].handler(**kwargs)

registry = CapabilityRegistry()
```

Registry 只保存"名字 + 描述 + 处理函数"三样东西，不关心能力来自一个完整的 App、一个函数，还是一个 MCP Server 暴露的工具。

## 三、注册几个真实能力

# world_state 模拟第 13 章提到的 Persistent World——所有能力共享的、持续存在的状态
world_state = {"emails": [], "calendar": [], "drafts": []}

## 四、实现 Event Bus

```python
class EventBus:
    def __init__(self, registry):
        self.registry = registry
        self.subscriptions = {}       # 记录"某类事件"应该触发哪些能力

    def subscribe(self, event_type, capability_name):
        # 订阅关系：当event_type 事件发生时，自动调用 capability_name这个能力
        self.subscriptions.setdefault(event_type, []).append(capability_name)
        print(f"[EventBus] 订阅:当 '{event_type}' 事件发生时，自动调用 '{capability_name}'")

    def publish(self, event_type, **payload):
        # 发布一个事件，EventBus 会自动查找所有订阅了这个事件的能力并依次调用
        print(f"\n[EventBus] 事件触发: {event_type} payload={payload}")
        handlers = self.subscriptions.get(event_type, [])
        results = []
        for cap_name in handlers:
            result = self.registry.invoke(cap_name, **payload)
            print(f"  -> 自动调用能力 '{cap_name}'，结果: {result}")
            results.append(result)
        return results

bus = EventBus(registry)
bus.subscribe("new_email", "draft_reply")
bus.subscribe("meeting_request", "schedule_event")
```

## 六、加入多个 Agent，共享同一个 World State

```python
class SimpleAgent:
    def __init__(self, name, bus):
        self.name = name
        self.bus = bus       # 多个 Agent 实例共享同一个 EventBus（进而共享同一个 Registry 和 world_state）

    def on_event(self, event_type, **payload):
        print(f"[{self.name}] 感知到事件: {event_type}")
        return self.bus.publish(event_type, **payload)

research_agent = SimpleAgent("研究助理", bus)
schedule_agent = SimpleAgent("日程助理", bus)

research_agent.on_event("new_email", email_content="能帮我总结一下这份市场报告吗？")
schedule_agent.on_event("meeting_request", title="季度复盘", date="本月底")

print("\n========== 最终 World State（多个 Agent 共享）==========")
print(world_state)
```

两个不同的 Agent 实例（`research_agent`、`schedule_agent`）各自感知不同的事件，但**共享同一个 `world_state` 和同一个 `registry`**——这正是本实验要观察的共享状态行为。

## 七、从雏形到可运行系统

本实验只实现了三个机制：可发现的能力、事件订阅、共享状态。真正的 Agentic OS 还需要权限系统、调度器（见 13.1）、持久化存储与语义化能力发现（见 4.1），这些差距已列在实验边界中。

---

## 实验边界

- Registry 与 World State 都在单进程内存中，没有持久化、并发控制与冲突解决；
- 没有权限体系、租户隔离、审计与撤销机制；
- 事件匹配是简化规则，未处理事件乱序、重复投递与死信；
- 没有跨设备同步与离线一致性；
- 这是概念雏形，不是可运行的操作系统或生产级平台。

## 本节小结

✅实现了一个最小的 Capability Registry，把函数、能力抽象成可注册、可发现的统一对象 ✅ 实现了一个 Event Bus，验证了"事件触发 → 自动匹配能力 → 自动执行"完全不需要人工点击的运行方式 ✅ 让多个 Agent 共享同一个 Capability Registry 和 World State，模拟了 Agentic OS 设想的最小雏形。一句话总结：**传统操作系统的核心是"应用 + 窗口 + 用户点击"，Agentic OS 设想的核心是"能力 + 事件 + 持续运行的 Agent"。**
