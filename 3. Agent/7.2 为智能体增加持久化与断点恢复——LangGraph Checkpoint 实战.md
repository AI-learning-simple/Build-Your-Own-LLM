## 一、问题设定：没有 Checkpoint 会怎样

下面以 6.1 节的 Agent Loop 为起点，假设程序在第 3 步时进程崩溃，观察有无 Checkpoint 的差别。没有持久化时，已经跑过的步骤全部作废，重新运行只能从头再来。

## 二、给 LangGraph 加上一个 Checkpointer

```python
import torch
from typing import TypedDict, List
from transformers import AutoTokenizer, AutoModelForCausalLM
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.sqlite import SqliteSaver

model_name = "Qwen/Qwen2.5-1.5B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype=torch.float16, device_map="auto")

def llm(prompt, max_new_tokens=100):
    messages = [{"role": "user", "content": prompt}]
    text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = tokenizer(text, return_tensors="pt").to(model.device)
    output = model.generate(**inputs, max_new_tokens=max_new_tokens, do_sample=False)
    return tokenizer.decode(output[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True)

class TaskState(TypedDict):
    steps: List[str]
    current_step: int
    results: List[str]

def process_step_node(state: TaskState) -> TaskState:
    step = state["steps"][state["current_step"]]
    print(f"正在执行第 {state['current_step'] + 1} 步: {step}")
    result = llm(f"请完成这个子任务：{step}")
    return {
        "results": state["results"] + [result],
        "current_step": state["current_step"] + 1,
    }

def should_continue(state: TaskState) -> str:
    return "continue" if state["current_step"] < len(state["steps"]) else "end"

graph = StateGraph(TaskState)
graph.add_node("process", process_step_node)
graph.set_entry_point("process")
graph.add_conditional_edges("process", should_continue, {"continue": "process", "end": END})

# 关键：给 compile() 传入 checkpointer，之后每一步执行完的状态都会自动保存进 SQLite 数据库
checkpointer = SqliteSaver.from_conn_string("agent_checkpoints.db")
app = graph.compile(checkpointer=checkpointer)
```

`SqliteSaver` 会把每一次节点执行后的完整 `State` 保存进一个本地 SQLite 数据库文件——这意味着即使程序崩溃重启，只要数据库文件还在，就能找回上一次的进度。

## 三、模拟"中途中断"

```python
# thread_id 用于唯一标识一次任务的执行线程，Checkpoint 就是按 thread_id 来存取的
config = {"configurable": {"thread_id": "task-001"}}

steps = ["查阅 Transformer 的基本结构", "总结 Attention 机制的作用", "写一句总结性的话"]
initial_state = {"steps": steps, "current_step": 0, "results": []}

# app.stream() 会逐步产出每个节点执行后的事件，而不是一口气跑完整张图
for i, event in enumerate(app.stream(initial_state, config)):
    print(f"[事件 {i}] {event}")
    if i == 0:
        print("模拟程序在这里意外中断！")
        break        # 手动中断，模拟进程崩溃——但 Checkpoint 已经悄悄保存了这一步的结果
```

我们故意在第一步执行完之后就手动 `break`，模拟"程序崩溃"——注意这里没有调用任何"保存进度"的代码，因为 `SqliteSaver` 已经在每一步执行完之后自动把`State` 写进了数据库。

## 四、"重启程序"后从断点恢复

```python
# 假设这里是重新启动的一个全新 Python 进程，重新连接同一个 checkpoint 数据库
resumed_checkpointer = SqliteSaver.from_conn_string("agent_checkpoints.db")
resumed_app = graph.compile(checkpointer=resumed_checkpointer)

# 用同样的 thread_id，才能读取到之前保存的那个任务的进度
same_config = {"configurable": {"thread_id": "task-001"}}

current_state = resumed_app.get_state(same_config)
print(f"从数据库恢复出的进度: 已完成 {current_state.values['current_step']} / {len(current_state.values['steps'])} 步")
print(f"已有结果: {current_state.values['results']}")

# 传入 None 表示"不提供新的初始状态"，LangGraph 会自动从 Checkpoint 里恢复上一次的状态
for event in resumed_app.stream(None, same_config):
    print(f"[恢复后继续执行] {event}")
```

调用 `resumed_app.stream(None, same_config)` 时传入的是 `None`（表示不提供新的初始状态），LangGraph 会自动从 `thread_id="task-001"` 对应的 Checkpoint 里读取上一次的状态，**从 `current_step=1` 继续往下执行，而不是从0重新开始**。

## 五、验证结果的完整性

```python
final_state = resumed_app.get_state(same_config)
print(f"最终完成步数: {final_state.values['current_step']} / {len(steps)}")
for i, r in enumerate(final_state.values["results"]):
    print(f"第{i + 1}步结果: {r[:50]}...")
```

三步任务里第一步的结果是"中断前"就已经保存好的，第二、三步是"恢复后"新执行产生的——**整个任务的连续性完全没有被中断打断**。

---

## 六、恢复结果说明了什么

从输出可以确认：恢复后的 `results` 仍包含中断前的第一步结果，后续步骤继续追加。需要强调，恢复的是图内状态，外部工具的副作用不会重放或回滚（见实验边界）。

---

## 实验边界

- 使用本地 SQLite 保存图状态，只验证单机单进程恢复；
- Checkpoint 恢复的是图内状态，不会重放或回滚外部工具的副作用；
- 没有并发写、租约、版本冲突与多副本恢复；
- 没有演示幂等键、补偿事务与人工对账；
- 生产环境还需考虑状态加密、保留策略与迁移。

## 本节小结

✅ 理解了没有持久化机制时，Agent 任务在中断后会彻底丢失进度 ✅ 用 LangGraph 的 `SqliteSaver` 亲手实现了状态的自动持久化 ✅ 模拟了"程序崩溃 → 重启 → 从断点恢复继续执行"的完整过程。一句话总结：**Checkpoint 机制让 Agent 的"运行进程"和"任务状态"彼此独立，这是 Graph Engineering 支撑长期任务、区别于普通脚本式Loop 的关键能力。**
