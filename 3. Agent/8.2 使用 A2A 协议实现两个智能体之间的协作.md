## 一、Agent Card：能力声明

A2A 协议里，每个 Agent 都需要发布一份 **Agent Card**——一份标准化的"能力说明书"，其他 Agent 通过它就能知道"这个 Agent 能做什么、怎么调用它"，不需要事先通过人工文档沟通：

```python
# 用一个字典模拟 Agent Card 的核心字段（真实协议里这是一份 JSON，公开在
# https://{domain}/.well-known/agent-card.json，并按 A2A 1.0 的字段命名）
hotel_agent_card = {
    "name": "酒店预订 Agent",
    "description": "根据城市、入住日期、预算，查询并预订酒店",
    "version": "1.0.0",
    "supportedInterfaces": [           # 1.0 用 supportedInterfaces 取代早期的单个 url 字段
        {"url": "http://localhost:9101", "protocolBinding": "JSONRPC", "protocolVersion": "1.0"},
    ],
    "capabilities": {"streaming": False, "pushNotifications": False},
    "defaultInputModes": ["text/plain"],
    "defaultOutputModes": ["application/json"],
    "skills": [
        {"id": "search_hotel", "name": "搜索酒店", "description": "根据城市和预算搜索可选酒店", "tags": ["hotel", "search"]},
        {"id": "book_hotel", "name": "预订酒店", "description": "预订指定酒店", "tags": ["hotel", "booking"]},
    ],
}

flight_agent_card = {
    "name": "机票预订 Agent",
    "description": "根据出发地、目的地、日期，查询并预订机票",
    "version": "1.0.0",
    "supportedInterfaces": [
        {"url": "http://localhost:9102", "protocolBinding": "JSONRPC", "protocolVersion": "1.0"},
    ],
    "capabilities": {"streaming": False, "pushNotifications": False},
    "defaultInputModes": ["text/plain"],
    "defaultOutputModes": ["application/json"],
    "skills": [
        {"id": "search_flight", "name": "查询航班", "description": "查询可选航班", "tags": ["flight", "search"]},
        {"id": "book_flight", "name": "预订航班", "description": "预订指定航班", "tags": ["flight", "booking"]},
    ],
}
```

> `supportedInterfaces` 是对照 A2A 1.0 字段的示意，两个 `localhost` 地址只是字典索引，没有监听中的网络端点；本例未验证这些字典是否通过官方 Agent Card schema。真实部署需可达端点、TLS、身份与授权策略。Agent Card 的 JWS 签名是可选完整性机制，不是唯一身份认证方式；验签还需要可信密钥来源，不能仅凭卡片自称的域名建立信任。

## 二、Agent 服务化实现

真实 A2A 服务需要实现所选传输绑定、消息结构和任务生命周期。这里仅用 Python 类模拟能力提供方：`get_agent_card`、`handle_task` 是本教材自定义方法，**不与标准 JSON-RPC 方法一一对应**，下面的 `{status, result}` 也不是标准 Task/Artifact 数据结构：

```python
class A2AAgent:
    """同进程能力提供方，不是符合 A2A 的网络服务。"""

    def __init__(self, card: dict):
        self.card = card

    def get_agent_card(self):
        # 对应 A2A 协议里 Client 获取 Agent Card 的方式
        # （真实场景是 GET https://{domain}/.well-known/agent-card.json）
        return self.card

    def handle_task(self, skill_id: str, params: dict) -> dict:
        # 自定义同步函数：接收参数并返回字典，不是标准协议方法
        raise NotImplementedError


class HotelAgent(A2AAgent):
    def __init__(self):
        super().__init__(hotel_agent_card)

    def handle_task(self, skill_id, params):
        if skill_id == "search_hotel":
            return {"status": "completed", "result": f"在{params['city']}找到3家预算内酒店：希尔顿、如家、亚朵"}
        if skill_id == "book_hotel":
            return {"status": "completed", "result": f"已预订{params['city']}的亚朵酒店，入住日期{params['date']}"}
        return {"status": "failed", "result": f"不支持的能力: {skill_id}"}


class FlightAgent(A2AAgent):
    def __init__(self):
        super().__init__(flight_agent_card)

    def handle_task(self, skill_id, params):
        if skill_id == "search_flight":
            return {"status": "completed", "result": f"找到{params['from']}到{params['to']}的3个航班，最早08:00起飞"}
        if skill_id == "book_flight":
            return {"status": "completed", "result": f"已预订{params['from']}到{params['to']}08:00 的航班"}
        return {"status": "failed", "result": f"不支持的能力: {skill_id}"}
```

## 三、协调者 Agent：发现能力，委托任务

现在写一个"旅行规划 Agent"，它自己不会订酒店、不会订机票，而是通过本地对象**发现**能力，并把参数**委托**给对应对象；固定调用顺序不是模型规划，也没有 A2A 网络通信：

```python
class TravelPlannerAgent:
    """协调者：不直接执行任务，而是委托给其他 A2A Agent"""

    def __init__(self):
        # 在真实场景下，这里应该是通过服务注册中心/已知的 endpoint 列表去发现 Agent
        self.known_agents = {
            "http://localhost:9101": HotelAgent(),
            "http://localhost:9102": FlightAgent(),
        }

    def discover(self):
        #遍历已知的 Agent，拉取它们的 Agent Card，了解各自的能力范围
        for endpoint, agent in self.known_agents.items():
            card = agent.get_agent_card()
            print(f"发现 Agent: {card['name']} | 能力: {[s['id'] for s in card['skills']]}")

    def delegate(self, endpoint: str, skill_id: str, params: dict) -> dict:
        # 把任务委托给指定的 Agent，并等待其返回执行结果（本例没有标准 Task 生命周期）
        agent = self.known_agents[endpoint]
        print(f"  → 委托任务给 {agent.card['name']}: {skill_id}({params})")
        return agent.handle_task(skill_id, params)

    def plan_trip(self, city, date, origin):
        print("=== 开始规划行程 ===")
        self.discover()

        flight_result = self.delegate("http://localhost:9102", "search_flight", {"from": origin, "to": city})
        print("  航班查询结果:", flight_result["result"])

        hotel_result = self.delegate("http://localhost:9101", "search_hotel", {"city": city})
        print("  酒店查询结果:", hotel_result["result"])

        # 拿到查询结果后，再分别委托预订任务——这一步真实场景中通常需要用户确认后才会执行
        book_flight = self.delegate("http://localhost:9102", "book_flight", {"from": origin, "to": city})
        book_hotel = self.delegate("http://localhost:9101", "book_hotel", {"city": city, "date": date})

        print("=== 行程规划完成 ===")
        print("机票:", book_flight["result"])
        print("酒店:", book_hotel["result"])


planner = TravelPlannerAgent()
planner.plan_trip(city="上海", date="2026-08-20", origin="北京")
```

## 四、与 8.1 的 MCP 对照

8.1 使用实际 MCP SDK 传输，本节则只演示任务委托思想。MCP 的工具可以封装完整 Agent 或工作流，A2A 服务也可以由确定性程序实现，不能按“是否会思考”划界。关键在公开契约：MCP 侧偏工具/资源访问，A2A 侧偏消息、任务状态与产物交换。

若要替换为真实远程 A2A 服务，必须增加官方 SDK 客户端/服务端适配、Agent Card schema 验证、标准消息与任务 ID、所选绑定的方法、状态查询/取消、错误映射与鉴权；不能只把类实例换成 URL 就声称互操作已经成立。流式能力必须在实现相应事件传输后才能声明为 true。

## 实验边界

- 两个 Agent 均在本机运行，未验证跨组织、跨网络与真实鉴权；
- 只覆盖能力发现与任务委托的主路径，未展开任务取消、流式进度与产物校验；
- 没有处理对方超时、部分完成、重复任务与幂等；
- Agent Card 内容为演示，生产环境需要 schema 验证、版本与信任策略；JWS 是可选签名机制，不能替代传输身份验证和调用授权；
- 本节不是协议实现；真实部署可使用与 A2A 1.0 匹配的官方 SDK，并按当前发行说明选择 SDK 版本，SDK 版本号不必与协议版本号相同；
- A2A 在 2026 年 3 月发布 1.0，字段命名（如 `supportedInterfaces`）与传输绑定仍在小幅演进，请以官方规范为准。

- 用近似 Agent Card 的字典展示能力声明，不声称已通过官方 schema 校验
- 用同进程固定流程体验“发现→委托→等待结果”，未进行真实 A2A 互操作测试
