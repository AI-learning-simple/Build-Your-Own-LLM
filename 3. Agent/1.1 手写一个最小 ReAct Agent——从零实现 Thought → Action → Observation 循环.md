# 1.1 手写一个最小 ReAct Agent——从零实现 Thought → Action → Observation 循环

> **本节目标**：第1章讲了 Agent 为什么会出现，但"Agent 会自主行动"这句话最好的理解方式，就是亲手写一个最简单的 Agent 循环，看着它一步步"思考、行动、观察"，直到给出最终答案。这一节我们完全不借助任何 Agent 框架，只用一个 Chat Model + 几行 Python，从零实现一个 ReAct（Reasoning + Acting）Agent。

## 一、准备一个可以调用的模型

```bash

```

> 如果你在国内访问 Hugging Face 下载模型缓慢或失败，可以先配置镜像，见《开始之前》一章的「P0.6 环境准备：国内网络访问与硬件门槛」。

```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

model_name = "Qwen/Qwen2.5-1.5B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype=torch.float16, device_map="auto")

def llm(prompt, stop=None, max_new_tokens=200):
    inputs = tokenizer(prompt, return_tensors="pt").to(model.device)
    output = model.generate(**inputs, max_new_tokens=max_new_tokens, do_sample=False)
    text = tokenizer.decode(output[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True)
    if stop:
        # 遇到 stop 词就截断——例如生成到"Observation:"就应该停下，
        # 因为 Observation 应该由我们的代码填入，而不是让模型自己"编"结果
        for s in stop:
            if s in text:
                text = text.split(s)[0]
    return text
```

## 二、两个最简单的工具

```python
def calculator(expression):
    # 真实执行数学表达式计算——这是模型自己做不到的事情，必须靠代码执行
    try:
        return str(eval(expression))
    except Exception as e:
        return f"计算出错: {e}"

def search(query):
    # 用一个假的知识库模拟"搜索"，重点是演示"外部信息如何被引入对话"这件事
    fake_knowledge_base = {
        "北京到上海的距离": "约1200公里",
        "光速": "每秒约30万公里",
    }
    for key, value in fake_knowledge_base.items():
        if key in query:
            return value
    return "未找到相关信息"

# 用字典把"工具名"映射到"真正的执行函数"，方便后面根据模型输出动态调用
tools = {"calculator": calculator, "search": search}
```

## 三、ReAct 的核心：Prompt 模板

```python
# 这份模板明确告诉模型：必须按照 Thought/Action/Observation 的固定格式输出
# {scratchpad} 会随着对话进行不断累积历史的 Thought/Action/Observation 记录
react_prompt_template = """请一步一步解决下面的问题。你可以使用以下工具：

calculator[表达式]：计算数学表达式
search[关键词]：查询知识库

请严格按照如下格式输出：

Thought: 描述你现在的思考
Action: 工具名[输入内容]
Observation: (工具返回的结果，会自动填入，你不需要自己写)
...(可以重复多次 Thought/Action/Observation)
Thought: 我已经得到了最终答案
Final Answer: 最终答案

问题：{question}

{scratchpad}"""
```

## 四、ReAct Loop：Thought → Action → Observation

```python
import re

def parse_action(text):
    # 从模型输出中提取 "Action: 工具名[参数]" 这种结构，工具名和参数分别取出
    match = re.search(r"Action:\s*(\w+)\[(.*?)\]", text)
    if match:
        return match.group(1), match.group(2)
    return None, None

def react_agent(question, max_steps=5):
    scratchpad = ""   # 累积保存每一轮的 Thought/Action/Observation，作为下一轮的上下文

    for step in range(max_steps):
        # 把当前问题和累积的历史全部拼进 Prompt，模型每次都能"看到"之前发生了什么
        prompt = react_prompt_template.format(question=question, scratchpad=scratchpad)
        # stop=["Observation:"] 确保模型只输出到 Action 为止，不会自己伪造 Observation
        response = llm(prompt, stop=["Observation:"], max_new_tokens=150)

        print(f"--- Step {step + 1} ---")
        print(response)

        # 如果模型认为已经得出最终答案，直接结束循环
        if "Final Answer:" in response:
            final_answer = response.split("Final Answer:")[-1].strip()
            return final_answer

        # 否则解析出要调用的工具和参数，真正执行它
        tool_name, tool_input = parse_action(response)
        if tool_name and tool_name in tools:
            observation = tools[tool_name](tool_input)
        else:
            observation = "未能识别有效的 Action，请重新思考。"

        print(f"Observation: {observation}\n")
        # 把这一轮的输出和真实执行结果都追加进 scratchpad，供下一轮参考
        scratchpad += response + f"\nObservation: {observation}\n"

    return "达到最大步数，未能得出最终答案。"
```

## 五、运行一次真实的 Agent 循环

```python
question = "北京到上海的距离是多少公里？如果一辆车每小时行驶100公里，需要多少小时到达？"
answer = react_agent(question)
print("\n========== Final Answer ==========")
print(answer)
```

观察打印出来的每一步，你会清楚地看到：模型先输出 `Thought`（决定先查距离），再输出 `Action: search[...]`，我们的代码执行真实的 `search` 函数并把结果作为 `Observation`塞回 Prompt，模型基于这个新信息继续 `Thought`（决定用 `calculator` 计算时间），最终输出 `Final Answer`。

## 六、这就是所有 Agent 框架的"地基"

LangChain、LangGraph、AutoGen 等框架内部本质上都是在做同一件事：**维护一个不断增长的上下文（Scratchpad），在"模型输出"和"工具执行"之间循环，直到模型认为任务完成**。区别只在于它们把 Prompt 模板、解析逻辑、状态管理这些细节封装得更工程化、更健壮（例如支持并行工具调用、更严格的输出格式约束、失败重试等）。理解了这几十行代码，你就理解了几乎所有 Agent 框架的核心运行机制。
