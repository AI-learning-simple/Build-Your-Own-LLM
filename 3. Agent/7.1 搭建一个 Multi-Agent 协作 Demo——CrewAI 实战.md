# 7.1 搭建一个 Multi-Agent 协作 Demo——CrewAI 实战

> **本节目标**：第7章讲了 Multi-Agent 为什么会出现——单个 Agent 精力有限，让多个各有分工的 Agent 协作，往往比一个"全能 Agent"完成得更好。这一节我们用当前最流行的多 Agent 框架 CrewAI，亲手搭建一个"研究员 + 撰稿人"两个 Agent 协作完成一篇短文的真实 Demo。

---

## 一、安装 CrewAI

```bash
pip install crewai crewai-tools
```

---

## 二、定义两个各有分工的 Agent

```python
from crewai import Agent, Task, Crew, LLM

#指向本地兼容 OpenAI 接口的推理服务（见下方说明），不需要调用任何付费 API
llm = LLM(model="openai/Qwen2.5-1.5B-Instruct", base_url="http://localhost:8000/v1", api_key="not-needed")

researcher = Agent(
    role="研究员",                # 角色名称，会影响模型的回答风格
    goal="收集关于给定主题的关键信息要点",                # 这个 Agent 存在的目标
    backstory="你是一名严谨的研究员，擅长把复杂主题总结成几个核心要点。",  # 类似 System Prompt，塑造"性格"
    llm=llm,
    verbose=True,      # 打印详细执行过程，方便观察 Agent 的思考轨迹
)

writer = Agent(
    role="撰稿人",
    goal="把研究员提供的要点写成一段通俗易懂的短文",
    backstory="你是一名擅长把技术内容写得通俗有趣的撰稿人。",
    llm=llm,
    verbose=True,
)
```

> 这里用 `base_url` 指向一个本地兼容 OpenAI 接口的推理服务（可以用第8.1节学过的 `vllm serve` 启动），这样就不需要调用任何付费 API，全程在自己的 8GB 显卡上运行。

---

## 三、定义两个有依赖关系的任务

```python
research_task = Task(
    description="研究\"Transformer 架构\"这个主题，列出 4-5 个最重要的知识点。",
    expected_output="一份包含4-5个要点的列表",
    agent=researcher,        # 指定由哪个 Agent 执行这个任务
)

writing_task = Task(
    description="根据研究员提供的要点，写一段200字左右的科普短文，语言通俗易懂。",
    expected_output="一段200字左右的中文短文",
    agent=writer,
    context=[research_task],   # 关键：声明这个任务依赖 research_task 的输出结果
)
```

`context=[research_task]` 是关键——它告诉 CrewAI：**撰稿人任务的输入依赖于研究员任务的输出**，CrewAI 会自动把 `research_task` 的结果传递给 `writing_task`。

---

## 四、组建 Crew 并运行

```python
crew = Crew(
    agents=[researcher, writer],
    tasks=[research_task, writing_task],       # 任务会按顺序依次执行（Sequential）
    verbose=True,
)

result = crew.kickoff()   # 启动整个协作流程，内部会自动按任务依赖顺序调度各个 Agent
print("\n========== 最终产出 ==========")
print(result)
```

运行后你会在终端看到两个 Agent 依次"发言"：研究员先输出几个要点，接着撰稿人基于这些要点生成最终的短文。**整个协作过程完全不需要我们手写任何"把A的输出传给B"的胶水代码**，CrewAI 已经把这部分工程自动化了。

---

## 五、加入第三个 Agent：审核员

```python
reviewer = Agent(
    role="审核员",
    goal="检查文章是否存在事实错误或表达不清晰的地方",
    backstory="你是一名严格的技术审核员，只指出问题，不做无关评价。",
    llm=llm,
    verbose=True,
)

review_task = Task(
    description="检查撰稿人写的短文，如果发现事实错误或表达问题，给出修改建议；如果没有问题，直接说\"审核通过\"。",
    expected_output="审核意见或\"审核通过\"",
    agent=reviewer,
    context=[writing_task],     # 审核任务依赖撰稿任务的产出
)

crew_v2 = Crew(
    agents=[researcher, writer, reviewer],
    tasks=[research_task, writing_task, review_task],   # 三个任务构成一条流水线
    verbose=True,
)

final_result = crew_v2.kickoff()
print(final_result)
```

现在流程变成了 **研究员 → 撰稿人 → 审核员** 三级流水线，这正是第7章讲的Multi-Agent 协作模式之一：**每个 Agent 只负责自己最擅长的一小段任务，通过明确的输入输出依赖串联起来，完成单个 Agent 难以独立高质量完成的复杂工作。**

---

## 六、和手写 Agent Loop 的对比

回顾 6.1 节手写的 `AgentLoop`——那是**一个 Agent 自己反复循环**；而 CrewAI 这里是**多个不同角色的 Agent 按依赖关系协作**。两者可以结合：每个 CrewAI 里的 Agent，其内部完全可以是一个像 6.1 节那样带Plan/Act/Reflect 循环的复杂 Agent，只是从Crew 的视角看，它就是"一个专注做好一件事的角色"。

## 本节小结

✅ 用 CrewAI 搭建了一个真实可运行的"研究员+撰稿人"两 Agent 协作流程 ✅ 通过 `context` 参数体验了 CrewAI 自动处理任务间依赖传递的机制 ✅ 扩展出"研究-撰写-审核"三级 Multi-Agent 流水线。一句话总结：**Multi-Agent 协作的核心不是"更多的模型"，而是"更清晰的角色分工与任务依赖关系"。**
