> **硬件要求**：CPU 即可运行；如本节接入真实 LLM 推理，建议 8GB+ 显存或按说明改用 API
>
> **本节目标**：9.1 节我们体验了 MCP——一个 Agent 如何连接"工具"；这一节体验 A2A——两个 Agent 如何互相声明能力、协商任务、完成协作。我们会手写一个简化版的 Agent Card 发现机制和任务委托流程，把A2A 协议的核心思想变成一段可以直接运行的代码。

## 一、Agent Card：Agent 如何向外界介绍自己

A2A 协议里，每个 Agent 都需要发布一份 **Agent Card**——一份标准化的"能力说明书"，其他 Agent 通过它就能知道"这个 Agent 能做什么、怎么调用它"，不需要事先通过人工文档沟通：

```python
# 用一个简单的字典模拟 Agent Card 的核心字段（真实协议里这是一份JSON）
hotel_agent_card = {
    "name": "酒店预订 Agent",
    "description": "根据城市、入住日期、预算，查询并预订酒店",
    "skills": [
        {"id": "search_hotel", "description": "根据城市和预算搜索可选酒店"},
        {"id": "book_hotel", "description": "预订指定酒店"},
    ],
    "endpoint": "hotel-agent://local",   # 真实场景下这里是一个真正的 HTTP 地址
}

flight_agent_card = {
    "name": "机票预订 Agent",
    "description": "根据出发地、目的地、日期，查询并预订机票",
    "skills": [
        {"id": "search_flight", "description": "查询可选航班"},
        {"id": "book_flight", "description": "预订指定航班"},
    ],
    "endpoint": "flight-agent://local",
}
```

## 二、把每个 Agent 实现成一个独立的"服务"

真实的 A2A 部署中，每个 Agent 都是一个独立运行、通过 HTTP 暴露接口的服务。为了让代码在一个文件里就能直接跑起来，这里用Python 类模拟"服务"的行为（对外的方法名和真实协议里的 JSON-RPC 方法一一对应）：

```python
class A2AAgent:
    """模拟一个符合 A2A 协议的 Agent 服务"""

    def __init__(self, card: dict):
        self.card = card

    def get_agent_card(self):
        # 对应 A2A 协议里 Client 获取 Agent Card 的方式（真实场景是访问 /.well-known/agent.json）
        return self.card

    def handle_task(self, skill_id: str, params: dict) -> dict:
        # 对应 A2A 协议的核心方法：接收一个任务请求，返回执行结果
        raise NotImplementedError


class HotelAgent(A2AAgent):
    def __init__(self):
        super().__init__(hotel_agent_card)

    def handle_task(self, skill_id, params):
        if skill_id == "search_hotel":
            return {"status": "completed", "result": f"在{params['city']}找到3家预算内酒店：希尔顿、如家、亚朵"}
        if skill_id == "book_hotel":
            return {"status": "completed", "result": f"已预订{params['city']}的亚朵酒店，入住日期{params['date']}"}
        return {"status": "failed", "result": f"不支持的能力: {skill_id}"}


class FlightAgent(A2AAgent):
    def __init__(self):
        super().__init__(flight_agent_card)

    def handle_task(self, skill_id, params):
        if skill_id == "search_flight":
            return {"status": "completed", "result": f"找到{params['from']}到{params['to']}的3个航班，最早08:00起飞"}
        if skill_id == "book_flight":
            return {"status": "completed", "result": f"已预订{params['from']}到{params['to']}08:00 的航班"}
        return {"status": "failed", "result": f"不支持的能力: {skill_id}"}
```

## 三、协调者 Agent：发现能力，委托任务

现在写一个"旅行规划 Agent"，它自己不会订酒店、不会订机票，而是通过 A2A 协议**发现**其他 Agent 的能力，并把任务**委托**给对应的 Agent：

```python
class TravelPlannerAgent:
    """协调者：不直接执行任务，而是委托给其他 A2A Agent"""

    def __init__(self):
        # 在真实场景下，这里应该是通过服务注册中心/已知的 endpoint 列表去发现 Agent
        self.known_agents = {
            "hotel-agent://local": HotelAgent(),
            "flight-agent://local": FlightAgent(),
        }

    def discover(self):
        #遍历已知的 Agent，拉取它们的 Agent Card，了解各自的能力范围
        for endpoint, agent in self.known_agents.items():
            card = agent.get_agent_card()
            print(f"发现 Agent: {card['name']} | 能力: {[s['id'] for s in card['skills']]}")

    def delegate(self, endpoint: str, skill_id: str, params: dict) -> dict:
        # 把任务委托给指定的 Agent，并等待其返回执行结果（对应 A2A 协议的Task 生命周期）
        agent = self.known_agents[endpoint]
        print(f"  → 委托任务给 {agent.card['name']}: {skill_id}({params})")
        return agent.handle_task(skill_id, params)

    def plan_trip(self, city, date, origin):
        print("=== 开始规划行程 ===")
        self.discover()

        flight_result = self.delegate("flight-agent://local", "search_flight", {"from": origin, "to": city})
        print("  航班查询结果:", flight_result["result"])

        hotel_result = self.delegate("hotel-agent://local", "search_hotel", {"city": city})
        print("  酒店查询结果:", hotel_result["result"])

        # 拿到查询结果后，再分别委托预订任务——这一步真实场景中通常需要用户确认后才会执行
        book_flight = self.delegate("flight-agent://local", "book_flight", {"from": origin, "to": city})
        book_hotel = self.delegate("hotel-agent://local", "book_hotel", {"city": city, "date": date})

        print("=== 行程规划完成 ===")
        print("机票:", book_flight["result"])
        print("酒店:", book_hotel["result"])


planner = TravelPlannerAgent()
planner.plan_trip(city="上海", date="2026-08-20", origin="北京")
```

## 四、与 9.1 的 MCP 对照

跑完上面的代码，可以与 9.1 的 MCP 对照：MCP 连接的是**工具**（Client 调用 Server 的某个具体方法，一问一答）；A2A 连接的是**另一个 Agent**（互换 Agent Card，委托一整个任务，对方内部可能还要经过多轮思考和工具调用）。因此 `HotelAgent`、`FlightAgent` 完全可以替换成两个独立部署的完整 Agent，协调者只依赖 Agent Card 声明的能力。

---

## 实验边界

- 两个 Agent 均在本机运行，未验证跨组织、跨网络与真实鉴权；
- 只覆盖能力发现与任务委托的主路径，未展开任务取消、流式进度与产物校验；
- 没有处理对方超时、部分完成、重复任务与幂等；
- Agent Card 内容为演示，生产环境需要签名、版本与信任策略；
- 协议实现随 SDK 版本变化，示例不保证与最新规范完全一致。

## 本节小结

✅ 理解并实现了 Agent Card——Agent 对外声明能力的标准化方式 ✅ 手写了一个协调者 Agent，通过"发现 → 委托 → 等待结果"的流程完成跨 Agent 协作 ✅ 对比了 A2A 和 MCP 的核心区别：一个连接的是"另一个有自主性的 Agent"，一个连接的是"没有自主性的工具"。一句话总结：**MCP 让 Agent 拥有更多能力，A2A 让多个 Agent 拥有共同完成任务的能力。**
