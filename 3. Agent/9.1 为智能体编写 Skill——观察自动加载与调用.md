```markdown
## 操作步骤
1. 从用户提供的任务列表中，区分"已完成"和"进行中"

已完成：
- ...

进行中：
- ...

下周计划：
- ...

```

```markdown
name: unit-convert

---

# 单位换算

## 操作步骤
1. 识别用户提供的数值和原始单位、目标单位
2. 使用标准换算公式计算结果，保留2位小数
3. 用"X 单位A≈ Y 单位B"的格式回复，附上使用的换算公式

## 常用换算公式
- 公里→英里：乘以 0.6214
- 摄氏度→华氏度：×9/5 + 32
- 公斤→斤：乘以 2
```

## 二、Skill Loader 实现：目录扫描与索引

```python
import os
import re
from pathlib import Path
import yaml

def parse_skill_md(path):
    # 为简单起见，索引阶段读取整个文件；只是正文不注入 LLM，而非零正文 I/O。
    file = Path(path)
    if file.stat().st_size > 64 * 1024:
        raise ValueError("Skill 文件超过本实验 64 KiB 上限")
    text = file.read_text(encoding="utf-8")
    match = re.match(r"\A---\r?\n(.*?)\r?\n---\r?\n(.*)\Z", text, re.S)
    if match is None:
        raise ValueError(f"缺少合法 frontmatter: {path}")
    meta = yaml.safe_load(match.group(1))
    if not isinstance(meta, dict):
        raise ValueError("frontmatter 必须为 YAML 映射")
    for key in ("name", "description"):
        if not isinstance(meta.get(key), str) or not meta[key].strip():
            raise ValueError(f"{key} 必须是非空字符串")
    if not re.fullmatch(r"[a-z0-9]+(?:-[a-z0-9]+)*", meta["name"]) or meta["name"] != file.parent.name:
        raise ValueError("name 必须是小写连字符格式并匹配目录名")
    return meta, match.group(2)


def load_skill_index(skills_dir):
    # 第一层：索引只保留 name/description/path；文件正文虽读入过，却不送给 LLM
    index = []
    for skill_name in os.listdir(skills_dir):
        skill_md_path = os.path.join(skills_dir, skill_name, "SKILL.md")
        if not os.path.exists(skill_md_path):
            continue
        meta, _ = parse_skill_md(skill_md_path)
        index.append({"name": meta["name"], "description": meta["description"], "path": skill_md_path})
    return index


skill_index = load_skill_index("skills")
for s in skill_index:
    print(f"[已发现 Skill] {s['name']}: {s['description']}")
```

这里 `read_text()` 已读取整个文件，解析器也返回了正文；索引丢弃正文，只把名称与描述用于路由。因此节省的是模型上下文，不是文件 I/O。若技能库很大，可改成只读 frontmatter 的索引器，但那是另一项优化。`yaml.safe_load` 支持 YAML 的引号和多行字符串，也避免任意 Python 对象构造；仍应限制文件大小并仅索引审核过的技能。

## 三、手写 Router：用 LLM 判断该不该用、用哪个 Skill

```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

model_name = "Qwen/Qwen2.5-1.5B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype=torch.float16, device_map="auto")

def ask_llm(prompt, max_new_tokens=200):
    messages = [{"role": "user", "content": prompt}]
    text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = tokenizer(text, return_tensors="pt").to(model.device)
    if inputs["input_ids"].shape[1] + max_new_tokens > 2048:
        raise ValueError("本实验上下文预算为 2048 token，拒绝静默截断")
    output = model.generate(**inputs, max_new_tokens=max_new_tokens, do_sample=False)
    return tokenizer.decode(output[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True)


def route_skill(user_query, skill_index):
    # 把所有 Skill 的"名字+描述"（第一层信息）交给模型，让它判断这次任务该用哪个
    skill_list_text = "\n".join([f"- {s['name']}: {s['description']}" for s in skill_index])
    prompt = f"""你是一个任务路由器。下面是当前可用的 Skill列表：
{skill_list_text}

用户请求：{user_query}

请判断这个请求最匹配哪一个 Skill 的 name，如果都不匹配，输出 none。只输出 name，不要输出其他任何文字。"""
    result = ask_llm(prompt, max_new_tokens=20).strip()
    return result


query1 = "帮我把这周做的3件事整理成周报"
query2 = "10公里等于多少英里？"
query3 = "今天天气怎么样？"

for q in [query1, query2, query3]:
    matched = route_skill(q, skill_index)
    print(f"用户请求: {q}  →  匹配的 Skill: {matched}")
```

## 四、加载匹配到的 Skill 正文，按照它的指导执行

```python
def run_with_skill(user_query, skill_index):
    matched_name = route_skill(user_query, skill_index)

    if matched_name == "none" or matched_name not in [s["name"] for s in skill_index]:
        # 没有匹配到任何 Skill，直接用模型原本的能力回答
        print("[未触发任何 Skill，直接回答]")
        return ask_llm(user_query)

    # 第二层：重新读取已选技能，并首次把正文注入本轮 LLM 上下文
    skill = next(s for s in skill_index if s["name"] == matched_name)
    _, skill_body = parse_skill_md(skill["path"])
    print(f"[触发 Skill: {matched_name}，加载完整 SKILL.md 正文]")

    # 把 Skill 正文当作额外的指令，和用户请求一起交给模型
    prompt = f"""请严格按照下面的操作指南来完成用户的请求。

{skill_body}

用户请求：{user_query}"""
    result = ask_llm(prompt, max_new_tokens=300)
    if matched_name == "weekly-report":
        lines = [line.strip() for line in result.splitlines() if line.strip()]
        headings = ["已完成：", "进行中：", "下周计划："]
        if any(lines.count(heading) != 1 for heading in headings):
            raise ValueError("周报缺少或重复必需标题，未通过格式验收")
        positions = [lines.index(heading) for heading in headings]
        if positions != sorted(positions):
            raise ValueError("周报章节顺序错误")
        for line in lines:
            if line in headings:
                continue
            if not line.startswith("- ") or not (1 <= len(line[2:]) <= 20):
                raise ValueError("周报条目格式或长度未通过验收")
    return result


print(run_with_skill("帮我把这周做的：修复了登录bug、开发了新首页、还在推进的API文档，整理成周报", skill_index))
print("\n---\n")
print(run_with_skill("10公里等于多少英里？", skill_index))
```

## 五、对比：有没有 Skill，回答质量差在哪里

```python
query = "帮我把这周做的：修复了登录bug、开发了新首页、还在推进的API文档，整理成周报"

print("=== 不使用 Skill（直接问模型） ===")
print(ask_llm(query))

print("\n=== 使用 Skill 机制 ===")
print(run_with_skill(query, skill_index))
```

请记录有无 Skill 的两次输出，不预设“加载后必然遵循格式”。这里贪心生成在同环境下本就可能稳定；真正要比较的是与模板的符合程度。代码对周报检查标题、顺序与条目长度，失败会明确报错；它尚未校验任务事实、是否凭空编造下周计划或单位换算数值，因此格式通过不等于业务正确。重复一组不同请求后再统计通过率，不能用一次展示声称已经验证质量提升。

## 实验边界

- Loader 是手写目录扫描，真实宿主框架的发现、注册与启用机制各不相同；
- Router 只做一次 LLM 判断，没有处理多 Skill 冲突、优先级与误触发；
- 限制总输入与输出预算为 2048 token；未测加载延迟、不同技能数下的上下文成本，也未证明所有任务都有收益；
- Skill 内容为演示用途，未涉及版本管理、依赖声明与回归测试；
- “自动加载”依赖宿主提供注册表与加载器，不是文件放进目录就一定生效。

## 本节小结

- 用安全 YAML 解析器实现 Skill Loader，区分磁盘读取与 LLM 上下文注入
- 手写了一个基于 LLM 判断的 Router，实现了"先判断该不该用、用哪个"的自动触发逻辑
- 只有命中 Skill 后才将正文注入生成提示词；索引时仍读取过文件正文
- 对比了有无 Skill 时，输出格式的一致性差异。一句话总结：**Skill 机制的核心不是"存了多少文档"，而是"用一句精确的 description，让 Agent 在还没读正文之前，就能准确判断该不该用"。**
