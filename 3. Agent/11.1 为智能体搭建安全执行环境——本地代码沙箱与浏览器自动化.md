# 11.1 执行环境实践——进程资源限制与只读浏览器操作

> **本节定位**：实践第 11 章的权限边界。方案 A/B 是**仅适用于已审核固定代码的进程与资源限制演示，不是可执行不可信代码的安全沙箱**。保留原文件名以便已有链接继续可用。
>
> **硬件要求**：默认实验只需 Python 3.11+、CPU；可选本地模型需要自行准备模型权重与相应内存。本节不依赖付费 API。
>
> **目标**：观察超时、资源限制和浏览器动作白名单分别约束什么；模型生成的代码默认只展示，不自动执行。

## 一、先分清三种边界

`exec()`、普通子进程、带 `resource` 限制的子进程都可能拥有当前用户的文件、网络和凭据访问权限。独立地址空间不等于权限隔离；`timeout` 也不是授权机制。真正执行不可信代码前，至少需要明确人工审阅与授权，以及独立配置的隔离执行服务：非特权身份、最小文件挂载、默认禁网、进程与资源配额、输出上限、审计和销毁策略。容器、gVisor、微虚拟机的隔离强度不同，不能只换一个函数名就称为沙箱。

下面故意不提供 `execute(model_output)` 入口，避免读者把免责声明之后的代码直接接成同权限自动执行链。

## 二、方案 A：只运行已审核固定代码，观察超时

保存为 `process_demo.py`，使用标准库，无需安装依赖：

```python
import subprocess
import sys

# 由教材作者给定的固定程序，不接收用户输入或模型输出。
APPROVED_CODE = "print(sum(range(101)))"

def run_fixed_demo():
    try:
        result = subprocess.run(
            [sys.executable, "-I", "-c", APPROVED_CODE],
            capture_output=True, text=True, timeout=3, check=False,
        )
        return {"stdout": result.stdout, "stderr": result.stderr,
                "returncode": result.returncode}
    except subprocess.TimeoutExpired:
        return {"stdout": "", "stderr": "直接子进程超时", "returncode": None}

if __name__ == "__main__":
    print(run_fixed_demo())
```

```bash
python process_demo.py
```

固定程序输出 `5050`。`-I` 减少 Python 环境与导入路径的影响，**不会隔离文件系统或网络**。`subprocess.run(timeout=...)` 超时会终止并等待直接子进程，但不保证清理其所有子孙进程；继承管道的后代也可能影响等待。`capture_output=True` 会在父进程内存中缓冲输出，不能用于无限输出的不可信程序。此处因代码固定且输出有界才采用这个简单写法。

## 三、方案 B：在固定子程序内部设置资源限制

此实验面向 Linux，保存为 `resource_demo.py`。macOS 虽有 `resource` 模块，但地址空间限制行为与 Linux 不完全一致；Windows 不适用。本节不使用 `preexec_fn`：在多线程服务中，它可能在 fork 后死锁。

```python
import subprocess
import sys

# 限制在解释器启动后设置；不能覆盖解释器启动阶段。
APPROVED_CODE = r'''
import resource
resource.setrlimit(resource.RLIMIT_CPU, (2, 3))
resource.setrlimit(resource.RLIMIT_AS, (256 * 1024 * 1024, 256 * 1024 * 1024))
print(sum(range(101)))
'''

if __name__ == "__main__":
    if not sys.platform.startswith("linux"):
        raise SystemExit("资源实验仅在 Linux 上运行；其他系统请先运行方案 A")
    try:
        result = subprocess.run(
            [sys.executable, "-I", "-c", APPROVED_CODE],
            capture_output=True, text=True, timeout=5, check=False,
        )
        print({"stdout": result.stdout, "stderr": result.stderr,
               "returncode": result.returncode})
    except subprocess.TimeoutExpired:
        print("直接子进程超时")
```

```bash
python resource_demo.py
```

CPU 时间不是墙钟时间。达到软 CPU 上限可能先收到信号，达到硬上限才强制终止；地址空间分配可能失败并抛出 `MemoryError`，而非一律杀进程。单进程 `rlimit` 不等于整个进程树的总配额，也不限制文件读取、网络或宿主用户权限。真实执行服务还需 cgroup/作业对象等进程树级约束、有限流式输出与可靠回收，不能把本例 A/B 直接作为 Agent 工具。

## 四、模型生成代码：默认只展示

保存为 `code_preview.py`。可选依赖与启动方式如下，首次加载可能下载模型；默认只用 CPU，耗时与内存取决于设备：

```bash
python -m pip install torch transformers accelerate
python code_preview.py
```

```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

MODEL_ID = "Qwen/Qwen2.5-1.5B-Instruct"

def preview_code(task):
    tokenizer = AutoTokenizer.from_pretrained(MODEL_ID)
    model = AutoModelForCausalLM.from_pretrained(MODEL_ID, torch_dtype=torch.float32)
    messages = [
        {"role": "system", "content": "只生成 Python 代码供人审阅，不执行。"},
        {"role": "user", "content": task},
    ]
    text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = tokenizer(text, return_tensors="pt")
    with torch.inference_mode():
        output = model.generate(**inputs, max_new_tokens=160, do_sample=False)
    code = tokenizer.decode(output[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True)
    print("待审阅的模型输出（未执行）：\n" + code)
    return {"status": "review_required", "code": code, "executed": False}

if __name__ == "__main__":
    preview_code("计算 1 到 100 的和")
```

这里没有隐藏的执行分支。若以后接入真实执行服务，应审阅**最终将执行的代码及其哈希、依赖、权限和目标数据**；审批后也必须进入真正隔离的环境，不能人工点一次确认后仍在宿主同用户子进程里执行。

## 五、只读浏览器工具：动作白名单先于模型选择

保存为 `browser_demo.py`。安装仅为读者运行说明，本章修订并未代替读者安装浏览器：

```bash
python -m pip install playwright
python -m playwright install chromium
python browser_demo.py
```

```python
from playwright.sync_api import sync_playwright

ACTIONS = {"GET_TITLE", "GET_HEADINGS"}

def read_page(action):
    if action not in ACTIONS:
        raise ValueError("不支持的动作，拒绝执行")
    with sync_playwright() as p:
        browser = p.chromium.launch(headless=True)
        try:
            context = browser.new_context(accept_downloads=False)
            page = context.new_page()
            # 本实验直接载入固定页面，不接收模型给出的 URL，也不加载外部网络资源。
            page.set_content("<html><head><title>实验页</title></head>"
                             "<body><h1>文档目录</h1><h2>运行环境</h2></body></html>")
            if action == "GET_TITLE":
                return page.title()
            return page.locator("h1, h2").all_inner_texts()
        finally:
            browser.close()

if __name__ == "__main__":
    print(read_page("GET_HEADINGS"))
```

若让模型选择动作，只把其完整输出与 `ACTIONS` 做精确匹配；未知动作拒绝，而不是模糊匹配后默认执行。这里的权限收缩来自固定页面和固定动作，不来自 `headless=True`——无头模式只是隐藏窗口。浏览器仍是拥有宿主权限的本地进程，浏览器漏洞和资源耗尽仍需操作系统隔离应对。

接入真实站点时，还要考虑 URL/重定向与子资源策略、下载、Cookie、独立会话、页面提示注入，以及提交表单等副作用的审批；仅校验初始 URL 不是网络隔离。本节没有实现通用浏览器 Agent，也没有证明任意页面安全。

## 六、验收与实验边界

1. 方案 A 的固定计算输出 `5050`；方案 B 在支持的 Linux 上输出同值，并保留退出码与错误信息。
2. `preview_code` 始终返回 `executed=False`，没有调用子进程或 `exec`。
3. 浏览器固定动作返回页面标题或标题列表；未注册动作抛出异常。
4. 以上验证的是控制流与固定样例，不是对恶意代码、无限输出、进程树逃逸或恶意网页的安全认证。

一句话总结：**进程管理解决运行问题，权限隔离解决信任问题，二者不能互相替代。** 下一节 12.1 将从进程管理视角实现迷你 Agent 调度器。
