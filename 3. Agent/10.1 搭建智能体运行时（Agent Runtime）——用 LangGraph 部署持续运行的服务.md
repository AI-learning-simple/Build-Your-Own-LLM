# 10.1 搭建智能体运行时（Agent Runtime）——用 LangGraph 部署持续运行的服务

> **本节定位**：实践第 10 章的服务化边界。完整服务文件写好后再启动，不在运行中追加路由。
>
> **硬件要求**：默认确定性演示只需 CPU；可选本地 Qwen 模型需自行准备权重与内存，不依赖付费 API。
>
> **目标**：模型/图只初始化一次，同一会话的读—推理—写串行，不同会话状态分开保存，并限制本地模型的并发调用。

## 一、脚本和服务的差别

脚本并非必然每次调用函数都加载模型；只有把初始化放入每次运行或每次请求的路径才会重复加载。服务化的重点是**初始化生命周期、请求入口、状态归属和并发控制**。本例是单节点问答图，不是完整自主 Agent Loop；可在相同服务边界内替换为第 6 章的图。

创建一个空实验目录，使用 Python 3.11+，安装：

```bash
python -m pip install fastapi uvicorn langgraph langchain-core pydantic requests
# 只有运行本地模型模式才需要：
python -m pip install torch transformers accelerate
```

## 二、一次写完整个服务

将下面**整个代码块**保存为 `agent_service.py`。`BACKEND=demo` 默认走确定性回声，便于先验收 HTTP 与状态；它不是语言模型。`BACKEND=local` 才加载本地模型。第一次加载可能下载权重。

```python
import os
from threading import Lock, Semaphore
from typing import TypedDict

from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field
from langgraph.graph import StateGraph, END

BACKEND = os.environ.get("BACKEND", "demo")
if BACKEND not in {"demo", "local"}:
    raise ValueError("BACKEND 只能是 demo 或 local")

if BACKEND == "local":
    import torch
    from transformers import AutoTokenizer, AutoModelForCausalLM
    tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-1.5B-Instruct")
    model = AutoModelForCausalLM.from_pretrained(
        "Qwen/Qwen2.5-1.5B-Instruct", torch_dtype=torch.float32,
    ).eval()  # CPU 基线；可按设备调整 dtype/device，需重新测内存和并发

model_gate = Semaphore(1)

def llm(messages):
    # 包含编码、生成、解码；不假定共享模型/Tokenizer 可随意并发。
    with model_gate:
        if BACKEND == "demo":
            return "[确定性演示] " + messages[-1]["content"]
        text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
        inputs = tokenizer(text, return_tensors="pt")
        if inputs["input_ids"].shape[1] > 2048:
            raise HTTPException(413, "上下文超过本实验 2048 token 预算，请新建会话")
        with torch.inference_mode():
            output = model.generate(**inputs, max_new_tokens=128, do_sample=False)
        return tokenizer.decode(output[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True)

class AgentState(TypedDict):
    messages: list[dict[str, str]]
    answer: str

def answer_node(state: AgentState):
    return {"answer": llm(state["messages"])}

graph = StateGraph(AgentState)
graph.add_node("answer", answer_node)
graph.set_entry_point("answer")
graph.add_edge("answer", END)
agent_app = graph.compile()
app = FastAPI(title="Single-process Agent Runtime")

class Query(BaseModel):
    question: str = Field(min_length=1, max_length=1000)

class ChatQuery(Query):
    session_id: str = Field(min_length=1, max_length=64, pattern=r"^[a-zA-Z0-9_-]+$")

sessions = {}
registry_lock = Lock()
MAX_SESSIONS = 100

def get_session(session_id):
    # 创建记录与锁必须原子，不能让同一 ID 得到两把不同的锁。
    with registry_lock:
        if session_id not in sessions:
            if len(sessions) >= MAX_SESSIONS:
                raise HTTPException(429, "演示会话数已达上限")
            sessions[session_id] = {"lock": Lock(), "history": [], "turn": 0}
        return sessions[session_id]

def run_graph(messages):
    return agent_app.invoke({"messages": messages, "answer": ""})["answer"]

@app.get("/health")
def health():
    return {"status": "ok", "backend": BACKEND}

@app.post("/agent/invoke")
def invoke_agent(query: Query):
    answer = run_graph([{"role": "user", "content": query.question}])
    return {"answer": answer}

@app.post("/agent/chat")
def chat_with_session(query: ChatQuery):
    session = get_session(query.session_id)
    # 覆盖读取历史、模型生成、保存历史整个事务，避免并发请求丢失轮次。
    with session["lock"]:
        messages = [{"role": "system", "content": "你是简洁的问答助手。"}]
        messages += list(session["history"])
        messages.append({"role": "user", "content": query.question})
        answer = run_graph(messages)
        session["history"] += [
            {"role": "user", "content": query.question},
            {"role": "assistant", "content": answer},
        ]
        session["history"] = session["history"][-8:]  # 最多保留最近四轮
        session["turn"] += 1
        return {"answer": answer, "turn": session["turn"]}
```

为什么是两种锁？会话锁保证同一会话的状态一致性，模型信号量限制共享模型的并发生成；仅加其中一个不能解决另一个问题。锁获取顺序固定为会话锁→模型信号量，注册表锁只在查找/创建时短暂持有。

## 三、写好文件后再启动

```bash
BACKEND=demo python -m uvicorn agent_service:app --host 127.0.0.1 --port 9000 --workers 1
# 停止上述进程后，可选改用本地模型：
# BACKEND=local python -m uvicorn agent_service:app --host 127.0.0.1 --port 9000 --workers 1
```

在第二个终端，把下面保存为 `client.py` 后执行 `python client.py`：

```python
from concurrent.futures import ThreadPoolExecutor
import requests

BASE = "http://127.0.0.1:9000"

def ask(session, question):
    response = requests.post(BASE + "/agent/chat", json={
        "session_id": session, "question": question,
    }, timeout=300)
    response.raise_for_status()
    return response.json()

print(requests.get(BASE + "/health", timeout=5).json())
# 在刚启动的服务上执行一次；重跑时换 session_id 或重启服务。
with ThreadPoolExecutor(max_workers=2) as pool:
    futures = [pool.submit(ask, "parallel_test", text) for text in ["第一条", "第二条"]]
    replies = [future.result() for future in futures]
assert sorted(item["turn"] for item in replies) == [1, 2]
assert ask("separate_test", "新会话")["turn"] == 1
print(replies)
```

并发请求获得锁的顺序不保证与客户端发出顺序相同；此处验收的是**不丢失更新**，若业务需要严格顺序应加序列号与队列。`demo` 模式不能验证模型记忆；在 `local` 模式下可再问“我叫小明”“我叫什么”，但模型答错不等于会话存储失效，应分别检查输入历史与生成质量。

## 四、从本地服务到生产运行时

本例使用同步路由，FastAPI 在线程池中运行处理函数；模型信号量限制活跃生成，不等于限制排队请求。生产环境仍需要有界队列、超时、取消和准入控制。

- 必须保持一个 worker；多 worker 各自持有模型、字典和锁，内存锁不能跨进程协调。
- 历史和轮次在内存里，重启即丢失。多副本需要共享存储、会话队列或带版本的事务；仅“换成 Redis 字典”并不会自动消除并发冲突。
- `session_id` 是状态键，不是用户身份或授权凭证。服务只监听回环地址；对外开放前需认证、会话归属检查和租户隔离。
- 保留轮数与 token 预算解决的是上下文增长，不是长期记忆；超预算明确拒绝，不悄悄截断 system 指令。
- 本例没有工具副作用、幂等重试、持久化恢复或故障转移，也不声称已经实现完整 Agent Runtime。
