```markdown
# 生成周报

- ...

进行中：
- ...

下周计划：
- ...

## 注意事项

```

```markdown
name: unit-convert
description: 当用户需要在不同度量单位之间转换时使用，例如公里转英里、摄氏度转华氏度、公斤转斤。
---

# 单位换算

## 操作步骤
1. 识别用户提供的数值和原始单位、目标单位

- 摄氏度→华氏度：×9/5 + 32
```

## 二、手写 Skill Loader：扫描目录，只索引"名字+描述"

```python
import os
import re

def parse_skill_md(path):
    # 手写一个极简的 YAML frontmatter 解析器，避免引入额外依赖
    text = open(path, encoding="utf-8").read()
    match = re.match(r"^---\n(.*?)\n---\n(.*)$", text, re.S)
    frontmatter_text, body = match.group(1), match.group(2)

    meta = {}
    for line in frontmatter_text.splitlines():
        key, _, value = line.partition(":")
        meta[key.strip()] = value.strip()

    return meta, body


def load_skill_index(skills_dir):
    # 第一层 Progressive Disclosure：只加载每个 Skill 的 name + description，不读正文
    index = []
    for skill_name in os.listdir(skills_dir):
        skill_md_path = os.path.join(skills_dir, skill_name, "SKILL.md")
        if not os.path.exists(skill_md_path):
            continue
        meta, _ = parse_skill_md(skill_md_path)
        index.append({"name": meta["name"], "description": meta["description"], "path": skill_md_path})
    return index


skill_index = load_skill_index("skills")
for s in skill_index:
    print(f"[已发现 Skill] {s['name']}: {s['description']}")
```

注意这一步只读取了每个 `SKILL.md` 的 frontmatter，完全没有加载正文——这正是第9章说的"第一层：常驻，只占极小的 Context"。

## 三、手写 Router：用 LLM 判断该不该用、用哪个 Skill

```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

model_name = "Qwen/Qwen2.5-1.5B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype=torch.float16, device_map="auto")

def ask_llm(prompt, max_new_tokens=200):
    messages = [{"role": "user", "content": prompt}]
    text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = tokenizer(text, return_tensors="pt").to(model.device)
    output = model.generate(**inputs, max_new_tokens=max_new_tokens, do_sample=False)
    return tokenizer.decode(output[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True)


def route_skill(user_query, skill_index):
    # 把所有 Skill 的"名字+描述"（第一层信息）交给模型，让它判断这次任务该用哪个
    skill_list_text = "\n".join([f"- {s['name']}: {s['description']}" for s in skill_index])
    prompt = f"""你是一个任务路由器。下面是当前可用的 Skill列表：
{skill_list_text}

用户请求：{user_query}

请判断这个请求最匹配哪一个 Skill 的 name，如果都不匹配，输出 none。只输出 name，不要输出其他任何文字。"""
    result = ask_llm(prompt, max_new_tokens=20).strip()
    return result


query1 = "帮我把这周做的3件事整理成周报"
query2 = "10公里等于多少英里？"
query3 = "今天天气怎么样？"

for q in [query1, query2, query3]:
    matched = route_skill(q, skill_index)
    print(f"用户请求: {q}  →  匹配的 Skill: {matched}")
```

## 四、加载匹配到的 Skill 正文，按照它的指导执行

```python
def run_with_skill(user_query, skill_index):
    matched_name = route_skill(user_query, skill_index)

    if matched_name == "none" or matched_name not in [s["name"] for s in skill_index]:
        # 没有匹配到任何 Skill，直接用模型原本的能力回答
        print("[未触发任何 Skill，直接回答]")
        return ask_llm(user_query)

    # 第二层 Progressive Disclosure：确定要用这个 Skill 之后，才真正读取它的完整正文
    skill = next(s for s in skill_index if s["name"] == matched_name)
    _, skill_body = parse_skill_md(skill["path"])
    print(f"[触发 Skill: {matched_name}，加载完整 SKILL.md 正文]")

    # 把 Skill 正文当作额外的指令，和用户请求一起交给模型
    prompt = f"""请严格按照下面的操作指南来完成用户的请求。

{skill_body}

用户请求：{user_query}"""
    return ask_llm(prompt, max_new_tokens=300)


print(run_with_skill("帮我把这周做的：修复了登录bug、开发了新首页、还在推进的API文档，整理成周报", skill_index))
print("\n---\n")
print(run_with_skill("10公里等于多少英里？", skill_index))
```

## 五、对比：有没有 Skill，回答质量差在哪里

```python
query = "帮我把这周做的：修复了登录bug、开发了新首页、还在推进的API文档，整理成周报"

print("=== 不使用 Skill（直接问模型） ===")
print(ask_llm(query))

print("\n=== 使用 Skill 机制 ===")
print(run_with_skill(query, skill_index))
```

对比两次输出，你通常会发现：**不使用 Skill 时，模型给出的周报格式和用词每次都可能不一样**（因为它只是凭常识理解"周报"该长什么样）；**使用 Skill 之后，输出严格遵循了 `SKILL.md` 里规定的"已完成/进行中/下周计划"三段式模板和字数要求**——这正是 Skill 的价值：把"团队约定好的具体做法"变成可复用、可稳定复现的指令，而不是每次都依赖模型自由发挥。

## 本节小结

✅ 手写了 Skill Loader，验证了"只索引名字+描述"这一层 Progressive Disclosure 机制的真实占用有多小 ✅ 手写了一个基于 LLM 判断的 Router，实现了"先判断该不该用、用哪个"的自动触发逻辑 ✅ 验证了只有真正命中某个 Skill 后，才会加载它完整的 `SKILL.md` 正文 ✅ 对比了有无 Skill 时，输出格式的一致性差异。一句话总结：**Skill 机制的核心不是"存了多少文档"，而是"用一句精确的 description，让 Agent 在还没读正文之前，就能准确判断该不该用"。**
