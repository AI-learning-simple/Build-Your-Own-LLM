# Experiment 15.2：亲手把一段音频变成"音频 Token"——分帧、提特征、量化

> **本节目标**：15.1 节我们验证了"图像 → 离散 Token"；本节把同一套思想搬到时间域——用纯 NumPy 把一段音频波形**切成帧、提取特征、用 k-means 学一个"音频词表"并量化**。你会亲眼看到：一段 1.2 秒的声音，最终变成了一串 0~7 的整数，而且**不同的声音自动落到不同的 Token**。这正是第15章讲的 EnCodec 这类真实音频编码器的核心思路（实验版）。全部代码纯 NumPy 运行，几秒钟即可跑完。

---

# 一、为什么音频也要"分词"？

第15章正文讲过：图像生成需要 VQ-VAE 给图像造"词表"，音频生成同样需要"音频词表"——EnCodec / SoundStream 就是用残差向量量化做到这一点的。但真实系统的神经网络编码器太复杂，本节用一个可运行的迷你版走通全链路：

```mermaid
flowchart LR
    A["波形<br/>(一维时间序列)"] --> B["分帧<br/>(切 20ms 一块)"] --> C["提特征<br/>(每帧一个向量)"] --> D["k-means 学词表<br/>(Codebook)"] --> E["量化<br/>(每帧 → 最近的 Code 编号)"]
```

对照着看：**分帧 = 图像里切 Patch，特征向量 = Patch 的 Embedding，k-means 学出的 Codebook = VQ-VAE 的词表，量化 = 查表取整数**——和第14、15章图像的路子完全同构，只是"切"的对象从二维像素变成了一维时间轴。

---

# 二、生成一段测试音频

任何声音都是不同频率正弦波的叠加（傅里叶分析的基本结论），所以我们用两段不同频率的正弦波 + 一段静音拼出测试音频——低音、安静、高音，三种"声音"一目了然：

```python
import numpy as np

sr = 8000  # 采样率 8kHz(电话语音标准)

# 440Hz 音 0.5s + 静音 0.2s + 880Hz 音 0.5s
t_a = np.arange(int(sr * 0.5)) / sr
t_b = np.arange(int(sr * 0.5)) / sr
seg_a = 0.5 * np.sin(2 * np.pi * 440 * t_a)      # A 音(低)
seg_b = 0.5 * np.sin(2 * np.pi * 880 * t_b)      # 高八度 A 音
seg_s = np.zeros(int(sr * 0.2))                  # 静音
audio = np.concatenate([seg_a, seg_s, seg_b])
audio = audio + 0.01 * np.random.RandomState(0).randn(len(audio))  # 加一点噪声
print(f"音频总长度: {len(audio)} 个采样点 = {len(audio)/sr:.1f} 秒 @ {sr}Hz")
```

```text
音频总长度: 9600 个采样点 = 1.2 秒 @ 8000Hz
```

---

# 三、分帧：把时间轴切成 20ms 的小块

图像切成 `16×16` 的 Patch，音频则切成**时间帧**。为什么是 20 毫秒？因为语音信号在这么短的时间内可以看作近似稳定的（这叫**短时平稳性**）——频率不会突变，FFT 算出的频谱才有意义。真实语音系统（Whisper 等）用的正是 20~30 毫秒的帧长。

```python
frame_len = 160                        # 20ms × 8000Hz = 160 个采样点
frames = [audio[i:i + frame_len] for i in range(0, len(audio) - frame_len + 1, frame_len)]
print(f"分帧:每帧 {frame_len} 采样 = 20ms,共 {len(frames)} 帧(帧0~24=440Hz音, 帧25~34=静音, 帧35~59=880Hz音)")
```

```text
分帧:每帧 160 采样 = 20ms,共 60 帧(帧0~24=440Hz音, 帧25~34=静音, 帧35~59=880Hz音)
```

9600 个采样点 → 60 帧，每帧 160 个数字——序列长度压缩了 160 倍，这就是"切块"的意义。

---

# 四、每帧提取 3 个特征：这一帧的"Embedding"

一个 160 维的原始帧还太原始（就像单个像素没有语义），我们把它压缩成 3 个有意义的数字——**能量、主频率、过零率**。这 3 个数字组成的向量，就是这一帧的迷你"Embedding"：

```python
def frame_features(f):
    rms = np.sqrt(np.mean(f ** 2))                       # ① 能量:这帧有多"响"
    spec = np.abs(np.fft.rfft(f * np.hanning(len(f))))   # ② 主频:FFT 后找峰值
    freqs = np.fft.rfftfreq(len(f), 1 / sr)
    peak_f = freqs[np.argmax(spec)] if rms > 0.02 else 0.0   # 静音帧主频无意义,记为 0
    zcr = np.mean(np.abs(np.diff(np.signbit(f).astype(float))))  # ③ 过零率:波形穿越0轴的频率
    return np.array([rms, peak_f, zcr])

X = np.array([frame_features(f) for f in frames])
print("每帧特征(前6帧): [能量, 主频Hz, 过零率]")
for i in range(6):
    print(f"  帧{i:2d}: {X[i][0]:.3f}  {X[i][1]:6.1f}  {X[i][2]:.3f}")
```

```text
每帧特征(前6帧): [能量, 主频Hz, 过零率]
  帧 0: 0.354   450.0  0.107
  帧 1: 0.351   450.0  0.107
  帧 2: 0.356   450.0  0.107
  帧 3: 0.351   450.0  0.107
  帧 4: 0.356   450.0  0.107
  帧 5: 0.353   450.0  0.107
```

**一个值得注意的细节：我们生成的是 440Hz 的音，检测出的主频却是 450Hz。** 这不是 bug——20ms 的帧长度决定了 FFT 的频率分辨率是 `8000 ÷ 160 = 50Hz`，440Hz 落在 `450Hz` 这个"格子"里。**任何测量都有精度上限**，真实系统的 Mel 频谱、神经编码器也一样，只是分辨率更高。这个例子告诉我们：量化（不管是我们这里的 50Hz 频率格，还是后面词表的 Code）必然带来信息损失——问题只在于损失是否可接受。

---

# 五、k-means：学一个"音频词表"

现在 60 个帧特征向量都在三维空间里。我们要学一个大小为 K=8 的"词表"——8 个 Code。方法是最经典的 **k-means 聚类**：随机初始化 8 个中心，迭代"把每个点归到最近的中心 → 用每簇的平均值更新中心"，直到收敛。**这 8 个学出来的中心向量，就是"音频词表"的 8 个 Code**（相当于 VQ-VAE 训练出来的 Codebook）：

```python
# 三个特征量纲完全不同(能量≈0.35, 频率≈450),先各列标准化再聚类
mu, sd = X.mean(0), X.std(0)
Xn = (X - mu) / (sd + 1e-9)

def kmeans(Xn, K, iters=50, seed=0):
    rng = np.random.RandomState(seed)
    centers = Xn[rng.choice(len(Xn), K, replace=False)]
    assign = np.zeros(len(Xn), dtype=int)
    for _ in range(iters):
        d = ((Xn[:, None, :] - centers[None, :, :]) ** 2).sum(-1)
        assign = d.argmin(1)
        for k in range(K):
            if (assign == k).any():
                centers[k] = Xn[assign == k].mean(0)
    return assign, centers

K = 8
codes, centers = kmeans(Xn, K)
```

注意这里的类比：k-means 的迭代（归簇 → 更新中心）和 VQ-VAE 训练 Codebook（把 Patch 特征归到最近的 Code → 用梯度更新 Code）是同一个思想——**让词表里的每个 Code 尽量代表一组真实出现的特征**。

---

# 六、量化：每帧 → 最近的 Code 编号

聚类完成后，每一帧只需要记住"我是第几号 Code"——60 帧就变成了一串 60 个整数，这就是这段音频的"Token 序列"：

```python
print("音频 Token 序列(K=8):")
print("  " + " ".join(str(c) for c in codes))
```

```text
音频 Token 序列(K=8):
  5 4 5 4 5 5 4 5 4 5 5 4 5 4 5 5 4 5 4 5 4 4 5 4 5 0 6 6 3 0 0 6 3 3 6 1 2 7 7 2 2 2 2 7 2 2 2 7 7 2 1 2 7 7 2 2 2 7 7 2
```

这串整数和第2章 BPE 切出来的 Token ID、第15.1节 VQ-VAE 切出来的图像 Code，**形式上完全一样**。更妙的是，看每个段落的 Code 分布：

```python
def dist(lo, hi, name):
    seg = codes[lo:hi]
    counts = {k: int((seg == k).sum()) for k in range(K) if (seg == k).any()}
    top = sorted(counts.items(), key=lambda kv: -kv[1])[:3]
    print(f"  {name}: 帧{lo}~{hi-1} 的 Code 分布 Top3 = {top}")

print("三个段落的 Code 分布:")
dist(0, 25, "440Hz 音")
dist(25, 35, "静音段")
dist(35, 60, "880Hz 音")
```

```text
三个段落的 Code 分布:
  440Hz 音: 帧0~24 的 Code 分布 Top3 = [(5, 14), (4, 11)]
  静音段: 帧25~34 的 Code 分布 Top3 = [(6, 4), (0, 3), (3, 3)]
  880Hz 音: 帧35~59 的 Code 分布 Top3 = [(2, 14), (7, 9), (1, 2)]
```

**三种声音被自动分到了完全不同的 Token 上**：440Hz 音几乎全是 Code 4/5，880Hz 音几乎全是 Code 1/2/7，静音段集中在 Code 0/3/6——"词表"在没有收到任何人工标注的情况下，自己学会了"低音、高音、安静"是三种不同的东西。这正是"音频分词"的意义：**一旦声音变成了整数序列，第1章学过的 Next Token Prediction 就可以直接用来"预测下一段声音"了**。

（静音段的 Code 最分散，是因为剩下的只有随机噪声——噪声没有稳定的特征可归，聚类时自然会分散到几个 Code。）

# 七、词表大小 K 的权衡

最后验证一个和第2章 BPE 完全一致的结论：**词表越大，量化越精细，信息损失越小**。用量化前后特征的平均误差来衡量：

```python
codes2, centers2 = kmeans(Xn, 2)
err2 = np.abs(Xn - centers2[codes2]).mean()
err8 = np.abs(Xn - centers[codes]).mean()
print(f"K=2 时量化误差: {err2:.4f}   ← 词表太小,信息损失大")
print(f"K=8 时量化误差: {err8:.4f}   ← 词表变大,损失变小")
```

```text
K=2 时量化误差: 0.3248   ← 词表太小,信息损失大
K=8 时量化误差: 0.0064   ← 词表变大,损失变小
```

K 从 2 涨到 8，误差从 0.32 降到 0.006——差了 50 倍。但词表不是越大越好：K 越大，模型要预测的类别越多、训练成本越高（第2章 BPE 的词表大小之争，在这里一模一样）。真实系统 EnCodec 用的词表是几千到几万，而且用**残差量化**解决精度问题：第一次量化后，把"剩余误差"再量化一次、再量化一次，用多级 Code 逼近原始信号——**这就是"残差向量量化（RVQ）"名字的由来**，本质上是本节实验的工程放大版。

# 本实验总结

✅ 用纯 NumPy 把一段 1.2 秒的音频变成了 60 个整数 Token ✅ 分帧（20ms）= 时间域的"切 Patch" ✅ 每帧 3 个特征 = 帧的迷你 Embedding ✅ 手写 k-means 学出"音频词表" = VQ-VAE 的 Codebook ✅ 不同声音（低音/静音/高音）自动落到不同 Code ✅ K 越大量化误差越小，词表大小是精度与成本的权衡。一句话总结：**音频的"分词"，就是把"切块 → 向量 → 量化 → 整数"在时间轴上再走一遍——和第14、15章图像的路线完全同构，这也是 EnCodec、Whisper 这些真实系统背后的统一思想。**

> 💡 **Insight：从第2章的 BPE，到 14.1 的 Patch Embedding，到 15.1 的 VQ-VAE，再到本节的音频分帧——整本书的"分词"只有一种思想：把连续的信号切成小块，再把小块变成（或量化成）离散的 Token。文字、图像、声音，概莫能外。**
