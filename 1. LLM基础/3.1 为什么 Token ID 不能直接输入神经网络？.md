# 实验 3.1：为什么 Token ID 不能直接输入神经网络？

> **硬件要求**：CPU 即可运行（普通笔记本可跑）
>
> **实验目标**
>
> 第二章中，我们已经能够把文本转换成 Token ID，例如 `I love AI` 编码为 `[2, 3, 1]`。这些整数可以作为索引交给神经网络框架，但不应直接当作连续标量特征。本节解释其中的区别，并引出 One-Hot 与 Embedding。

---

# 一、回顾第二章

目前我们的整个工程如下：`Text → Tokenizer → Token IDs`。例如 `I love AI` 经过 Tokenizer 得到 `I→2, love→3, AI→1`，最终 `[2,3,1]`。很多初学者第一次都会产生一个想法：**既然已经是数字了，那为什么不能直接送进神经网络？** 这是一个非常好的问题。

---

# 二、做一个最简单的实验

假设 Vocabulary 如下：

| Token  | ID |
| ------ | -: |
| apple  |  0 |
| banana |  1 |
| cat    |  2 |
| dog    |  3 |

如果直接输入神经网络，观察这些数字隐含的数学关系：`3 > 2 > 1 > 0`，甚至 `dog - cat = 1`，`cat - banana = 1`。这些关系是真的吗？当然不是。

---

# 三、Token ID 只是编号

换一个角度：假设学校里`张三→1001`，`李四→1002`，`王五→1003`，难道 `1003 > 1002` 说明王五比李四"更大"？当然不是，学号只是**唯一编号（Identifier）**，没有任何数学意义。Token ID 也是一样，它只是 Vocabulary 中的位置。

---

# 四、修改编号会发生什么？

原来 `apple→0, banana→1, cat→2, dog→3`。现在重新排序：`dog→0, cat→1, banana→2, apple→3`。语言发生变化了吗？没有，真正变化的只有编号。说明 Token ID 本身没有任何语义。

---

# 五、神经网络真正需要什么？

普通线性层会对输入数值执行乘加，因此若直接把 ID `2`、`3` 当标量，它会把编号差异误当成可计算的大小与距离。Token ID 应先作为类别身份：可以显式转成 One-Hot，也可以直接作为 Embedding 查表索引。查表得到的连续向量可参与点积、线性变换和梯度更新；这些向量是否表达有用关系，取决于后续训练目标与数据。

---

# 六、第一个解决方案：One-Hot Encoding

若要显式表示类别身份，同时不引入编号的大小关系，可以使用：

> **One-Hot Encoding**

例如 Vocabulary `apple, banana, cat, dog`：

```text
apple  → [1,0,0,0]
banana → [0,1,0,0]
cat    → [0,0,1,0]
dog    → [0,0,0,1]
```

任意两个不同 One-Hot 向量的欧氏距离都是 $\sqrt{2}$，因此这种表示只保留类别身份，不编码 `dog > cat`，也尚未编码 `cat` 与 `dog` 的语义相似性。

---

# 七、为什么叫 One-Hot？

观察 `[0,0,1,0]`，只有一个位置是 `1`，其它全部是 `0`，因此叫 One-Hot，意思是**只有一个位置是激活（Hot）的**。

---

# 八、完整数据流

到这里，整个系统已经演进成：

```mermaid
flowchart LR
    A[Text] --> B[Tokenizer] --> C["Token ID"] --> D[One-Hot] --> E[Neural Network]
```

是不是比 `Token ID → Neural Network` 合理很多？

---

# 九、One-Hot 真的是最终方案吗？

若 Vocabulary 有 100,000 个 Token，显式 One-Hot 就有 100,000 维且只有一个非零元素。实际实现通常不会构造这个稀疏向量，而是直接按 Token ID 查找参数矩阵中的一行：

> **Embedding Matrix**

下一节会看到：Embedding lookup 在前向结果上等价于 `One-Hot × Embedding Matrix`，但无需显式构造 One-Hot。Embedding Matrix 本身是可学习的参数映射，并不是 One-Hot 编码。

---

# 实验代码

```python
#!/usr/bin/env python3
vocab = ["apple", "banana", "cat", "dog"]

token_id = 2
one_hot = [0] * len(vocab)
one_hot[token_id] = 1
print(one_hot)  # [0,0,1,0]

token_id = 0
one_hot = [0] * len(vocab)
one_hot[token_id] = 1
print(one_hot)  # [1,0,0,0]
```

---

# 实验收获（Takeaways）

✅ Token ID 是类别索引，不应直接当作带大小关系的标量特征。
✅ One-Hot 显式保留类别身份并消除编号的序数关系，但不会自动产生语义。
✅ Embedding lookup 可直接用 ID 选择可学习向量。
❌ 显式 One-Hot 维度等于词表大小，通常没有必要实际构造。

---
