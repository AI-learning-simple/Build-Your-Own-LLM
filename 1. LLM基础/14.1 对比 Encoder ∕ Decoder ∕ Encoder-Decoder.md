# 14.1 对比编码器（Encoder）∕解码器（Decoder）∕编码器-解码器（Encoder-Decoder）

> **硬件要求**：建议 GPU——需加载小型预训练模型做架构对比；纯 CPU 也能运行，只是较慢
>
> **本节目标**：分别调用仅编码器（Encoder Only）、仅解码器（Decoder Only）和编码器-解码器（Encoder-Decoder）三类开源模型检查点（checkpoint），观察它们的输入输出接口、注意力可见性与常见任务形式。由于模型规模、数据和训练目标并不一致，本实验是行为演示，不是受控的架构优劣比较。
>
> **硬件说明**：三个模型的参数量、精度和运行时缓存不同，实际内存/显存占用取决于设备、dtype、输入长度和库版本。示例统一选择 CUDA（可用时）或 CPU；若资源不足，请分别运行三个代码段，不要同时常驻。CPU 可以运行，但生成速度可能较慢。

# 一、环境准备与模型选择

| 架构 | 模型 | 参数量 | 作用 |
|---|---|---|---|
| Encoder Only | `bert-base-chinese` | ~1亿 | 理解、填空 |
| Decoder Only | `Qwen/Qwen2.5-0.5B-Instruct` | ~5亿 | 续写、生成 |
| Encoder-Decoder | `google/flan-t5-small` | ~8000万 | 指令式 Seq2Seq（示例做英文摘要） |

> **比较边界**：这不是受控架构消融实验。三个 checkpoint 的参数量、预训练语料、训练目标、Tokenizer 和指令微调状态均不同；输出差异不能单独归因于 Encoder/Decoder 结构。本节只比较各 checkpoint 的标准调用接口与注意力可见性。

# 二、体验 Encoder（BERT）：擅长"填空"，不擅长"续写"

BERT 训练时用的是"完形填空"（Masked Language Model），因此天生适合"给你一句话缺一个词，猜出缺的是什么"：

```python
from transformers import AutoTokenizer, AutoModelForMaskedLM
import torch

device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

bert_name = "bert-base-chinese"
bert_tok = AutoTokenizer.from_pretrained(bert_name)
bert_model = AutoModelForMaskedLM.from_pretrained(bert_name).to(device)
bert_model.eval()

text = "北京是中国的[MASK]都。"
inputs = bert_tok(text, return_tensors="pt").to(device)
mask_pos = (inputs["input_ids"][0] == bert_tok.mask_token_id).nonzero(as_tuple=True)[0].item()

with torch.no_grad():
    logits = bert_model(**inputs).logits

top5 = torch.topk(logits[0, mask_pos], k=5).indices
print("BERT 填空结果:", [bert_tok.decode([t]) for t in top5])
```

试试把 `text` 换成 `"我今天心情很[MASK]。"`，你会发现 BERT 能利用**左右两侧**的信息一起判断，这正是第 14 章讲的**双向 Attention**。

`AutoModelForMaskedLM` 没有 `.generate()` 所需的因果语言模型头与自回归训练目标，因此不能像下文的 Qwen 那样直接续写。可以把 Encoder 接到 Decoder 或迭代 Mask 解码器上实现生成；这里观察到的是这个 checkpoint、任务头和训练目标的接口差异，不是 Encoder 数学结构“绝对不能生成”。

# 三、体验 Decoder（GPT/Qwen）：擅长"续写"，看不到未来

```python
from transformers import AutoTokenizer, AutoModelForCausalLM

gpt_name = "Qwen/Qwen2.5-0.5B-Instruct"
gpt_tok = AutoTokenizer.from_pretrained(gpt_name)
gpt_dtype = torch.float16 if device.type == "cuda" else torch.float32
gpt_model = AutoModelForCausalLM.from_pretrained(gpt_name, torch_dtype=gpt_dtype).to(device)
gpt_model.eval()

prompt = "北京是中国的"
inputs = gpt_tok(prompt, return_tensors="pt").to(device)
output = gpt_model.generate(**inputs, max_new_tokens=20, do_sample=False)
print("GPT 续写结果:", gpt_tok.decode(output[0], skip_special_tokens=True))
```

这个 CausalLM checkpoint 按 Token 逐步生成；在一次标准前向中，每个位置只能关注自己及左侧位置。经过 infilling 格式、特殊训练或把左右上下文都放到当前位置之前，Decoder-only 模型也能完成填空类任务，因此“看不到右边”描述的是注意力拓扑，不是任务能力的绝对边界。

# 四、体验 Encoder-Decoder（T5）：先理解，再重新生成

T5 类模型习惯用"任务前缀"告诉模型要做什么任务：

```python
from transformers import AutoTokenizer, AutoModelForSeq2SeqLM

t5_name = "google/flan-t5-small"
t5_tok = AutoTokenizer.from_pretrained(t5_name)
t5_model = AutoModelForSeq2SeqLM.from_pretrained(t5_name).to(device)
t5_model.eval()

text = "summarize: The Transformer architecture, introduced in 2017, relies entirely on attention mechanisms and has become the foundation of almost all modern large language models."
inputs = t5_tok(text, return_tensors="pt").to(device)
output = t5_model.generate(**inputs, max_new_tokens=30)
print("T5 摘要结果:", t5_tok.decode(output[0], skip_special_tokens=True))
```

> 提示：`flan-t5-small` 在多任务指令数据上微调过，比未做任务微调的 `mt5-small` 更适合直接演示 `summarize:`。它先编码完整输入，再由带 Cross-Attention 的 Decoder 自回归生成目标序列。输出质量同时受模型规模、训练数据和指令微调影响，不能作为 Encoder-Decoder 架构优于或劣于 Qwen/BERT 的证据。

# 五、三种架构一张表看懂

| | 输入方式 | 输出方式 | 能否看到完整上下文 | 典型任务 |
|---|---|---|---|---|
| BERT（Encoder） | 一次性输入整句话 | 对某个位置输出一个类别/词 | ✅ 双向 | 分类、填空、检索 |
| GPT（Decoder） | 已生成的历史 Token | 逐个 Token 向后生成 | ❌ 只能看左边 | 续写、聊天、代码生成 |
| T5（Encoder-Decoder） | 完整输入序列 | Decoder 从零生成全新序列 | Encoder 端双向，Decoder 端只能看左边 | 翻译、摘要、改写 |

# 六、同一个句子，三个模型的"性格"对比

用同一个输入 `"人工智能正在改变世界。"` 分别调用三个模型（BERT 做 `[MASK]` 填空、GPT 做续写、T5 做 `translate to English:` 前缀翻译），把三个输出打印在一起对比，你会非常直观地感受到：**同样是 Transformer，三种架构的"性格"完全不同**——BERT像一位阅读理解专家，GPT像一位健谈的续写者，T5像一位专业翻译。这正是第 14 章反复强调的核心观点：**没有最好的 Transformer，只有最适合任务的 Transformer。**
