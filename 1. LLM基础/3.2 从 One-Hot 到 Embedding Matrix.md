# 实验 3.2：从 One-Hot 到 Embedding Matrix

> **硬件要求**：CPU 即可运行（普通笔记本可跑）
>
> **实验目标**
>
> 上一节用 One-Hot 消除了 Token ID 人为引入的大小关系，但 One-Hot 本身没有语义。若 Vocabulary 有 100,000 个 Token，每个显式 One-Hot 也有 100,000 维。本实验说明 Embedding Matrix 如何把类别身份映射为可学习的稠密向量。

---

# 一、One-Hot 的问题

继续使用上一节的 Vocabulary（apple/banana/cat/dog），One-Hot 很容易理解。但如果 Vocabulary 变成 100000 个 Token，`cat` 对应 `[0,0,...,1,...,0]`，长度 100000，其中真正有用的数据只有一个 `1`，其它 99999 个都是 `0`，是不是非常浪费？

---

# 二、再观察一下 One-Hot

```text
apple  → [1,0,0,0]
banana → [0,1,0,0]
cat    → [0,0,1,0]
dog    → [0,0,0,1]
```

One-Hot 用“哪一个位置是 1”记录 Token 身份。只有当它右乘一个参数矩阵时，结果才等于选择该矩阵中对应的一行；One-Hot 本身不是查表，也不包含稠密向量。

---

# 三、换一种保存方式

假设提前准备一个表：

```text
apple  → [0.12, 0.83]
banana → [-0.55, 0.27]
cat    → [0.91, -0.18]
dog    → [0.88, -0.22]
```

现在已经不需要 100000 个 0，只需要直接找到 `cat` 对应的 `[0.91,-0.18]` 即可，是不是快很多？

---

# 四、这张表叫什么？

这张二维表就是 **Embedding Matrix**，它的 shape 是 `4 × 2`（4 行、2 列）：

```python
embedding = [
    [0.12, 0.83],      # apple
    [-0.55, 0.27],     # banana
    [0.91,-0.18],      # cat
    [0.88,-0.22]       # dog
]
```

这里的 `4` 表示 Vocabulary 大小（一共有 4 个 Token），`2` 表示 Embedding Dimension（每个 Token 用 2 个数字表示）。真正 GPT 可能是 `100000 × 768` 或 `150000 × 4096`，原理完全一样。

---

# 五、Lookup（查表）

Tokenizer 输出 `cat → 2` 后，Embedding 前向操作在概念上就是取 `embedding[2]`。框架内部会执行 gather/index 操作，但无需构造 One-Hot 再做稀疏矩阵乘法：

```python
embedding = [[0.12,0.83],[-0.55,0.27],[0.91,-0.18],[0.88,-0.22]]
token_id = 2
vector = embedding[token_id]
print(vector)  # [0.91,-0.18]
```

这里没有乘法、加法、神经网络，只是 Python 列表索引。所以 Embedding 又叫 **Lookup Table（查找表）**。

---

# 六、One-Hot 与 Embedding 的关系

Embedding Matrix 是从类别空间到稠密向量空间的可学习参数。对某个 Token，下面两种前向写法数学等价：

1. 构造 One-Hot，再计算 `one_hot @ embedding_matrix`；
2. 直接执行 `embedding_matrix[token_id]`。

例如 `[0,0,1,0]` 右乘行分别为 `[1,0]、[2,3]、[4,5]、[6,7]` 的矩阵，会得到第三行 `[4,5]`。实际实现通常采用第二种 lookup，结果相同，但不构造高维 One-Hot。

---

# 七、完整代码

```python
#!/usr/bin/env python3
vocab = ["apple", "banana", "cat", "dog"]
embedding = [[0.12,0.83],[-0.55,0.27],[0.91,-0.18],[0.88,-0.22]]

token = "cat"
token_id = vocab.index(token)
vector = embedding[token_id]

print("Token:", token)          # cat
print("Token ID:", token_id)    # 2
print("Embedding:", vector)     # [0.91,-0.18]
```

输出结果为:
```
Token: cat
Token ID: 2
Embedding: [0.91, -0.18]
```

---

# 八、现在这些向量有意义吗？

这里的数值只是手工示例，尚未由任务训练得到。实际模型通常初始化 Embedding 参数，再由损失函数的梯度更新被访问到的行。训练后向量是否呈现可解释相似性，取决于数据、目标函数、模型结构和分析方式，并不保证任意“相似词”都单调靠近。

---

# 九、本实验修改了什么？

相比上一节，唯一变化是 `One-Hot → Embedding Matrix`，Language Model、Attention、Transformer 全部没有出现，只是增加了 Lookup。整个数据流升级为：

```mermaid
flowchart LR
    A[Text] --> B[Tokenizer] --> C["Token IDs"] --> D["Embedding Matrix"] --> E[Vectors]
```

# 实验收获（Takeaways）

✅ 理解显式 One-Hot 的维度为何随词表增长。
✅ 理解 Embedding Matrix 是可学习参数，lookup 与 `One-Hot × Matrix` 的前向结果等价。
❌ 当前手工示例没有训练，因此不能据此解释语义。
