# 第一章：语言模型到底是什么？
---

> **目标：**
>
> 理解一句话：
>
> **GPT 并不会思考，它只是不断预测"下一个 Token"。**
>
> 如果这一章理解了，后面 80% 的内容都会变得顺理成章。

---

# 第一节：为什么会有语言模型？

很多人第一次接触 ChatGPT 时都会觉得：

> "它知道答案。"

实际上，这个理解并不准确。

更准确的说法应该是：

> **它学习了语言中的统计规律。**

举个最简单的例子。

如果我写：

```
中国的首都是
```

你大概率会想到：

```
北京
```

为什么？

因为你并不是重新推导了一遍中国的行政区划。

而是因为：

> **你在过去见过无数次这句话。**

于是：

```
中国的首都是

↓

北京
```

已经成为一种统计规律。

语言模型学习的，也是这种规律。

---

再举一个例子。

```
1

↓

2

↓

3

↓

?
```

你几乎都会回答：

```
4
```

不是因为你真的理解了数字。

而是因为：

```
1 2 3 4
```

这个序列出现过无数次。

语言模型学习的，就是：

> **给定前面的内容，预测后面最可能出现什么。**

---

所以：

GPT 本质上只有一个任务。

```
Predict Next Token
```

中文一般翻译成：

> **预测下一个 Token。**

注意。

不是：

```
预测一句话
```

不是：

```
预测答案
```

不是：

```
预测知识
```

而是：

```
预测

下一个 Token
```

这是整本书最重要的一句话。

---

# 第二节：什么叫 Language Model？

Language Model（语言模型）的定义其实非常简单：

> **根据已经出现的内容，预测后面最可能出现的内容。**

例如：

输入：

```
今天天气很
```

模型会计算：

```
热      0.62

好      0.18

冷      0.07

差      0.03

……
```

最后选择：

```
热
```

于是输出变成：

```
今天天气很热
```

然后继续预测：

```
今天天气很热

↓

今天气很热，

↓

今天气很热，我们

↓

今天气很热，我们去

……
```

于是：

一句话就是：

> **一个 Token 一个 Token 长出来的。**

不是一次生成整句话。

---

# 第三节：什么是 Token？

这里一定不要把 Token 理解成"单词"。

它不是。

它只是：

> **模型处理文本时最小的基本单位。**

不同模型：

Token 不一样。

例如：

```
Hello
```

可能被切成：

```
Hello
```

也可能：

```
Hel

lo
```

也可能：

```
H

e

l

l

o
```

以后第二章会专门实现 Tokenizer。

现在先知道：

```
文本

↓

Token

↓

编号(ID)

↓

向量(Vector)
```

整个 GPT 都是在处理：

```
编号
```

而不是文字。

---

# 第四节：为什么不是预测一句话？

很多人都会问：

既然最终要回答一句话。

为什么不直接预测：

```
整个答案？
```

例如：

输入：

```
2+3=
```

直接输出：

```
5
```

看起来不是更简单吗？

实际上，这几乎不可行。

因为一句话的可能性太多了。

例如：

```
你好
```

后面可能是：

```
你好呀

你好！

你好，请问……

你好，很高兴认识你……

你好，今天怎么样……
```

如果一次预测整句话。

模型需要面对：

```
无限种可能。
```

而：

预测一个 Token。

例如：

```
你好

↓

，
```

或者：

```
！

```

可能性就小得多。

于是问题变得容易学习。

所以 GPT 把复杂问题变成了：

```
很多很多次

预测一个 Token
```

这就是现代自回归语言模型（Autoregressive Language Model）的核心思想。

---

# 第五节：为什么这件事居然有效？

这是 Karpathy 视频里最精彩，也是最容易让人震撼的一点。

如果模型只是不断预测：

```
下一个 Token
```

为什么最后会：

* 写代码
* 做数学
* 翻译
* 写小说
* 做 Agent

答案是：

> **因为这些能力，本质上都体现在语言序列中。**

例如：

写 Python：

```
for i in range(
```

后面最可能出现：

```
10):
```

例如：

数学：

```
2+3=
```

后面最可能：

```
5
```

例如：

翻译：

```
Hello

↓

你好
```

例如：

函数调用：

```
{"tool":"calculator","args":{"a":2,"b":3}}
```

也是：

Token。

所以：

越来越大的模型。

越来越大的数据。

越来越好的优化器。

最终产生了：

我们今天看到的大模型能力。

这也是所谓的：

> **"Scaling is all you need."**

当然，这句话后来被证明并不完整，因为还需要高质量数据、对齐（Alignment）、工具使用（Tool Use）和推理训练（Reasoning），但它揭示了一个关键事实：**很多复杂能力，是在持续优化"预测下一个 Token"这个目标时自然涌现出来的。**

# 本章实验（下一部分）

这一章的实验，我们**不会急着写 GPT**。

我们会先写一个只有 **30 行左右 Python** 的字符级语言模型（Character Language Model），不用任何深度学习框架。

你会亲眼看到：

* 为什么"预测下一个字符"就能学会语言的基本统计规律；
* 什么叫训练数据；
* 什么叫概率；
* 为什么 GPT 的本质只是把这个思想扩展到了更大的模型。

这一小实验会成为后面 Transformer、Pretraining 和 SFT 的共同基础。下一节开始，我们正式动手写第一个可以"学习语言"的程序。
