# 实验 2.2：从 Character Tokenizer 演进到 Word Tokenizer

> **实验目标**
>
> 上一节，我们完成了第一个 Character Tokenizer，它已经能够正常完成 `Text → Token IDs → Text` 整个编码流程。但 Character Tokenizer 有一个很大的问题：
>
> **它不知道什么是"单词"。**
>
> 本实验，我们将升级 Tokenizer，从 Character 升级到 Word，观察两者之间的区别。

---

# 一、Character Tokenizer 的问题

回顾上一节的 `CharacterTokenizer`，如果输入 `text = "I love AI"`，编码之后，模型看到的是 `I`、空格、`l`、`o`、`v`、`e`、空格、`A`、`I` 这样一个个孤立的字符，而不是 `love` 这个整体。这意味着模型必须自己去学习 `l+o+v+e = love`，效率非常低。这一节，我们不再修改 `CharacterTokenizer`，而是设计一个全新的、独立的 `WordTokenizer`。

---

# 二、设计 Word Tokenizer

如果直接按空格切分 `I love AI`，得到 `I / love / AI`，是不是就更合理？于是 Word Tokenizer 的第一步就是 `words = text.split()`：

```python
text = "I love AI"
print(text.split())
```

输出：`['I','love','AI']`。是不是已经比 Character 更符合人的理解？

---

# 三、实现 WordTokenizer

和上一节一样，把下面的代码粘贴到脚本最上面即可，不需要新建额外的文件：

```python
class WordTokenizer:

    def __init__(self, text):
        self.build(text)

    def build(self, text):
        words = text.split()
        vocab = sorted(set(words))
        self.stoi = {w: i for i, w in enumerate(vocab)}
        self.itos = {i: w for w, i in self.stoi.items()}
```

这里 Vocabulary 变成 `AI, I, love` 这样的完整词，而不是 `A, I, l, o, v, e` 这样的字符。

---

# 四、实现 encode()

```python
def encode(self, text):
    return [self.stoi[word] for word in text.split()]
```

测试：

```python
tokenizer = WordTokenizer("I love AI")
print(tokenizer.encode("I love AI"))
```

输出：`[1,2,0]`。是不是已经非常接近 GPT？

---

# 五、实现 decode()

```python
def decode(self, ids):
    return " ".join(self.itos[i] for i in ids)
```

测试 `tokenizer.decode([1,2,0])` 输出 `I love AI`，整个流程已经打通。

---

# 六、完整代码

```python
class WordTokenizer:

    def __init__(self, text):
        self.build(text)

    def build(self, text):
        words = text.split()
        vocab = sorted(set(words))
        self.stoi = {w: i for i, w in enumerate(vocab)}
        self.itos = {i: w for w, i in self.stoi.items()}

    def encode(self, text):
        return [self.stoi[w] for w in text.split()]

    def decode(self, ids):
        return " ".join(self.itos[i] for i in ids)
```

总代码不到 30 行。

---

# 七、运行结果

```python
text = "I love AI"
tokenizer = WordTokenizer(text)
print(tokenizer.stoi)         # {'AI': 0, 'I': 1, 'love': 2}
print(tokenizer.encode(text))  # [1, 2, 0]
print(tokenizer.decode([1, 2, 0]))  # I love AI
```

---

# 八、Character 与 Word 对比

同一句话 `I love AI`：

| Tokenizer | Token 数 |
|------------|---------:|
| Character | 9 |
| Word | 3 |

Word Tokenizer 直接把 Token 数下降 **67%**，意味着 Transformer、Attention、Embedding 全部都会变快。

---

# 九、Word Tokenizer 的问题

很多同学到这里都会觉得 Word Tokenizer 已经完美了，但真正的问题才刚刚开始。假设训练数据是 `I love AI`，Vocabulary 只有 `AI, I, love`。如果用户输入 `I love ChatGPT`，编码时立即报错：

```
KeyError: 'ChatGPT'
```

因为 Vocabulary 根本没有 `ChatGPT`。现代 NLP 把这个问题称为 **Out-of-Vocabulary（OOV）**，也叫 Unknown Word，这是 Word Tokenizer 最大的问题。

---

# 实验收获（Takeaways）

✅ 学会实现 Word Tokenizer，理解 Character 与 Word 的区别。
✅ Word Token 数量明显减少。
❌ Word 无法处理新词（OOV）。
