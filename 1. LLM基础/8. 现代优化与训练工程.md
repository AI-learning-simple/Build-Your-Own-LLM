# 8. 现代优化与训练工程

> **本章目标**
>
> 第7章已经建立 `gradient → parameter update` 的基本训练闭环。本章讨论在更真实的 Loss 曲面和数据规模下，如何选择更新规则、初始化参数、调度学习率并评估泛化能力。8.1 用同一个二维函数比较 SGD、Momentum、Adam 与 AdamW；8.2 将完整方法扩展到 WikiText-2。

---

# 一、为什么朴素梯度下降还不够

朴素梯度下降只看当前梯度，并用同一个全局学习率缩放所有参数。这个规则适合建立原理，但真实训练会遇到三个问题：

1. 不同方向的曲率和梯度尺度可能差异很大；
2. Mini-Batch 梯度带有采样噪声，更新方向会波动；
3. 同一个学习率不一定适合训练的所有阶段。

现代优化器仍然根据梯度降低 Loss，但会额外记录历史方向、逐参数尺度或训练步数。回顾朴素更新公式：

```math
\theta_t=\theta_{t-1}-\eta g_t
```

**这个公式的作用**：把当前梯度缩放成一次参数改变量。`g_t=∇_θL_t` 是第 `t` 步梯度，`η` 与代码中的 `lr` 都表示学习率。后续优化器都从这条规则出发，只是改变“实际使用哪个方向和尺度”。

---

# 二、Momentum：为更新方向增加“惯性”

Mini-Batch 梯度会随抽样数据波动。如果每一步完全相信当前梯度，参数轨迹可能左右摇摆。Momentum 不只看当前梯度，而是保存一个“历史方向” `v`：新梯度与历史方向一致时，移动会逐渐加速；符号频繁变化时，波动会被部分抵消。

例如历史方向为 `2.0`、当前梯度为 `-1.0`、`β=0.9`，新的平滑方向是 `0.9×2.0+0.1×(-1.0)=1.7`，不会因一次反向噪声立刻掉头。

通用写法是：

```math
v_t=\beta v_{t-1}+(1-\beta)g_t
```

```math
\theta_t=\theta_{t-1}-\eta v_t
```

**这组公式的作用**：先把历史梯度与当前梯度融合成平滑方向，再据此更新参数。

- `g_t`：当前 Step 的梯度；
- `v_t`：平滑后的更新方向；
- `β`：历史保留比例，越接近 `1`，惯性越强；
- `η`：全局学习率。

不同资料也会使用 `v_t=βv_{t-1}+g_t` 等等价缩放约定。阅读实现时应先确认公式约定，而不是只看变量名。

---

# 三、Adam：同时估计方向与尺度

Momentum 只平滑方向，但不同参数的梯度尺度可能相差很大。例如两个参数梯度分别为 `0.01` 和 `10`，若直接共用同一学习率，第二个参数的更新可能大得多。Adam 为每个参数分别记录：

- 一阶矩 `m`：近期梯度的平均方向；
- 二阶矩 `v`：近期梯度平方的平均，用来估计尺度。

先更新两个状态：

```math
m_t=\beta_1m_{t-1}+(1-\beta_1)g_t
```

```math
v_t=\beta_2v_{t-1}+(1-\beta_2)g_t^2
```

训练初期两个移动平均都从 `0` 开始，数值会偏小，因此需要偏差修正：

```math
\hat m_t=\frac{m_t}{1-\beta_1^t},\qquad
\hat v_t=\frac{v_t}{1-\beta_2^t}
```

最后形成实际参数更新：

```math
\theta_t=\theta_{t-1}-\eta\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon}
```

**这组公式的作用**：用 `m̂` 决定主要方向，用 `√v̂` 对每个参数的更新进行尺度归一化。

- `β₁、β₂`：一阶矩和二阶矩的历史保留比例；
- `t`：当前更新步数；
- `ε`：防止分母为 0 的小常数；
- `η`：Adam 的全局学习率。

公式较长，但主线只有一句话：**Adam = Momentum 式方向平均 + 逐参数尺度调整。** 8.1 会在同一二维 Loss 上比较三种轨迹。

---

# 四、AdamW：把学习更新与权重衰减分开

先明确两个词：**正则化（Regularization）** 指为了改善泛化能力、在训练中主动加入的额外限制，它通常会让训练集 Loss 变差一点，但希望验证集表现更好。
**权重衰减（Weight Decay）** 是其中一种做法：每步都把参数轻微拉向 `0`，避免个别权重无限增大。

若参数为 `2.0`、学习率为 `0.001`、衰减系数为 `0.01`，仅衰减一项会让参数减少 `0.001×0.01×2=0.00002`。

AdamW 将“根据 Loss 梯度学习”和“按参数大小衰减”写成两个独立部分：

```math
\theta_t
=
\theta_{t-1}
-
\eta\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon}
-
\eta\lambda\theta_{t-1}
```

**这个公式的作用**：明确区分自适应梯度更新与权重衰减。

- 中间一项：来自 Loss 梯度的 Adam 更新；
- 最后一项：独立的权重衰减；
- `λ`：Weight Decay 强度。

工程中通常会通过参数分组，把 Bias、Norm 参数或某些 Embedding 排除在权重衰减之外；具体选择依赖模型配置。下图把参数空间中的更新轨迹和训练时间上的学习率变化放在一起：

# 五、学习率调度

固定学习率不是唯一方案。常见训练过程分为：

```text
较小学习率
→ Warmup 升至峰值
→ 按 Cosine、Linear、WSD 等规则衰减
```

Warmup 减小训练初期参数和优化器状态尚未稳定时的更新幅度；衰减阶段则在训练后期缩小步长。学习率调度作用于每一个 `optimizer.step()`，不能与 Epoch 数量混为一谈。

---

# 六、权重初始化

如果同一层所有神经元拥有完全相同的初始权重，它们会接收相同梯度并持续保持对称，因此权重不能全部设为同一个值。随机值也不能尺度失控，否则多层传播后激活值或梯度可能迅速放大、缩小。

常见原则是让输入与输出的方差保持在可控范围：

- Xavier 初始化常用于线性或近似对称激活；
- Kaiming 初始化针对 ReLU 一类只保留部分激活的函数；
- Embedding 常使用小尺度随机分布初始化。

初始化只决定训练起点，不直接写入语义。Embedding 与网络权重仍需通过训练数据和 Loss 获得结构。

---

# 七、训练稳定性：梯度裁剪

即使使用了 AdamW 和 Warmup，个别 Batch 仍可能产生异常大的梯度，一步就把参数推到很差的位置。
**梯度裁剪（Gradient Clipping）** 用于限制这种情况：在 `optimizer.step()` 之前，先算出所有参数梯度拼起来的总长度（范数），如果超过阈值，就按比例整体缩小。

```python
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
optimizer.step()
```

它只改变梯度的**长度**，不改变方向；总范数小于阈值时不做任何处理。这是训练 Transformer 时常见的稳定性措施，11.1 节的 nanoGPT 训练代码会实际用到。

---

# 八、从训练拟合到泛化评估

训练集 Loss 下降，只说明模型越来越适合参与参数更新的数据。如果模型把训练数据的细节甚至噪声都记住了，导致训练集 Loss 很低、但在没见过的数据上明显更差，这种现象叫**过拟合（Overfitting）**；反过来，模型连训练集都拟合不好，叫**欠拟合（Underfitting）**。判断过拟合必须同时看两条曲线：训练 Loss 继续下降，而验证 Loss 开始上升。

要真正执行这个判断，先要建立两个概念：**数据怎么分工**，以及**用什么指标衡量**。

**概念一：一份语料切成三份。** 训练、验证、测试三份数据都在训练开始前从同一份语料里一次性"留出"，区别只在留出之后各自被允许怎么用：

1. **训练集（Training Set）**：参数更新的唯一来源。训练 Loss 下降，只说明模型越来越适合参与参数更新的数据——它学到的规律能不能迁移，训练集自己说了不算；
2. **验证集（Validation Set）**：开发期间被反复查看的那份——选超参数、监控过拟合、决定何时早停、挑选检查点都看它。在它上面算出的 Loss（代码与日志里写作 `val loss`，训练侧对应 `train loss`）可以参与**决策**，但绝不进入**梯度**——它为什么不能进梯度、进去了会怎样，等讲验证过程时第 1 条会给出答案；
3. **测试集（Test Set）**：被"锁起来"的那份——训练不看它、调参不看它、选检查点也不看它。直到所有配置都定稿、模型不再改动，才在它上面做最后一次只读测量，用来报告模型的最终泛化水平。

验证集与测试集跑的是同一种测量，地位却不同——验证集像模拟考，可以反复做、用来调整；测试集像最终考试，只考一次，成绩才算数。原因是：若反复用同一份验证集挑选超参，超参同样会慢慢"记住"验证集（间接过拟合），验证 Loss 就不再客观；测试集从头到尾不参与开发，才有资格当最终裁判。

**三份数据怎么切？** 比例没有唯一标准，常见约 **8:1:1**（训练占大头）。切法上，推荐先打乱再按比例随机切，避免"数据本身的顺序"成为一种偏差；如果类别不均衡，还应分层抽样，保证三份里各类别比例相近。另一种常见做法是**顺序切分**——直接按文本顺序截断，它隐含"数据各部分规律相近"的假设。本书的两个实验正好演示了这两种来源：11.1 对 tiny-shakespeare 做顺序切分（前 90% 训练、后 10% 验证，未单独切测试集）；8.2 直接使用 WikiText-2 发布时自带的固定 train / validation / test 划分，并遵守"Vocabulary 只用训练集建立、验证与测试里的未登录词统一映射为 `<unk>`"的防泄漏原则。

**概念二：用什么指标衡量。** 单看一个 Batch 的 Loss 噪声很大，语言模型通常把大量预测位置的平均 Loss 作为指标，再换算成 Perplexity 报告：

```math
\text{PPL}=\exp(\text{mean cross entropy})
```

**这个公式的作用**：把平均对数损失转换成更直观的正数尺度，用于观察同一 Tokenizer、Vocabulary 和评测语料下的相对变化。它不是实际候选 Token 数，也不适合跨不同分词方案直接比较。

**概念齐了，那"验证 Loss"到底怎么算出来？** 做法是一句话：训练每进行一段，就暂停下来测量一次。这里的"一段"只是抽象说法，泛指"训练向前推进了一段距离"；至于按 Epoch 还是按固定步数暂停，由代码的训练循环决定，8.2 与 11.1 会在各自的循环里说明。每次暂停后，在验证集上做一次"只读测量"：把验证样本喂进模型，前向算出 Loss，然后继续训练。它和训练循环长得几乎一样，区别只有三条，而这正是原理所在：

1. **只前向、不反向**：只计算 Loss，绝不调用 `backward()` 与 `optimizer.step()`。验证数据一旦参与参数更新，就变成了"训练数据"，验证 Loss 会虚低——这是数据泄漏最常见的形态；
2. **关掉只在训练时生效的行为**：有些层在训练阶段会引入随机性、或依赖随 Batch 变化的统计，导致同一输入每次前向的结果不完全相同；验证要的是稳定、可比的测量，所以测前要把模型切到"评估模式"（PyTorch 里是 `model.eval()`，测完用 `model.train()` 切回）。这类"训练态"组件要到第 11 章的 Dropout 才会遇到，8.2 与 11.1 的训练循环里已经能看到这对切换；
3. **取平均而不是看单次**：单个 Batch 的 Loss 噪声很大，验证通常遍历整个验证集（或多次随机抽样），把各 Batch 的 Loss 按样本数加权平均，得到一个稳定的验证 Loss，再换算成 PPL 这类便于阅读的指标。

8.2 会把这条流程落到 WikiText-2 上：`evaluate()` 在 `torch.no_grad()` 下遍历 `valid_loader` 逐 Batch 累加 Loss，每个 Epoch 结束后打印一次验证 Loss 与验证 PPL；11.1 的 `estimate_loss()` 是同一原理的简化版。到时可以拿着上面这三条区别，逐行对照代码验证。

**拿到两条曲线之后怎么用？** 把验证 Loss 与同一时刻的训练 Loss 放在一起看，就构成了对过拟合的"体检"：两者一起下降，说明模型还在学习可迁移的规律；训练 Loss 继续下降而验证 Loss 开始回升，就是本节开头定义的过拟合——此时应停止训练，或回退到验证 Loss 最低时保存的检查点。**早停（Early Stopping）**在实现上就是这句话。

至此，把数据分工、指标和验证流程都对齐后，一份完整的训练工程还需要：

1. 只用**训练集（Training Set）**建立 Vocabulary 和估计预处理统计量；
2. 用**验证集（Validation Set）**选择配置、监控过拟合——它参与决策，但不参与参数更新；
3. 用**测试集（Test Set）**做最终检查，且只用于最后一次评估；
4. 保存模型参数、Vocabulary 和结构配置；
5. 记录随机种子、数据版本与关键超参数。
