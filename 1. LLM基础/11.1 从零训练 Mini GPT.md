# 11.1 从零训练 Mini GPT

> **本节目标**：第 11 章已经从理论上拼出了完整的 `TransformerBlock`（Multi-Head Attention + FFN + Residual + LayerNorm + Dropout），并说明了 GPT 还需要 Token Embedding 和 Position Embedding。本节把这些模块集中实现成一个 Mini GPT，从零开始训练，观察 Loss 下降并验证模型能够学习语料中的字符模式。
>
> **硬件要求**：这是全书对硬件要求最低的一次实验。模型只有几百万参数，**8GB 显存的入门级显卡（如 RTX 3060/4060）绰绰有余，甚至纯 CPU 笔记本也能在几分钟内跑完**。这也是为什么我们先从"从零训练"开始：模型足够小，才有可能手写、可控、跑得动。

# 一、为什么要完成一次训练实验？

前面几节我们推导了 Embedding、Attention、Transformer Block 每一个模块的原理，但"知道原理"和"看到它真的在学习"是两件不同的事。本节不追求效果多好，只追求一件事：**用自己写的代码，把一个模型从"什么都不会"训练到"能写出几句像样的话"**，验证前面章节讲的所有理论都能在真实代码里跑通。

# 三、准备语料

用一段公开的中文文本作为训练语料，例如唐诗、《红楼梦》片段，或者任意几十 KB 的中文 txt 文件都可以。这里以字符级建模（复用第2章 Character Tokenizer 的思路）：

```python
# corpus.txt 放几百 KB 的中文文本即可，越多效果越好
text = open("corpus.txt", encoding="utf-8").read()

chars = sorted(set(text))
vocab_size = len(chars)
stoi = {ch: i for i, ch in enumerate(chars)}
itos = {i: ch for ch, i in stoi.items()}

def encode(s):
    return [stoi[c] for c in s]

def decode(ids):
    return "".join(itos[i] for i in ids)

data = encode(text)
print("语料长度:", len(data), "词表大小:", vocab_size)

# 把数据切成 train/val 两份(90/10):train 用来训练,val 用来监控是否过拟合
n_train = int(len(data) * 0.9)
train_data, val_data = data[:n_train], data[n_train:]
```

> 本书验证时使用的语料是唐诗+诗经+宋词（约 138,184 个字符），上面的输出为 `语料长度: 138184, 词表大小: 4698`。换成你自己的 `corpus.txt`，这两个数字会不同，不影响后续流程。

# 四、构建训练样本

复用第6章的思路：每一个位置的输入是"前面一段连续 Token"，目标是"往后挪一位的同一段 Token"（Next Token Prediction 最直接的实现方式）：

```python
import torch

block_size = 64  # 上下文窗口长度（Context Window）

def get_batch(data, batch_size=32):
    idx = torch.randint(0, len(data) - block_size - 1, (batch_size,))
    x = torch.stack([torch.tensor(data[i:i + block_size]) for i in idx])
    y = torch.stack([torch.tensor(data[i + 1:i + block_size + 1]) for i in idx])
    return x, y
```

`x` 是输入，`y` 是 `x` 整体右移一位的结果——这就是第1章已经定义的 **Next Token Prediction**：序列中每个位置都根据左侧上下文预测下一个 Token。

# 五、拼出完整的 Mini GPT

结构为：`Token Embedding + Position Embedding → N × TransformerBlock → LayerNorm → Linear（映射回词表）`。这些组件的职责已经在第 11 章讲清，本节从完整类定义开始集中实现：

```python
import torch.nn as nn

class TransformerBlock(nn.Module):
  def __init__(self, d_model, n_heads, d_ff, dropout=0.1):
    super().__init__()
    self.ln1 = nn.LayerNorm(d_model)
    self.attn = nn.MultiheadAttention(d_model, n_heads, dropout=dropout, batch_first=True)
    self.dropout1 = nn.Dropout(dropout)
    self.ln2 = nn.LayerNorm(d_model)
    self.ffn = nn.Sequential(nn.Linear(d_model, d_ff), nn.GELU(), nn.Linear(d_ff, d_model))
    self.dropout2 = nn.Dropout(dropout)

  def forward(self, x, attn_mask=None):
    normed = self.ln1(x)
    attn_out, _ = self.attn(normed, normed, normed, attn_mask=attn_mask, need_weights=False)
    x = x + self.dropout1(attn_out)
    x = x + self.dropout2(self.ffn(self.ln2(x)))
    return x


class MiniGPT(nn.Module):
  def __init__(self, vocab_size, d_model=128, n_heads=4, d_ff=512, n_layers=4, block_size=64):
    super().__init__()
    self.token_emb = nn.Embedding(vocab_size, d_model)
    self.pos_emb = nn.Embedding(block_size, d_model)
    self.blocks = nn.ModuleList([TransformerBlock(d_model, n_heads, d_ff) for _ in range(n_layers)])
    self.ln_f = nn.LayerNorm(d_model)
    self.head = nn.Linear(d_model, vocab_size)
    self.block_size = block_size

  def forward(self, idx):
    B, T = idx.shape
    pos = torch.arange(T, device=idx.device)
    x = self.token_emb(idx) + self.pos_emb(pos)
    mask = torch.triu(torch.ones(T, T, device=idx.device), diagonal=1).bool()
    for block in self.blocks:
      x = block(x, attn_mask=mask)
    x = self.ln_f(x)
    return self.head(x)
```

模型只有 4 层、每层 4 个 Head、隐藏维度 128。具体参数量受词表大小影响，应由代码统计；能否在某台设备上顺利训练还取决于 Batch Size、序列长度、dtype 和后端，不能只凭层数承诺。

# 六、训练循环

复用第4、6章讲过的 Cross Entropy Loss，以及第7章讲过的梯度下降：

```python
device = "cuda" if torch.cuda.is_available() else "cpu"
model = MiniGPT(vocab_size, block_size=block_size).to(device)
num_params = sum(p.numel() for p in model.parameters())
print(f"参数量: {num_params:,}")
optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=0.01)

@torch.no_grad()
def estimate_loss(data, eval_iters=20):
    # 关闭 Dropout，并对多个随机 Batch 求均值以降低评估噪声
    model.eval()
    losses = []
    for _ in range(eval_iters):
        x, y = get_batch(data)
        x, y = x.to(device), y.to(device)
        logits = model(x)
        loss = nn.functional.cross_entropy(logits.reshape(-1, vocab_size), y.reshape(-1))
        losses.append(loss.item())
    model.train()
    return sum(losses) / len(losses)

for step in range(2001):  # 包含 step 2000
    x, y = get_batch(train_data)     # 训练只用 train_data
    x, y = x.to(device), y.to(device)

    logits = model(x)  # (B, T, vocab_size)
    loss = nn.functional.cross_entropy(logits.reshape(-1, vocab_size), y.reshape(-1))

    optimizer.zero_grad()
    loss.backward()
    nn.utils.clip_grad_norm_(model.parameters(), 1.0)   # 梯度裁剪，定义见第8章第七节
    optimizer.step()

    if step % 200 == 0:
        train_loss = estimate_loss(train_data)
        val_loss = estimate_loss(val_data)
        print(f"step {step:4d}: train loss {train_loss:.3f}, val loss {val_loss:.3f}")
```

一次运行的示例结果如下。初始化、随机 Batch、硬件和语料都会影响数值与耗时；修改为多 Batch 平均评估后，输出不必与下表逐项一致：

```text
step    0: train loss 8.643, val loss 8.552
step  200: train loss 6.126, val loss 6.069
step  400: train loss 5.839, val loss 6.022
step  600: train loss 5.576, val loss 5.753
step  800: train loss 5.330, val loss 5.666
step 1000: train loss 5.201, val loss 5.684
step 1200: train loss 5.073, val loss 5.542
step 1400: train loss 4.902, val loss 5.488
step 1600: train loss 4.795, val loss 5.736
step 1800: train loss 4.404, val loss 5.434
step 2000: train loss 4.480, val loss 5.377
```

初始 Loss 约 8.6，接近 `log(词表大小) = log(4698) ≈ 8.46`——模型完全随机瞎猜时的 Loss 就是这个量级（这正是第4章说的"训练真正优化的是 Loss"的起点）。2000 步后 train loss 降到 4.48，模型确实"学到了一些东西"。

**val loss 告诉我们什么？** 训练集与验证集 Loss 的差值称为**泛化差距（Generalization Gap）**。训练 Loss 更低并不自动等于“背诵”，而某一个评估点的 val loss 回升也可能来自随机 Batch 噪声。只有当多批次平均后的验证 Loss 持续变差、同时训练 Loss 继续下降时，才有较充分的过拟合迹象；应结合更多评估点或固定验证集判断。

**怎么应对过拟合？** 可以增加数据、采用合适的 Dropout/weight decay、减小模型或按验证指标早停。`AdamW` 只有在设置非零 `weight_decay` 时才提供相应正则化；示例可显式写成 `torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=0.01)`，具体值需要根据验证集调节。

# 七、生成文字

训练完成后，使用前面已经建立的自回归生成方式，一个 Token 一个 Token 地续写；第 15 章会进一步讨论解码、KV Cache 与推理效率：

```python
@torch.no_grad()
def generate(model, prompt, max_new_tokens=100):
  model.eval()
  idx = torch.tensor([encode(prompt)], device=device)
  for _ in range(max_new_tokens):
    idx_cond = idx[:, -block_size:]
    logits = model(idx_cond)
    probs = torch.softmax(logits[:, -1, :], dim=-1)   # 只取最后一个位置的概率分布
    # 解码策略：这里用 Sampling（按概率随机抽一个）
    # 若改成 Greedy（每次都取概率最高的），换成 probs.argmax(dim=-1, keepdim=True)
    next_id = torch.multinomial(probs, num_samples=1)
    idx = torch.cat([idx, next_id], dim=1)
  return decode(idx[0].tolist())

print(generate(model, "床前明月光"))
```

第1章提到的**解码策略**在这里第一次落到代码上：

- `probs.argmax(...)` 是 **Greedy**：每步都选概率最高的 Token，输出稳定但容易重复；
- `torch.multinomial(probs, 1)` 是 **Sampling**：按概率随机抽取，概率 `0.6` 的 Token 大约六成情况被选中，输出更多样但可能不通顺。

Top-k 是先只保留概率最高的 k 个候选再采样；Temperature 是在 Softmax 前把 Logits 除以一个数 `T`，`T<1` 使分布更尖锐、更接近 Greedy，`T>1` 使分布更平坦、更随机。15.3 节会在真实模型上用 `temperature=0.0` 与 `temperature=0.7` 对比这个效果。

# 八、训练前后对比

在训练刚开始（step 0）和训练结束（step 2000）分别调用一次 `generate`，你会清楚看到：

- **训练前**：输出几乎是随机字符的堆砌，毫无规律；
- **训练后**：输出开始出现语料中真实存在的词语搭配、常见句式，甚至偶尔押韵——虽然远远达不到 ChatGPT 的水平，但它确确实实"学到了一些东西"。

本书验证时的真实输出（prompt 为 `床前明月光`，语料是繁体字版的唐诗宋词，所以生成结果也是繁体）：

```text
训练前: 床前明月光叡類勛營灿萏支駟搓坊互敷獻蔭公裴垂女暎勍觥有补劳稳嘏蘆爵斩界噎廬消离專襞扯坏泞弱麯旧岁曰枿枕忻博賀学氓伊醫焚山根括贄遽高
训练后: 床前明月光無荒。
操天原高城，誤遵蕩己沙。
延乾承西北，洞調幽邊入。
龙按西池鄉，柳杯風筠昏。
上閣臺宸眉主，壺夜夜劫川羞鄉輝。
```

训练前的输出是一个毫无章法的"乱码"；训练后模型开始模仿语料里的五言诗格式——每句五个字、句末有标点、甚至出现了"高城""西北"这类语料中的常见搭配。**把语料换成简体文本，生成结果自然也会是简体。**

这个对比本身就是对前面章节全部理论最直接的验证：**Embedding、Attention、FFN、Residual、LayerNorm，这些模块组合起来，真的能够从数据中学习规律。**

# 九、这和真正的 GPT 差多少？

| | Mini GPT（本节） | GPT-2 Small | GPT-3 |
|---|---|---|---|
| 参数量 | 以 `num_params` 实际输出为准 | 1.24 亿 | 1750 亿 |
| 层数 | 4 | 12 | 96 |
| 训练数据 | 约 140 KB（本书示例） | WebText，约 40GB 文本 | 约 3000 亿训练 Token |
| Tokenizer | 字符级 | BPE | BPE |

它们都遵循 Decoder-only、自回归 Next Token Prediction 的基本框架，但差别不只在规模。真实 GPT 还涉及更成熟的 Tokenizer、数据清洗与配比、学习率调度、分布式训练、精度与稳定性工程；现代 LLM 又常使用 RoPE、RMSNorm、SwiGLU、GQA 等架构改动。公开资料不足的闭源模型不在这里猜测参数量或结构。
