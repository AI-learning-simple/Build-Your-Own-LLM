# 15.2 In-Context Learning——Few-shot 与 Zero-shot 实验

> **本节目标**：用运行时随机生成的不透明标签比较同一测试集上的 0 / 1 / 3 / 5-shot，观察模型能否从上下文示例归纳临时标签映射。实验只测量一次 Prompt 内的行为，不预设 Zero-shot 必败或 Few-shot 必胜。
>
> **硬件说明**：示例使用 1.5B 模型推理；实际内存/显存取决于 dtype、后端、量化方式、上下文长度和运行时版本，请以本机测量为准。

# 二、加载模型

```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

model_name = "Qwen/Qwen2.5-1.5B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype=torch.float16, device_map="auto")

def ask(prompt, max_new_tokens=60):
    messages = [{"role": "user", "content": prompt}]
    text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = tokenizer(text, return_tensors="pt").to(model.device)
    output = model.generate(**inputs, max_new_tokens=max_new_tokens, do_sample=False)
    return tokenizer.decode(output[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True)
```

# 三、设计一个运行时随机标签任务

若使用凯撒密码等公开规则，模型可能依赖预训练知识；若不同 shot 数使用不同问题，也无法公平比较。下面固定同一组情感分类测试句，只在程序运行时为“积极 / 消极 / 中性”随机生成三个不透明标签（nonce）。模型无法从标签名字猜语义，只能从 Prompt 中的示例归纳映射。

```python
import secrets

sentiments = ["积极", "消极", "中性"]
nonce_labels = set()
while len(nonce_labels) < len(sentiments):
    nonce_labels.add(f"L_{secrets.token_hex(4)}")
label_for = dict(zip(sentiments, nonce_labels))
labels = list(label_for.values())
# 打乱展示顺序，避免“类别顺序 = 标签顺序”意外泄漏映射。
secrets.SystemRandom().shuffle(labels)
print("本次运行的映射（只用于评分）:", label_for)

# 前 3 条各覆盖一个类别；第 4、5 条提供重复证据。
demo_pool = [
    ("这次更新非常好用，我很满意。", "积极"),
    ("客服一直不回复，体验很差。", "消极"),
    ("包裹今天下午送到。", "中性"),
    ("设计漂亮，操作也很顺手。", "积极"),
    ("电池半天就没电了。", "消极"),
]

test_set = [
    ("画面清晰，声音也很棒。", "积极"),
    ("程序频繁崩溃，根本无法使用。", "消极"),
    ("会议改到周五上午十点。", "中性"),
    ("这顿饭让我非常失望。", "消极"),
    ("文件已经上传到服务器。", "中性"),
    ("安装简单，运行速度很快。", "积极"),
]
```

# 四、公平比较 0 / 1 / 3 / 5-shot

四个条件共享同一套随机标签映射、同一个测试集和同一套生成参数；示例集合采用前缀嵌套，因此 `n=3` 包含 `n=1` 的示例，`n=5` 又包含 `n=3` 的示例。唯一变化是 Prompt 中示例的数量。

```python
def build_prompt(num_examples, query):
    lines = [
        "请把文本分为积极、消极或中性，但只输出对应的不透明标签。",
        "允许的标签：" + "、".join(labels),
        "不要解释。",
    ]
    if num_examples:
        lines.append("示例：")
        for text, sentiment in demo_pool[:num_examples]:
            lines.append(f"文本：{text}\n标签：{label_for[sentiment]}")
    lines.append(f"待分类文本：{query}\n标签：")
    return "\n".join(lines)


def extract_label(text):
    # 只接受本次运行生成的完整 nonce；避免用自然语言人工判分。
    found = [label for label in labels if label in text]
    return found[0] if len(found) == 1 else None


def evaluate(num_examples):
    correct = 0
    for text, sentiment in test_set:
        raw = ask(build_prompt(num_examples, text), max_new_tokens=20)
        predicted = extract_label(raw)
        expected = label_for[sentiment]
        correct += predicted == expected
        print(f"{num_examples}-shot | {text} | 预测={predicted} | 正确={expected}")
    return correct / len(test_set)


for n in [0, 1, 3, 5]:
    accuracy = evaluate(n)
    print(f"{n}-shot accuracy: {accuracy:.1%}\n")
```

`0-shot` 时三个 nonce 没有语义线索；`1-shot` 只暴露一个类别；到 `3-shot` 才首次覆盖三个类别；`5-shot` 增加了重复证据。结果不保证随示例数单调上升：小测试集、示例顺序和模型本身都会造成波动。若要形成可靠结论，应更换测试句、示例顺序和随机映射重复多轮，再报告均值与方差。

# 七、为什么这不是"训练"？

代码没有调用 `backward()` 或 `optimizer.step()`，也没有修改 `model.parameters()`；示例与问题只是同一 Prompt 的输入。自回归生成会执行多次前向步骤，但全程仍是推理。这里所谓“学会映射”是条件分布随上下文变化，不是参数更新。

# 本节小结

✅ 用运行时随机 nonce 消除了标签语义与预训练记忆捷径 ✅ 在相同映射、测试集和生成参数下比较 0 / 1 / 3 / 5-shot ✅ 使用自动精确匹配评分，而非主观挑选输出 ✅ 明确了单次小样本结果不保证单调趋势，可靠结论需要多轮均值与方差 ✅ 全程只做推理，不更新模型参数
