# 第一节：为什么计算机看不懂文字？

我们先抛开 AI，假设现在让 Python 做一件事情：

```python
print("Hello")
```

屏幕上会输出：

```text
Hello
```

看起来 Python 好像认识 `"Hello"`，其实不是：在计算机内部，它们最终都会变成数字。

在计算机内部实际上类似于：

```text
[72,101,108,108,111]
```

这是 ASCII（以及后来 Unicode）的编码思想。

所以第一件事情我们要建立一个概念：文字只是人类看的，**计算机只能处理数字**。

既然文字已经能变成数字，为什么语言模型不直接使用 ASCII 编码，原因有三个。

---

## 原因一：数字没有语义

例如：

```text
A -> 65

B -> 66
```

66 比 65 大。

这是不是意味着 "B > A" ？显然不是。ASCII 数字只是编号，没有任何语义。

再例如：狗和猫的Unicode 编号可能相差几千。但它们实际上语义很接近。

---

## 原因二：一个汉字会被字节编码拆碎

ASCII 一个字符正好一个字节，但中文不行。"你好"在 UTF-8 下要 6 个字节，如果直接把每个字节当 Token，一个汉字就被切成 3 个**彼此无关**的数字，模型很难从中学到"一个字"的语义。所以**字节**不是 NLP 想要的单位。

---

## 原因三：英文也有问题

例如："playing" ASCII 需要7个字符，但对于理解语义有意义的是：

```text
play
+
ing
```

于是：

Tokenizer 出现了。

---

# 第三节：Tokenizer 到底是什么？

> **Tokenizer 就是把人类语言切成模型可以学习的单位(Token)。**

注意不是切成字符，也不是切成单词。而是**切成最适合模型学习的单位**。 例如一句话 "I love AI." 

Character Tokenizer：

```text
I
l
o
v
e
A
I
```

Word Tokenizer：

```text
I
love
AI
```

语言模型 Tokenizer：

可能：

```text
I

love

AI
```

也可能：

```text
I

lov

e

AI
```

甚至：

```text
lov

e
```

Tokenizer 有很多策略，本章的实验部分，我们会逐步实现。

---

# 第四节：Token 与 Token ID

模型真正处理的是 Token ID，假设 Tokenizer 建立了一个词表（Vocabulary）：

| Token  | ID |
| ------ | -: |
| I      |  0 |
| love   |  1 |
| AI     |  2 |
| Python |  3 |
| <EOS>  |  4 |

于是输入 "I love AI" 会变成 [0,1,2]，语言模型永远不会看到 "I love AI"，真正看到的是：

```text
0
↓
1
↓
2
```

> **LLM 学习的是 Token ID 序列，而不是文字本身。**

---

# 第五节：Vocabulary（词表）

Tokenizer 的核心就是 **Vocabulary（词表）**，它其实就是一本字典，例如：

```text
Vocabulary

I         → 0
love      → 1
AI        → 2
Python    → 3
is        → 4
great     → 5
```

以后任何文本都会：

```text
文字
↓
Token
↓
Token ID
```

后面的 Embedding 就是把 Token ID 转化为 Vector，下一章会详细介绍。

我们会遵循"从简单到复杂"的原则，一共做四个小实验：

   * 亲手实现一个几十行代码的 BPE。
