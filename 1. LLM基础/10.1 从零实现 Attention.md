# 实验 10.1：从零实现注意力机制（Attention）

> **硬件要求**：CPU 即可运行（普通笔记本可跑）

## 实验目标

第 10 章主章节已经讲完 Attention 的概念。本实验用 NumPy 从零实现 Attention 的核心计算流程：允许"回头查看" → 人为打分 → 字符串匹配的局限 → Dot Product → Softmax → Weighted Sum，体会 Attention 的每一步是怎么自然推导出来的。

---

## 一、允许"回头查看"

先体会 Attention 的核心思想：当读到 `it` 时，不依赖 RNN/LSTM 那种把全部历史压缩进一个固定向量（Memory）的做法，而是直接查看所有历史 Token：

```python
sentence = ["The", "animal", "didn't", "cross", "the", "street", "because", "it"]
current = "it"
history = sentence[:-1]

print("Current:", current)
print("History:", history)
```

输出：

```text
Current: it
History: ['The', 'animal', "didn't", 'cross', 'the', 'street', 'because']
```

如果允许模型查看所有历史 Token，你认为应该关注哪几个？最可能是 `animal` 和 `street`，而不是 `didn't` 和 `because`。模型第一次拥有了**选择关注对象（Attention）的能力**。

---

## 二、从人为打分到自动匹配

先手动打分体验一下 Attention Score（每个历史 Token 的重要程度）：

```python
history = ["The", "animal", "didn't", "cross", "the", "street"]
scores = {"The":0.01, "animal":0.95, "didn't":0.02, "cross":0.05, "the":0.01, "street":0.80}
for word in history:
    print(word, "->", scores[word])
```

但真正的大模型不会手写 `scores["animal"] = 0.95`，而是自己计算。先尝试最简单的规则——字符串匹配：

```python
history = ["Tom", "likes", "basketball", "Alice", "likes", "music"]
query = "music"
scores = [1 if word == query else 0 for word in history]
print(scores)  # [0,0,0,0,0,1]
```

---

## 三、字符串匹配的局限

如果 Query 变成 `songs`，历史只有 `music`，字符串匹配立即失效（`songs != music`），但人类知道 `songs ≈ music`。这说明 Attention 不能比较字符串，而应该比较**语义（Semantic Similarity）**——也就是比较 Embedding 向量之间的相似度。

---

## 四、用 Dot Product 计算 Token 相似度

用第 10 章统一的例子 `The cat is sleeping`，把每个 Token 表示成 2 维向量，用 `cat` 的 Embedding 和每个词的 Embedding 做点积：

```python
import numpy as np

embedding = {
    "The":      np.array([0.1, -0.2]),
    "cat":      np.array([1.0,  0.5]),
    "is":       np.array([-0.1, 0.1]),
    "sleeping": np.array([0.9,  0.6]),
}

query = embedding["cat"]
for word, vec in embedding.items():
    print(word, "->", np.dot(query, vec))
```

输出：

```text
The -> 0.0
cat -> 1.25
is -> -0.05
sleeping -> 1.2
```

`cat` 和自己（1.25）、和 `sleeping`（1.2）的点积明显更大，和 `The`（0.0）、`is`（-0.05）几乎没有关联——符合直觉：`cat` 应该更关注 `sleeping`（谓语动作）。这组分数 `[0.0, 1.25, -0.05, 1.2]`，会在下一步继续用来算 Softmax。

---

## 五、用 Softmax 把分数变成权重

Dot Product 得到的分数既不是概率，也不保证非负、和为 1。用 Softmax 转换（减去最大值保证数值稳定）：

```python
scores = np.array([0.0, 1.25, -0.05, 1.2])  # The, cat, is, sleeping
exp = np.exp(scores - np.max(scores))        # 减去最大值，数值更稳定
weights = exp / np.sum(exp)
print(np.round(weights, 3))  # [0.114 0.398 0.109 0.379]
```

结果：`The 11.4%, cat 39.8%, is 10.9%, sleeping 37.9%`——`cat` 主要关注自己和 `sleeping`（合计约 78%）。这组权重 `[0.114, 0.398, 0.109, 0.379]`，会在下一步继续用来做 Weighted Sum。

---

## 六、用 Weighted Sum 得到新的表示

最后按权重把所有 Token 的 Embedding 加权求和，得到 `cat` 融合上下文后的新表示：

```python
embedding_mat = np.array([
    [0.1, -0.2],   # The
    [1.0,  0.5],   # cat
    [-0.1, 0.1],   # is
    [0.9,  0.6],   # sleeping
])
weights = np.array([0.114, 0.398, 0.109, 0.379])  # 来自上一步

output = np.sum(embedding_mat * weights.reshape(-1,1), axis=0)
print(np.round(output, 3))  # [0.74 0.415]
```

新的 `cat' = [0.74, 0.415]`，比原来的 `cat = [1.0, 0.5]` 略微"偏向" `sleeping = [0.9, 0.6]` 的方向——这正是 Attention 的效果：`cat` 的新表示已经融合了 `sleeping` 带来的上下文信息，而不再是一个孤立的词向量。

---

## 本实验总结

✅ 用代码体会了"允许回头查看" ✅ 从人为打分过渡到字符串匹配 ✅ 发现了字符串匹配无法处理语义相近的问题 ✅ 用 Dot Product 计算了向量相似度 ✅ 用 Softmax 把分数变成非负、和为 1 的权重 ✅ 用 Weighted Sum 得到了融合上下文的新表示。
