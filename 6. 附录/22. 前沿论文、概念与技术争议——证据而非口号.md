# 22. 前沿论文、概念与技术争议——证据而非口号

> **更新基准：2026-11-26。** 本章把经典基础、前沿研究、工程进展和观点分开。论文及概念不加入千项软件计数；arXiv 预印本不自动代表同行评审，摘要阅读也不等于复现。

## 22.1 本次重点核验的 2026 年研究

| 研究 | 首次提交／资料日期 | 主要问题 | 本次证据边界 |
|---|---|---|---|
| [From Recall to Forgetting](https://arxiv.org/abs/2604.20006) | 2026-04-21 | 个性化 Agent 如何更新、遗忘失效记忆；提出 Memora | 已读取摘要页，不能由摘要推断所有人群和长期效果 |
| [MemGym](https://arxiv.org/abs/2605.20833) | 2026-05-20 | 长任务中的动态记忆，尝试隔离记忆与其他能力 | 已读取摘要页，替代执行评价的可靠性仍需论文细节 |
| [SAM: State-Adaptive Memory](https://arxiv.org/abs/2605.24468) | 2026-05-23 | 根据当前状态按需召回历史信息 | 已读取摘要页，成本、消融和泛化需进一步核验 |
| [METR 开发者生产率实验更新](https://metr.org/blog/2026-02-24-uplift-update/) | 2026-02-24 | 工具变化、参与者选择与并行 Agent 如何影响生产率测量 | 研究说明，不是通用提效百分比 |

这些论文的重点是提出可检验问题，而不是证明“长记忆已解决”。更近的项目或文章也不能仅因为日期更新就获得更强证据等级。

## 22.7 2026 年工程前沿：以实际资料为锚点

- **训练与后训练进一步组合**：torchtitan、verl 和 Megatron 配套项目扩展工作流，但也出现拆仓、recipe 和依赖迁移。见 1，不将产品名相同视为接口兼容。
- **推理开始强调跨实例协调**：Dynamo、llm-d 关注路由、缓存和阶段分离。见 2—3，不宣称所有负载都需要分离。
- **Harness 工程**：上下文选择、工具契约、状态、预算、测试和恢复决定 Agent 的实际能力。DeepSeek 原型是可阅读的案例，不是通用完成态。
- **记忆从保存转向更新与遗忘**：本章三篇 2026 年论文提供不同研究切口，效果仍需任务级验证。
- **机器人从演示转向数据与运行系统**：LeRobot、openpi 等使数据、策略与硬件接口更可复用；实机安全和成本仍未被软件自动解决。

## 22.8 概念与争议速查

| 概念／观点 | 可取的理解 | 不应作出的推论 |
|---|---|---|
| Test-time scaling | 用更多推理计算改善部分任务 | 思考越久必然越正确 |
| MoE | 以稀疏激活组织容量与计算 | 总参数大就必然更贵或更强 |
| 长上下文 | 扩大可输入的信息量 | 自动记住、更新和正确利用所有信息 |
| Context engineering | 系统化选择、组织与更新上下文 | 只改提示词就能代替工程 |
| Harness | 模型周围的工具、状态与控制系统 | 一个框架拥有所有模型能力 |
| Agentic RL | 用环境反馈优化多步行为 | 训练奖励等于现实价值 |
| Synthetic data | 用模型或模拟产生数据 | 不需要质量、去重和来源控制 |
| Verifiable reward | 利用可验证结果提供反馈 | 所有真实任务都有可靠自动判定 |
| LLM-as-a-Judge | 用模型辅助评价 | 评审输出就是客观事实 |
| World model | 学习环境与动作后果 | 视频好看就代表物理正确 |
| 小模型／端侧 | 在任务和设备约束下优化 | 一定比云端更隐私或更便宜 |
| 多 Agent | 利用职责分离或并行 | 人数更多就推理更强 |
| 开放权重 | 可获得模型参数 | 代码、数据、许可全部开放 |
| Agent-Native | 围绕可执行任务设计系统 | 企业必然无人化 |
| 数据飞轮 | 使用反馈持续改进 | 自动获得无偏且合法的新数据 |

这些是本书的辨析框架，不是统一行业共识。遇到观点时应追问：证据、反例、测量、适用范围和可证伪条件是什么？

## 22.9 论文阅读与复现卡

每次阅读记录：版本与日期、问题、假设、方法、数据、基线、预算、指标、消融、失败样本、开放资产和许可。复现不成功时区分实现差异、数据差异、硬件差异与结论不稳健。
