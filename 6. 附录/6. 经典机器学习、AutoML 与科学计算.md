# 6. 经典机器学习、AutoML 与科学计算

> **更新基准：2026-11-26。** 大模型没有替代全部机器学习。表格、时间序列、图、优化和统计建模仍是 AI 产品的重要组成部分。

## 6.1 为什么要保留这整章

业务问题经常有结构化输入、较小数据量和明确标签。梯度提升树、线性模型、概率模型或规则系统可能更便宜、更容易解释，也更容易建立可靠基线。

| 方向 | 代表生态 | 典型问题 |
|---|---|---|
| 数组与数值计算 | NumPy、SciPy、Julia | 线性代数、积分、优化、模拟 |
| 通用机器学习 | scikit-learn | 分类、回归、聚类、流水线 |
| 梯度提升 | XGBoost、LightGBM、CatBoost | 表格预测、排序 |
| AutoML | AutoGluon、FLAML、auto-sklearn | 候选模型、特征与集成搜索 |
| 超参数优化 | Optuna、Ray Tune、Hyperopt | 搜索、试验调度与资源管理 |
| 时间序列 | sktime、Darts、GluonTS、StatsForecast | 预测、异常与多序列建模 |
| 概率编程 | PyMC、Pyro、NumPyro、Stan | 不确定性、层次模型 |
| 图学习 | PyG、DGL、NetworkX | 图表示、关系和图算法 |
| 优化求解 | OR-Tools、CVXPY、Pyomo | 资源分配与约束优化 |
| 可解释性 | SHAP、LIME、InterpretML | 特征贡献与模型行为分析 |

上述类别可以组成混合系统：LLM 提取文字字段，传统模型预测，优化器生成可行方案，业务系统执行。

## 6.2 AutoML 不是自动定义问题

AutoML 可以搜索候选，但不会自动确定标签是否合理、训练集是否泄漏、业务损失如何衡量。把随机切分用于明显时间依赖的数据，可能得到虚高结果。

需要先定义：预测时能知道哪些信息、错误成本是否对称、样本是否独立、部署后的输入是否同分布。再选择搜索预算、验证方式和早停规则。

## 6.3 时间序列和图的特殊边界

时间序列应使用尊重时间顺序的验证，考虑节假日、异常、外生变量和层级一致性。一个统一基础模型可以作为候选，但不能因此省略季节性和朴素基线。

图模型可能通过边关系发生数据泄漏。训练时可见的邻居和部署时可见的图不同，转导式与归纳式任务要分开。图数据库、图算法库和图神经网络也不是同一层软件。

## 6.4 可信比较

同时报告业务指标、校准、推理成本、训练成本和稳健性。对类别不平衡，准确率可能掩盖少数类问题；对概率输出，需要检查校准而不只是排序能力。

SHAP 等解释工具描述模型行为，不自动提供因果解释。因果推断需要额外假设、设计与识别条件，不能从一张特征重要性图得出干预结论。

## 6.5 选择顺序

先建立简单基线 → 做数据质量检查 → 选择有业务意义的验证 → 再增加模型复杂度 → 检查部署约束。只有当新模型带来的收益超过数据、算力和维护成本时，复杂度才值得保留。

对于初学者，这也是连接本书神经网络原理与真实业务的一条低成本路线，不需要大规模 GPU 集群。
