# 4. 硬件、编译器与算子——AI 计算的底座

> **更新基准：2026-11-26。** 硬件型号、系统平台、软件后端和实际交付状态分别核验。本章不把厂商峰值指标当作真实模型性能。硬件介绍不混入软件项目计数。

## 4.1 从芯片到整座集群

AI 计算需要 CPU、GPU／专用加速器、主存、HBM、存储、网络、电力和散热共同配合。一个“大 GPU 数量”的系统可能被网络、检查点或数据供给限制。

| 范畴 | 代表方向 | 选型要点 |
|---|---|---|
| 通用 CPU | x86、Arm、服务器与端侧 CPU | 指令集、NUMA、内存带宽、向量化 |
| GPU | NVIDIA、AMD、Intel 等生态 | 可用显存、支持精度、内核与驱动 |
| 专用加速器 | TPU、Trainium／Inferentia、昇腾等 | 编译与模型支持、平台约束 |
| 边缘计算 | Jetson、Apple silicon、移动 NPU、开发板 | 功耗、内存、温度与部署格式 |
| 互连 | NVLink、PCIe、InfiniBand、以太网／RoCE | 拓扑、带宽、拥塞、集合通信 |
| 存储 | 本地 NVMe、对象存储、并行文件系统 | 吞吐、元数据、小文件和检查点 |
| 供电散热 | 机柜供电、风冷／液冷、设施监控 | 持续功耗与运维，而非只看标称功率 |

## 4.2 2026 年硬件阅读方法

NVIDIA 的 Blackwell 页面区分 GPU 架构、GB200／GB300 NVL72 等机架级系统、HGX 平台和 DGX 系统。GPU 内部裸片互连与 GPU 之间的 NVLink 不是同一对象。[1]

2026-01-05 的 Rubin 公告介绍 Vera CPU、Rubin GPU、NVLink 6、ConnectX-9、BlueField-4 和 Spectrum-6 的系统协同。[2] 公告、量产、云端可用与客户交付不是同一里程碑；这篇历史公告不能独自证明 11 月每个配置已可采购。

AMD 产品页的检索结果已包含 MI350／MI400 家族，但本次英文正文读取超时。具体规格、供货和 ROCm 兼容应回到对应型号文档，不按摘要补全。[3]

## 4.3 软件栈的四层

1. **设备接口**：CUDA、HIP／ROCm、Metal、SYCL 等，与驱动和硬件能力相联系。
2. **中间表示与编译**：LLVM／MLIR、XLA、TVM、IREE 等，负责程序表示、优化和后端生成。
3. **高性能库**：BLAS、DNN、集合通信、稀疏和张量库。
4. **模型专用内核**：FlashAttention、FlashInfer、CUTLASS、Triton kernels 等。

Triton 编程语言与 Triton Inference Server 名称相近，但不是同一个项目。Triton kernel 也不保证比库函数快：布局、形状、精度、寄存器和硬件决定结果。

## 4.4 核心概念

- **Roofline**：结合算术强度、计算上限与内存带宽理解瓶颈，而不是只盯 FLOPS。
- **算子融合**：减少中间结果读写与启动开销，但可能增加寄存器压力或限制复用。
- **混合精度**：不同计算和状态采用不同表示；FP8／FP4 支持不能只看硬件名称，还要看缩放、格式和软件实现。
- **集合通信**：all-reduce、all-gather、reduce-scatter 等服务于不同并行方案；通信与计算重叠需要实际验证。
- **KV Cache**：影响推理并发与上下文容量，不能把全部显存只留给模型权重。
- **统一内存／共享内存／HBM**：这些术语描述不同层次，不能互相替换。

## 4.5 实际选择

研究者通常应先使用框架成熟内核，确认瓶颈后再写定制算子。专业平台团队则需要建立模型级基准、数值误差检查、性能回归和跨设备支持矩阵。

硬件比较至少固定模型、批量、长度、精度、输出质量和能耗测法。厂商报价还应计入互连、主机、供电、空间、保修和可用率。低单卡价格可能对应更高总任务成本。
