# 17. 机器人、强化学习与仿真

> **更新基准：2026-11-26。** 仿真成功、策略基准与真实机器安全是不同证据。下表介绍工具，不构成设备操作许可或安全认证。

## 17.1 从本体到任务系统

| 层次 | 代表生态 | 负责什么 |
|---|---|---|
| 机器人中间件 | ROS 2、DDS 相关组件 | 节点、消息、设备与系统协作 |
| 几何与运动 | Pinocchio、MoveIt、优化与规划库 | 运动学、动力学、路径和轨迹 |
| 物理仿真 | MuJoCo、PyBullet、Isaac Sim／Lab、Genesis | 动力学、传感器、并行环境 |
| 环境接口 | Gymnasium、PettingZoo | 单／多智能体交互约定 |
| RL 算法 | Stable-Baselines3、RLlib、CleanRL、TorchRL | 策略学习与实验 |
| 模仿与机器人学习 | LeRobot、robomimic、Diffusion Policy | 数据、策略、训练与评测 |
| VLA | OpenVLA、openpi 等 | 视觉语言条件下的动作建模 |
| 世界模型 | Dreamer 类方法、模型预测与规划 | 预测和闭环决策 |

## 17.2 LeRobot：端到端工具不是端到端保证

本次 LeRobot 官方 README 覆盖数据格式、策略、硬件与插件：数据可结合 Parquet 与视频／图像，提供共享和处理能力；策略涉及 ACT、Diffusion、VLA、RL 等方向。[1]

部分硬件原生支持，部分通过社区插件。插件会引入依赖与执行风险，实际关节、相机、单位和动作范围需要标定。标准数据格式也不代表所有数据能够直接混合训练。

## 17.3 openpi 与 VLA

openpi 提供 π 系列策略相关实现，具体模型头、输入和动作规范不同。本次 README 的代码许可信息不能被扩展成所有权重都同许可，仍需逐模型检查。[2]

语言指令理解并不自动保证动作安全。跨本体迁移需要适配观测、动作、频率和控制边界，并对实际环境验证；某个机器平台上的专家权重不是通用即插即用驱动。

## 17.4 仿真器怎么选

- 研究控制和接触时，看物理模型、求解器与可复现性。
- 大规模学习时，看并行吞吐、重置成本和训练集成。
- 视觉训练时，看传感器、光照、材质和真实差异。
- 部署验证时，看本体模型、时序、延迟和安全边界。

不能把不同场景下的仿真 FPS 直接比较。简单环境的百万步吞吐，不代表复杂柔性、接触或高分辨率视觉场景同样快。

## 17.5 学习方法的选择

行为克隆需要示范覆盖；强化学习依赖奖励和探索；离线 RL 受数据支持范围约束；世界模型会累积预测误差；VLA 依赖训练分布与动作接口。没有一种方法自动解决所有分布偏移。

评测应包括连续成功、接管、碰撞、失败恢复、动作平滑、泛化与数据成本。只统计挑选后的演示成功率不够。

## 17.6 真机部署底线

先仿真和回放，再在低速、受限空间与人员监护下验证。保留独立急停、限位、速度／力限制和故障处理，不让通用 LLM 直接替代低层安全控制。

设备折旧、维修、标定、充电和现场人员也是总成本。机器人商业部署案例的判断见第五部分，不由模型论文分数直接推导。
