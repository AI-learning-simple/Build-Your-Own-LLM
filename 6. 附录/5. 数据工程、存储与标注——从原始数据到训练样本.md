# 5. 数据工程、存储与标注——从原始数据到训练样本

> **更新基准：2026-11-26。** 数据基础设施属于 AI 生态，但数据库、ETL 和格式本身不一定包含机器学习。批量表提供公开项目元数据，正文提供选型框架。

## 5.1 数据生命周期

采集与授权 → 原始保存 → 解析 → 清洗 → 去重 → 标注与质量检查 → 数据集划分 → 版本化 → 训练／检索 → 反馈与删除。这条链不必采用同一家供应商，但必须能够追踪数据来源与变化。

| 层次 | 代表项目／标准 | 主要用途 |
|---|---|---|
| 文件与列式格式 | Arrow、Parquet、JSONL、WebDataset | 高效传输与组织样本 |
| 本地分析 | DuckDB、Polars、pandas | 快速分析、转换、抽样 |
| 分布式处理 | Spark、Flink、Ray Data、Dask | 大规模批处理和流处理 |
| 数据连接 | Airbyte、Meltano、dlt | 接入数据库与业务源 |
| 编排 | Airflow、Dagster、Prefect | 依赖、重试与数据资产 |
| 湖仓与表格式 | Iceberg、Delta Lake、Hudi | 表级事务、版本和元数据 |
| 标注 | Label Studio、CVAT、doccano、Argilla | 人工标注与反馈 |
| 文档解析 | Docling、Unstructured、Marker、MinerU | PDF、版式、表格与文本 |
| 质量与血缘 | Great Expectations、Pandera、OpenLineage | 校验、约束与过程追踪 |
| 数据版本 | DVC、lakeFS、数据集 revision | 复现与回滚 |

## 5.2 文档解析不是 OCR 一个按钮

扫描页需要识别文字，原生 PDF 可能已经含文字；表格、公式、页眉、阅读顺序和跨页关系仍需重建。解析错误会在 RAG 或训练里被模型放大。

比较 Docling、Unstructured、Marker、MinerU 等工具时，使用真实文件集，检查段落顺序、表格结构、图片说明、引用位置和失败率。不要只看单张样例的视觉效果。解析输出应关联原文件、页码和坐标，便于人工回查。

## 5.3 训练数据与检索数据不同

训练数据改变参数；检索数据在运行时提供上下文。二者对时效、删除和权限的要求不同。不能因为文件可以被公开访问，就认定可以用于任意训练或再分发。

数据集切分应避免近重复文档、同一用户、时间穿越或同源样本泄漏。标签一致性、标注者分歧和低质量样本也应记录，而不是用更大数据量掩盖问题。

## 5.4 流水线可靠性

- 保留原始数据与转换版本，清洗不可追溯会阻碍错误定位。
- 采用幂等写入，明确任务重试是否重复追加。
- 数据集快照、模型 revision 和实验指标应相互关联。
- 检查缺失、重复、异常分布和字段漂移，不只验证 JSON 可解析。
- 删除请求需要覆盖衍生文件、索引、缓存和备份策略；不是删除一行原始记录就结束。

## 5.5 怎么选

小型数据集先用本地列式工具，不必直接搭集群。需要低延迟事件处理时考虑流系统，需要跨团队可复现时考虑资产、血缘和版本管理。标注工具要检查数据权限、导出格式与审阅流程；托管版本的许可和费用另行确认。

性能评价包括吞吐、峰值内存、失败恢复、正确性和总处理成本。数据吞吐再高，错位标签和泄漏仍会让实验无效。
