# 16. 语音、音频与实时交互

> **更新基准：2026-11-26。** 语音识别、合成、分离、实时传输和语音 Agent 是不同层次。声音样本与生成内容必须获得适当授权，不应用于冒充他人。

## 16.1 音频生态地图

| 模块 | 代表生态 | 核心任务 |
|---|---|---|
| 音频处理 | librosa、torchaudio、FFmpeg 等 | 采样、频谱、编解码与变换 |
| ASR | Whisper、faster-whisper、FunASR、NeMo Speech | 语音转文字 |
| VAD | Silero VAD 等 | 判断语音活动区间 |
| 说话人处理 | pyannote、SpeechBrain 等 | 分段与说话人相关建模 |
| TTS | CosyVoice、Fish Speech、Piper、Coqui TTS 等 | 文字到语音 |
| 音乐与分离 | 音乐生成、Spleeter、Demucs 等 | 创作、音源分离与修复 |
| 实时 Agent | Pipecat、LiveKit Agents 等 | 音频传输、对话与工具协调 |
| 多模态音频模型 | 音频理解、语音语言模型 | 统一或端到端交互 |

## 16.2 两条实时路线

**级联路线**：VAD／ASR → 文字模型 → TTS。组件可替换、调试清楚，但错误会传播，端点判断和每层等待可能增加时延。

**端到端语音路线**：模型直接处理和生成音频或混合序列，可能更好保留语气与互动信息；但可解释、文字审计、工具执行和错误定位有不同挑战。

二者都需要处理打断、回声、噪声、网络抖动、会话恢复和说话人切换。只是把三个 API 串起来，不等于已经形成自然的实时对话。

## 16.3 最新项目状态应逐项核验

本次旧 NeMo 仓库入口已经显示为 `NVIDIA-NeMo/Speech`，说明大型框架的领域拆分会影响依赖与示例。CosyVoice 等项目也可能调整维护组织，表格使用 API 返回的规范地址，不用旧组织名重复计数。

Coqui TTS 等历史项目仍可能具有参考价值，但不能由历史热度推断商业支持持续存在。安装前检查归档、发行、依赖与维护信息。

## 16.4 评价标准

ASR 看 WER／CER、术语、标点、说话人、时间戳与实时率；TTS 看清晰度、自然度、发音、语言、稳定性和首音频延迟；音乐与分离需要任务特定评价。

实时体验应测端到端首响应、打断停止时间、误触发、漏检和连续会话稳定性。只报告模型计算时间会漏掉音频缓冲、网络和播放等待。

## 16.5 隐私与授权

录音可能包含个人信息和敏感对话。应明确采集同意、存储、删除、转写与第三方处理。声音克隆需要明确授权和用途控制；公开样本不等于可以任意生成具有该声音身份的内容。

医疗、客服等专业记录还需要人工核对，不能因识别输出流畅就忽略否定、数字、名称与时间错误。
