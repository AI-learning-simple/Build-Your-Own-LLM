# 导读——如何使用本附录

> **编辑基准日：2026-11-26。** 本附录汇集面向 AI 开发、选型和研究的参考资料，供阅读正文时查阅与延伸学习，不要求安装所有软件。本部分与前五部分一样，主章从 `1` 开始编号；导读不编号。

## 一、收录范围与边界

本部分沿着硬件 → 编译与算子 → 数据 → 训练 → 推理 → 分布式 → 模型 → 检索 → Agent → 应用 → 评测与运营展开，并补充商业平台、论文和技术争议。前三章按读者最常见的工程问题组织，最后一章提供总树。

“包罗万物”在这里意味着尽可能覆盖 AI 开发和应用的主要层次，**不意味着一个静态文档能够穷尽全部项目、行业或未来技术**。传统机器学习、科学计算、数据库、容器和开发工具也是 AI 系统的一部分，但不因被收录就变成 AI 专用产品。

本附录内容分为三类：

1. **专题说明**：中文解释原理、主流工具分工、选择方法、常见误区和官方阅读入口。
2. **项目索引**：千项级软件仓库资料，提供名字、用途自述、来源、热度快照、更新时间和许可提示。
3. **延伸资料**：硬件与商业产品、论文、概念和观点，不混入软件数量凑数。

## 二、“1000 项”究竟如何计数

正式证据保存于 [`assets/catalog.json`](<assets/catalog.json>)，统计由 [`assets/summary.json`](<assets/summary.json>) 和末章生成。软件项目以 GitHub 返回的**规范仓库 ID** 去重，每个项目只分配一个主章节；重命名或转移组织但 ID 不变，不增加计数。

统计对象是可识别的软件项目或独立组件，不是公司数、独立商业产品数，也不是一千个都经过实测的推荐清单。一个生态的独立运行时与可独立使用的配套组件可以分别收录；同一仓库内的功能、模型参数版本、重复目录和论文引用不拆成多项。

默认发现条件为：GitHub 相关主题检索、至少 300 Stars、未归档、非 fork、2025-01-01 以来有推送。显式加入的主流锚点可以例外，例如重要的新项目或需要说明归档迁移的历史项目。候选还要排除纯资源列表、课程和明显偏题内容，再按主题归类与控制篇幅。

这不是“下载量排行榜”：Stars 有年代、语言和平台偏差；最近推送也可能只是自动依赖更新。较少 Stars 的企业软件、闭源应用或关键底层组件同样可能重要。

## 三、如何理解证据质量

| 标签／信息 | 证明的内容 | 不能证明的内容 |
|---|---|---|
| GitHub API 元数据 | 仓库身份、当时的热度、推送和许可检测字段 | 软件可靠、安全、适合生产 |
| README／官方文档阅读 | 维护者声明的能力、边界、迁移信息 | 全部功能都已实测可用 |
| 官方产品页面 | 产品定位和公开说明 | 各地区、套餐都有相同功能 |
| 论文摘要／原文 | 提出了方法或在所述条件下报告结果 | 已成为通用定律或成熟产品 |
| 资讯聚合站 | 新项目和事件线索 | 官方身份、性能与商用状态 |

批量项目表主要是**元数据核验级**。主章中重点阅读过文档的条目会单列出处；不能把这些重点核验扩展成“所有项目全文都已审查”。项目自述可能带有营销语言，本书保留其原文定位，但不采信“最快”“最强”等没有同条件测试的结论。

AIBase 等网站用于发现线索，重要结论回到官方仓库、文档和论文。例如 DeepSeek 的 `dsh-superagent-prototype` README 明确称其为研究原型、非正式产品，且部分文章构想没有实现；不能只按资讯标题写成成熟平台。

## 四、时效：明确知道什么，不假装永远最新

编辑日与网络采集时间不是一回事。JSON 中记录逐项 `fetched_at`，查询证据记录 HTTP 日期、实际查询和返回 ID；项目表中的日期是 `pushed_at`，不是稳定版本发布日期。

`latest` 和 `main` 文档经常包含尚未稳定发布的功能。部署需要固定包版本、镜像、模型 revision、驱动、工具和协议版本，并做兼容测试；本书不复制一份很快过时的“统一最新版本号”。

如果来源不可达、发生迁移或证据冲突，应降低结论强度并记录待核验，而不是自动补全。TGI、AutoGen、NeMo 等条目的维护或拆仓变化，正说明历史教程不能直接代表当前选型。

## 六、维护和复核

[`assets/catalog.py`](<assets/catalog.py>) 是本附录引用的正式采集与生成脚本，不运行任何被收录仓库的代码。`collect` 仅调用公开 GitHub 元数据接口，可选使用环境变量中的 `GITHUB_TOKEN` 提高配额，脚本不会保存令牌。`audit` 则访问正文中的外部官方／论文网页，只检查 HTTP 响应与页面标题，不代表完整内容审查；记录见 [`assets/source_audit.json`](<assets/source_audit.json>)。

`collect` 默认续采未完成查询，`collect --refresh` 重新查询当前发现窗口并更新命中仓库；未再次命中的项目仍保留原采集时间，不能视为全量重新核验。跨日期制作新版本时还应更新编辑基准日和发现窗口。`curate`、`render`、`validate` 分别负责筛选、生成和校验。章节目录块和总树由保存快照生成；正文是编辑内容，不由仓库 README 指令自动改写。刷新后必须复核分类、归档、许可和新旧名称。

查询失败会保留历史记录；查询未返回某个名称可能是迁移、不可达或索引问题，不等于项目不存在。统计中的未解析锚点需要人工复核，不使用猜测补造条目。

使用第三方软件时，还要独立检查供应链、许可证、模型权重与数据条款。GitHub 的许可字段为空或 `NOASSERTION` 不表示可以任意商用。下载和执行仓库代码不是阅读本附录的必要步骤。
