# 10. 协议、工具、浏览器与执行环境

> **更新基准：2026-11-26。** 工具可连接不等于被授权，浏览器能够点击不等于业务已经完成，协议相同也不保证实现完全互操作。

## 10.1 连接对象速查

| 技术 | 连接对象 | 主要内容 |
|---|---|---|
| Function／Tool Calling | 模型输出与应用工具 | 名称、参数、结果和控制循环 |
| MCP | Agent 应用与工具／资源服务 | 工具、资源、Prompt 等协作接口 |
| A2A | 独立 Agent 系统 | 消息、任务状态、产物和协作 |
| AG-UI | 用户界面与 Agent 后端 | 流式事件、状态同步与交互 |
| OpenAPI | HTTP API 的描述与契约 | 接口、参数与响应结构 |
| 商务协议 | Agent、商家和交易参与方 | 商品、结账、订单等语义 |

MCP 本次规范页标注 **2026-07-28**，A2A 页面标注 **v1.0**。[1][2] 文档版本不是所有 SDK 都已实现该版本的证明。

## 10.2 MCP 不是新的权限万能层

服务器可以公开工具、资源与模板，客户端仍需决定如何将它们暴露给模型。授权的适用方式与传输相关，HTTP 与本地 `stdio` 不应机械使用同一流程。

工具描述和工具返回也可能包含不可信内容。应用应限制能力清单，校验参数，隔离凭据并在服务端执行授权。不能把网页正文中的命令当成用户的新指令。

第三方 MCP Server 是普通软件供应链的一部分：依赖、运行权限、数据外发和维护状态都需要审查。支持协议不等于通过安全认证。

## 10.3 浏览器与抓取工具

Playwright、Puppeteer、Selenium 提供浏览器自动化；Browser Use 等将模型选择动作接入浏览器；Crawl4AI、Firecrawl、Scrapy 等关注采集、提取或索引工作流。它们处在不同层次。

优先使用被允许且稳定的正式接口。浏览器适用于没有合适 API 的授权流程，但页面布局、异步加载、登录和弹窗都可能改变。抓取需尊重访问权限和站点限制，不应用来规避付费、验证码或身份控制。

## 10.4 执行环境

| 环境 | 优点 | 必须理解的边界 |
|---|---|---|
| 本地进程 | 开发简单 | 可能继承用户文件与网络权限 |
| 容器 | 易复现、依赖隔离 | 不自动构成强安全边界 |
| 微虚拟机／专用沙箱 | 更强隔离方向 | 启动成本、网络与挂载仍需配置 |
| 浏览器隔离会话 | 可分离登录与状态 | Cookie、下载、扩展和外网仍有风险 |
| 托管执行平台 | 运维简化 | 数据位置、费用、条款和供应商依赖 |

E2B 等项目可提供执行基础设施，实际安全保证仍取决于部署配置与使用方式。不要把生产密钥注入任意代码执行会话。

## 10.5 工具调用成功的定义

HTTP 200、进程退出码 0 和页面点击成功都不是最终业务验收。需要用订单号、文件校验、数据库状态或服务回执确认目标已完成。

对于有副作用的操作，记录幂等键和动作标识；超时后先查询状态。读取网站、发邮件、下单和付款应拥有不同的权限等级，不能因它们都通过浏览器完成就一并授权。

## 10.6 选型建议

先定义工具契约和错误语义，再决定是否需要 MCP；先确定跨 Agent 互操作需求，再决定是否需要 A2A；先保证后端审批真正生效，再设计 AG-UI 的审批体验。

协议的价值在于降低连接成本，而不是替代业务规则、状态保存和责任设计。
