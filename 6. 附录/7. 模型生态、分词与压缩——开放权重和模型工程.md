# 7. 模型生态、分词与压缩——开放权重和模型工程

> **更新基准：2026-11-26。** 本章按模型任务与工程对象组织，不把参数大小、量化版本或同一模型的镜像分别计数。开放权重、开放代码、开放数据和可商用是不同条件。

## 7.1 模型生态有哪些对象

| 对象 | 代表生态／工具 | 作用 |
|---|---|---|
| 模型托管与卡片 | Hugging Face Hub、ModelScope、官方仓库 | 权重、配置、版本、许可与任务说明 |
| 模型定义 | Transformers、各家参考实现 | 网络结构、加载、生成和适配 |
| 分词 | Tokenizers、SentencePiece、tiktoken | 文本与离散序列的映射 |
| 张量与权重格式 | safetensors、GGUF、ONNX 等 | 安全加载、部署或模型交换 |
| 参数高效适配 | PEFT、LoRA 相关工具 | 以较少可训练参数适配任务 |
| 量化与压缩 | bitsandbytes、GPTQ／AWQ 实现、压缩工具 | 降低权重、激活或缓存资源 |
| 合并与转换 | mergekit、转换脚本、Bridge 类工具 | 模型组合与跨训练／推理生态转换 |

格式的目的不同：ONNX 是模型计算表示相关标准，safetensors 关注张量保存，GGUF 常用于特定本地运行时。不能只把文件后缀改掉就完成转换。

## 7.2 模型家族怎么查

截至本次访问，Qwen 官方组织覆盖文本、视觉语言、图像与语音等类型，DeepSeek 官方组织包含文本、代码与多模态方向。[1][2] 官方组织页面会滚动更新，不适合将某个列表永久称为“当前全部最新模型”。

其他值得按任务查阅的家族包括 Llama、Gemma、Mistral、Phi、OLMo、GLM、Kimi、MiniMax、InternLM、InternVL、Hunyuan、Wan，以及嵌入、重排、语音和视觉专用模型。商业 API 家族另见 21。

模型卡应回答：用途、输入模态、上下文、训练／评测说明、许可、硬件、模板和限制。文档未说明的内容不要从家族名称推定；“开放模型”也不能自动译成符合所有开源定义的模型。

## 7.3 模型选择不是只看榜单

先建立实际任务集，再比较正确性、格式、工具使用、语言覆盖、时延、费用和可靠性。模型在数学题上进步，不代表你的长文档检索或业务 API 调用一定变好。

评测还需要固定模型 revision、模板、采样、最大输出和可用工具。基于 API 的评测要保留测试日期，服务端模型可能更新。公开榜单可能存在数据污染或测量差异，不能只比较一个总分。

## 7.4 量化与压缩的边界

- **权重量化**：节省权重存储，计算加速依赖内核和硬件。
- **激活量化**：影响运行中的数值范围，需要校准或适当训练。
- **KV 量化**：减少上下文与并发的缓存成本，可能影响生成质量。
- **蒸馏**：把教师行为转移到学生模型，需要数据与训练，并不自动继承全部能力。
- **剪枝／稀疏**：参数减少不保证实际更快，取决于稀疏结构和执行支持。
- **模型合并**：权重组合是一种实验方法，不保证能力相加，也需要检查许可兼容。

“4 bit 模型”描述不完整：哪些张量 4 bit、分组大小、缩放、计算精度与缓存精度都可能不同。

## 7.5 必须固定的工程信息

保存 tokenizer、chat template、special tokens、权重 revision、适配器、量化配置与运行时版本。训练与服务模板不一致，可能造成角色错位、错误停止或工具调用失效。

加载来源不可信的模型时，注意自定义代码、序列化和依赖风险。不要因为仓库热门就无条件启用远程代码执行。许可应分别检查代码、基础权重、适配器、数据和再分发条款。
