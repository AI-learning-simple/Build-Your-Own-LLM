# 12.1 亲手实现一个任务分解与技能调度的具身 Agent

> **本节目标**：用纯 Python 手写一个"泡咖啡"任务的 Skill Library（模拟机器人技能，故意加入随机失败来模拟真实抓取的不确定性）和一个 Planner，完整实现"任务分解 → 执行 → 失败检测 → 重试/重新规划"的闭环，最后再展示如何把模拟 Planner 换成一次真正的 LLM 调用。

---

# 一、环境准备

本节核心逻辑只需要 Python 标准库即可运行。

---

# 二、搭建 Skill Library（模拟机器人技能）

每个技能函数对应第2~11章讨论过的一个已经训练好的底层策略，这里用简单的打印语句模拟"机器人真的执行了这个动作"，并且故意让 `pick` 技能有一定概率失败，模拟第8章讨论过的真实抓取的不确定性：

```python
import random

class RobotSkillLibrary:
    def __init__(self):
        self.state = {"gripper_holding": None}

    def locate(self, obj):
        print(f"    [Skill] locate({obj}) -> 已找到 {obj} 的位置")
        return True

    def pick(self, obj):
        success = random.random() > 0.3   # 模拟真实抓取70%的成功率
        if success:
            self.state["gripper_holding"] = obj
            print(f"    [Skill] pick({obj}) -> 抓取成功")
        else:
            print(f"    [Skill] pick({obj}) -> 抓取失败（打滑）")
        return success

    def place(self, location):
        if self.state["gripper_holding"] is None:
            print(f"    [Skill] place({location}) -> 失败（手上没有持物）")
            return False
        held = self.state["gripper_holding"]
        print(f"    [Skill] place({location}) -> 已把 {held} 放到 {location}")
        self.state["gripper_holding"] = None
        return True

    def press_button(self, button):
        print(f"    [Skill] press_button({button}) -> 已按下")
        return True

    def pour(self, src, dst):
        print(f"    [Skill] pour({src} -> {dst}) -> 已倒出")
        return True
```

# 三、搭建 Planner（这里用规则表模拟 LLM 的任务分解结果）

```python
def llm_planner(task):
    """
    为了让整个流程完全可运行、不依赖下载任何模型，这里用一个规则表
    模拟"如果让一个LLM来分解这个任务，它会给出的技能序列"。
    在真实项目里，这个函数的实现会替换成对一个真正的LLM的调用
    （见本节末尾的"接入真实LLM"部分），其余的执行与重试框架完全不需要改动。
    """
    plans = {
        "泡一杯咖啡": [
            ("locate", ["杯子"]),
            ("pick", ["杯子"]),
            ("place", ["咖啡机出水口下方"]),
            ("press_button", ["咖啡机电源"]),
            ("pour", ["咖啡机", "杯子"]),
        ],
    }
    return plans.get(task, [])
```

# 四、执行器：闭环的执行 + 失败检测 + 重试

```python
def run_embodied_agent(task, max_retries_per_step=3):
    robot = RobotSkillLibrary()
    plan = llm_planner(task)

    print(f"任务: {task}")
    print(f"Planner 给出的初始计划: {plan}\n")

    for step_index, (skill_name, args) in enumerate(plan):
        print(f"[第{step_index + 1}步] 执行 {skill_name}({', '.join(args)})")
        attempt = 0
        success = False

        while attempt < max_retries_per_step and not success:
            attempt += 1
            success = getattr(robot, skill_name)(*args)
            if not success and attempt < max_retries_per_step:
                print(f"    [Planner] 检测到失败，这是第{attempt}次尝试，准备重试...")

        if not success:
            print(f"\n任务失败：{skill_name} 连续 {max_retries_per_step} 次尝试均未成功，"
                  f"需要人工介入或触发更高层的重新规划（比如换一种抓取姿态）。")
            return False

    print("\n任务完成！机器人按顺序成功执行了全部技能。")
    return True

random.seed(1)
run_embodied_agent("泡一杯咖啡")
```

**预期输出**（因为 `pick` 有随机失败的可能，具体是否触发重试、重试几次，每次运行会不同；下面是某一次典型运行的示例——`locate/place/press_button/pour` 都是确定性成功，只有 `pick` 可能需要重试）：

```
任务: 泡一杯咖啡
Planner 给出的初始计划: [('locate', ['杯子']), ('pick', ['杯子']), ('place', ['咖啡机出水口下方']), ('press_button', ['咖啡机电源']), ('pour', ['咖啡机', '杯子'])]

[第1步] 执行 locate(杯子)
    [Skill] locate(杯子) -> 已找到 杯子 的位置
[第2步] 执行 pick(杯子)
    [Skill] pick(杯子) -> 抓取失败（打滑）
    [Planner] 检测到失败，这是第1次尝试，准备重试...
    [Skill] pick(杯子) -> 抓取成功
[第3步] 执行 place(咖啡机出水口下方)
    [Skill] place(咖啡机出水口下方) -> 已把 杯子 放到 咖啡机出水口下方
[第4步] 执行 press_button(咖啡机电源)
    [Skill] press_button(咖啡机电源) -> 已按下
[第5步] 执行 pour(咖啡机 -> 杯子)
    [Skill] pour(咖啡机 -> 杯子) -> 已倒出
```

因为 `pick` 单次成功率是70%，连续3次都失败的概率只有 `0.3³ = 2.7%`，所以绝大多数情况下（约97.3%的概率）任务最终都会成功，只是可能需要1~2次重试——这正是"闭环重试机制"在数学期望上带来的鲁棒性提升。

# 五、接入真实 LLM：把规则表换成一次真正的调用

真实项目里，只需要把 `llm_planner` 函数内部的实现，换成第三部分讲过的对一个真正的语言模型的调用（比如本地部署的 Qwen 模型），并约定好输出格式为 JSON——这正是第三部分第2章 **Tool Calling** 讲过的"约束解码保证输出合法 JSON"的直接复用：

```python
# 真实 LLM Planner 示意代码（需要 pip install transformers torch，需要下载模型权重）
from transformers import AutoModelForCausalLM, AutoTokenizer
import json

model_name = "Qwen/Qwen2.5-1.5B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype="auto", device_map="auto")

def llm_planner_real(task, available_skills):
    prompt = (
        f"你是一个机器人任务规划器。可用的技能有：{available_skills}。\n"
        f"请把任务「{task}」分解成一系列技能调用，严格以JSON数组格式输出，"
        f"每一项是 [技能名, [参数列表]]，不要输出任何其他文字。"
    )
    messages = [{"role": "user", "content": prompt}]
    text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = tokenizer(text, return_tensors="pt").to(model.device)
    output_ids = model.generate(**inputs, max_new_tokens=200)
    response = tokenizer.decode(output_ids[0][inputs.input_ids.shape[1]:], skip_special_tokens=True)
    return json.loads(response)   # 解析成 [(skill_name, args), ...] 格式，供 run_embodied_agent 直接使用
```

**除了 `llm_planner` 这一个函数的内部实现，`run_embodied_agent` 里的执行、失败检测、重试逻辑完全不需要做任何修改**——这正是分层架构"关注点分离"的价值：升级 Planner 的智能程度，不会影响底层执行框架的稳定性。

# 六、思考题

本节的重试策略非常朴素——失败了就原地重试同一个动作。可以思考一下：如果 `pick(杯子)` 连续失败了3次，比"原地重试"更聪明的做法可能是什么？（提示：可以考虑"换一个抓取角度""先重新定位一次物体，因为可能是物体位置估计有误""请求人类远程协助"这几个方向，这些正是更高级的具身智能体在真实产品中会实现的恢复策略。）
