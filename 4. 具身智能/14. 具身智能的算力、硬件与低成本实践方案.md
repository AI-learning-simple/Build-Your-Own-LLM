# 14. 具身智能的算力、硬件与低成本实践方案

> **本章目标**
>
> - 分清 CPU 必修、GPU/模型选修与真机拓展，不把“可理解核心原理”写成“所有实验仅 NumPy 即可跑通”
> - 区分代码参考、软件实测、闭环评测与真机验收
> - 按完整 BOM 与版本记录预算，不拿无日期的零件价格冒充整机现价

## 一、先选路线，而不是先买硬件

本部分有足够多的小规模 CPU 实验帮助建立核心直觉，但**不是所有实验都只依赖标准库/NumPy，也不是全部都无需 GPU**。已有电脑可以覆盖下列必修路线，无需先购买机器人。

| 层级 | 内容 | 资源与边界 |
|---|---|---|
| CPU 必修：算法与模拟 | 运动学、表格 RL、BC/DAgger toy、深度反投影、8.1 奖励塑形、9.1 线性动态/MPC、11.1 稳定域与分类、12.1 技能状态机、13.1 数据分桶 | 标准库/NumPy 为主，部分需 Pandas/绘图库；没有真机运动，不声称复现完整论文 |
| CPU 可做：框架小实验 | 8.2 PyTorch + Gymnasium；10.1 PyBullet；10.2 MuJoCo；10.4 Genesis CPU 基础参考；10.5 LeRobot CPU smoke test | 需要额外依赖、兼容 Python/系统、数据下载及可能的视频解码；CPU 可运行不等于快速训练 |
| GPU/模型选修 | 7.1 本地 VLM、VLA 推理/微调、10.3 Isaac Lab；LeRobot 较完整视觉训练 | 依模型与版本选择 GPU/显存或合规 API；7.1 的模型下载与推理不是 NumPy 路线；10.3 无对应硬件可跳过 |
| 真机拓展 | 低成本机械臂、相机、遥操作、标定、闭环部署 | 需本体与完整防护、标定、时间同步、通信 watchdog、独立急停及现场验收；不属于软件示例自动通过的范围 |

PPO、MPC、PyBullet 等经典内容保留：它们帮助看清采样、控制、物理仿真与数据接口，并不因 VLA 更新而失去教学价值。CPU toy 与 GPU 参考在同一课程中可以并存，前提是诚实标注依赖和验证层级。

## 二、怎样判断“跑通了”

建议为每个实验记录下面四个不同结论，而不是只有一个“成功”标签：

1. **接口核验/参考代码**：根据固定版本文档检查，尚未在本机运行。
2. **软件 smoke test**：导入、一次前后向或数步仿真、文件回读通过；不等于模型学会任务。
3. **闭环评测**：独立场景、多训练种子与多回合统计；训练 loss、单次视频不替代成功率。
4. **真机验收**：延迟与 stale 数据处理、碰撞/接触边界、停止机制、安全事件和故障恢复均经过现场检查。

本次修订没有安装大型框架或下载模型，8.2 的新版训练、10.2 的 MuJoCo/Parquet、10.3 Isaac Lab、10.4 Genesis、10.5 LeRobot 等参考链路不能写成“本次已实测”。有明确局部 CPU 数值/状态测试的章节，也只证明相应 toy 或接口逻辑，不扩大到全栈。

## 三、算力预期：依任务、版本和输入规模估算

- **手写小模型/几何算法**：CPU 一般足够。不要把这个结论外推到原版视觉 ACT、Diffusion Policy 或大 VLA。
- **8.2 PPO**：小 MLP 可以 CPU 训练，但多种子对照增加总交互预算；代码运行时间与是否收敛要分别报告。
- **10.5 LeRobot 0.4.4**：显式 `--policy.device=cpu` 可做少步 smoke test，较完整训练可选择 GPU；1000 步和 loss 下降不是工业级能力证明。
- **10.3 Isaac Lab v2.3.0**：对应安装页列出 Ubuntu 22.04 / Windows 11、32 GB RAM 和 16 GB VRAM 起的基本要求，并需兼容 NVIDIA GPU/驱动及 Isaac Sim；4096 环境不是最低配置保证。以锁定发布版要求为准，不混用 main 分支后续后端。
- **VLA/VLM**：显存由参数量、精度、图像数/分辨率、上下文、batch 和优化器决定，不能一律承诺“8GB 就够”。参数高效微调也仍需加载骨干及激活。
- **云 GPU**：在小样本上测吞吐、显存峰值后估算时长，加上模型/数据传输、存储和闲置实例费用；本章不提供未经当日报价核验的“几元完成”承诺。

## 四、低成本开源硬件与完整 BOM

SO-100 / SO-101、Koch、LeKiwi 是可研究的开源硬件路线，支持情况以所用 LeRobot 发布版和具体驱动为准；“有社区插件”不等于对任意同名硬件即插即用。

| 方案 | 适合学习什么 | 不应忽略什么 |
|---|---|---|
| SO-100 / SO-101 | 机械臂装配、标定、遥操作与短程操作策略 | 单从臂还是主从两臂，舵机型号、相机、电源、线缆及备件 |
| Koch | 另一种开源臂结构与控制生态 | 物料供应、固件及校准流程不同 |
| LeKiwi | 移动与操作结合 | 额外底盘、供电、通信、场地与运动防护 |

**预算口径日期：2026-11-27；本次未查询商家报价，以下不是现价清单。** 原稿没有可追溯 BOM 日期的“几百到一千余元”不再作为整套系统报价。实际预算至少分列：本体零件、主从臂数量、打印/加工、相机与支架、电源与电池、控制器/计算机、急停防护、运输税费与备用件；保存供应商、币种、含税/运费及**报价日期**。引用开源 BOM 时还要记录仓库 tag/commit 和发布日期，不能把某年的裸从臂零件成本当作今天的完整训练平台价格。

低价不等于无风险。先在限速、隔离、有人监督的场景标定与验收，确认单位、坐标、关节限位、动作频率和停止行为；不要直接把教程随机策略或未经评测的 checkpoint 发到电机。

## 五、诚实的预期管理

从小规模实验理解训练机制，不等于复现 RT-2、π0 或大规模 VLA 的数据与算力。下载现有检查点做推理、对一个任务微调、从零预训练，是三个完全不同的资源问题；前两者可能适合个人，后者通常需要大规模组织化采集与训练。

本课程的可交付目标是：能解释数据/动作契约，跑一个符合自己资源的最小实验，知道未测什么，并能设计下一步闭环验收。无需因暂时没有 GPU 或机器人就放弃 CPU 主线，也无需为“全栈复现”的口号盲目购买设备。

## 本章总结

- CPU 必修能建立核心直觉；PyTorch、仿真器、模型/GPU 与真机拓展必须单独说明依赖。
- 参考代码、smoke test、策略性能和真机安全是不同验证层级。
- 预算用带日期与完整边界的 BOM，不编造现价；硬件投入不能替代安全与数据工程。
