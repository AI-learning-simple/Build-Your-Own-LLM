# 13.1 清洗与分析一份机器人采集数据集

> **定位**：CPU 教学实验，需要 NumPy、Pandas，无需机器人。这里生成的是 episode 级合成摘要，**不是完整机器人轨迹，也不验证失败数据能提高策略性能**。
>
> **目标**：对成功/失败做分桶，注入少量坏记录触发清洗，分清“任务失败”与“数据损坏”，建立后续复核和独立验收的接口。本次修订环境没有 Pandas，以下流水线未实测，不提供伪精确输出。

```python
import numpy as np
import pandas as pd

rng = np.random.default_rng(0)

def simulate_data_collection(n_teleop=50, n_policy_assisted=150):
    records = []
    for episode_id in range(n_teleop + n_policy_assisted):
        teleop = episode_id < n_teleop
        steps = int(rng.integers(15, 25) if teleop else rng.integers(10, 40))
        records.append({
            "episode_id": episode_id,
            "method": "teleop" if teleop else "policy_assisted",
            "success": True if teleop else bool(rng.random() < 0.6),
            "num_steps": steps,
            "start_time_s": 0.0,
            "end_time_s": steps * 0.1,
            "sample_period_s": 0.1,
            "schema_version": "episode-summary-v1",
            "calibration_id": "synthetic-no-camera",
        })
    return pd.DataFrame(records)

clean_source = simulate_data_collection()
print(clean_source.groupby("method")["success"].agg(["mean", "count"]))

# 三条故意注入的坏记录：重复、过短、缺失时间。
duplicate = clean_source.iloc[[0]].copy()
short = clean_source.iloc[[1]].copy()
short["episode_id"], short["num_steps"], short["end_time_s"] = 200, 2, 0.2
missing = clean_source.iloc[[2]].copy()
missing["episode_id"], missing["end_time_s"] = 201, np.nan
raw = pd.concat([clean_source, duplicate, short, missing], ignore_index=True)
```

遥操作必成功只是本例的生成假设，真实遥操作也可能失败。150 条辅助采集的成功概率是 0.6，其成功率标准误约 `sqrt(0.6×0.4/150)=0.04`；`0.56–0.64` 只是约一个标准差区间，**不是保证范围**。失败期望为 60 条，即**辅助采集的 40%**，或全部 200 条的 30%，不能混用分母。

## 二、清洗损坏记录，不是抹掉失败

```python
duplicate_mask = raw.duplicated("episode_id", keep="first")
finite_time = np.isfinite(raw[["start_time_s", "end_time_s", "sample_period_s"]]).all(axis=1)
valid_duration = np.isclose(raw["end_time_s"] - raw["start_time_s"],
                            raw["num_steps"] * raw["sample_period_s"])
valid = (~duplicate_mask & finite_time & valid_duration
         & raw["num_steps"].ge(5) & raw["sample_period_s"].gt(0))
quarantine = raw.loc[~valid].copy()
clean_df = raw.loc[valid].copy()
assert len(raw) == 203 and len(quarantine) == 3 and len(clean_df) == 200
assert not clean_df.duplicated("episode_id").any()
print("原始/隔离/合格:", len(raw), len(quarantine), len(clean_df))

# 示例按独立 episode 切分；真实数据必须按采集会话/场景分组，防近重复泄漏。
acceptance = clean_df[clean_df["episode_id"] % 5 == 0].copy()
development = clean_df[clean_df["episode_id"] % 5 != 0].copy()
assert set(acceptance.episode_id).isdisjoint(set(development.episode_id))
# acceptance 从此封存，不加入以下复核、训练候选集合。
success_candidates = development[development["success"]].copy()
failure_review = development[~development["success"]].copy()
failure_review["failure_reason"] = "待专家复核"
failure_review["corrected_action_available"] = False
print("开发成功候选/失败待复核/封存验收:",
      len(success_candidates), len(failure_review), len(acceptance))
```

这里三个坏记录确实触发规则；但“少于 5 步”只是示例阈值，真实快速成功也可能很短，所以放入 **quarantine 待检查**，而非无条件永久删除。代码只能发现摘要层问题，不能声称已经检查过图像掉帧、传感器漂移或失败原因。

## 三、真实轨迹还缺哪些检查

| 检查 | 必须记录或验证的内容 |
|---|---|
| 时序对齐 | 相机曝光、状态采样、动作命令及实际执行时间；时钟偏移、容忍窗口、stale 帧；不能仅按文件行号对齐 |
| 单位与坐标 | 米/弧度/秒、动作是绝对值还是增量、相机/基座/末端坐标；内外参与控制接口版本 |
| episode 边界 | reset、成功、失败、人工接管、terminated/truncated；窗口与动作块不能跨 reset |
| 重复与泄漏 | 轨迹 ID、来源会话、近重复视频；同一场景切片不能随机散入训练和验收 |
| 学习目标 | 成功示范可作 BC 候选；失败须纠正动作标签、有效恢复片段，或配套奖励/next state 的合适 RL 目标 |
| 版本与验收 | 固定 schema、数据修订、策略版本；封存验收数据不回流训练，反复调参后另建验收集 |

**为何不直接拼回所有失败动作？** 那可能教会模型重复错误。分桶只告诉我们哪些案例值得复核，不能证明数据增益。要验证飞轮收益，应比较“相同训练预算的成功数据基线”与“加入已纠正失败/恢复数据”的策略，在未参与采集选择和调参的场景上多种子评测，并报告成功率、安全事件与旧能力回退。

## 思考与总结

1. 如果失败来自坏标定，应补专家动作，还是先修正坐标与同步？
2. 如何防止一个长 episode 的近重复帧占据全部 batch？
3. 若根据验收失败不断补采，为什么原验收集必须改叫开发集？
