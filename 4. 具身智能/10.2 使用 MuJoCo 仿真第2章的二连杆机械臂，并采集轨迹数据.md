# 10.2 使用 MuJoCo 仿真第2章的二连杆机械臂，并采集轨迹数据

> **定位**：CPU 仿真选修，需要 Gymnasium、MuJoCo、Pandas、PyArrow；不是 NumPy-only。本次修订未安装这些依赖或实测下文代码。
>
> **目标**：加载 Reacher，理解运动学与动力学的区别，保存带明确时间边界的转移记录。生成的是 **LeRobotDataset 风格的独立 Parquet**，不是完整 LeRobotDataset。

## 一、环境与版本

```bash
pip install "gymnasium[mujoco]" pandas pyarrow
```

本节使用 `Reacher-v5` 默认配置。它与第2章同属平面二连杆结构，但连杆长度、坐标约定、关节范围与驱动参数需读模型确认，不能说物理参数完全一致。默认观测为 **10 维 float64**，动作空间为 **2 维 float32**；旧 `Reacher-v4` 默认 11 维，v5 去掉了末端相对位置中恒定的 z 分量。更换版本要同步检查数据 schema、模型输入和归一化统计，不能说用法与数据完全一致。

```python
import gymnasium as gym
import numpy as np
import mujoco

env = gym.make("Reacher-v5")
print("版本:", gym.__version__, mujoco.__version__)
print("观测空间:", env.observation_space)
print("动作空间:", env.action_space)
obs, _ = env.reset(seed=0)
assert obs.shape == (10,) and obs.dtype == np.float64
assert env.action_space.shape == (2,)
print("实际初始观测:", obs)  # 使用真实打印，不编造 cos/sin 不一致的向量
# 前四项依次是两关节的 cos、sin。
assert np.allclose(obs[:2] ** 2 + obs[2:4] ** 2, 1.0)
print("控制步长秒:", env.unwrapped.dt)
env.close()
```

第2章的 FK 根据关节角算末端位置；这里的动作是经过 actuator 映射的关节控制量，MuJoCo 再积分质量、惯性、阻尼等决定运动。`action∈[-1,1]` 是控制输入范围，不能不看模型的 gear 与 actuator 设置就把它当作任意机器人的 N·m 力矩。也不能把 IK 的角度直接当成这一动作接口的输入。

## 二、采集完整转移，而不是把 done 合并丢掉

以下代码独立创建环境，采集 3 个完整回合，不跨 reset 拼成一条轨迹。使用 `env.unwrapped.dt` 记录**仿真时间**，不冒充真实采集的墙钟时间。

```python
import pandas as pd

env = gym.make("Reacher-v5")
env.action_space.seed(42)
records = []
try:
    dt = float(env.unwrapped.dt)
    for episode_index in range(3):
        obs, _ = env.reset(seed=42 + episode_index)
        frame_index = 0
        while True:
            action = env.action_space.sample()
            next_obs, reward, terminated, truncated, _ = env.step(action)
            records.append({
                "episode_index": episode_index,
                "frame_index": frame_index,
                "timestamp_s": frame_index * dt,
                "next_timestamp_s": (frame_index + 1) * dt,
                "observation.state": obs.tolist(),
                "next_observation.state": next_obs.tolist(),
                "action": action.tolist(),
                "reward": float(reward),
                "terminated": bool(terminated),
                "truncated": bool(truncated),
                "env_id": "Reacher-v5",
                "gymnasium_version": gym.__version__,
                "mujoco_version": mujoco.__version__,
                "schema_version": "toy-transition-v1",
                "state_convention": "cos[2],sin[2],target_xy[m],qvel[rad/s],fingertip_minus_target_xy[m]",
                "action_convention": "MuJoCo actuator ctrl[-1,1]; see Reacher XML gear",
                "coordinate_frame": "Reacher model world xy; not camera coordinates",
            })
            obs = next_obs
            frame_index += 1
            if terminated or truncated:
                break
finally:
    env.close()

df = pd.DataFrame(records)
df.to_parquet("reacher_transitions.parquet", index=False)
loaded = pd.read_parquet("reacher_transitions.parquet")
states = np.asarray(loaded["observation.state"].tolist())
next_states = np.asarray(loaded["next_observation.state"].tolist())
actions = np.asarray(loaded["action"].tolist())
assert states.shape == next_states.shape == (len(loaded), 10)
assert actions.shape == (len(loaded), 2)
assert np.isfinite(states).all() and np.isfinite(next_states).all()
assert not loaded.duplicated(["episode_index", "frame_index"]).any()
for _, episode in loaded.groupby("episode_index", sort=False):
    assert np.array_equal(episode["frame_index"], np.arange(len(episode)))
    assert episode.iloc[-1]["terminated"] or episode.iloc[-1]["truncated"]
print("回读记录数/状态/动作:", len(loaded), states.shape, actions.shape)
```

这里的 transition 已含 next state、reward、terminated/truncated，可作为离线 RL 数据适配的起点；但随机策略数据覆盖、奖励定义、终止语义和归一化仍需审计，**有这些字段不等于拥有可直接训练有效策略的完整离线 RL 数据集**。TimeLimit 是否 bootstrap 要与任务目标一致，见 8.2。

## 三、为什么还不是 LeRobotDataset

仅写一个 Parquet 不能由 LeRobot loader 直接加载。完整格式还有对应版本的 `meta/info.json`、feature schema、统计量、episode/task 元数据、文件路径/索引约定及视频时间对齐等。实际接入应使用 **LeRobot 0.4.4 对应的 Dataset 创建/转换 API**，做一个 episode 的加载、采样、回读验证，再扩大规模。

若增加 `render_mode="rgb_array"`，要给每帧保留对应仿真时间，说明是动作前还是动作后图像；真实机器人还需要相机/关节/动作时钟对齐、单位与坐标标定、掉帧检查。ACT/Diffusion Policy 还需按 episode 构建动作块及末尾 mask，不能因两者都用 Parquet 就说“格式完全一致”。

## 四、思考与总结

- IK 解给角度目标；力矩环境需要闭环控制器把目标转成控制量，瞬移关节不能代表真实电机执行。
- 保留版本、单位、坐标、时间、episode 边界和末观测，比只保存 `(state, action, done)` 更利于复用。
- 本节是轻量 CPU 物理仿真与数据契约示例，不是真机采集，也不提供未运行的精确日志。
