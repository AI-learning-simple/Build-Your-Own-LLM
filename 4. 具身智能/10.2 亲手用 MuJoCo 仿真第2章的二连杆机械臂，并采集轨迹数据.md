# 二、加载 MuJoCo 内置的 Reacher 环境：一个真实的二连杆机械臂

Gymnasium 内置的 `Reacher` 环境，本体正是一个平面二连杆机械臂——**和第2章我们亲手推导正逆运动学时用的模型完全一致**，只不过这一次，关节的力矩、惯性、阻尼、碰撞检测，全部由 MuJoCo 物理引擎真实计算，而不是我们自己写的三角函数公式：

```python
import gymnasium as gym
import numpy as np

env = gym.make("Reacher-v4")   # 如果这个版本号在你安装的 gymnasium 里不存在，
                                # 可以用 gymnasium.pprint_registry() 查看当前实际可用的 Reacher 版本号，用法完全一致

print("观测空间:", env.observation_space)
print("动作空间:", env.action_space)

observation, info = env.reset(seed=0)
print("\n初始观测:", observation)
```

**预期输出**：`Reacher` 的观测是一个11维向量（包含两个关节角度的 cos/sin、关节角速度、目标位置、末端到目标的向量等），动作是一个2维连续向量（对应两个关节各自的力矩，值域通常是 `[-1, 1]`）：

```
观测空间: Box(-inf, inf, (11,), float32)
动作空间: Box(-1.0, 1.0, (2,), float32)

初始观测: [ 0.985 -0.174  0.932  0.362 -0.043  0.021 -0.123  0.089  0.021 -0.045  0.012]
```

（具体的初始观测数值取决于随机种子和 MuJoCo 内部的初始化，但维度、取值范围是固定的。）

# 三、对比：与第2章手写的正逆运动学模型有何不同

第2章的二连杆机械臂，我们直接用 `x = l1·cos(θ1) + l2·cos(θ1+θ2)` 这样的解析公式计算末端位置——这是一个**理想化的运动学模型**，完全没有考虑质量、惯性、关节摩擦、驱动力矩的限制。而 MuJoCo 里的 `Reacher`，每一个关节的运动，都是**动力学方程**（力矩如何转化为角加速度、角加速度如何积分成角速度和角度）真实求解出来的结果：

```python
for step in range(20):
    action = env.action_space.sample()   # 随机力矩
    observation, reward, terminated, truncated, info = env.step(action)
    if step % 5 == 0:
        print(f"step={step}: reward={reward:.3f}")
env.close()
```

**这正是"运动学（Kinematics）"和"动力学（Dynamics）"的区别**：第2章只回答了"关节角度和末端位置之间的几何关系"，而 MuJoCo 额外回答了"多大的力矩，经过多长时间，才能让关节转到那个角度"——后者才是真实机器人控制必须面对的完整物理问题，也是第11.1节将会展开的控制论例子里"未知动态系数 m"这类参数真正的物理来源。

# 四、采集交互轨迹，并保存为 LeRobotDataset 风格的格式

复用第10章"数据集"一节介绍的设计原则——**数值数据用 Parquet 存储**（`Reacher` 没有相机图像观测，所以省略视频部分；如果换成有图像观测的 MuJoCo 环境，比如 `gym.make(..., render_mode="rgb_array")`，思路完全一致，只是多了一步用 `imageio` 把每帧画面编码成 MP4）：

```python
import pandas as pd

env = gym.make("Reacher-v4")
observation, info = env.reset(seed=42)

records = []
for t in range(50):
    action = env.action_space.sample()
    next_observation, reward, terminated, truncated, info = env.step(action)

    records.append({
        "episode_index": 0,
        "frame_index": t,
        "observation.state": observation.tolist(),
        "action": action.tolist(),
        "reward": float(reward),
        "done": bool(terminated or truncated),
    })

    observation = next_observation
    if terminated or truncated:
        observation, info = env.reset()

env.close()

df = pd.DataFrame(records)
df.to_parquet("reacher_episode_000000.parquet")
print(f"已采集并保存 {len(df)} 步交互数据到 reacher_episode_000000.parquet")

# 还原验证
df_loaded = pd.read_parquet("reacher_episode_000000.parquet")
states = np.array(df_loaded["observation.state"].tolist())
actions = np.array(df_loaded["action"].tolist())
print("状态矩阵形状:", states.shape)   # 预期 (50, 11)
print("动作矩阵形状:", actions.shape)  # 预期 (50, 2)
```

**预期输出**：

```
已采集并保存 50 步交互数据到 reacher_episode_000000.parquet
状态矩阵形状: (50, 11)
动作矩阵形状: (50, 2)
```

这份用真实 MuJoCo 机械臂采集到的数据，其状态、动作维度（11维状态、2维动作）和存储格式，与第6章讨论过的 ACT/Diffusion Policy 训练所需要的数据格式完全一致——**如果把这里的随机策略换成一个真正训练好的策略，采集到的数据就可以直接用来做模仿学习或离线强化学习。**

# 五、思考题

`Reacher` 的动作空间是关节力矩（Torque Control），而第2章的逆运动学直接输出的是关节角度（Position Control）。可以思考一下：如果已经有第2章那样的逆运动学解，能不能直接把算出来的关节角度"设置"给 MuJoCo 里的机械臂，跳过力矩控制这一层？这样做和真实机器人的实际工作方式相比，少考虑了什么？（提示：真实电机不能"瞬间"把关节转到指定角度，这中间需要一个第11.1节将会讨论的闭环控制过程。）
