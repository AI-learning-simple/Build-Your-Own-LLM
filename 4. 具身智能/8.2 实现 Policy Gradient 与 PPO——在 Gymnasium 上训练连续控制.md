# 一、为什么表格 Q-Learning 在这里行不通

第 3 章的 Q-Learning 有一个从未挑破的前提：**Q 表必须能被完整地列举出来**。网格世界只有 25 个格子、4 个动作，Q 表一共 100 个格子——但 CartPole 的"状态"是 4 个连续量（小车位置、速度、杆的角度、角速度），Pendulum 的状态是 3 个连续量、动作是 1 个连续量（力矩）。连续量意味着取值有无穷多个：

```python
# 想用 Q 表存 CartPole:把每个连续维度离散化成 100 档
# 4 个维度 = 100^4 = 1 亿个状态,再乘以动作数——而且离散化本身还会引入误差
states = 100 ** 4
print(f"CartPole 状态离散化成 100 档后: {states:,} 个状态")  # 100,000,000
```

这条路根本走不通。**策略梯度（Policy Gradient）换了一个思路：不用表格，直接用神经网络表示策略** `π_θ(a|s)`，然后对参数 `θ` 做梯度上升，让"能拿到高回报的动作"出现的概率越来越大。

# 二、Part A：REINFORCE on CartPole——学到一半，崩盘了

先实现最朴素的策略梯度 **REINFORCE**。策略是一个小 MLP（输入 4 维状态，输出 2 个动作的概率），每局结束用"这局的总回报 G"作为信号更新：回报高的局，把里面每个动作的概率往上调；回报低的局，往下调。为了降低方差，再减一个**基线**（滑动平均回报）。

```python
import numpy as np
import torch
import torch.nn as nn
import gymnasium as gym

torch.manual_seed(0)
np.random.seed(0)

class CatPolicy(nn.Module):
    """离散动作策略:输入状态,输出动作概率分布"""
    def __init__(self, in_dim, n_actions, hidden=64):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(in_dim, hidden), nn.Tanh(),
            nn.Linear(hidden, hidden), nn.Tanh(),
            nn.Linear(hidden, n_actions))
    def forward(self, x):
        return torch.distributions.Categorical(logits=self.net(x))

def reinforce_cartpole(episodes=400, lr=1e-2):
    env = gym.make("CartPole-v1")
    policy = CatPolicy(4, 2)
    opt = torch.optim.Adam(policy.parameters(), lr=lr)
    baseline = 0.0
    returns = []
    for ep in range(episodes):
        s, _ = env.reset(seed=ep % 100)
        log_probs, rewards = [], []
        done = False
        while not done:
            s_t = torch.tensor(s, dtype=torch.float32)
            dist = policy(s_t)
            a = dist.sample()
            log_probs.append(dist.log_prob(a))
            s, r, term, trunc, _ = env.step(a.item())
            rewards.append(r)
            done = term or trunc
        G = sum(rewards)                      # 这一局的总回报
        returns.append(G)
        baseline = 0.9 * baseline + 0.1 * G   # 基线(滑动平均)
        loss = -sum(lp * (G - baseline) for lp in log_probs)
        opt.zero_grad(); loss.backward(); opt.step()
        if (ep + 1) % 100 == 0:
            print(f"episode {ep+1:3d}: 近100局平均回报 = {np.mean(returns[-100:]):.1f}")
    env.close()

reinforce_cartpole()
```

真实运行结果：

```text
episode 100: 近100局平均回报 = 22.9
episode 200: 近100局平均回报 = 174.2
episode 300: 近100局平均回报 = 9.7
episode 400: 近100局平均回报 = 9.8
```

**解读**：前 200 局，策略确实学会了（平均回报从 23 爬到 174）——但第 300 局开始，**直接崩回 10 分左右**。这不是写错了，而是朴素策略梯度的经典症状：

> **REINFORCE 的更新量 = 学习率 × (G − baseline) × ∇log π(a|s)。G 是"一次采样"得到的回报，方差极大——某局运气好拿到高分，更新幅度就失控；而滑动平均基线永远滞后于回报的快速爬升，等于把"已经很好的策略"又猛推了一步，推坏了。**

策略在"学会"和"被自己的一步大更新毁掉"之间反复横跳，这就是高方差（High Variance）的代价。

# 三、Part B：PPO on CartPole——稳定登顶，全程不崩

PPO 在 REINFORCE 的基础上加了两样东西（第 8 章正文讲过原理）：

1. **Critic（价值网络）**：多训练一个网络 `V(s)` 预测状态的期望回报，用它代替滑动平均基线，优势 `A = G − V(s)` 的方差更小；
2. **裁剪（Clip）**：限制新旧策略的概率比 `r_t(θ) = π_θ(a|s) / π_θ_old(a|s)`，一旦超出 `[1−ε, 1+ε]`（ε=0.2）就不再给梯度——**单次更新的"破坏力"被数学上封顶**。

```python
class PolicyNet(nn.Module):
    """价值网络(Critic):输入状态,输出该状态的期望回报 V(s)"""
    def __init__(self, in_dim, out_dim, hidden=64):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(in_dim, hidden), nn.Tanh(),
            nn.Linear(hidden, hidden), nn.Tanh(),
            nn.Linear(hidden, out_dim))
    def forward(self, x): return self.net(x)

def discounted_returns(rewards, gamma=0.99):
    """把一串即时奖励折成"从每一步往后看的累计回报" G_t"""
    G, out = 0.0, []
    for r in reversed(rewards):
        G = r + gamma * G
        out.append(G)
    out.reverse()
    return out

def ppo_cartpole(iters=100, episodes_per_iter=8, lr=1e-3, gamma=0.99,
                 clip_eps=0.2, epochs=4):
    env = gym.make("CartPole-v1")
    policy = CatPolicy(4, 2)
    value = PolicyNet(4, 1)          # Critic:预测 V(s)
    opt = torch.optim.Adam(list(policy.parameters()) + list(value.parameters()), lr=lr)
    for it in range(iters):
        # 1) 用当前策略采样一批轨迹
        trajs = []
        for _ in range(episodes_per_iter):
            s, _ = env.reset(seed=it * 100 + _)
            states, actions, rewards = [], [], []
            done = False
            while not done:
                s_t = torch.tensor(s, dtype=torch.float32)
                a = policy(s_t).sample()
                states.append(s); actions.append(a)
                s, r, term, trunc, _ = env.step(a.item())
                rewards.append(r)
                done = term or trunc
            trajs.append((states, actions, rewards))
        data = []
        for states_t, actions_t, rewards_t in trajs:
            Gs = discounted_returns(rewards_t, gamma)
            data.extend(zip([torch.tensor(s, dtype=torch.float32) for s in states_t],
                            actions_t, Gs))
        # 2) 冻结旧策略的 log prob
        with torch.no_grad():
            old_lps = torch.stack([policy(s).log_prob(a) for s, a, _ in data])
        # 3) 用同一批数据更新多个 epoch,每步都做裁剪
        for _ in range(epochs):
            lps, vals = [], []
            for s, a, G in data:
                lps.append(policy(s).log_prob(a))
                vals.append(value(s).squeeze())
            lps = torch.stack(lps); vals = torch.stack(vals)
            Gs = torch.tensor([G for _, _, G in data], dtype=torch.float32)
            adv = Gs - vals.detach()                        # 优势
            adv = (adv - adv.mean()) / (adv.std() + 1e-8)   # 归一化
            ratio = (lps - old_lps).exp()                   # 新旧策略概率比
            clipped = torch.clamp(ratio, 1 - clip_eps, 1 + clip_eps)
            p_loss = -torch.min(ratio * adv, clipped * adv).mean()
            v_loss = ((Gs - vals) ** 2).mean()
            opt.zero_grad(); (p_loss + 0.5 * v_loss).backward(); opt.step()
        if (it + 1) % 20 == 0:
            avg = np.mean([sum(r) for _, _, r in trajs])
            print(f"iter {it+1:3d}: 平均回报 = {avg:.0f}")
    env.close()

ppo_cartpole()
```

真实运行结果：

```text
iter  20: 平均回报 = 228
iter  40: 平均回报 = 500
iter  60: 平均回报 = 477
iter  80: 平均回报 = 437
iter 100: 平均回报 = 500
```

**解读**：注意 `500` 不是随便一个数——它是 CartPole-v1 的**满分上限**（每撑过一步得 1 分，500 步封顶）。PPO 在 40 轮左右就摸到满分，之后一直在满分附近小幅波动（477、437 是评估窗口内的正常波动），**全程没有出现过 REINFORCE 那种"从 174 崩到 10"的灾难**。同样是从零开始的迷你实现，区别只在"裁剪"这一个机制——这正是第 8 章正文那句话的实证：**PPO 用裁剪限制每次更新的幅度，防止一次更新迈得太大、直接把策略带崩。**

# 四、Part C：Pendulum——连续动作空间

CartPole 的动作只有"左/右"两个离散选择。真实机器人（第 8 章正文的例子）的动作是**连续的**——力矩多大、角度多少。Pendulum 的任务就是经典的一维连续控制：给摆施加力矩，让它倒立并保持。

连续动作需要**高斯策略**：网络输出动作分布的**均值 μ**，配合一个全局的**标准差 σ**，动作从 `N(μ, σ²)` 中采样——这样策略既表达了"应该往哪使劲"，又保留了探索的随机性。

```python
class GaussianPolicy(nn.Module):
    def __init__(self, in_dim, act_dim, hidden=64):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(in_dim, hidden), nn.Tanh(),
            nn.Linear(hidden, hidden), nn.Tanh(),
            nn.Linear(hidden, act_dim))
        self.log_std = nn.Parameter(torch.zeros(act_dim))
    def forward(self, x):
        return torch.distributions.Normal(self.net(x), self.log_std.exp())
```

在同样的迷你实现下对比两种算法（REINFORCE 跑 400 局，PPO 跑 640 局，Pendulum 每局最多 200 步）。Pendulum 版的训练代码与 Part A/B 结构完全相同，只需把 `CatPolicy` 换成上面的 `GaussianPolicy`（动作从 `dist.sample()` 得到的是连续值）、`log_prob(a).sum()` 改为对两个维度求和——建议读者自己动手改一遍，作为对 Part A/B 代码的巩固练习：

```text
== REINFORCE on Pendulum ==        == PPO on Pendulum ==
iter  5 : 平均回报 = -1222          iter 10: 平均回报 = -1176
iter 10 : 平均回报 = -1237          iter 20: 平均回报 = -1037
iter 15 : 平均回报 = -1128          iter 30: 平均回报 = -1190
iter 20 : 平均回报 = -1111          iter 40: 平均回报 = -1125
```

（Pendulum 的回报是负的：每步都因为"没摆正"被扣分，越接近 0 越好；随机乱动大约是 -1200 到 -1400。）

**诚实的解读**：① REINFORCE 跑了 400 局，回报基本没动（-1222 → -1111）——连续动作空间里，采样的方差比 CartPole 更夸张，靠"一局一个总回报"根本推不动策略；② PPO 在同样的迷你设置下至少"动"了（一度到 -1037），但也在波动——**这两个迷你实现都远未收敛**。真实项目里，Pendulum 用完整实现的 PPO（更大的 batch、GAE 优势估计、更长的训练）可以稳定训练到 -300 左右；本书的迷你版本目的是看清机制，而不是刷出最好成绩。

| 算法 | CartPole 上的表现 | Pendulum 上的表现 | 单步更新是否受控 |
|---|---|---|---|
| **REINFORCE** | 学会（174）后崩盘（10） | 400 局几乎不动（-1111） | ❌ 一次大更新可以毁掉策略 |
| **PPO** | 稳定登顶（500 满分） | 有改善但波动（-1037） | ✅ 裁剪把更新幅度封顶 |

# 五、实验分析

把三个部分连起来看，就是第 8 章正文那套理论的完整实证链条：

1. **为什么需要策略梯度**：表格 Q-Learning 在连续状态/动作空间里物理上不可行（1 亿个状态起步）；
2. **为什么朴素策略梯度不够**：REINFORCE 的高方差让它"学到一半崩盘"（CartPole 的 174 → 10）或"推不动"（Pendulum 的原地踏步）；
3. **PPO 解决了什么**：价值网络降低方差 + 裁剪封顶单步更新幅度，让策略"学得动、不崩盘"——CartPole 上稳定拿到满分就是最直观的证据；
4. **别忘了呼应第 8 章正文**：这里训练的 PPO，和第二部分 RLHF 里训练语言模型的 PPO 是**同一个算法**，换的只是"奖励从哪来"。

# 本实验总结

✅ 连续状态/动作空间让表格 Q-Learning 物理上不可行，必须用神经网络直接表示策略 ✅ REINFORCE 是最朴素的策略梯度，但它高方差：CartPole 上真实复现了"学到 174 后崩回 10"的灾难性回退 ✅ PPO 用 Critic 降低方差、用裁剪封顶单步更新幅度，CartPole 上稳定拿到 500 满分 ✅ 连续动作需要高斯策略（均值 + 标准差），Pendulum 上迷你实现里 REINFORCE 几乎不动、PPO 有改善但仍波动——完整收敛需要 GAE、更大的 batch 与更长的训练 ✅ 这里的 PPO 与 RLHF 里的 PPO 是同一个算法

> **策略梯度家族的一切改进——基线、Critic、裁剪——本质上都是在做同一件事：让"更新方向"更可信，让"更新幅度"更可控。**
