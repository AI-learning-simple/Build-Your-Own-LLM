# 二、任务设定：2D 导航到原点

我们设计一个足够简单、但能完整暴露分布偏移问题的任务：一个点状"机器人"处在二维平面上的位置 `p = (x, y)`，目标是走到原点 `(0, 0)`。**专家策略**是一个已知的最优解——始终朝着原点方向、以固定速度前进的单位向量：

```python
import numpy as np

np.random.seed(42)

def expert_action(p):
    """专家策略：返回指向原点的单位向量"""
    p = np.atleast_2d(p)
    norm = np.linalg.norm(p, axis=1, keepdims=True)
    norm = np.maximum(norm, 1e-6)
    return -p / norm
```

**关键的实验设计**：为了让分布偏移问题真实地暴露出来，专家演示数据**只采集自第一象限**（`x>0, y>0`）——这在现实中非常常见：人类采集示范数据时，往往只覆盖了任务的"正常"情况，很难穷举所有可能出现的异常状态。

```python
def sample_training_data(n=500):
    radius = np.random.uniform(1.0, 3.0, size=n)
    angle = np.random.uniform(0, np.pi / 2, size=n)   # 仅第一象限：0° ~ 90°
    px, py = radius * np.cos(angle), radius * np.sin(angle)
    P = np.stack([px, py], axis=1)
    A = expert_action(P)
    return P, A

P_train, A_train = sample_training_data(500)
```

# 三、用 NumPy 手写一个两层策略网络

结构：`输入(2) → 隐藏层(32, tanh) → 输出(2, tanh)`。输出用 `tanh` 是因为专家动作是单位向量，各分量取值范围是 `[-1, 1]`，`tanh` 的值域正好匹配。

```python
def init_model(hidden=32, seed=0):
    rng = np.random.default_rng(seed)
    return {
        "W1": rng.normal(0, 0.3, size=(2, hidden)),
        "b1": np.zeros(hidden),
        "W2": rng.normal(0, 0.3, size=(hidden, 2)),
        "b2": np.zeros(2),
    }

def forward(model, P):
    z1 = P @ model["W1"] + model["b1"]
    h1 = np.tanh(z1)
    z2 = h1 @ model["W2"] + model["b2"]
    pred = np.tanh(z2)
    return pred, h1

def train_bc(model, P, A, epochs=2000, lr=0.05):
    N = P.shape[0]
    for epoch in range(epochs):
        pred, h1 = forward(model, P)
        loss = np.mean((pred - A) ** 2)

        # 反向传播（手动求导，链式法则）
        d_pred = 2 * (pred - A) / N
        d_z2 = d_pred * (1 - pred ** 2)                 # tanh 导数
        d_W2 = h1.T @ d_z2
        d_b2 = d_z2.sum(axis=0)
        d_h1 = d_z2 @ model["W2"].T
        d_z1 = d_h1 * (1 - h1 ** 2)
        d_W1 = P.T @ d_z1
        d_b1 = d_z1.sum(axis=0)

        for name, grad in [("W1", d_W1), ("b1", d_b1), ("W2", d_W2), ("b2", d_b2)]:
            model[name] -= lr * grad

        if epoch % 500 == 0:
            print(f"epoch {epoch:4d}  loss={loss:.4f}")
    return model

model = init_model()
model = train_bc(model, P_train, A_train)
```

**预期趋势**：这是一个平滑、低维、样本充足的回归问题（只是学习"指向原点的方向"），梯度下降应该能稳定收敛。典型的 loss 曲线大致是：

```
epoch    0  loss=0.6831
epoch  500  loss=0.0186
epoch 1000  loss=0.0052
epoch 1500  loss=0.0029
epoch 1999  loss=0.0021
```

（具体数值受随机种子、学习率影响会有出入，但应该呈现"快速下降后趋于平稳、且最终 loss 很小"的趋势——说明网络已经在第一象限内学会了"专家策略"这个函数。）

# 四、验证：训练分布内表现完美，分布外开始失控

```python
def bc_policy(model, p):
    pred, _ = forward(model, p.reshape(1, -1))
    direction = pred[0]
    norm = np.linalg.norm(direction)
    return direction / max(norm, 1e-6)   # 归一化成单位方向，保证每步移动距离一致

def rollout(model, start, steps=20, step_size=0.3):
    p = np.array(start, dtype=float)
    trajectory = [p.copy()]
    for _ in range(steps):
        a = bc_policy(model, p)
        p = p + step_size * a
        trajectory.append(p.copy())
    return np.array(trajectory)

# 分布内起点（第一象限，训练时见过这一类状态）
traj_in = rollout(model, start=(2.0, 2.0))
print("分布内起点 (2,2) 最终位置:", traj_in[-1], " 到原点距离:", np.linalg.norm(traj_in[-1]))

# 分布外起点（第三象限，专家数据从未覆盖过这一片区域）
traj_out = rollout(model, start=(-2.0, -2.0))
print("分布外起点 (-2,-2) 最终位置:", traj_out[-1], " 到原点距离:", np.linalg.norm(traj_out[-1]))
```

**预期结果**：

- **分布内起点 `(2, 2)`**：网络在这一片区域被充分训练过，20步后应该已经稳定收敛到原点附近（到原点距离应远小于1，通常在 `step_size` 量级左右，即 0.3 上下浮动）。
- **分布外起点 `(-2, -2)`**：网络在第三象限从未见过任何训练样本，`tanh` 网络在这个区域的输出完全是"外推"结果，没有任何理论保证它会指向正确方向。实际运行时可能看到轨迹在错误方向上徘徊、走出弯曲甚至发散的路径，20步后到原点的距离往往远大于分布内的情况，**任务大概率无法在有限步数内成功完成**——这正是4.3节讲的分布偏移问题在代码层面的真实体现：**策略从未犯错时，看起来完美；一旦所处状态落在训练分布之外，行为就变得不可预测。**

# 五、用 DAgger 修复：把策略自己走出来的"陌生状态"也纳入训练

```python
def collect_visited_states(model, start_points, steps=20, step_size=0.3):
    visited = []
    for start in start_points:
        p = np.array(start, dtype=float)
        for _ in range(steps):
            visited.append(p.copy())
            a = bc_policy(model, p)
            p = p + step_size * a
    return np.array(visited)

# 覆盖四个象限的起点，模拟"策略在真实部署中可能走到的各种状态"
probe_starts = [(2, 2), (-2, 2), (-2, -2), (2, -2), (3, -1), (-1, 3), (-3, 1), (1, -3)]

for dagger_round in range(3):
    visited_states = collect_visited_states(model, probe_starts)
    expert_labels = expert_action(visited_states)          # 对每一个访问到的状态，请"专家"给出正确动作
    P_train = np.concatenate([P_train, visited_states], axis=0)
    A_train = np.concatenate([A_train, expert_labels], axis=0)
    model = train_bc(model, P_train, A_train, epochs=1000, lr=0.05)
    print(f"--- DAgger 第 {dagger_round + 1} 轮，训练集已扩充到 {len(P_train)} 条样本 ---")

# 重新测试分布外起点
traj_out_after_dagger = rollout(model, start=(-2.0, -2.0))
print("DAgger 之后，分布外起点 (-2,-2) 最终位置:", traj_out_after_dagger[-1],
      " 到原点距离:", np.linalg.norm(traj_out_after_dagger[-1]))
```

**预期结果**：因为 `expert_action()` 是一个已知的解析函数（可以对任意状态给出正确答案，这里扮演"随时待命的人类专家"），DAgger 每一轮都能把策略自己暴露出来的所有陌生状态，用正确的标签重新纳入训练集。三轮迭代之后，训练数据已经覆盖了全部四个象限，`(-2, -2)` 这个原本的分布外起点，现在应该也能像分布内起点一样，稳定地收敛到原点附近——**分布偏移问题被彻底修复，且修复的方式没有改变任何网络结构或损失函数，只是改变了"训练数据从哪里来"。**

# 六、思考题

DAgger 这里之所以能工作，是因为我们有一个"随叫随到、对任意状态都能给出正确答案"的解析专家函数 `expert_action()`。但在真实机器人场景里，"专家"往往是一个真人操作员——每多问一次"这个状态该怎么办"，都意味着要占用一次真人的时间成本。可以思考一下：如果专家的反馈次数是有限的、宝贵的，应该优先针对哪些状态去问专家，才能用最少的标注成本，最大程度地修复分布偏移问题？
