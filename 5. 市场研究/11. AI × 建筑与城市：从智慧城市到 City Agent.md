# 11. AI × 建筑与城市：从智慧城市到城市智能体（City Agent）

如果说上一章讨论的是：

> **能源如何被 Agent 管理。**

那么这一章继续向上抽象：

> **整个城市能不能成为一个 Agent？**

城市比任何一个单独的工业系统都复杂。

它同时包含：

```text
人
建筑
道路
车辆
能源
水
垃圾
通信
商业
医疗
教育
公共安全
```

这些系统过去由不同部门、不同软件、不同基础设施分别管理。

而 Agent 的出现，让我们第一次有机会尝试：

> **用统一的目标、状态和行动框架，把这些系统连接起来。**

---

# 11.1 什么是 City Agent

不要把 City Agent 理解成：

> 一个“会聊天的城市助手”。

它真正应该做的是：

```text
Observe
 ↓
Understand
 ↓
Plan
 ↓
Coordinate
 ↓
Execute
 ↓
Monitor
```

也就是说：

> **City Agent 是一个城市级任务协调系统。**

---

# 11.2 一个城市其实已经是一个巨大的 Agent

如果从 Agent 的角度观察城市：

```text
城市
 ↓
感知
 ↓
状态
 ↓
决策
 ↓
执行
 ↓
反馈
```

其实已经非常接近 Agent。

只不过过去：

```text
感知 → 摄像头
决策 → 政府部门
执行 → 基础设施
反馈 → 数据平台
```

彼此之间没有真正统一起来。

---

# 11.6 城市世界模型

```text
                 City World Model
                        │
       ┌────────────────┼────────────────┐
       ↓                ↓                ↓

```

> **State Fusion。**

---

# 11.8 城市 Agent 不应该直接相信所有数据

例如：

```text

```

怎么办？

Agent 需要判断：

```text

```

然后形成：

> 当前最可能的城市状态。

这和自动驾驶中的 Sensor Fusion 非常类似。

---

# 11.9 City Agent 的第二层：Intent

城市管理最终不是为了：

> 让 AI 看懂城市。

而是为了：

> 完成城市目标。

例如：

```text
降低拥堵
降低能源消耗
提高公共安全
减少污染
缩短急救时间
```

这些就是：

> City Intent。

---

# 11.10 城市目标可能相互冲突

例如：

```text
减少交通拥堵
```

可以通过：

> 提高道路通行能力。

但这可能导致：

```text
汽车更多
能源消耗增加
污染增加
```

因此城市 Agent 不能只有一个指标。

它实际上需要进行：

> **Multi-objective Optimization。**

---

# 11.11 城市 Agent 的目标函数

可以抽象成：

```text
City Utility =
交通效率
+
能源效率
+
安全
+
经济
+
环境
+
居民体验
```

但这些指标之间并不是简单相加。

例如：

```text

成本 ↑

安全 ↑
自由度 ↓

环保 ↑
短期经济成本 ↑
```

因此城市 Agent 必须处理：

> Trade-off。

# 11.51 行业实践：城市大脑与数字孪生的十年

城市级的 Agent 是本书所有行业里最超前的一章，所以更需要诚实地区分：哪些已经发生，哪些仍是设计。

已经发生的是“感知与局部优化”。代表案例是杭州城市大脑：从 2016 年起用 AI 优化交通信号配时，试点区域的通行效率有可感知的改善；新加坡的 Virtual Singapore 项目则建了整座城市的数字孪生，用于规划决策的推演。到 2020 年代中期，全球数百个城市部署了某种形式的“城市 AI 中枢”。

但这些都还不是本章描述的 City Agent：

```text
现状：
摄像头 + 数据平台 + 人工决策
（看得见，部分环节自动优化）

City Agent 设想：
城市目标 → Agent 分解 → 跨部门执行 → 反馈闭环
（能行动，且为结果负责）
```

差距在哪里？在于城市的“执行器”是分散的：信号灯、公交调度、市政施工分属不同部门，任何一个 Agent 都无法跨部门调用它们。这不是技术问题，是治理问题——一座城市愿意把多少决策权交给一个系统？

受影响的人群（以现状推演）：

* 交通与市政调度人员：最先与 AI 协同的岗位，异常处置效率决定体验；
* 城市规划师：数字孪生让“方案推演”代替“方案争论”；
* 市民：服务响应变快，但城市监控与数据使用的边界需要新的公共讨论。

城市这一章的启示是反向的：它提醒我们，Agent 化的瓶颈通常不是模型能力，而是组织与权限——城市是所有行业里权限最碎片化的，所以它可能是最后完成的，尽管它可能是最早开始的。
