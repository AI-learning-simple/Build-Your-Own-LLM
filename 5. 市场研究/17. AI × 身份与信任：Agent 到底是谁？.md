# 17. AI × 身份与信任：Agent 到底是谁？

> **研究更新日：2026-11-25。** 规范以本次访问版本为准：MCP 授权页标注 2026-07-28，A2A 最新发布版标注 1.0.0。实现时必须固定实际版本，不能依赖会变化的 `latest`。

## 17.1 一个名字不能回答身份问题

当某个服务声称“我是采购 Agent”，至少要分别确认：

- 它运行在哪个经过验证的服务端点？
- 谁部署、维护并承担服务责任？
- 当前代表哪个用户或组织？
- 这次任务允许读取和修改哪些资源？
- 授权何时到期、如何撤销？
- 出错后由谁响应，能提供什么证据？

Agent 的显示名称、模型名称和运行实例不是同一个概念。相同应用也可能为多个租户运行，不能只按一个全局 API Key 区分所有权限。

## 17.2 身份、授权与信任必须分开

| 概念 | 回答的问题 | 常见误解 |
|---|---|---|
| 身份认证 | 请求来自谁 | 登录成功就能做任何操作 |
| 授权 | 对这个资源允许做什么 | 有令牌就代表用户同意付款 |
| 委托 | 本次代表谁、允许转交到哪里 | 可以把原用户凭据交给所有下游 |
| 能力声明 | 服务声称会做什么 | 声明本身证明效果与可靠性 |
| 业务信任 | 是否满足履约、质量和责任要求 | 有签名就代表内容真实或服务可靠 |
| 审计 | 当时发生了什么 | 模型事后解释就是操作记录 |

传统 IAM 已经有服务身份、角色、委托、令牌交换等机制。Agent 带来的挑战是动态工具选择和长任务让这些机制需要更细粒度地组合，不是所有身份技术都必须推倒重来。

## 17.3 MCP：授权规范的准确范围

本次读取的 MCP 授权规范说明：[1]

- 授权机制本身是可选的；支持授权的 HTTP 实现应遵循相应规范。
- 授权服务器需要实现 OAuth 2.1 相关要求；OAuth 2.1 在该规范引用中仍是草案，不能写成已发布 RFC。
- MCP 服务器作为资源服务器，提供 Protected Resource Metadata，客户端据此发现授权服务器。
- 资源服务器必须验证访问令牌确实为自己这个目标受众签发。
- 不允许将不适用于该服务器的令牌直接接受并向下游透传。
- `stdio` 不应套用同一 HTTP OAuth 流程，凭据可来自运行环境。

这并不意味着所有 MCP 工具都没有长期密钥，也不意味着业务参数校验、支付审批和数据权限已经自动完成。具体部署仍要设计凭据存储、轮换和最小权限。

## 17.4 A2A Agent Card：服务名片，而非信用证明

A2A 1.0.0 的规范定义 Agent Card，用于描述服务、接口、能力、技能及认证要求，并提供签名等相关结构。[2]

签名验证可以帮助确认内容完整性和签名者，但还需要可信密钥来源、端点校验和业务尽调。不能因为名片写着“某企业的 Agent”就承认其代表权。

认证后的任务和产物也必须按租户、用户与授权范围隔离。能够获取一张 Agent Card，不等于能够读取该服务处理的全部任务。

## 17.5 一个更清楚的委托模型

以下为工程建议，不是新增通用标准。每次任务应能关联：

1. **委托人**：谁提出并拥有这个任务。
2. **执行服务**：哪个应用、版本和实例处理。
3. **目标资源**：哪些文档、账户、设备或对象。
4. **允许动作**：只读、创建草稿、修改、提交等分别授权。
5. **约束**：预算、数量、时间、地域或其他适用条件。
6. **审批证据**：批准了哪些具体参数，而不是一份模糊目标。
7. **结果回执**：实际发生的业务操作及状态。

下游调用应使用适当的独立授权或受控凭据机制，不把高权限秘密暴露给模型。将 API Key 放进提示词，不会因为加入“请保密”而变安全。

## 17.6 信任还要覆盖输入和输出

外部网页、文件和工具返回内容都是数据，不能自动升级成操作指令。否则攻击者可能通过普通业务材料改变 Agent 的行为。

防护应包括明确的数据与指令边界、受控工具清单、参数校验、最小权限，以及对敏感操作的独立批准。模型自检可以辅助发现异常，但不是唯一安全屏障。

日志也要遵循数据最小化。可以记录操作摘要、资源标识、版本和审批，不必永久保存全部敏感材料，更不应把凭据写入 Trace。

## 17.7 商业机会与验收

企业会需要 Agent 身份管理、授权网关、连接器治理和审计工具，但这些能力也可能被现有身份与云平台吸收。不能用注册 Agent 总数直接估算独立身份产品的市场收入。

采购时应验证：越权是否在服务端阻断、撤销多久生效、租户是否隔离、下游权限是否收窄、审批能否绑定实际参数、审计是否完整，以及故障时是否默认拒绝危险操作。

**本章判断：**有价值的产品不是再发一张“Agent 身份证”，而是把既有身份、任务委托和真实业务动作可靠关联起来。

> “知道它是谁”只是起点；更重要的是，知道它这一次代表谁、能做什么，以及实际做了什么。
