# 6. AI × 金融：从智能分析到金融 Agent

> **研究更新日：2026-11-25。** 本章侧重金融机构内部知识、客户服务、研究与运营；投顾和保险见第 12 章。内容是产业与工程分析，不构成投资建议。

## 6.1 金融的数字化不等于可以自由自动化

金融业务包含信息收集、判断、授权、执行与记录。大量信息已数字化，但一份文档摘要、一次客户答复和一笔资金操作的后果并不相同。

传统系统中的规则引擎、统计模型和交易系统已经承担大量自动化工作。新一代大模型主要补充非结构化材料理解、自然语言交互和跨工具协调，不应把全部金融自动化算成 LLM Agent 的新增市场。

## 6.2 从低副作用任务切入

| 工作流 | AI 的适当角色 | 结果如何验收 | 关键边界 |
|---|---|---|---|
| 内部知识检索 | 查找条款、产品资料和操作手册 | 引用是否正确、版本是否有效 | 按用户权限检索 |
| 研究材料处理 | 提取财务字段、比较披露 | 与原始材料和计算工具核对 | 区分事实与判断 |
| 客户服务 | 回答标准问题、收集材料、转交 | 问题解决、重开、投诉 | 不编造收费或承诺 |
| 对账与运营 | 识别不一致、解释异常、建工单 | 系统余额、业务回执 | 写操作受控 |
| 交易相关辅助 | 提供信息、生成待审批方案 | 独立规则和责任人员复核 | 不等于获准自主交易 |

一个能分析表格的 Agent，不应因此获得账户全权限。权限应根据具体操作，而不是根据“助手很聪明”来授予。

## 6.3 行业案例：存在产品，但注意时间与证据

### Morgan Stanley：知识与会议工作流

Morgan Stanley 在 2024 年发布 AI @ Morgan Stanley Debrief，定位包括客户会议笔记、摘要和后续沟通初稿。[1] 这是明确的工作流产品，但属于历史发布案例，不能把 2024 年的采用口径更新成 2026 年客户数字。

本次能够确认官方公告摘要，但相关站点正文访问超时。因此，本章只保留产品定位，不引用未经本次核验的用户比例、收益或新版本能力。

### Klarna：2026 年继续进入购物与支付入口

Klarna 2026-05-20 的官方公告摘要介绍了在 ChatGPT 中推出 Shopping Search 应用。[2] 它说明金融服务公司正在向商品发现入口延伸；不能由此推断已开放自主信贷审批或所有支付执行。

该网页正文存在人机验证，2025 年年报本次读取也受到访问限制。因此，本章不沿用“客服节省 4,000 万美元／年”“等效 700 岗位”作为最新经营结果，更不将历史工作量等效直接写成实际裁员人数。

这种保留并不意味着产品无效，而是说明**当前可核验材料不足以支持更强的结论**。

## 6.4 研究 Agent 不是自动获利机器

研究流程适合使用 Agent 整理公告、核对数据和运行已批准的计算，但模型生成的解释不等于可靠预测。

设计评测时至少要避免：

- 把未来信息混入历史回测；
- 忽略费用、滑点和流动性；
- 只展示最好的一次结果；
- 将过去相关性理解为稳定因果；
- 把自动生成的数字当作已验证财务数据。

研究交付物应包含来源、数据期、计算过程和不确定性。涉及交易和客户权益的执行，应留在明确授权、限额和复核的业务系统中。

## 6.5 适合金融的有界执行架构

建议将模型与可信执行层分离：

1. **证据层**：检索原始文件，保留日期、版本和访问权限。
2. **计算层**：使用确定性程序计算金额、利息、差额和统计量。
3. **决策支持层**：模型解释证据并提出下一步，不伪造缺失事实。
4. **授权层**：校验用户、账户、任务、额度及审批状态。
5. **执行层**：通过受控接口完成操作，提供明确业务回执。
6. **审计层**：记录请求、输入、工具版本、批准与结果，并按需要脱敏。

MCP 的授权规范可用于部分工具接入，但不会替金融机构定义业务审批规则。[3] 协议连接成功不等于操作获得批准。

## 6.6 商业价值必须包含错误成本

客服不能只看自动回复比例，还要看一次解决率、重复联系、人工升级、客户损失和投诉。内部研究不能只看草稿生成速度，还要看复核和纠错时间。

建议按“最终完成且质量合格的任务”核算成本：

\[
\text{单位完成成本}=\frac{\text{模型、工具、人工复核、运维与错误处理总成本}}{\text{合格完成任务数}}
\]

未完成、重试和转人工消耗都应进入分子。用咨询量增长带来的总客服费用上升，直接否定单位效率改善不合理；反过来，只展示自动化比例而不披露总成本也不充分。

## 6.7 机会与现实约束

**本章判断：**有来源的文档处理、权限感知检索、对账异常和客户服务辅助，比无边界的自主投资 Agent 更容易建立可验收的交付标准。

独立团队的优势可能来自特殊业务材料、系统连接和评测集，而不是一个通用聊天界面。障碍包括数据权限、历史系统、组织责任与采购验证，不能仅靠更长上下文解决。

> 金融 Agent 的核心价值是降低完成可靠业务流程的成本，而不是让模型获得更多未经约束的决策权。
