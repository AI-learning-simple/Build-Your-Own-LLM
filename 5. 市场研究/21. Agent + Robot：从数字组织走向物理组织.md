# 21. Agent + Robot：从数字组织走向物理组织

在前面几章中，我们先后讨论了 **Agent Economy** 与 **Agent-Native Enterprise**。

前者解决的是：

> Agent 如何参与经济活动。

后者解决的是：

> Agent 如何组成一个组织。

但这些组织目前仍然主要存在于：

```text
软件
数据
网络
企业系统
```

真正的下一步是：

> **让 Agent 进入物理世界。**

当 Agent 能够控制：

```text
机器人
机械臂
无人车
无人机
生产线
仓库
农业设备
家庭设备
```

Agent 就从：

> **Digital Worker**

变成：

> **Physical Worker。**

这意味着 Agent 时代开始真正进入物理生产。

---

# 21.1 从 Digital Agent 到 Physical Agent

可以把演进过程理解成：

```text
LLM
 ↓
Agent
 ↓
Agent + Tools
 ↓
Agent + Computer
 ↓
Agent + Robot
 ↓
Physical Agent
```

前几个阶段主要操作：

```text
信息
软件
数据
```

而最后一个阶段开始操作：

```text
物体
机器
环境
空间
```

---

# 21.2 软件世界与物理世界的根本区别

软件世界：

```text
输入
 ↓
计算
 ↓
输出
```

错误通常可以：

```text
Undo
Rollback
Retry
```

物理世界则不同：

```text
Action
 ↓
Physical State Change
```

一旦机械臂：

> 撞坏设备。

通常不存在：

```text
Ctrl + Z
```

因此：

> **Physical Agent 对可靠性的要求远高于 Digital Agent。**

---

# 21.3 Physical Agent 的基本闭环

一个机器人 Agent 最基本的循环是：

```text
Observe
 ↓
Understand
 ↓
Plan
 ↓
Act
 ↓
Observe
```

也就是：

> **感知（Perception）→ 规划（Planning）→ 行动（Action）→ 反馈（Feedback）**

这和传统软件 Agent 的：

```text
Think
 ↓
Tool
 ↓
Result
```

有本质区别。

---

# 21.4 为什么机器人必须持续闭环

假设 Agent 要：

> 把杯子放到桌面。

数字 Agent 可以：

```text
调用 API
 ↓
返回成功
```

机器人却必须考虑：

```text
杯子在哪里？
手在哪里？
桌子在哪里？
障碍物在哪里？
抓到了吗？
杯子滑了吗？
放稳了吗？
```

因此：

> **Physical Agent 不能只依赖一次性 Planning。**

---

# 21.5 Physical Execution Loop

可以抽象为：

```text
┌───────────────┐
│   Perception  │
└───────┬───────┘
        ↓
┌───────────────┐
│ World State   │
└───────┬───────┘
        ↓
┌───────────────┐
│    Planning   │
└───────┬───────┘
        ↓
┌───────────────┐
│    Action     │
└───────┬───────┘
        ↓
┌───────────────┐
│   Feedback    │
└───────┬───────┘
        └──────────→ Perception
```

这实际上就是：

> **Physical Execution Loop。**

---

# 21.6 与我们之前讨论的 Execution Trajectory 的关系

前面讨论 Agent 架构时，我们提出：

这个思想在机器人上更加重要。

> “把仓库里的红色箱子拿过来。”

否则：

> LLM 的语言空间和机器人的物理执行空间之间存在巨大鸿沟。

---

# 21.8 VLA 的作用

> Vision-Language-Action（VLA）

成为具身智能的重要路线。

它尝试建立：

```text

+

 ↓
Action
```

也就是：

> 从视觉与语言直接预测动作。

---

# 21.9 但 VLA 不等于整个 Robot Agent

这是非常重要的一点。

VLA 更接近：

> **Action Model。**

完整机器人 Agent 仍然需要：

```text
Goal
 ↓
Task Planning
 ↓

 ↓

 ↓

 ↓

```

因此：

> VLA 是机器人 Agent 的核心模型之一，但不是整个 Agent 系统。

# 21.10 Robot Agent 的分层结构

一个比较完整的架构可以是：


不同层解决完全不同的问题。

---

# 21.11 Planning 和 Control 不能混在一起

例如：

> “把货物放到 B 区。”

这是：

```text
Planning
```

而：

```text

```

属于：

```text
Control
```

两者的时间尺度不同。

---

# 21.12 多时间尺度

机器人 Agent 通常需要：

```text
Long Horizon
    ↓
Mission Planning

Medium Horizon
    ↓
Task Planning

Short Horizon
    ↓
Motion Planning

Very Short Horizon
    ↓
Control
```

例如：

```text
10 min
→ 完成仓库补货

1 min
→ 完成一组搬运

100 ms
→ 修正机械臂轨迹

1 ms
→ 电机控制
```

---

# 21.13 为什么不能让 LLM 控制电机

因为：

```text
LLM
```

不适合直接处理：

```text

10ms
100Hz
```

级别的实时控制。

所以必须形成：

```text

 ↓
Task
 ↓
Policy
 ↓
Controller
 ↓
Motor
```

# 21.16 Physical Capability



---

# 21.17 Capability 不应该暴露底层电机

例如：

不应该让 Agent 直接调用：

```text

```

而应该提供：

```text

```

也就是：

> **Semantic Capability。**

> Skill / Task 层能力。

# 21.57 行业实践：Figure、Optimus 与人形机器人的商业化元年

本章的概念——Physical Agent、Physical Cloud——在 2025 到 2026 年间开始有了第一批商业坐标。

```text
Figure：其 Figure 02 机器人在宝马工厂
参与试点作业（箱体搬运，约 20 秒每箱），
公司估值达到约 390 亿美元

Tesla Optimus：进入特斯拉自有工厂
承担搬运类任务，对外演示持续迭代

1X：家用机器人 NEO 开放预订，
探索家庭场景的订阅模式

Apptronik：估值约 55 亿美元，
Apollo 机器人面向物流与制造
```

为什么人形机器人突然从演示走向了部署？

因为基础模型补上了最后一块拼图：VLA（视觉-语言-动作）模型。传统工业机器人是“固定程序 + 精确重复”，换一个任务就要重新编程；VLA 架构的机器人可以接受自然语言指令、泛化到没见过的物体——这正对应本章“Agent 是大脑、Controller 是脊髓”的分层：大模型负责理解与规划，实时控制器负责物理执行。

但要诚实地区分两件事：

```text
结构化场景（工厂、仓库）：
环境可控、任务重复 → 已经开始商业试点

非结构化场景（家庭、开放世界）：
长尾无限、安全要求极高 → 仍是数年之外
```

受影响的人群：

* 仓储与产线工人：第一批与物理 Agent 竞争的体力岗位，但试点期更多是“人机混班”；
* 危险作业工种（高空、高温、有毒环境）：机器人替代的正当性最强、阻力最小的方向；
* 机器人运营商：Physical Capability as a Service 的商业模式正在成型——按小时租用机器人而非购买；
* 制造业国家：劳动力成本优势在物理 Agent 的单位成本曲线面前需要重新定价。

物理组织的启示：数字 Agent 的边际成本趋近于零，而物理 Agent 有真实硬件成本——这决定了两条曲线的速度差异。数字组织先行十年，物理组织是慢变量，但它的终态影响更深：当生产本身可以按需组合，制造业的全球化逻辑都会被重写。
