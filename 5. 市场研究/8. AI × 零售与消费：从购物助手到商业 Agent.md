# 8. AI × 零售与消费：从购物助手到商业 Agent

> **研究更新日：2026-11-25。** 重点区分推荐、加购、支付与履约。产品范围以有日期的公告为准，不将首发计划当作今天已经全面实现的功能。

## 8.1 从搜索关键词到表达需求

消费者购物通常需要发现商品、核对规格、比较价格、确认配送、付款和处理售后。AI 可以减少信息整理和跨页面操作，但不能消除库存、支付、配送和退货等交易约束。

因此，商业 Agent 不应只评估“推荐是否像人”，还要评估商品信息是否准确、最终价格是否真实、操作是否获准、订单能否被追踪。

## 8.2 最新产品变化：Rufus 已不只是原来的 Rufus

Amazon 的官方文章首次发布于 **2026-05-13**，在 **2026-11-13** 更新国际可用范围，介绍将 Rufus 与 Alexa+ 整合为 **Alexa for Shopping**。[1]

文章披露 Rufus 在 **2025 年帮助过超过 3 亿名顾客**。这是使用覆盖，不是月活、付费用户或独立买家成交量。

截至该次更新，文章列出美国、英国、德国、法国、意大利、西班牙、加拿大、日本、印度、巴西、墨西哥、奥地利和澳大利亚等 13 国的正式提供，以及阿联酋、土耳其的测试版。平台包括 Amazon Shopping 应用、网站和 Echo Show，但不能据此认定所有地区功能完全相同。

列出的功能包括商品问答、比较、价格历史和购物任务；AI 概览仍在扩大覆盖。**功能已存在、功能正在扩量、地区尚在测试，是三个不同状态。**

本次可核验页面没有“120 亿美元增量销售”数据，因此不将该数字继续作为本章的收益锚点。即便其他公告存在类似估算，也需要核验归因方法，不能用用户相关性证明因果。

## 8.3 交易基础设施：ACP 与 UCP

| 项目 | 可核验时间与主体 | 解决的问题 | 不代表什么 |
|---|---|---|---|
| Agentic Commerce Protocol，ACP | OpenAI 于 2025-09-29 公告，与 Stripe 及商家伙伴共同开发 | Agent 与商家间的交易流程 | 自动覆盖全球商家 |
| Universal Commerce Protocol，UCP | Google Developers 于 2026-01-11 介绍，与 Shopify、Etsy、Wayfair、Target、Walmart 共同开发 | 商务能力与结账等共同语义 | Amazon 主导或 2025 年已统一成型 |

ACP 首发公告中的 Instant Checkout 面向美国 ChatGPT 用户和美国 Etsy 卖家，其他商家及地区当时部分属于计划。[2] 这是历史首发范围，不是当前覆盖清单。

UCP 支持与既有 API、MCP、A2A 和支付相关机制配合，Google 的参考落地也有商家资格与接入要求。[3] 协议开放，不等于每个商家已经支持，也不等于交易责任被协议接管。

## 8.4 谁控制入口，谁完成交易

零售 AI 的竞争至少涉及三类参与者：掌握用户入口的平台、掌握商品和库存的商家，以及承担支付和履约的服务商。

推荐入口可以变化，但以下信息必须由权威业务系统提供：

- 商品标识、规格、变体和当前库存；
- 含税费与运费的最终价格；
- 可交付范围、预计时间与退货条件；
- 支付状态、订单号和退款状态。

模型不应根据历史页面猜库存，也不应在价格变化后沿用旧授权。商家提供结构化、可更新的数据，比单纯增加营销文案更重要。

## 8.5 一个受控购物 Agent 的边界

建议按交易阶段设置权限：

1. **发现与比较**：只读；明确广告、推荐与用户偏好的来源。
2. **建立购物车**：限定商品和数量，展示替代品和总价变化。
3. **提交支付**：要求明确授权；必要时再次确认金额、收货信息与条件。
4. **查询与售后**：以商家回执为事实来源，撤销、退款分别处理。
5. **异常恢复**：超时后先核对订单是否创建，不能直接重复付款。

定时购买还需要预算、有效期、商品条件和撤销机制。不能把“帮我看看有没有优惠”解释为无限期购买授权。

## 8.6 商业模式与真实指标

平台可能通过流量、订阅、商家服务或交易相关收费变现；具体费率和归因必须依据当时合同。独立开发者可寻找商品数据治理、垂直选型、企业采购和售后协作等需求。

建议同时跟踪：推荐后购买、支付成功、履约成功、退货、取消、客服升级、客诉与净毛利。只提高加购率，却增加退货或损害信任，不是完整的商业收益。

**本章判断：**购物 Agent 正从问答延伸到交易工作流，但它更可能先在合作商家和明确授权的环境中落地。跨任意网站、任意品类自主购买，不应作为默认能力。

> 商业 Agent 的成熟标志，不是能替用户点多少次按钮，而是能否把一笔被明确授权的交易正确完成，并处理失败与售后。
