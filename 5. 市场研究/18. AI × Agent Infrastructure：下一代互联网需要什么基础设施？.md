# 18. AI × Agent Infrastructure：下一代互联网需要什么基础设施？

> **研究更新日：2026-11-25。** 基础设施需求来自任务规模、可靠性与安全要求，而不是“未来会有多少亿 Agent”的未经验证推算。本章区分规范、框架能力与建议架构。

## 18.1 不必重新发明互联网

HTTP、数据库、消息队列、身份系统和云运行时已经支持大量机器协作。Agent 增加了动态选择工具、长时间等待、非确定性输出和人工介入，但仍可以复用成熟基础设施。

真正需要加强的是：将模型输出转成受控任务，让任务在失败后可恢复，让副作用不会随重试重复发生，并能解释每个结果的成本与证据。

## 18.2 三类连接，不是一条固定协议栈

| 协议 | 主要连接对象 | 核心能力 | 本次版本／状态 |
|---|---|---|---|
| MCP | Agent 应用与工具、资源服务 | 能力接入及相关交互 | 授权页标注 2026-07-28 |
| A2A | 独立 Agent 系统 | 任务、消息、状态、产物 | 最新发布版 1.0.0 |
| AG-UI | 用户侧应用与 Agent 后端 | 流式事件、状态和交互 | 动态文档，按访问日记录 |

三者是功能互补关系，不是像网络分层那样每次请求都必须经过的严格栈。[1][2][3]

AG-UI 支持把进度、交互和人工参与传到界面，但“展示审批按钮”不等于服务端已经强制校验授权。A2A 描述任务协作，也不自动保证外部副作用恰好发生一次。

## 18.3 运行时应该管理什么

一个任务的可靠运行至少需要以下能力：

| 能力 | 解决的问题 | 不足时的后果 |
|---|---|---|
| 任务状态与持久化 | 记录执行进度 | 中断后只能从头开始 |
| 调度、并发与预算 | 控制资源消耗 | 队列拥堵和费用失控 |
| 工具执行与隔离 | 限制访问范围 | 越权和环境污染 |
| 重试与幂等 | 处理暂时故障 | 重复创建、付款或发送 |
| 人工介入 | 处理需要批准的动作 | 不确定任务被强行执行 |
| 可观测与评测 | 定位失败和版本退化 | 只有“成功／失败”，没有原因 |

模型本身不应成为唯一的状态存储。上下文窗口里的一段文字，也不等于可靠保存的任务记录。

## 18.4 检查点不等于业务事务

LangGraph 的持久化文档描述了通过 checkpointer 保存线程状态，以及跨线程 Store 等机制。[4] 内存后端在进程结束后不能提供持久恢复，需要选择适当的持久化后端与保留策略。

但图状态保存与外部业务操作不是同一事务。例如订单已经创建，Agent 尚未保存回执时进程终止；恢复后若直接重做，就可能创建第二笔订单。

因此，以下属于应用必须补齐的设计：

- 为业务写操作设置稳定的操作标识和幂等键；
- 在结果不明时先查询权威系统，而不是盲目重试；
- 区分未开始、处理中、成功、失败和结果未知；
- 对无法撤销的动作保留人工升级路径；
- 明确哪些节点恢复时可能再次运行。

选框架不能只看是否有“持久化”功能，还要测试实际故障时的副作用。

## 18.5 工具、数据与安全的共同边界

工具网关可以统一认证、限流、版本、参数校验和日志，但不应把所有后端接口包装后无差别暴露给模型。

权限需要贯穿检索和执行：用户不能读的文档，不应先进入模型上下文再要求模型保密；用户不能批准的付款，也不能因为 Agent 已生成理由而放行。

Trace 应记录模型与工具版本、任务输入摘要、耗时、成本、状态和业务回执。敏感信息应脱敏，必要材料设置保留期限。可观测性不是收集一切数据。

## 18.6 用结果评测，而非用调用量评价基础设施

运行平台应至少支持：

- 离线固定任务集与错误样本；
- 模型、提示词、工具和协议版本回归；
- 超时、断网、重试和权限撤销测试；
- 线上抽检、人工复核与故障归因；
- 单位合格任务的总成本与完成时延分布。

同一个“成功率”必须说明分母、任务难度、是否允许人工帮助以及评价方法。不能把 API 返回 200 或 Agent 自报完成当作业务完成。

## 18.7 商业机会和平台竞争

买方包括应用团队、企业平台团队和服务商。可以形成产品的方向包括连接器质量、运行托管、持久化、权限控制、评测与成本管理。

**本章判断：**这些需求真实，但并不保证每一层都会成为独立公司。云平台、模型平台、应用厂商和开源组件可能同时提供相近能力。独立产品需要证明跨平台价值、集成优势或明确的可靠性收益。

如果一个普通工作流配合现有队列和数据库就能解决问题，就没有必要先建设庞大的“Agent OS”。基础设施应随真实瓶颈增长。

> 下一代 Agent 基础设施的关键，不是让模型无限运行，而是让任务在预算、权限与质量约束下可靠结束。
