# 5. AI × 汽车与航空航天——智能驾驶与自主系统

汽车是一个非常特殊的产业。

它既是制造业产品，又是移动计算平台；既需要大量机械工程，又越来越依赖软件和 AI。

如果说上一章的半导体回答的是：

> AI 运行在哪里？

那么汽车回答的是：

> **AI 如何开始控制一个真正高速运动的物理系统？**

进一步延伸到航空航天，则会遇到更加极端的问题：

> **当机器运行在几乎无法人工干预的环境中，AI 应该承担多少决策？**

因此，汽车与航空航天可以帮助我们理解 AI 从：

```text
Information Intelligence
```

走向：

```text
Physical Autonomy
```

的过程。

---

## 一、汽车正在从机械产品变成计算平台

传统汽车的核心结构可以简单理解为：

```text
Engine
+
Transmission
+
Chassis
+
Mechanical Systems
```

现代汽车则越来越接近：

```text
Sensors
+
Compute
+
Software
+
Network
+
AI
+
Mechanical System
```

尤其是新能源和智能汽车的发展，使汽车逐渐成为：

> **一台能够移动的计算机。**

但它又比普通电脑复杂得多。

因为电脑出错，通常只是程序崩溃。

汽车出错，则可能影响人的生命安全。

## 五、多传感器融合

单一传感器通常存在局限。

例如摄像头：

```text
视觉信息丰富
但受光照影响
```

Radar：

```text
距离和速度信息好
但语义理解能力有限
```

LiDAR：

```text
三维几何信息丰富
但成本和环境因素需要考虑
```

因此自动驾驶需要：

> Sensor Fusion。

可以理解为：

```text
Camera
   \
Radar ----→ Fusion → World Model
   /
LiDAR
```

## 十一、自动驾驶为什么需要“实时性”

假设车辆以：

```text
100 km/h
```

行驶。

车辆每秒前进大约：

```text
27.8 米
```

如果系统延迟几秒才做出决策，车辆已经移动了很远。

所以自动驾驶系统必须同时满足：

```text
智能
+
实时
+
稳定
+
可验证
```

这也是为什么自动驾驶不能简单理解成：

> 把一个大模型放进汽车。

## 十二、大模型会不会直接驾驶汽车


## 十三、这与具身智能中的“分层 vs 端到端”高度一致

## 三十六、行业实践：Waymo 与端到端的分野

自动驾驶是 Agent 进入物理世界最早、也最残酷的试验场。

Waymo 是规则式路线走到头之后转向数据驱动的代表。到 2025 年，Waymo 的无人驾驶付费出行已经扩展到多个美国城市，每周付费行程达到数十万量级——这个数字在 2024 年还只是它的零头。更重要的是它证明了商业模式：去掉安全员之后，单公里成本结构第一次成立。

Tesla 走的是另一条路：FSD（Supervised）装在数百万辆量产车上，用真实道路数据迭代端到端模型。2024 年底发布的 V12 版本彻底转向端到端架构——感知、预测、规划不再分别写规则，而是由神经网络直接从像素到轨迹。

两条路线的分野，恰好对应本章讨论的范式问题：

```text
规则式 ADAS：
工程师穷举场景 → 写规则 → 长尾永远写不完

端到端 / VLA：
数据驱动 → 模型泛化 → 长尾由规模解决
```

这本质上是“传统软件”与“Agent”的分界线在汽车行业的重现：前者是人把世界编码成规则，后者是模型从数据里学出对世界的反应。

受影响的人群已经非常具体：

* 网约车司机：Waymo 运营城市的部分行程已经由无人车完成，这是 Agent 对一个职业的直接替代；
* 私家车车主：驾驶任务从“全程操作”变为“监督接管”；
* 事故责任体系：保险、法规、车企的责任划分被重新洗牌。

汽车行业的启示：物理世界的高风险 Agent，落地路径不是“能力渐进”，而是“地理围栏 + 安全冗余下的规模爬坡”——先在一小片区域做到比人安全，再扩张。
