# 3. AI × 制造业——智能工厂与 AI Native Factory

> **研究更新日：2026-11-25。** 本章将传统工业 AI、工程 Agent 与生产控制分开讨论。“AI Native Factory”是组织和架构方向，不是已经统一定义、全面实现的工厂等级。

## 3.1 工厂并不天然拥有可直接使用的数据

制造业拥有 ERP、MES、PLM、SCADA 和 PLC，但系统存在不等于信息完整互通。设备编号可能不一致，工艺版本可能滞后，停机原因依赖人工填写，旧设备甚至没有可靠的数字接口。

过去，工程师和班组长承担了大量跨系统解释工作：看图纸、查手册、追踪物料、判断故障、安排工序。AI 的价值往往首先出现在这些信息密集环节，而不是接管整条生产线。

## 3.2 三种不同的产品市场

| 市场 | 主要技术与产品 | 买方 | 更合适的验收指标 |
|---|---|---|---|
| 单点工业智能 | 视觉质检、异常检测、预测性维护 | 质量与设备团队 | 漏检率、误报、停机、维护成本 |
| 工程 Copilot／Agent | 手册检索、代码草稿、配置与验证 | 自动化工程团队 | 含复核的工程工时、测试通过率 |
| 运营优化 | 排程、能耗优化、异常工单 | 工厂运营团队 | 交付、在制品、能耗、总成本 |

这三类产品可能组合，但不能把视觉质检装机量当成工业 Agent 客户量。生产优化也必须考虑物料、人员、设备和质量约束，不能只优化一个局部指标。

## 3.3 2026 年案例：Eigen Engineering Agent

Siemens 在 **2026-04-20** 的官方新闻稿中宣布 Eigen Engineering Agent 商用，面向 TIA Portal 工程环境，覆盖 PLC 编程、HMI 可视化和设备配置等任务。[1]

公告有两个容易混淆的数字：

- **超过 60 万 TIA Portal 用户**：指相关平台的用户基础，不是已经购买 Eigen 的客户数量。
- **工程效率最高提升 50%**：是西门子对指定自动化工程任务的宣称，不是全厂生产率、平均交付周期或利润提升 50%。公告未公开完整独立验证方法。

因此，正确理解不是“无人化工厂已经实现”，而是**AI 从生成建议进一步进入既有工程工具的任务执行与校验环节**。产品是否适合某个项目，还要核对软件版本、部署方式、授权和测试流程。

## 3.4 另一个证据：机器人也仍按工位验收

BMW 在 2026-06-25 的披露中回顾了 Figure 02 在车身车间放置钣金件的试点，并介绍 Figure 03 的新物流排序项目。[2]

前者辅助了超过 30,000 辆 BMW X3 的生产，但不是机器人独立制造了这些汽车。后者当时仍是新用例演示与项目启动，没有公开相同口径的长期产出数据。

这类案例提示我们：即便在高度组织化的工厂，物理智能也要从工位、物料和节拍边界清楚的任务开始。详见[第 21 章](<21. Agent + Robot：从数字组织走向物理组织.md>)。

## 3.5 一个可靠的工程闭环

以下是建议的职责链，而非厂商产品规格：

1. **读取上下文**：设备型号、项目版本、工艺约束和批准的技术文档。
2. **生成变更**：形成代码、配置或排程候选，不直接覆盖生产版本。
3. **静态与仿真校验**：语法、接口、边界条件、互锁和回归测试。
4. **人工批准**：由有责任的工程人员评估差异和风险。
5. **受控发布**：维护窗口、版本留档、回退计划和变更权限。
6. **现场验证**：记录异常、节拍、质量与接管，检查预期收益是否兑现。

大模型不能替代安全 PLC、急停、机械防护或实时控制系统。生产网络也不能因为接入 Agent 就向所有工具开放写权限。

## 3.6 怎样计算“节省”

假设某任务的代码生成更快，但需要额外检查、仿真和现场修复，最终净节时可能小于生成环节的提速。评价单位应是**通过验收的工程变更**，而不是生成代码的行数。

项目看板至少需要：

- 工程准备、生成、复核、调试和返工的总时间；
- 同类任务的首次通过率与缺陷逃逸率；
- 生产切换期间的停机和回退；
- 跨设备、跨产线复制时的额外集成工作；
- 软件、算力、数据整理和持续运维成本。

OEE 等综合生产指标同时受到产品组合、原料和人员影响。没有控制这些因素，就不能将上线前后的全部变化归因于 AI。

## 3.7 商业机会与落地障碍

**已有产品方向**是把 AI 嵌入工程和运营软件。**本章判断**是，垂直团队更适合寻找平台尚未充分覆盖的任务：特定设备的故障定位、工艺知识整理、工单质量控制或跨系统变更追踪。

主要障碍不是单一模型分数，而是：

- 行业和工厂之间的数据、设备和流程差异；
- 现场知识难以完整转成文档；
- 采购、验证和部署周期长；
- 软件收益与硬件停机风险不对称；
- 平台内置能力与独立产品的竞争。

> 智能工厂的进展应以“更多任务可以可靠、可追溯地完成”衡量，而不是以装了多少 Agent 衡量。
