# 12. AI × 金融与保险：从智能投顾到金融 Agent Network

> **研究更新日：2026-11-25。** 本章侧重投顾、保险核保与理赔；金融机构内部运营见第 6 章。“Agent Network”是协作架构，不意味着 AI 可以独立承担投资或保险责任。本章不构成投资建议。

## 12.1 两个市场，不同的验收方式

投顾围绕客户目标、风险承受能力、资产配置和持续服务；保险围绕风险定价、保障承诺、理赔及资本约束。它们都处理大量文件，但最终产品不是文件，而是对客户权益有影响的决策与服务。

规则型自动投顾、传统风险模型和自动理赔已经存在。LLM 可以增加对话和文档理解能力，但不能把既有业务规模全部算成生成式 AI 的新增市场。

## 12.2 最新公司数据：Lemonade 2026 年第三季度

Lemonade 于 **2026-11-05** 发布第三季度结果。[1] 本次读取了官方股东信，关键数据如下。[2]

| 指标 | 2026 年第三季度披露 | 准确解释 |
|---|---|---|
| In Force Premium，IFP | 15.51 亿美元，同比增长 34% | 在保业务的年化保费规模，不是季度收入 |
| 客户数 | 3,520,555，同比增长 23% | 公司客户，不是 AI Agent 独立用户 |
| 季度收入 | 3.36 亿美元，同比增长 73% | 财务收入口径，不能与 IFP 相加 |
| 季度净亏损 | 4,400 万美元 | 不能因规模增长就称公司已盈利 |
| 当季毛损失率 | 65%；上年同期 62% | 与过去 12 个月毛损失率不是同一指标 |

这些数据说明公司经营规模及承保表现，**没有提供“AI 导致了多少增长或利润”的独立因果分解**。损失率还受到业务结构、赔付、灾害和前期准备金变化影响。

“秒级理赔”即便存在于特定简单案件，也不能代表所有案件，更不能证明复杂争议能够无人工处理。评价保险 AI 时，应同时看案件分布、人工升级、漏赔错赔和客户申诉。

## 12.3 AI 可以进入哪些工作流

| 场景 | 适当的自动化职责 | 需要控制的风险 |
|---|---|---|
| 投顾材料准备 | 汇总客户提供的信息、生成待审报告 | 信息缺失、风险偏好误判 |
| 组合监测 | 发现偏离、解释变化、提示复核 | 数据时点、计算错误、过度交易 |
| 核保材料处理 | 提取字段、核对材料、标记不一致 | 遗漏、误识别、无依据推断 |
| 理赔受理 | 收集材料、匹配保单、分派任务 | 条款版本和保障范围错误 |
| 简单理赔协作 | 按明确规则执行受控步骤 | 重复支付、异常案件误放行 |
| 复杂案件 | 组织证据并辅助责任人员 | 不应让模型自行编造拒赔理由 |

不同产品和人群需要分别验证。一个文档模型在常见模板上表现好，不代表能正确处理所有条款、附件与例外情形。

## 12.4 为什么不应追求“全自动决策”作为唯一指标

自动化比例越高，不一定越好。如果系统为了提高比例而减少必要复核，损失可能集中出现在低频复杂案件中。

更合理的是根据金额、复杂度、证据完整性和错误后果决定处理路径：

1. 标准且可验证的任务可自动完成限定步骤。
2. 信息缺失时请求补充，不能自动补出事实。
3. 判断依据冲突时转交专业人员。
4. 影响客户权益的决定应有可解释、可复核的依据。
5. 已执行付款和客户通知需要确认回执与后续纠错渠道。

这里的复核不是让另一个 LLM 表示同意，而是结合原始材料、业务规则和责任人员。

## 12.5 Agent Network 到底连接什么

保险流程可能涉及客户入口、保单系统、材料审核、服务商、付款和客服。拆分为多个服务可以降低耦合，但会增加身份、状态和一致性问题。

A2A 规范可以描述跨 Agent 的任务、状态与产物，本次访问的最新发布版为 **1.0.0**。[3] 它不替代合同、客户授权、业务审批或资金结算。

一次理赔任务完成，不代表整个案件已经结案。网络中需要统一案件标识、来源追踪、可恢复状态和明确责任方，避免多个 Agent 重复请求材料、重复批准或重复支付。

## 12.6 买方和单位经济

买方包括保险公司、服务机构和财富管理团队。可售产品可以是材料处理、辅助审核、工作流集成或持续质量监测。

尽调应看：每案总处理成本、处理周期分布、人工复核时间、错误赔付、重开与申诉、客户满意度，以及上线后样本结构是否变化。不能只计算模型调用费，也不能把人员工时减少全部视为立即可兑现的现金节省。

**本章判断：**更有说服力的市场切入点，是在不降低客户保障与决策质量的前提下，减少具体流程中的摩擦。已有软件平台的 AI 收入只能说明横向产品需求，不能替代保险行业自己的采用和收益证据。

> 金融与保险 Agent 的成熟度，体现在处理依据、授权、结果和责任是否都能追踪，而不是是否没有人工参与。
